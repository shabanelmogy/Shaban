# مرجع الإعدادات عند مراجعة شاشات سيجما

تاريخ التحقق المصدري: ١ نوفمبر ٢٠٢٦. هذا المرجع يشرح تقسيم الإعدادات
ويربطها بمراجعة الشاشات. لا يحوّل خيارًا محفوظًا إلى قاعدة أعمال مفعّلة؛
الأثر المثبت يحتاج مسار قراءة واستخدام فعليًا في الواجهة أو الخادم.

تملك [الكتلة الخلفية ١٦](../../backend/16-pattern-4-settings.md) نمط الحفظ،
وتملك [واجهة الإعدادات](../../ui/screens/06-tabbed-settings-workspace.md)
شكل الشاشة. أما الحقول الموجودة فتجدها في
[فهرس الحقول والأقسام](FIELD_CATALOG.md)، وتفاصيل تنفيذ التنسيق في
[مراجعة المهمة](<F:/My Work/Sigma/reviews/SETTINGS_LAYOUT_FEATURE_REVIEW.md>).

## كيف تستخدم المرجع في مراجعة شاشة؟

١. حدد عائلة الشاشة من الجدول أدناه، ثم راجع الحقول ذات الصلة في الفهرس.
اسم الخيار يرشح معناه؛ لا يثبت وحده أنه موصول أو أنه قاعدة مالية معتمدة.

٢. تتبع المسار كاملًا: صفحة الإعدادات ← خدمة القراءة والحفظ ← الحقل المخزن
← مالك السياسة أو الخدمة المستهلكة ← سلوك الشاشة والتحقق الخلفي. سجّل
الخاصية والملف والسطر، وما يحدث عند غياب الإعداد أو فشل تحميله.

٣. ميّز بين اختيار واجهة، وافتراضي مستند جديد، وتحقق إلزامي، وحساب أو ترقيم
يملكه الخادم، وتفضيل عرض أو طباعة. تغيير العرض لا يُسقط تحقق الخادم،
والإخفاء ليس صلاحية، وإعداد جديد لا يعيد كتابة التاريخ المالي تلقائيًا.

٤. سجل الحالة: «استهلاك مثبت»، أو «محفوظ والاستهلاك غير مثبت في نطاق
المراجعة»، أو «تغطية جزئية»، أو «قرار مطلوب». عدم وجود استخدام مثبت
يعني فجوة تتبع أو تنفيذ؛ لا يعني حذف الخيار أو اختراع سلوكه.

٥. راجع نطاق الاشتراك والمفتاح المنطقي، وافتراضيات الغياب، وعمر القراءة
والكاش والإبطال، وحماية مسودة المستخدم، وأثر التغيير على السجلات السابقة.
اربط النتيجة بعقد الشاشة ودليلها وباختبار المالك المطلوب.

|---|---|---|
| النظام والعرض | العامة، الملف التعريفي، إدارة المستخدمين، مفاتيح الربط | التنسيق المحلي والوقت، صور الطباعة، خيارات التسجيل والمساعدة التجريبية؛ تتحقق من المستهلك الفعلي لكل اختيار |
| المستندات والأرقام | ترقيم المستندات | عند إنشاء رقم أو كود أو السماح بإدخاله يدويًا؛ تتبع مولد الخادم بدل توليد رقم منافس في الواجهة |
| الحقول والمستندات | الحقول، النماذج والحقول، مستندات العقود، تنسيق الهوية | عند إظهار حقل أو إلزامه أو ضبط وثيقة أو صيغة هوية؛ تثبت الربط والتحقق على الجانبين |
| التشغيل والتأجير | العامة، الليموزين، المعدات، الورشة، العطلات | الحجوزات والعقود والحركات والرحلات والجداول؛ لا تخلط بين سياسة مدة/تسعير وخيار عرض |
| الفوترة والمالية | العامة، الرسوم، الوسيط، الخصم المباشر، بوابة الدفع، مراكز التكلفة | الضريبة والرسوم والدفعات والتخصيص والأبعاد؛ الحساب والتحقق في المالك الخلفي، ولا تُخزن نتائج المسودة كسلطة |
| التكامل والتنبيهات | سالك، درب، المخالفات، الإشعارات، مفاتيح الربط | حسابات الجهات والتحديث والتنبيهات؛ تعديل إعداد لا يعني استدعاء جهة خارجية أو إرسال رسالة |
| الموارد البشرية | الموارد البشرية، العطلات، العامة | السياسات المرتبطة بالموظفين والجداول والعطلات؛ تميّز الاسم المشابه عن الإعداد الذي يقرأه المسار فعلًا |

## صفحات الوحدة الأربع والعشرون

تبدأ المسارات أدناه من صفحة الإعدادات. أسماء مالكي النقل هي أسماء المسارات
الفعلية في خدمة الواجهة، وليست ادعاء بمطابقة كل خدمة لنمط الحفظ الحديث.

| الصفحة | المسار الفرعي | مالك النقل | حدود الاستخدام أثناء المراجعة |
|---|---|---|---|
| العامة | `common` | `SettingsCommonModel` | إعدادات عامة متعددة المجالات؛ راجع القسم والحقل والمستهلك، وليس الصفحة كلها كقاعدة واحدة |
| الملف التعريفي | `profile` | `SettingsProfileModel` | ترويسة وشعار؛ اربطهما بمخرجات الطباعة الفعلية |
| الترقيم | `documentNumber` | `SettingsDocumentNumberModel` | البادئات والأجزاء والأطوال واليدوي؛ لا تفترض استخدام كل خيار لكل مستند |
| إدارة المستخدمين | `userManagement` | `RegistrationSettings` | خيارات التسجيل الحالية؛ لا تمنح آلية صلاحيات جديدة |
| سالك | `eSalik` | حسابات سالك وإعداداتها الرئيسية | صفوف الحسابات وإعدادات المعالجة؛ بيانات الجهة ليست جدول إعدادات فرديًا موحدًا |
| درب | `eDarb` | حسابات درب وإعداداتها الرئيسية | تميّز حسابات الجهة عن إعدادات الفوترة الرئيسية |
| الخصم المباشر | `directDebitAuthorizationSetting` | `DirectDebitAuthorizationSetting` | حقول تهيئة الخصم؛ لا تثبت عملية بنكية منفذة |
| الليموزين | `limousineSettings` | `LimousineSettings` | خيارات الرحلات والتوزيع والفوترة؛ توجد أمثلة استهلاك خلفي مثبتة أدناه |
| الإشعارات | `notificationsSettingsModel` | `NotificationsSettingsModel` | إعدادات بطاقة الفحص وواتساب وصفوف أحداث الحجز؛ الحفظ لا يساوي الإرسال |
| بوابة الدفع | `paymentGatewaySetting` | `PaymentGateway` | طريقة الدفع والمفاتيح والرابط؛ لا تعتمد نجاح الدفع من إعداد الرابط |
| مستويات الاعتماد | `approvalLevel` | `ApprovalLevel` | ضبط الصفوف؛ لا يثبت أن كل مستند يستهلك هذه السياسة أو يطبق صلاحيات |
| الورشة | `workshopSetting` | `WorkshopSetting` | خيارات الورشة؛ راجع المستهلك الخلفي، لا مجرد نموذج الحفظ |
| المخالفات | `finesSettings` | `fines` | صفوف ملفات المرور وحواراتها؛ إجراءات الصف مستقلة عن حفظ إعدادات عامة |
| الرسوم | `chargeSettings` | `ChargeSettings` | مفتاح الوحدة/نوع الرسم/نوع المعدل؛ لا تنشئ حلقة حفظ لكل صف |
| الوسيط | `brokerSetting` | `BrokerSetting` | خيارات الوساطة؛ افصل التهيئة عن الحساب والأثر المالي |
| تنسيق الهوية | `nationIDFormat` | `NationalIdFormatSettingModel` | صفوف بلد/صيغة؛ تحتاج الشاشة المستهلكة إلى تطبيقها وتحققها |
| الموارد البشرية | `hrmSetting` | `HrmSetting` | إعداد الموارد البشرية تحت الإدارة؛ لا تخلطه بمالك مسار الموارد البشرية الآخر دون تتبع |
| مفاتيح الربط | `apiKeySetting` | `ApiKeySetting` ومالك المساعدة التجريبية | حفظ Google مستقل عن DeepSeek وتفضيلاته؛ لا تعرض مفاتيح سرية في سجل أو توثيق |
| مستندات العقود | `agreementDocument` | `AgreementDocument` | أسماء الوثائق والإلزام والطباعة والترتيب؛ تتبع تطبيق الإلزام فعليًا |
| النماذج والحقول | `formsAndFields` | `FormConfiguration` | حقول بحسب نوع النموذج؛ تختلف عن مجموعة الحقول الثابتة في الصفحة التالية |
| الحقول | `fields` | `FieldsSettings` | تسع عشرة مجموعة كيان، تحفظ معًا؛ وجود علم إلزام في الإعداد لا يثبت تحقق الشاشة |
| مراكز التكلفة | `costCenters` | `SettingsCostCentersModel` | الإلزام والاختيار؛ ليست قائمة تعريف مراكز التكلفة نفسها |
| المعدات | `equipment` | `EquipmentSettings` | إلزام جدول الوقت للفوترة كما يعرضه النموذج؛ يراجع ربطه الفعلي أثناء مراجعة الفوترة |
| العطلات | `holidaysSetting` | `SettingsHolidayModel` | قائمة تواريخ وأسماء؛ توجد قراءة مثبتة في جدول وقت السائق |

## الأقسام الداخلية الكبيرة

يبحث كل مربع بحث في أسماء التبويبات الموجودة في شريطه، سواء صفحات
الإعدادات أو الأقسام الرأسية أو المجموعات الداخلية. اكتب جزءًا من الاسم،
ثم اختر نتيجة أو امسح البحث لإعادة القائمة. تظل المسودة معروضة أثناء
الكتابة، ويفتح الحفظ قسم الحقل غير الصالح حتى إذا أخفته التصفية.

توضيح لاحق بتاريخ٢ نوفمبر٢٠٢٦: عندما يضم القسم أكثر من مجموعة، تظهر
المجموعات في تبويبات أفقية داخله، مع بقاء الأقسام الرئيسية رأسية. مثلًا
يضم العام والنظام تبويبي بيانات النظام والعملة وخيارات إضافية. تحافظ
التبويبات على القيم والحفظ الكلي وتفتح المجموعة غير الصالحة أثناء التحقق.

تحسين العرض بتاريخ٢ نوفمبر٢٠٢٦: تجمع البطاقات المعنونة الحقول المرتبطة
داخل القسم، وتفصل شبكة الإدخال عن صفوف الاختيارات. تتمدد التسميات الطويلة
دون قص، ويتوسط النص رأسيًا بجوار مربع الاختيار. يستجيب عدد الأعمدة لعرض
محتوى التبويب الفعلي، مع بقاء التمرير والحفظ والنموذج في مالكيها الحاليين.

تستخدم العامة ١١ قسمًا: العام والنظام، الضريبة والتسعير، التأجير والحركات،
الفوترة والمشتريات، المقبوضات والمدفوعات، العملاء وجهات الاتصال، الأسطول
والأصول، الورشة، التقارير والطباعة، الحجوزات وعروض الأسعار، والوقود.
هذا تصنيف عرض للحقول الحالية؛ لا يغيّر مفاتيحها أو نطاق حفظها أو دقتها الرقمية.

تستخدم صفحة الترقيم ٨ عائلات: العقود والتسليم، عروض الأسعار والاستفسارات،
الحجوزات، الفواتير والإشعارات، الشيكات وتحويلات البطاقات، السندات المالية،
الورشة، وأكواد البيانات الأساسية. تبقى عناوين الأنواع التفصيلية داخل عائلتها.

تستخدم الحقول ١٩ قسمًا حسب مجموعاتها الموجودة: العميل الفردي، الشركة،
المركبة، العقد، الإشعار الدائن، اليومية، فاتورة المورد، الدفع، المورد،
الموظف، الفاتورة، الصنف، الحساب، العمل، مرتجع الأصناف، طلب الشراء، عرض
التأجير، استفسار التأجير الطويل، وعرض الليموزين. تظهر المجموعة عندما تعيدها
قراءة الإعدادات. تغيير القسم يحافظ على نموذج الصفحة؛ الحفظ يشمل جميع أقسامه.

## شكل الحفظ الخلفي الذي يجب اختياره

تستخدم إعدادات السجل الواحد المالك المشترك للقراءة والحفظ بحسب الاشتراك،
مع إنشاء السجل عند أول حفظ، وقراءة آخر سجل عند وجود تكرارات قديمة. تستخدم
الإعدادات المتعددة مساعد التحديث بحسب المفتاح المنطقي ثم حفظًا واحدًا.
لا يحذف إغفال صف من طلب الحفظ إعدادًا قديمًا؛ الحذف عملية صريحة بعقدها.

تثبت خدمة الورشة والشاشات الست المنقولة استخدام أساس السجل الواحد. وتستخدم
الحقول والإشعارات المساعد المشترك. توجد فروق حالية في العامة والترقيم
ومراكز التكلفة والمعدات وغيرها؛ لذا يُقرأ نمط الخلفية والمصدر معًا قبل
تغيير شاشة. تحسين التنسيق لا يغلق هذه الفروق ولا يبرر نسخ المسار القديم.

يحتاج نقل مالك قديم إلى النمط الموحد شريحة عقد مستقلة تتتبع الكتّاب والقراء
والتحقق والافتراضيات والتكرارات والفهرس ومستهلكي واجهة البيانات. لا تنشئ
ترحيلًا أو تحذف بيانات ضمن إعادة ترتيب التبويبات.

## نموذج قرار يوضع في عقد الشاشة

| عنصر المراجعة | ما يجب تسجيله |
|---|---|
| الإعداد المعني | الصفحة، القسم، اسم الخاصية، نوعها ومجالها |
| مالك القراءة والحفظ | الخدمة والمسار، نطاق الاشتراك، المفتاح المنطقي، شكل الرد |
| الاستهلاك | الملف والدالة والسطر، واجهة/خادم، والنتيجة المرئية أو التحقق الفعلي |
| الغياب والفشل | القيمة الافتراضية الموثقة أو توقف الإجراء ورسالة إعادة المحاولة |
| التاريخ والمسودة | مستند جديد أم قائم، لحظة تثبيت القيمة، وعدم الكتابة فوق مسودة المستخدم |
| التحديث | المصدر المباشر أو الكاش المعتمد، الإبطال ومراقبة السياق عند الحاجة |
| التغطية | مثبت/جزئي/غير مثبت في النطاق/قرار مطلوب، مع سبب محدد |
| التحقق | الدليل المصدري، وما يجب أن يتحقق منه المالك بالتشغيل |

تظل قياسات السرعة، وظهور التنسيق، ولوحة المفاتيح، وسلوك الحفظ والجهات
الخارجية تحققًا تشغيليًا منفصلًا. هذا المرجع لا يمنح إذن تنفيذ أو تشغيل.
