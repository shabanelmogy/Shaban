## المصالحة المالية وعقد القراءة

| الاهتمام | التنفيذ |
|---|---|
| وحدة الرأس | الرأس و`Lines` دائمًا بالأساسية مع الهوية والكود والكسور الصريحة؛ لا استخدام لـ`CurrencyToBaseRate` لإعادة بناء الماضي |
| أصول العملات | عند طلب الأصل، `CurrencySections` مستقلة حسب العملة، وبكل قسم افتتاح ومدين ودائن وصافي وختام وسطور مرتبة بالتاريخ ثم القيد ثم السطر |
| أصل الإثبات | المبلغ الأصلي المخزن ولقطة الرأس المطابقة للاشتراك والمصدر والعملة والأساسية وتاريخ الاعتراف، بدقة صالحة وسعر مؤرخ سابق أو مساوٍ؛ لا معدل حالي ولا استنتاج مبلغ مفقود |
| نقص الإثبات | يُحجب قسم العملة المتأثرة كاملًا، حتى لا يبدو الجزء السليم رصيدًا كاملًا؛ يعود `OriginalAmountsIncomplete` للتحذير وتبقى كل سطور الأساس |
| الافتتاح | مجاميع SQL لسطور الحساب المرحلة غير الملغاة السابقة للبداية؛ لا قراءة لكل حساب ولا جمع جداول الأرصدة الافتتاحية مرة ثانية |
| المرشحات | الحساب والفرع ومجموعة مركز التكلفة والبحث في رقم/وصف القيد تطبق على الافتتاح والحركة معًا؛ النهاية تشمل كامل اليوم؛ الحد الأعلى لا يستدعي AddDays على أقصى تاريخ |
| البحث عن المركبة | الحقل القائم يبحث رقم القيد ووصفه؛ لم يخترع ربط VehicleId أو يزعم انتماءً مباشرًا |
| الدقة | محولات المال الحالية تخرج النص العشري في DTO، ويجمع `SumCurrencyReadAmounts` في المالك المالي المشترك دون قيد مبلغ إدخال مفرد؛ الـBigInt/النص في الجدول والبطاقات والتصدير دون Number |
| الإجماليات | إجماليات الأساس فقط أعلى التقرير، وإجماليات كل أصل بجانب قسمه؛ لا إجمالي يجمع العملات |
| الإخراج بلا حركة | القدرة الاختيارية المشتركة `hasOutput` تتيح طباعة/تصدير الافتتاح والإجماليات والتحذير بلا صفوف حركة؛ لا صف مالي وهمي |
| القوائم والخرائط | التقرير لا يملك ListVM أو AutoMapper أو مصدر كتابة؛ استجابة typed واحدة؛ لا endpoint جديد ولا تغيير مسار القائمة |

أعمدة السطور: التاريخ، النوع، رقم القيد، الطرف، المركبة، البيان، العملة، المدين، الدائن، الرصيد. يقابلها `LedgerLineVm`: `Date`, `Type`, `VoucherNo`, `Contact`, `Vehicle`, `Description`, `CurrencyCode`, `Debit`, `Credit`, `Balance`، مع هوية القيد والسطر والعملة وكسور العرض المطلوبة للترتيب والمفتاح والتنسيق. كل قيم المال نصية في JSON؛ لا يغير المحول العقود الأخرى.

## المالك المشترك والتحميل والكاش

- المسار الفعلي `/Ledger` من `pages/routing.ts` إلى `Ledger_Routes` ثم `LedgerComponent`، وطلب التشغيل المباشر `AccountReports/Ledger` عبر `AccountReportEndpointService`؛ لا كاش للبيانات المالية.
- خيارات الحساب ومجموعة مراكز التكلفة قراءات مباشرة من مالكيها الذين لم يفعلا `cacheSelect`. فرع الأستاذ مصدر مرجعي opted-in عبر `BranchService`؛ الكاتب الحالي يبطل المصدر، ويمر Bootstrap الناجح المحدود إلى watch منفصل عبر `ReferenceLookupBindings` مع احتفاظ التسمية المختارة وعرض فشل/Retry وتوقف عند انتهاء السياق/التدمير.
- أضيفت `watchOptions` و`refreshOptions` الاختياريتان لتعريف الفلتر؛ المستهلك الجديد الوحيد هو فرع الأستاذ. لا كاش جديد للحساب أو السياسة أو الأستاذ.
- يملك `ReferenceLookupStatus` lease تهيئة الخيارات على مؤشر الصفحة. قراءة التقرير تستخدم `startLoading` وfinalize؛ أزيل المؤشر المحلي المكرر، وبقي busy وaria-busy وتعطيل النموذج والأخطاء وإعادة البحث.
- انتهاء سياق مالك الكاش يلغي التقرير والخيارات وwatch، ويمسح النتائج والتسميات والاختيارات المرجعية ويعيد التهيئة دون IDs من رابط السياق القديم، حتى بعد Reset. يوجد سياج إصدار لكل callback وmicrotask. يمتد سياق المالك القائم إلى اللغة والاعتماد أيضًا؛ تتطلب النتيجة بحثًا جديدًا عند تغيره.
- أضيفت `ReferenceLookupBindings.clear()` لتفكيك subscriptions ومسح حالتها وإتاحة ربط المفاتيح في السياق الجديد؛ يستدعيها التقرير والتدمير، ولا تغير دورة المستهلكين القائمين.
- أضيفت `AccountReportSection.summaryCards` اختيارية، مع الشكل المشترك `document` لتمرير الأقسام داخليًا وظهور إجماليات كل وحدة بجانبها. الإخراج الكامل يستخدم كل الأقسام والإجماليات وتحذير النقص، ويحل اللغة عند التصدير.
- إلغاء تجهيز الطباعة يستعمل `ReportPrintSession.cancelPending`؛ حوار طباعة فتحه المتصفح بالفعل يبقى ملك المتصفح.

## المراجع وقبول الأدلة

طُبقت مهارة Sigma وكتل التقرير UI20/22/19 وBE17 وعقد الدقة المالي؛ الإصدار الأمامي في المصدر Angular21.2.25، وخلفية ViewModels تستخدم SDK/net10 مع مرجع Helpers وإدراج المصدر الافتراضي، لذا يدخل ملف القسم الجديد تلقائيًا. قُرئ مدخل سبيد ثم شاشة الأستاذ `21-accounts/screens/18-ledger.md` وشفرة `C0500`، وبالأخص `getLedgerView` (السطور687–715) الذي يعلن طلب العملات المتعددة؛ هذا دليل واجهة لا معادلة خادم. لم يظهر شرح مستقل باسم Ledger في بحث فهرس الشروح؛ العقد المعتمد هو مصدر تقسيم الوحدات والدقة. لا صور مرفقة أو معاينة مرئية أو تشغيل خارجي لهذه الشريحة. مرجع PrimeNG الحالي أكد `optionDisabled` في Select؛ قبلت أداة `validate_usage` المقطع النهائي دون قضايا، من `primeui://primeng/components/select.md` و[وثيقة Select](https://primeng.dev/select). هذا فحص metadata فقط، لا تجميع Angular.

## الأداء والفهارس

أزيل تحميل ميتاداتا كل الحسابات من هذا المسار، وأصبح الافتتاح مجمعًا في SQL حسب العملات/الإثبات؛ لا تجلب سطور التاريخ كلها للذاكرة. تنفذ قراءة الافتتاح ثم الحركة بالتتابع على DbContext واحد، وتبقى تفاصيل الفترة استجابة كاملة غير مقسمة، مع grouping محلي واحد لكل عملة ودون استعلام لكل سطر. لم يُقَس زمن أو SQL/IO أو رؤية مؤشر التحميل، ولا يدعي هذا انخفاض زمن مقاسًا.

لا تعديل فهرس أو هجرة. بعد قياس خطة التنفيذ للمالك يمكن تقييم فهرس سطور `(SubscriptionId, AccountId, JournalVoucherId)` مع تغطية المبالغ/الأبعاد القصيرة بحسب الخطة، ومقارنة تداخله مع فهارس FK الفعلية وكلفة الكتابة والتخزين. البحث Contains في الوصف لا يبرر تضمين نص طويل في فهرس. يحتاج المالك مقارنة نفس المستأجر والحساب والفترة والحجم، ومراقبة SQL لترجمة GroupBy وDateOnly وRound وتجميع decimal، ومقارنة صفوف وإجماليات الإخراج. قراءتان منفصلتان لا تثبتان لقطة DB متسقة في سباق كتابة؛ لم يضف التقرير عقد snapshot isolation جديدًا.

## سيناريوهات قبول المالك — لم تُشغّل

1. قيد أساسي قبل الفترة وآخر داخل آخر يوم بها: يتطابق افتتاح + صافي = ختام، ويشمل الوقت بعد منتصف الليل في اليوم الأخير.
2. عملتان أجنبيتان مثبتتان: كل عملة بقسم وافتتاح ورصيد مستقلين، والأساسي كامل دون جمع الأصول.
3. سعر يومي جديد بعد التسجيل: لا يغير الأصل المحفوظ أو التقرير التاريخي.
4. أصل أجنبي ناقص اللقطة قبل الفترة أو داخلها: يحجب كامل قسم تلك العملة ويحذر، مع إبقاء الأساسي، ولا يُخمن سعر/مبلغ.
5. افتتاح بلا حركة حالية: الطباعة وإكسل متاحان ويحملان الافتتاح والختام والكود والكسور.
6. قيمة نصية أكبر من مجال Number أو مجموع أكبر من حد مدخل مفرد: نفس الخانات في JSON والعرض والطباعة وإكسل والفرز/الفلترة المحلية.
7. تطبيق مرشح رقم/وصف أو فرع: يطابق نطاق الافتتاح نطاق الحركة؛ لا يدخل مصدر لاحق للنهاية.
8. تغيير الشركة/الجلسة أثناء التقرير أو Bootstrap ثم Retry وReset: تلغى الردود القديمة، ولا يعاد ID الحساب من رابط قديم، ولا يعيد رد قديم البيانات.
9. تحديث Branch في الخلفية/الفشل/Retry: يحفظ المختار وتبقى التسمية، ويمنع اختيار مرجع محتفظ به معطل، ويعمل retry من المالك المشترك.

لا هجرة جديدة لهذه الشريحة. اقتراح رسائل تسجيل فقط: الخلفية `fix(currency): read historical ledger originals in separate currency sections`، والواجهة `fix(currency): preserve exact ledger output and expire stale report context`.
