# التراجع عن مرحلة موافقة

طلب المالك إضافة Unapprove عندما لا تكون المرحلة التالية معتمدة، وحسم السماح لآخر مرحلة قبل اعتماد المستند نفسه فقط ومنع التراجع بعد اعتماده. هذا توسيع لإجراءات صفوف المراحل في المالك المشترك؛ لا يدمج الاعتماد التشغيلي بالمراحل ولا يعكس ترحيلًا أو اعتمادًا للمصدر.

العقد: يعاد استخدام POST decision الحالي بقيمة Decision=1، مع ExpectedVersion وExpectedOrder إلزاميين للتراجع وسبب غير فارغ حتى 500 حرف. يعيد الرد ApprovalWorkflowVM الحالي مع CanUnapprove على كل مرحلة (وكذلك ApprovalStepSummaryVM للبوابة الأصلية). لا خاصية إذن جديدة؛ يتطلب View وManageApproval والتعيين الحي للمرحلة وفرع التعامل نفسه. لا تجاوز للدور باسم مدير الشركة ولا قصر على صاحب القرار السابق. يظهر الإجراء للمؤهل الحالي لنفس المرحلة.

المرحلة المستهدفة معتمدة من المحاولة الأحدث ذات نسخة المصدر الحالية. كل المراحل التالية بلا قرار: يسمح null/Pending فقط، ويمنع Approved أوRejected لحفظ تسلسل القرارات. يمنع التراجع إن كانت المحاولة مرفوضة أو المصدر معتمدًا/مرحلًا/مبطلًا. يستمد منع المصدر من القيم الحقيقية لحقول اعتماده المعروفة وبيانات قيده، وليس نص SourceStatus المعروض. تُعاد قراءة هذه الأدلة تحت قفل DocumentApprovalRun نفسه الذي يحمي اعتماد المصدر.

عند النجاح تعود المرحلة Pending وتعود المراحل التالية إلى null، وتصبح المحاولة Pending مع CompletedAt=null ونسخة جديدة، ويضاف قرار 1 بالسبب والفاعل والتاريخ. يحتفظ سجل القرارات بكل الأحداث السابقة. يعرض الصف آخر حدث بما فيه وقت التراجع؛ لا مسح للقرارات أو التعيينات. لا تغيير مخطط أو migration، ولا ذاكرة مشتركة عبر الطلبات. يعتمد العرض على نتيجة الكتابة ويعطل صلاحية الاعتماد التشغيلي المخزنة في الواجهة بعد التراجع حتى إعادة عرض مأمونة، دون GET زائد لكل صف.

النطاق: خدمة المراحل وDTO/قارئ المصدر وبوابة العرض والفروع، المكون المشترك وApproval Documents والترجمات والدليل ومواصفات محصورة. الجذر يملك الخلفية والتكامل والمطابقة؛ يمكن تفويض الواجهة على ملفات منفصلة بعد تثبيت هذا العقد. التحقق المسموح بناء المشاريع المحصورة وفحص المصدر؛ تشغيل الاختبارات وSQL والمتصفح معلق.

المراجع: كتاب الواجهة UI7/13/22/26/28 وإجراءات الخلفية BE8 وMaster4/5/7، وعقد تصحيح اعتماد أمر الشراء القائم للحفاظ على الفصل. مرجع Speed المؤرخ 2026-10-28 شاشة 18-vouchers/07 وC1398 يصرّح unApprovePurchaseOrder لاعتماد المصدر؛ لا يثبت تراجع مراحل Sigma. فُحص مدخل دليل Speed ومرجع Odoo المكمل؛ قرار تراجع المراحل خاص بطلب المالك ولا يثبت هذان المرجعان قواعده. فحص الوصفات الثماني نجح قبل الاستخدام. لا تغيير حقول/أموال/أعداد/تصميم خارج صف الإجراء الحالي.

## مطابقة التنفيذ والتحقق

| الجانب | المالك الفعلي والنتيجة |
|---|---|
| انتقال المرحلة | DocumentApprovalRun.CanUnapproveStep/UnapproveStep؛ إعادة آخر مرحلة معتمدة إلى Pending وإضافة حدث القرار 1 دون حذف التاريخ |
| API والصلاحيات | DocumentApprovalService.DecideAsync تحت ExecuteLockedAsync؛ View/ManageApproval والتعيين والنسخة/الترتيب ونسخة محتوى المصدر قبل التحوير |
| الحالة الأصلية | DocumentApprovalSourceReader يقرأ أعلام الاعتماد والقبول والرواتب والترحيل والإبطال. يراجع دفعة واحدة جميع مفاتيح EF المباشرة إلى JournalVoucher بما فيها قيود تجهيز بيع المعدة والحسابات البنكية؛ القيد المفقود أو المخفي أو المرحل أو المعتمد يمنع التراجع |
| حدود الفرع | ActionFilter وController وInbox يزيلون صلاحية التراجع من الصف عند غياب التعامل على الفرع؛ POST يعيد الفحص الحي |
| المستهلكون | DocumentApprovalCycle وApprovalDocuments؛ ActionList ونموذج سبب مربوط بالصف والنسخة وفحص الوصول عند الإرسال وتجاهل نتائج السياق المنتهي |
| النتيجة والتحميل | استجابة POST مباشرة مع إبطال canApprove/canReject الأصليين بعد التراجع؛ لا GET لكل صف أو cache عبر الطلبات؛ مالكا تحميل الحوار والصفحة السابقان |
| السجل | آخر حدث في صف المرحلة، وكل أحداث السير في العرض المركزي/المخصص للمراحل. تحتفظ نافذة المصدر بعقد سجل المصدر السابق |
| العقد والشكل | الأعمدة كما هي: الإجراء، الترتيب، الاسم، الحالة، المستخدم، التاريخ، السبب. إضافة CanUnapprove إلى DTO المرحلة فقط؛ لا AutoMapper أو مخطط أو أموال |
| الدليل | تحديث UserGuide/content/approval-status-guide.ts المستهلك من أدلة الوحدات الحالية؛ لا مسار دليل جديد |

المواصفات المضافة تغطي إعادة آخر مرحلة ومنع التراجع بعد قرار تالٍ والسبب وحفظ التاريخ وتعيين المرحلة السابقة مقابل التالية والمشاهد فقط واعتماد المصدر والترحيل والقيد المرتبط وقيدي تجهيز البيع. تغطي مواصفات الواجهة الصف القديم وتغير النسخة وسحب المنحة والسبب ونتيجة الحفظ دون إعادة قراءة. جُمعت المواصفات ولم تُشغّل.

المراحل 1/4/5/6 بقدر الإجراء المشترك؛ لا CRUD/مرشحات/تقارير منفصلة. تولى الجذر الخلفية والتكامل والمطابقة، وعامل واحد موروث النموذج تولى الواجهة بملكية مستقلة ثم مراجعة الخلفية للقراءة فقط. كشف قيدي تجهيز البيع المختلفين وأُصلحا في قارئ المصدر نفسه مع مواصفة؛ لم يجد ملاحظات تكامل إضافية. سبب التفويض تقليل زمن الواجهة المستقلة بعد تجميد العقد.

التوقيت وخطة SQL والقبول البصري معلقون. أضيف فحص صلاحية لآخر مرحلة معتمدة محتملة وفحص مجمع للقيود المرتبطة عند الحاجة. لا فهرس جديد: وصول المحاولة الحالي للشركة/النوع/المستند/الجيل ومفاتيح القيد وقرارات المحاولة تغطي الطلب الفردي مصدرًا. يلزم قياس SQL قبل اقتراح تكلفة كتابة إضافية.

قبول المالك بعد تشغيل النسخ المبنية: التراجع عن الأولى قبل الثانية، ثم منع التراجع عنها بعد اعتماد الثانية؛ التراجع عن الأخيرة قبل اعتماد المصدر ومنعه بعد اعتماده/ترحيله؛ رفض نسخة قديمة أو سحب الدور/منحة الفرع مع بقاء السجل. لا اعتماد أو ترحيل تلقائي ضمن التعديل.
