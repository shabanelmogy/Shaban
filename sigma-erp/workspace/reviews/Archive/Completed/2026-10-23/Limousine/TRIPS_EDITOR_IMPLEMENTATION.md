## Decisions and contract reconciliation

- UI screen02, routed Create/Edit/View: charges/tax/net summary and owned documents satisfy UI13's routed-editor decision. Existing input fields and internal/external vehicle rules are preserved. Create carries no record identity; Update adds only the parent id. Tenant, number, lifecycle, audit and net fields are absent from writes.
- New typed document writes use type/number/issuedBy/path/issue/expiry/international; Add omits child id, Update sends saved ids and zero for new rows. Snapshot order and removal are retained for the root's backend ownership reconciliation. Shared `PartnerDocumentType` carries the actual explicit backend `DocumentType` values0–38; the old string-enum index mapping was removed. `createDocumentRow`/`documentPayload` retain the canonical CustomerDocument validators and `CustomerDocuments` folder.
- Root's BE3 amendment flattens the editor's actual labels instead of carrying navigation graphs: `customerName`, `tripTypeName`, `pickUpLocationName`, `dropOffLocationName`, `vehicleTypeName`, `vehiclePlateNo`, `driverName`, `supplierName`. Frontend `TripBookingDetailsDTO` and `savedLabel` consume exactly these labels. Root owns the matching backend producer and historical freeze amendment.
- Local datetime transport uses `toApiDateTime`, with no UTC `Z` serialization. Document dates use the shared row payload mapper; issue/expiry must be valid and expiry must be after issue. Schedule requires drop-off later than pickup. Saved View totals use the returned `netCharges`, `charges`, `tax` and `discount`; View never loads tax/edit lookups or replaces those values with a preview.
- Editable monetary values are finite/nonnegative; text maxlength/email validators match the source VMs. Manual tax is available only under `allowTaxEditingInLimoTrip`; otherwise the tax amount uses `TaxSettingsService.previewTax`. The existing shared Common tax service owns its documented fallback behavior; the feature invents no rate or new tax policy.
- Shared `mergeSelectOptions` retains actual detail-derived labels for a current selection absent from a successful lookup. Incoming labels win; no label is invented for an unknown saved value. A saved vehicle is retained only under its saved vehicle type, so changing type still clears an ineligible selection. This is presentation compatibility; the backend remains the validity owner.
- View names come from its detail read. Editable lookup/settings failures block Save and expose retry; generic selectors support `skipErrorInterceptor`, and the root's typed settings/vehicle reads suppress interceptor errors. `Repository.GetDropdownAsync` was inspected: Location uses ShortName, Driver uses name parts, ordinary masters use Name. Vehicle options use the actual `VehicleListModel.vehicleTypeId`, preserving filtering through identity instead of legacy label comparison.
- Routes `create`, `view/:id`, `edit/:id` carry explicit mode and the editor guard. List guard calls the root-owned `TripBookingsComponent.canDeactivate`. Legacy `details/:id?mode=edit` and `?edit=true` use a CanActivate UrlTree redirect, preserving applied list/print parameters. Return drops editor-only flags and retains the list state.
- Pending discard is subscription-deferred (UI10): captured mode/id/disposed and one-use subscription gates reject obsolete decisions. Controls freeze without events, and a recursive disabled-state snapshot restores the same still-active record only after cancellation and outside upload/save/cleanup. Pristine upload cleanup is also deferred. Interrupted cleanup stays open with retry. Route parameter changes cancel the previous detail/lookup subscriptions and reinitialize the new record, preserving loader balance and preventing stale responses.
- Internal saved non-New trips require a driver, matching the service update guard; New trips retain optional driver selection. The initial three-hour drop-off default is preserved verbatim from the old editor, and does not introduce a tariff duration rule.
