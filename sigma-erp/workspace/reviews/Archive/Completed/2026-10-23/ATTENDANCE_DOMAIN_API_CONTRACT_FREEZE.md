Existing `Attendance` entity, EF configuration, subscription base and four nullable TimeSpan properties remain unchanged. Pattern: BE13 normal entity over the existing generic service/controller. ## Endpoints, actions and persistence

| Operation | Existing API | Request/response | Ownership and behavior |
|---|---|---|---|
| Read list | GET Attendance | ListSmBase / Results<AttendanceListVM> | tenant/live query, API count and server paging |
| Read detail | GET Attendance/GetByWithNavigationsId/{id} | id / Result<AttendanceDetailVM> | inherited tenant/live lookup; scalar name flattening |
| Create | POST Attendance | AttendanceAddVM / Result | FK/date validation then one inherited entity save |
| Edit | PUT Attendance | AttendanceUpdateVM / Result | tenant identity/FK/date validation then one inherited entity save |
| Delete | DELETE Attendance?id={id} | id / Result | confirmed in UI; RemoveWithChildrenAsync(id, CancellationToken.None), no owned children; usage check and soft delete in one save |
| Lookups | Staff/GetSelect, Shift/GetSelect | Results<DropDownSelect> | existing roots; Staff for filters, Shift only when editing/creating |

There is no owned aggregate collection, upload, approval/posting state or duplicate business key. No explicit transaction is needed for the one-save generic entity path. Existing duty-schedule read and inherited bulk endpoints remain compatibility paths; no new frontend bulk caller is created. Their pre-existing limitations are recorded in the implementation review, outside this CRUD handoff.

Five justified overrides only: ApplyListFilters (feature date bounds), MaterializeListAsync (narrow names projection), AddAsync/UpdateAsync (required date) and RemoveAsync (guarded shared deletion). Generic behavior is inherited elsewhere. Four one-way AutoMapper mappings; no ReverseMap/Ignore.

## UI integration and recovery

List-owned modal Create/View/Edit. The existing create/details URLs and new explicit view/edit compatibility URLs load the same list/modal, guarded by CanDeactivate; ID changes after a successful guard decision recreate the child editor. Invalid IDs close the old surface. Normal row actions do not navigate to another editor implementation.

View renders saved values, hides Save and offers Edit/Close. Dirty X/Cancel/Escape/navigation uses deferred shared discard confirmation and freezeFormState; cancellation retains values/dirty state. Save failures have separate inline state and retain inputs. Success closes once and refreshes applied filters/page/sort. Delete backs up one page when deleting the last visible row.

AttendanceService is providedIn root over the existing BaseService HttpClient; no extra provider or manual token. Every inline-owned request sends X-Skip-Error-Interceptor. Both declared and transport failures are visible; standard mutations retain the global single success-toast owner. No permission mechanism is invented; controls are presentation, authentication remains the existing shell's responsibility.

No entity/EF modification, migration, build, test, lint, browser, database, commit or push is part of this handoff.
