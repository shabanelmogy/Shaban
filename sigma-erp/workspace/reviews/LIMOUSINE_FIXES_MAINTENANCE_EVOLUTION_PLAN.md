# خطة إصلاح ملاحظات الليموزين — ٣١ أكتوبر ٢٠٢٦

شريحة تقرير استخدام الليموزين مع التمرير Frozen بطلب المالك: Extend API بقراءة صفحة إضافية GET TripBooking/UtilizationReportPage، مع filters نفسها وOffset صفري وPageSize=120 (حد أقصى240). رد Result<LimousineUtilizationReportPageDto> يحوي fromDate/toDate/breakup/rows/offset/pageSize/totalCount وsummary كاملة للفترة في offset0 فقط وnull فيما بعد. totalCount من عدد أيام الفترة ×24 للساعي أو ×1 لليومي، بما يشمل الصفوف الصفرية، والترتيب تاريخ/ساعة تصاعدي. تبقى قراءة UtilizationReport الكاملة الحالية للطباعة/التصدير والتوافق. الملخص من SQL للفترة كاملة؛ استعلام صفوف الصفحة يقتصر على مجال الأيام/الساعات المطلوب ولا يولد المصفوفة الكاملة ثم يقطعها. لا cache مالي/تشغيلي أو schema/index/migration جديد. Extend للمالك DataTable بمدخلات incremental=false وhasMore=false وloadMoreError فارغ ومخرج loadMoreRequested: عند ظهور آخر صف تُطلب دفعة واحدة فقط، ويقف التلقائي عند الخطأ ويعرض Retry/Load More قابلًا للوحة المفاتيح. العرض الجزئي لا يدعي فلاتر/ترتيب خلايا محليًا على كل التقرير؛ تُعطل حتى اكتمال المجموعة، وتبقى فلاتر التقرير الأصلية. Keep للإجماليات الكاملة والحد366 يومًا وtenant/branch/customer/vehicleType وكل المعاني المالية والحالات. Frontend يثبت filter/revision ويلغي/يمسح الصفحات عند تغيره أو السياق، ويمنع duplicates/out-of-order، ويحتفظ بما حُمّل عند فشل load-more مع Retry. كل قراءات التقرير/إضافة الصفحة/تجهيز output تملك page loader العام؛ cache المراجع والـsilent refresh كما هي. Print/Excel يجلبان الرد الكامل في عملية صريحة، ويتحققان من اكتماله؛ print يستخدم مصفوفة منفصلة مؤقتة ويعيد عرض الصفحات بعده. هذا استثناء نقل مصرح من المالك لUI20 وليس تغيير تقرير إلى CRUD.

شريحة تخفيف فتح قائمة الرحلات Frozen بتفويض المالك «تمام طبق التعديل»: Keep لطلب الرحلات والقوائم الست وإعدادات تشغيل الليموزين وأهلية الإرسال؛ نقل قراءتي ضريبة الإنهاء والسياسة المالية فقط من bootstrap الصفحة إلى فتح حوار الإنهاء وكل Retry فيه. السياسة المالية تبقى force fresh، والضريبة عبر singleton cache الحالي، دون كاش جديد. حوار الإنهاء يملك local loading/error/Retry وready مستقلة تمنع العرض القابل للتحرير والحفظ حتى نجاح القراءتين والتحقق من دقة العملة، مع حفظ المسودة والإلغاء بالسياق/التدمير والتحقق من جلسة الحوار. لا تغيير payload/حسابات/خادم/SQL/schema/index/migration. مرشح فهرس التاريخ يبقى اقتراحًا غير منفذ حتى خطة/IO/توقيت. الشكل UI02 للقائمة ومحررها، وحوار الإجراء وفق UI11/22/28؛ نفس API المجمد لا قرارات أعمال مفقودة.

متابعة ثبات قائمة الحجز Frozen: Keep لتركيب الأب/الابن الحالي، وExtend لارتفاع/overflow المالك EditorTabs الرأسي وتركيز لوحة المفاتيح المحلي؛ دون نسخة CSS/scroll في الميزة أو تغيير قراءة/كتابة أو نموذج. يعالج مخاطر التمرير المصدرية في بلاغ المالك، ويظل إثبات السبب والقبول البصري داخل التطبيق pending.

تصحيح المالك اللاحق لتبويبات حجز الرحلة، Frozen: يحتفظ محرر الحجز بتبويبي البيانات العامة والمستندات أفقيين كما كانا، وتنتقل الأقسام الستة الموجودة داخل البيانات العامة فقط إلى تبويبات رأسية: بيانات الحجز، المواعيد، التسعير، المركبة والسائق، بيانات الضيف، المعلومات الإضافية. هذا العقد يحل محل تفسير الطلب السابق الذي جعل التبويبين الرئيسيين رأسيين. Keep للمالك المشترك ودعم orientation الحالي، وExtend لتركيب مستهلك الحجز بحالتين مستقلتين وIDs منفصلة وفتح تبويبي الأب/الابن قبل تركيز خطأ التحقق. توزيع جانبي150–190px وفجوة12px يتكدس تحت700px؛ نموذج واحد محفوظ والإجماليات والـfooter خارج التوزيع، والطباعة تجهز جميع الأقسام. لا تغيير API أو الحقول أو المال أو قراءات/تحميل/كاش أو schema/migration. يعاد استخدام التقرير والخطة والدليل؛ لا نسخ تبويبات أو حقول جديدة.

تصحيح المالك اللاحق لشاشة التعريفة (الصورة33.png و«كانت مظبوطة قبل كده، بلاش اختراعات»، ثم رفض Create Trip Type في كل التبويبات): يلغي اعتماد المحرر الحالي على useTripTypeMatrix=true المذكور تاريخيًا بالأسفل. العقد المصحح Frozen: المحرر يستخدم GET/Save الحاليين بمسارهما الأصلي false، بأقسام LimousineTariffType وصفوف VehicleTypeId/LimoRateType. لا أقسام من أسماء سجلات TripType في الأساسية أو الشركات. تبقى الأقسام القابلة للطي وReset بجوار Customer، ودقة المال والسياق والكاش وحماية اللقطة/المخفي. لا حذف أو تحويل للصفوف الديناميكية ولا إزالة API أو schema/migration؛ تحمي الخدمة فصل النطاق بشرط TripTypeId==null. الصورة والمصدر السابق دليلان على الرجوع للعقد الأصلي؛ لا تحويل ordinal أو اختراع /Hour غير المدعوم في enum الحالي. التفاصيل والمطابقة في تقرير التسليم. هذا تصحيح لربط المحرر لا إعادة نسخة تاريخية كاملة فوق إصلاحات أخرى.

## الدليل والوضع القائم

ترث الخطة بيان النطاق والمراجع والبصمات والمقارنات في `LIMOUSINE_FULL_STACK_REVIEW.md` وتقارير المسارات الثلاثة بتاريخ اليوم. تمت إعادة قراءة التقرير والعقود والمهارة والكتل الحالية، واجتاز فحص الحزم الثماني بداية التنفيذ. لا تغييرات سابقة في المستودعين. أشكال الواجهات والخلفية والمراجع تظل كما اختيرت في بيان المراجعة؛ هذه خطة تصحيح مالكي المصدر الحاليين.

## خريطة الأثر والبدائل

القراءات ← خدمات المصدر الحالية ← الردود المسماة ← المكونات والقوالب والمخرجات؛ الكتّاب الحاليون يحتفظون بالحالة والترقيم والمعاملة ومصدر الضرائب. الجذر يملك الواجهات المشتركة والتوثيق والترجمة والتكامل. المحافظة على الصفوف المخفية أفضل من ضمها إلى حذف غير مرئي؛ الرفض عند اصطدام مفتاح يحفظ الفهرس القائم ويمنع إعادة التفعيل الضمني. الإسقاط المحدود أفضل من تغيير المستودع العام أو الاكتفاء بإخفاء الحقول بعد تحميل graph. القيم المالية العشرية والعداد ذو الست منازل قرار تأسيسي قائم من المالك؛ لا استثناء لبيانات تجريبية.

## الترحيل والتحقق والتسلسل

لا تُنشأ أو تعدّل migrations أو snapshots. تُبلّغ أسماء ترحيل فريدة للمالك بعد استقرار تعديلات EF مع توضيح int→decimal ودقة العداد وتفرد الحذف اللين وأي قرار لاحق. لا backfill أو تحديث قاعدة أو تعطيل تاريخ.

يعمل ثلاثة مسارات مستقلة بعد هذا التجميد: الخلفية، واجهة الرحلات، وبقية واجهات البيانات الأساسية/التقارير؛ الجذر يملك العروض والفواتير والمالكين المشتركين ودليل الاستخدام والترجمة والتجميع. لا ملف يكتبه عاملان. كل عامل يقرأ كتل شريحته والمصدر المرجعي الحقيقي، يحفظ تغييرات الآخرين، ويتوقف عن الجزء المتعارض فقط. الجذر يراجع الفروق كاملة في كل مستودع.

التحقق مصدرّي فقط: المنتج/المستهلك وأنواع/nullability/الواردات والحقول والفلاتر والمعاملة والحالة والمراجع والترجمات والـdiff/whitespace. لا builds/tests/lint/browser/database/commits/migrations/Graphify/Sigma MCP. قياس cold/warm وHTTP/SQL/IO وخطة الاستعلام والـRTL والثيم والأحجام والعرض محفوظ للمالك كما في المراجعة. لا ادعاء تسريع مقاس من انخفاض استدعاءات المصدر.
