## ١. الهدف والحدود

**الهدف:** أن تجلب سيجما مخالفات المرور ورسوم سالك ودرب تلقائيًا من الجهات، وتطابقها
مع المركبات والعقود والحركات وقت وقوعها، وتحمّلها على العميل أو الموظف أو الشركة حسب
الإعدادات، ثم ترحّلها محاسبيًا وتعرضها في تقارير وتسويات، بمستوى Speed الوظيفي.

**خارج النطاق في هذه الخطة:** الوقود، مخالفات قطر وعُمان (تُترك كتوسعة لاحقة في
نفس المحوّلات)، مكوّن مشاركة بيانات Speed، منتجات TFMS/FMS المنفصلة في Speed، إرسال
واتساب الفعلي (يُخطط له كمستهلك لاحق لخدمة الرسائل الموجودة).

**شرط النجاح:** دورة كاملة قابلة للتتبع لكل سجل: مصدر ← تنزيل ← معالجة ومطابقة ←
تحميل أو استبعاد ← فوترة ← ترحيل شهري ← تسوية مع الجهة.

## ٣. كيف يعمل Speed — الآلية المؤكدة

### الجلب

Speed يجلب البيانات بإضافة كروم (الإصدار الثالث من بيان الإضافات MV3) تعمل في متصفح الموظف.

| الخطوة | الدليل | النوع |
|---|---|---|
| الصفحة تتحقق من وجود عنصر `#speedExtV3` الذي تحقنه الإضافة | `chromeExtDownloader.isMv3ExtensionAvailable` (العرض الحي) | كود واجهة |
| الصفحة ترسل `window.postMessage({ isFromSpeedApp: true, request })` بنوع العملية والحسابات والفترة والإعدادات ورابط البوابة | `downloadFinesV3` / `downloadTollsV3` | كود واجهة |
| الإضافة تفتح تبويب البوابة وتسجّل الدخول | قيمة `action: 'openTab'` والروابط أدناه | كود واجهة + استنتاج |
| رمز التحقق يُعرض في شاشة Speed ويُعاد بحدث `sendCaptchaAndDownloadEvent` | `sendCaptcha` | كود واجهة |
| مخالفات أبوظبي عبر تم تحتاج موافقة من الجوال وحساب هوية رقمية لكل مستخدم | رسالة `ACCEPT LOGIN FROM MOBILE APP`، و`uaeFineService.getUaePasses` | كود واجهة |
| الإضافة تجلب الحسابات من الخادم وترسل النتائج للحفظ الجماعي | `salikAccount.getSalikAccountsForExtension`، `uaeFine.saveFinesInBulk`، `toll.saveTollsInBulk(New)`، `toll.prepareDataForExtension` | أسماء خدمات (لم تُستدعَ) |
| الخادم يقدّم كود قراءة للإضافة | `toll.jsLoaderForExtension` | استنتاج من الاسم فقط |
| بعد اكتمال التنزيل تُستدعى المعالجة | `callbackOnComplete → processFines / processTolls` | كود واجهة |

روابط البوابات كما وردت في الكود:

```text
مخالفات دبي:     https://ums.rta.ae/violations/public-fines/fines-search
مخالفات أبوظبي:  https://www.tamm.abudhabi/wb/adp/general-service/login?redirectUrl=…/pay-traffic-fines   (TAMM)
                 https://evg.ae/_layouts/evg/finepayment0.aspx?language=en                                (EVG)
مخالفات قطر:     https://fees2.moi.gov.qa/moipay/inquiry/violation
مخالفات عُمان:    https://www.rop.gov.om/OnlineServices/eTraffic/english/default.aspx
سالك:            https://customers.salik.ae/connect/login?lang=en
درب:             https://darb.itc.gov.ae/RucWeb/login
```

لا توجد واجهة برمجية عامة من الجهات للشركات. هذا ما أظهره بحث 2026-11-10: صفحة درب
الرسمية، وبرنامج تأجير منافس يعتمد استيراد الكشوف، ولا ذكر لواجهة برمجية لدى الجهات.

### البديل اليدوي

استيراد ملف إكسل لكل جهة (Administration ← Data Import) بأعمدة ثابتة (القسم ٨).

### المعالجة

تطابق المعالجة السجل مع المركبة ثم العقد أو الحركة. تقرير المخالفات يعرض لكل سجل:
رقم العقد، نوع الحركة ورقمها، الموظف، الفاتورة، فاتورة المورد (الجهة) وحالة سدادها،
وقيد اليومية المدين. وتصنّف الحالة إلى: بعقد، بدون عقد، أخرى.

## ٨. العقد الموحد للبيانات (Ingestion contract)

نقطة استقبال واحدة يستخدمها استيراد الملف والإضافة، بالسجل نفسه. الحقول مأخوذة من
أعمدة استيراد Speed مع إضافة ما يلزم لمنع التكرار.

```text
POST /ExternalCharges/Ingest
{
  source:      "File" | "Extension" | "Api",
  kind:        "SalikToll" | "DarbToll" | "DubaiFine" | "AbuDhabiFine",
  accountRef:  string?        // اسم حساب سالك/درب أو رقم ملف المرور
  runId:       guid           // من سجل التنزيل
  records: [ {
     externalId:        string   // Transaction Id لسالك، Fine No للمخالفة، مفتاح مركّب لدرب (انظر القرار D5)
     occurredAt:        datetime // Trip Date Time / Fine Date Time (بتوقيت الإمارات، يُحوّل UTC في الخادم)
     postedAt:          date?    // Transaction Post Date
     plateNo:           string
     plateSource:       string?  // Plate Source (المخالفات)
     plateCode:         string?  // Plate Type/Code
     tagNo:             string?  // Tag No (سالك)
     location:          string?
     direction:         string?
     description:       string?  // المخالفات
     authority:         string?  // المخالفات
     amount:            decimal  // المبلغ المستحق
     originalAmount:    decimal? // المخالفات
     discountRate:      decimal? // المخالفات
     blackPoints:       int?     // المخالفات
     isPayable:         bool?    // المخالفات
     contractNoHint:    string?  // Contract No إن وُجد في الملف — تلميح لا يتجاوز المطابقة الزمنية
     raw:               json     // السجل الأصلي للتدقيق
  } ]
}
→ Results<IngestSummary> { received, inserted, duplicates, updated, rejected[{row, reason}] }
```

القواعد المقترحة:

- **منع التكرار:** مفتاح فريد على مستوى الاشتراك `(SubscriptionId, Kind, ExternalId)`.
- **إعادة الإرسال:** آمنة دائمًا. السجل الموجود يُحدَّث فقط في الحقول التي تغيّرها الجهة، مثل المبلغ بعد خصم أو غرامة تأخير، ويُسجَّل التغيير. لا يُحدَّث سجل حُمّل أو رُحّل إلا بمستند تصحيح (القرار D9).
- **المبالغ:** تتبع سياسة المال في `references/numeric-policy`.
- **الوقت:** يُحفظ UTC مع أصل التوقيت.
- **الحساب:** الخادم يحسب الرسم الإضافي والضريبة والإجماليات. لا يُقبل أي إجمالي من العميل.

## ١٠. محرك المطابقة الزمني (مقترح — يحتاج تأكيد المالك)

```text
لكل سجل (لوحة + مصدر + رمز أو وسم، وقت t):
 1) المركبة: مطابقة الوسم (سالك) أو اللوحة + المصدر + الرمز، كما كانت صالحة وقت t.
    إن لم تُعرف ← MatchStatus = UnknownVehicle   (يظهر في "غير معروف" ويقبل الربط اليدوي)
 2) العقد: عقد للمركبة بحيث  DateAndTime ≤ t < وقت الإرجاع الفعلي (أو الآن إن كان مفتوحًا)،
    مع احترام استبدال المركبة داخل العقد.  ← OnAgreement (العميل والسائق من العقد)
 3) وإلا حركة غير إيجارية أو ورشة أو استلام أو تسليم تغطي t   ← OnMovement (موظف أو عميل أو ورشة)
 4) وإلا                                                          ← CompanyInternal (مصروف داخلي)
 5) تلميح رقم العقد من الملف يُستخدم للتحقق فقط؛ الاختلاف ← Conflict للمراجعة
```

- **المعالجة تعيد الحساب** للسجلات غير المحمّلة فقط. السجل المحمّل أو المرحّل لا يتغير إلا بإجراء صريح.
- **عدادات النتيجة** كما في Speed: الإجمالي، بعقد، بعميل أو حركة، داخلي، غير معروف.
- **قواعد الاستثناء من الإعدادات:** عدم إنشاء ذمة على الورشة، وعدم إنشاء ذمة على الموظف لحركات التشغيل.

## ١٨. الأمان والخصوصية

- **كلمات مرور البوابات:** تُشفّر عند الحفظ، ولا تعود في أي استجابة قراءة. تُعطى للإضافة فقط بطلب مصادق عليه، لحساب واحد، وقت التشغيل.
- **سجل الوصول:** يُسجّل كل طلب لبيانات الدخول ضمن سجل التدقيق الموجود.
- **رسائل الإضافة:** مقيدة بأصل سيجما، بخلاف Speed الذي يرسل إلى كل الأصول.
- **الهوية الرقمية:** لا تُخزن إلا كمعرّف للمستخدم كما في `FinesUserMapping`. لا تُخزن أي بيانات دخول لها.
- **الصلاحيات:** لا آلية صلاحيات في التطبيق حاليًا، فلا يوصف إخفاء زر كحماية.
