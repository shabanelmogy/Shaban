# إصلاح بقاء القائمة الجانبية بعد فتحها

| البند | القيمة |
|---|---|
| Status | Implemented — source-only |
| Owner verification pending | yes |
| Date | 2026-11-18 |
| Tier | S |
| Scope | LayoutComponent، عمر Drawer عند التنقل |

أبلغ المالك أن القائمة الجانبية كلها تُغلق فور فتحها وأكد أن المقصود القائمة كاملة. أثبت فحص المصدر أن LayoutComponent كان يضع mobileNavigation=false مع كل NavigationEnd، بما يشمل تحديث query/fragment للشاشة نفسها أو انتهاء انتقال بدأ قبل فتح القائمة.

يعتمد الإصلاح UI1 وUI28 ومالك LayoutComponent القائم. قرئ دليل Speed العام ومقدمة تحليل القائمة والكود المؤرخ ٢٨ أكتوبر. يعرض المرجع روابط الوحدات والمسارات، ولا يحدد دورة PrimeNG Drawer في Sigma؛ سلوك PrimeNG في هذه النقطة تابع لمالك القشرة المعتمد. دليل Odoo غير منطبق على هذا الإصلاح. قُرئ مصدر PrimeNG PanelMenu محليًا للتفريق بين فتح المجموعة وإغلاق القائمة، ثم حُصر التعديل في مالك القشرة بعدما أكد المالك أن القائمة كلها تغلق.

يحفظ الفتح معرف التنقل الجاري أو آخر انتقال ناجح عبر إشارات Router الموجودة أصلًا في navigationActivityInterceptor. يحتفظ LayoutComponent بهوية المسار الكامل من جذر UrlTree دون query/fragment، مع الحفاظ على matrix parameters والمخارج. يُغلق الدرج تلقائيًا بعد اكتمال انتقال أحدث إلى مسار شاشة مختلف. تنتهي الانتقالات السابقة ويُحدّث المسار المعروف مع بقاء الدرج الجديد مفتوحًا. يمر زر القائمة واختصار البحث بنفس مالك الفتح. تبقى آلية التركيز والإغلاق اليدوي لمالك Drawer القائم.

كتبت مواصفتان قبل تعديل المصدر، لتحديث رابط الشاشة نفسها وانتهاء انتقال كان جاريًا وقت الفتح. تشمل المواصفتان انتقالًا لاحقًا لشاشة مختلفة وتتحققان من الإغلاق عنده. لا تفويض لتنفيذ اختبارات التشغيل أو المتصفح في هذه المهمة، ولذلك قبول السلوك الفعلي معلق. الإصلاح لا يطلب HTTP أو قاعدة بيانات أو lookup/cache جديدًا، ولا يغير مالك التحميل أو API أو الصلاحيات أو الحسابات أو schema. لا مؤشر أداء أو فهرس جديد مطلوب، وتوقيت ظهور الدرج قبول بصري معلق.

حُدثت فقرة القائمة في SHARED_SCREEN_GUIDANCE بالعربية والإنجليزية داخل قارئ الدليل المشترك، وتوثق UI1 ومهارة Sigma سبب مقارنة هوية المسار ومعرف الفتح. جُددت الحزم الثماني بالمولد وفق التفويض القائم. لم يُستخدم وكلاء لأن الإصلاح صغير ومتسلسل.

اقتراح commit للواجهة هو Fix sidebar drawer dismissal on same-page navigation، وللوثائق Record sidebar opening navigation lifetime.


## نتيجة التحقق

نجح تجميع LayoutComponent ومواصفاته باستخدام Angular compiler مع إعداد فحص معزول في .codex-build/sidebar-open-specs.json. صححنا مسار typeRoots في إعداد الفحص المعزول بعد فشل محاولته الأولى في العثور على Jasmine. نجح بناء Angular development النهائي بصفر أخطاء في ١١٠٫٧٢٢ ثانية، والسجل .codex-build/sidebar-open-angular-build.log والمخرج .codex-build/sidebar-open-web. لا يساوي تجميع المواصفات تنفيذ اختبارات سلوكها.

روجع فرق ملفات layout.component.ts وlayout.component.spec.ts ودليل الاستخدام، وفرق UI1 والموجهات المولدة. نجح فحص فرق المصدر واتساق الحزم الثماني. انتهى الإصلاح في المصدر والبناء، وتبقى تجربة فتح القائمة أثناء انتقال قائم وتحديث query ثم اختيار شاشة أخرى، بالعربية والإنجليزية وفي العرض الضيق، معلقة للمالك. لم تُنفذ اختبارات التشغيل أو المتصفح أو قاعدة بيانات أو نشر أو commit.
