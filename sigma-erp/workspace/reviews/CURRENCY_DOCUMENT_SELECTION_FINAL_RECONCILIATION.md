## القرارات والعقود الحالية

العقود المستهلكة: [اختيار الحركة](CURRENCY_DOCUMENT_SELECTION_CONTRACT_FREEZE.md)، [القيد المولد](CURRENCY_GENERATED_DRAFT_SELECTION_CONTRACT_FREEZE.md)، [الصرف](CURRENCY_PAYMENT_SELECTION_CONTRACT_FREEZE.md)، [المشتريات](CURRENCY_PURCHASING_SELECTION_CONTRACT_FREEZE.md)، [القبض](CURRENCY_RECEIPT_SELECTION_CONTRACT_FREEZE.md)، و[الإشعاران](CURRENCY_NOTES_SELECTION_CONTRACT_FREEZE.md).

اعتمد المالك استقلال عملة الحركة عن افتراضي الطرف، وتحويل المبالغ الحالية للحفاظ على المعادل. ثم اعتمد السماح بتغيير المسودة وقيدها المولد غير المرحل المملوك معًا بلا تخصيص أو أثر نهائي؛ هذا ينسخ قفل أي مستند لمجرد وجود رقم قيد في السجلات الأقدم. كما اعتمد ربط إشعار التسليم ببند الفاتورة الأصلي. توجيهه الأخير اختيار الأنسب وإكمال التنفيذ دون أسئلة. البيانات القديمة تجريبية؛ لم يُضف مسار ترميم أو backfill لها.

| المطلب | مطابقة المصدر وقرار التنفيذ |
|---|---|
| الافتراضي | يهيئ المستند الجديد فقط؛ اللقطة المقبولة والمحفوظة تسبق أي تحديث افتراضي أو كاش |
| المبالغ الحالية | المالك المشترك يستقبل نصوص المدخلات الحالية؛ لا يعود لمبالغ آخر حفظ عند التحويل |
| السعر المؤرخ | أحدث سعر لا يتجاوز يوم الاعتراف؛ بلا fallback ثابت أو مستقبلي؛ المعاينة لا تستهلكه |
| أول حفظ | دليل دائم يستهلك السعر حتى في المسودة؛ إضافة يوم جديد تبقى ممكنة وفق حارس عدم إعادة تسعير يوم مستخدم |
| الحفظ العادي | يحتفظ باللقطة؛ التغيير الصريح يعيد التحقق ويحفظ مراجعة مع previousUsageId |
| التاريخ والعملة | قبول التاريخ الجديد بنفس العملة أولًا، ثم تحويل العملة؛ لا استعمال خفي لسعر تاريخ المصدر القديم |
| الدقة | نقل مالي نصي، تخزين أصل22,6 وسعر28,12، وسياسة0–6 للأجنبية؛ BigInteger/BigInt وAwayFromZero |
| المدخل والمخزن | HTTP يرفض الكسور الزائدة حتى الأصفار؛ قراءة SQL تستخدم المقياس الرياضي ولا ترفض أصفار التخزين |
| المصدر المالي | العملة والأسعار من المصدر؛ مصدر مختلف لا يصفر مسودة بها مال، والجديدة الخالية فقط يمكن تهيئتها من المصدر |
| القيد المولد | فحص ملكية/حالة/تخصيص قبل التعديل؛ المصدر ولقطته ثم سطور الأصل والقيد في نفس المعاملة؛ تحويل للأساسية مرة واحدة |
| التوازن | يرفض عدم توازن الأصل أو الأساسي أو تحول موجب إلى صفر؛ لا balancing plug |
| الحالة النهائية | المرحل أو المعتمد أو المبطل أو المشترك أو المخصص أو ذو أثر نهائي يمنع تغيير اللقطة؛ اليومية المولدة لا تُعدل يدويًا |
| الخروج والسياق | توقيع/نسخة للمعاينة، إلغاء القراءات المتأخرة، حفظ المدخلات عند الفشل، حراس حفظ وخروج مستقلة عن دورة الكتابة |

| إشعار التسليم | فاتورة معدات مصدرية تمثل بندًا أصليًا؛ تثبيت الوحدة والسعر والعملة وحجز الكمية والصافي والضريبة | لا مصدر غير مرحل أو مبطل أو مختلف العميل/الفرع/التسليم؛ لا تجاوز متبقٍ |
| مولد الفاتورة الأساسي | إزالة اعتماد القبول على افتراضي العميل/السائق؛ استخدام الأساسية الفعلية التي سُعّر بها المصدر وإظهار سبب القفل | منشأ من مصدر وينشئ قيدًا مرحلًا؛ لم تُخترع له دورة مسودة أو تُفتح الأجنبية دون تبني السلسلة المالية |

تستخدم خدمة القبض قراءتي السياق المحليتين بدل تفاصيل البيع العامة ذات عقد المال العددي. تحمل قراءة تحصيلات الفاتورة واتفاقية البيع ومالية فاتورة المعدات المبلغ النصي وكسور العملة ورمزها. يستخدم مولد القبض من فاتورة المعدات الرصيد النصي الفعلي مباشرة. لا يمكن استرجاع أرقام ضائعة بتحويل Number إلى String.

المشتريات تبقي Tax على سطر أمر الشراء نسبة، لا مبلغًا. الحساب الدقيق للضريبة مرة لكل معدل ثم توزيعها من المالك المشترك، والأسعار×الكميات والخصم النسبي تحسب دون overflow وسيط. المصدر المحفوظ يظل مرجع الحساب؛ لا إجمالي يرسله العميل بوصفه حقيقة مالية.

قرار AutoMapper: الخرائط تنقل المدخلات القابلة للتحرير، والخدمات تملأ المشتقات واللقطة والأعلام. تحديث الإشعار يصالح الأطفال داخل نفس الكيانات المتتبعة بهوياتهم، ويرفض الطفل الغريب أو المكرر، ويحفظ معدل الضريبة السابق؛ لا clear/recreate لمعرفات قائمة. لا تخمين لهوية الشركة من معرف جهة اتصال متصادم؛ يستخدم المدين الطرف المحاسبي نفسه الذي يحله builder.

رابط اتفاقية الدائن اختياري عند الإنشاء، ويثبت الخادم أهليته لنفس العميل والاشتراك. يمكن استبدال الرابط المحفوظ باتفاقية مؤهلة؛ null عند التعديل يحتفظ بالرابط وفق ملحق العقد، ولذلك لا تعرض الواجهة مسح رابط محفوظ بوصفه عملية مدعومة. الرابط تشغيلي ولا يحدد عملة المستند. رقم الإشعار مولد خادميًا ويقرأ من No.

## بند الفاتورة الأصلي وحماية المصدر

تقرأ الشريحة فاتورة المعدات المرتبطة بالتسليم، وتتحقق من العميل والفرع والوحدة والكمية والسعر والعملة وقيد المصدر. تحجز الإشعارات المعلقة والمعتمدة غير المبطلة أو المحذوفة كمية المصدر وصافيها وضريبتها؛ يستبعد التعديل نفسه. تأخذ الشرائح الجزئية نصيبها من المبلغ والضريبة المحفوظين، وآخر كمية باقيهما. اعتماد أو استعادة شريحة محفوظة يحفظ قيمتها ويتحقق من السعة والدليل؛ لا يعيد تسعير باقي التقريب بسبب إبطال شريحة أخرى.

تمنع أعلام الفاتورة وخدمة إجراءاتها إبطال المصدر أو تغيير أثره مع إشعار حي. لا يغير الإشعار رجوع المعدة أو المخزون أو ساعات التشغيل. لا يملك المصدر لقطة مستقلة لدور حساب الضريبة؛ لذلك تقبل الشريحة فقط تطابق الصافي والضريبة مع حسابات قيد المصدر المثبتة، وترفض تعارض الربط بدل تخمينه من الوصف. الضريبة صفر لا تستلزم سطر ضريبة. فتح تبديل دور الحساب التاريخي يحتاج عقد لقطة مصدرية مستقلًا.

## عقد القراءة والقوائم

فاتورة المورد: الأعمدة no/date/supplierName/branchName/totalAmount/dueAmount/currencyCode/billType/approvalStatus/discount/closed/supplierBillNo/supplierBillDate/isLoan، مع حقول الهوية والحالة اللازمة. مبالغ totalAmount/dueAmount/discount نصية وكسور الصف للعرض والتصدير؛ SearchListDto العام لم يُفتح كمسار أجنبي.

سند الصرف: القائمة لا تعرض مبالغ؛ بقيت حقولها الحالية مع أعلام الموافقة. قوائم طلب وأمر الشراء والاستلام والقبض تعتمد أعمدة المال الظاهرة وexactMoney وكسور الصف، مع SQL decimal للفرز/المرشحات. قائمتا الإشعارين لا تعرضان أعمدة مبالغ؛ أضيف رمز العملة، وتعرض التفاصيل والطباعة مبالغها النصية بدقة المستند. لا يجمع ملخص مالي عملات مختلفة. تتبع حقول الموافقة النصية دقة ورمز المستند من DocumentApprovalContext. تحتفظ العقود التفصيلية أعلاه بمنتجي الحقول ومستهلكيها.

مطابقة أعمدة الإشعارين مع ListVM: الدائن يعرض id/creditNoteNo/type/createdAt/currencyCode/branch/customer، والمدين يعرض type/createdAt/currencyCode/branch/supplier، مع id وisActive وisDeleted لهوية الصف ومرشحات الحالة والسجل. مالك grid-row يحول الحقول إلى display_* فقط ولا يعيد تفسير المال كعدد. حقول تفاصيل القائمة القديمة باقية بعقدها؛ لم تستعمل لتكوين إجمالي مختلط جديد.

## التحميل والكاش ودورة الطلب

| المصدر/العملية | تصنيف القراءة ومالك العرض | دورة الحياة |
|---|---|---|
| قائمة العملات | مرجع مشترك معتمد | bootstrap ناجح ثم watch مستقل؛ selected-label وRetry وتنظيف السياق والتدمير |
| افتراضي العميل | استثناء PartnerCurrencyLookupService المعتمد | مفتاح الطرف؛ لا يكتب فوق لقطة مقبولة، refresh محتفظ صامت |
| افتراضي المورد | تفاصيل تشغيلية مباشرة | لا opt-in جديد للكاش؛ إلغاء القراءة السابقة وسياق الهوية |
| افتراضي المدين المحاسبي | قراءة سياق محلية مباشرة | resolver نفسه للحساب؛ لا افتراض أن ContactId هو CustomerId |
| السياسة المالية | singleton مستثنى بعقده | فشل الإعداد لا يتحول إلى نتيجة مالية صالحة |
| معاينة التحويل | POST قراءة تشغيلية بلا كاش وNAVIGATION_READ_ONLY | start/finalize في الصفحة أو الحوار حسب LOOKUP_LOADING_SCOPE؛ ينتهي read loader قبل التأكيد |
| تفاصيل/مصادر/أرصدة | تشغيلية مباشرة | cancellation/version/context guards؛ حوار محلي فوق القناع، وصفحة بمالكها العام |
| الحفظ/الإجراءات | كتابة مستقلة | freeze/busy وحماية الملاحة، لا تعتمد على انتهاء مؤشر القراءة |

مصادر الفرع وطريقة الدفع المعتمدة تحتفظ بالكاش وwatch عند مالكها؛ الحسابات والبنوك والأسعار والذمم والمصادر لا تُخزن لمجرد أنها GET. فشل envelope أوHTTP يحتفظ بالمدخلات وله رسالة وإعادة محاولة. الحفظ لا يعمل بلقطة ناقصة أو تاريخ غير مقبول. قفل النموذج أثناء المعاينة لا يعطل زر التصحيح والاستعادة في المالك نفسه.

## الأداء والفهارس

تختار المعاينة السعر مرة لكل aggregate، لا لكل مبلغ، وحد المبالغ10000. المصدر وقيده يقرآن بدفعات معرفات، لا استعلام لكل بند. قراءات سياق القبض محدودة بمصدر واحد ومجاميع التحصيل وجدول أقساطه، وتعيد استعمال مالك توزيع الأقساط. قراءة مصادر الإشعار لها حد صريح ولا تعرض اقتطاعًا يوحي باكتمال النتائج.

الاحتياجات الحالية تستفيد من فهرس سعر العملة/التاريخ، ودليل الاستخدام، وFK لمصدر الفاتورة/الإشعار وأمر الشراء، وجدول أقساط البيع (SalesAgreementId,Date). لا فهرس إضافي يُنشأ بلا قياس SQL يثبت قصور التغطية. على المالك تأكيد الفهارس الفعلية، خصوصًا Receipt.SalesAgreementId وCreditNoteDetail.InvoiceId، ومراجعة خطة شرط ربط الاتفاقية أو عرضها. الفائدة المحتملة تقليل البحث؛ الكلفة تخزين وصيانة كل كتابة، ولا اقتراح مكرر دون دليل. لا تعديل مخطط ولا قياس زمن أُجري هنا.

القبول المطلوب: إصدار ومخطط وtenant واحد، بيانات مماثلة وحجم مصادر معلن، قياس الشبكة والطلبات وSQL plan والمدة قبل/بعد، ثم تزامن المصدر/التخصيص/السعر. مطابقة المصدر لا تثبت السرعة أو رؤية المؤشر أو RTL والثيم والطباعة.

## التحقق والتسليم

التحقق مصدرّي فقط. روجعت الفروق المحددة في مستودعي SigmaBackend وSiGmaAngularFrontEnd، والملفات الجديدة والعقود المتصلة والـnamespaces ومراجع المشروعات وإدراج SDK وملفات TypeScript الصريحة والترجمات وحراس المصادر. تكمل نتائج الفحوص النهائية في سجل الإغلاق أدناه. لا يثبت ذلك نجاح compilation أو EF translation أو الحسابات والتزامن بالتشغيل.

لا migrations أو ModelSnapshot عُدلت لهذه الشريحة. توجد تغييرات سابقة بهذه الملفات محفوظة ولم تُرجع أو تُنسب لهذا التسليم. يحتاج المالك مراجعة فرق النموذج وتجهيز هجرات ExtendBillCurrencySelection وExtendPaymentCurrencySelection وExtendPurchasingCurrencySelection وExtendReceiptCurrencySelection وExtendCreditDebitNoteCurrencySelection، أو دمج الاحتياجات فيما لم يطبق بعد. تشمل الأخيرة توسيع أموال الإشعارات ووحدة المصدر المحفوظة وعلاقة InvoiceBase. لا هجرة جديدة لإزالة شرط افتراضي الطرف بالمولد.

رسالتا commit مقترحتان فقط:

```text
backend: feat(currency): persist independent voucher currency snapshots and owned draft journals
```
