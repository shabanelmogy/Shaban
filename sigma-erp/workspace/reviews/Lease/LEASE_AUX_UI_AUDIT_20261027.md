## Confirmed findings

### AUX-01 — P2: returning to Quotation/Master loses the saved column filters

`L/LeaseQuotation/components/list/list.component.ts:58` and `L/LeaseMasterAgreement/components/list/list.component.ts:63` read `grid` into `initialGridFilters`, but their `appliedFilters` initializers use only `currentFilters()` (Quotation:101; Master:108). The restoration methods preserve the already empty `appliedFilters.grid` instead of consuming the snapshot (Quotation:382–395; Master:296–313). The first `requestList()` therefore reads without the saved predicate and rewrites the URL with an empty grid value. This affects editor/View/Print return, reload and a link carrying column filters: the result/count/export context broadens. Inquiry correctly seeds its column filter from the snapshot (`LeaseInquiry/.../list.component.ts:65`). Recommendation: seed the actual applied filters before the first read and URL write; retain the explicit Clear/Reset paths. Owning blocks UI6/10.

### AUX-02 — P2: Tariff drops its active column filters when opening the editor

`L/LeaseTariff/components/list/list.component.ts:156–158` navigates with `search`, page and page size plus the vehicle label, omitting the active `lastFilters.grid`. The editor returns its snapshot query parameters (`.../details/details.component.ts:315,798–799`), so the predicate cannot survive configure/View → return even though the list correctly seeds and writes grid state (`.../list.component.ts:35,79,185`). Recommendation: use the same applied list-state serialization for editor navigation as the list route; keep the transient vehicle label separate. Owning UI6/10.

### AUX-03 — P2: approved Customer source cache and open-option watches are bypassed

`L/LeaseQuotation/services/leasequotation.service.ts:108–123`, `L/LeaseMasterAgreement/services/leasemasteragreement.service.ts:53–57`, and `L/LeaseInquiry/services/leaseinquiry.service.ts:76–80` issue direct HTTP for `Customer/GetSelect`. The actual source opts in (`modules/shared/service/customer.service.ts:10`), and BaseService already owns finite/cache/watch seams (`base-service.service.ts:102–136`). These adapters bypass coalescing, source invalidation, context fencing and active tenant notifications. Actual consumers only assign arrays after finite reads: Quotation list:344–355 and details:276–291; Master list:277–293; Inquiry list:359–375 and details:416–449. None binds a successful Customer bootstrap to `ReferenceLookupBindings`/`watchSelectList`, clears options on shared context changes or preserves selected labels through current-option getters. Consequently repeated list/editor acquisition always requests fresh full choices and an already open choice list never observes approved source revalidation/remote edits. Recommendation: delegate to CustomerService with the existing inline feedback mode, retain finite successful bootstrap, then bind one watch per consumer with selected-ID/current-option preservation and teardown. Do not cache the neighboring sources that have no source opt-in. Owning UI2 mandatory gate.

### AUX-04 — P2: required routed lookups have no page progress owner; Inquiry dialog lookup has no aggregate progress

Quotation/Master/Inquiry filter customer loads only toggle local flags and finalize them; none drives `LoadingService` or `ReferenceLookupStatus` (same list methods cited in AUX-03). Quotation/Master templates additionally pass the flags to per-select loading (`Quotation/.../list.component.html:14`; Master list HTML:27). When the list read completes before its lookup, the shell progress ends with required choices still pending. Quotation create/edit lookup and contact batches similarly only toggle flags (`.../details/details.component.ts:276–307`, HTML:21,25); Save remains blocked without the required page progress owner. Inquiry's modal lookup/contact flags (`.../details/details.component.ts:416–475`) gate Save, but its HTML:23–29 renders progress for `loadingDetails` only, so opening Create or changing customer has no aggregate lookup/contact loading state. Recommendation: reuse ReferenceLookupStatus's page default and inherited EditorDialog scope, aggregating all required bootstrap flags per surface and keeping errors/Retry and busy state. Existing shared CSS already hides duplicate routed StateMessages when the page host exists (`src/index.html:67–84`); those suppressed messages are **not** a separate duplicate-spinner finding. Owning UI22, 2026-10-26 rule.

### AUX-05 — P3: dialog reads still acquire an unnecessary hidden global page count

The following body-appended EditorDialog reads render a local StateMessage but start/end the global count: Cost Setting details (`.../details/details.component.ts:316–323`), Inquiry detail (`.../details/details.component.ts:372–381`), Inquiry logs (`.../logs-dialog/logs-dialog.component.ts:81–91`), Clause type detail (`.../details/details.component.ts:184–191`), Clause collection (`.../clauses/clauses.component.ts:250–257`), and Quotation→Master creation detail (`.../master-agreement-dialog/master-agreement-dialog.component.ts:126–128`). Their subscription teardown/finalize and identity checks are present, and shared portal precedence hides shell progress while their local StateMessage is visible. The mismatch is ownership: UI22 says dialog reads stay local without a hidden global count. Recommendation: retain local busy/StateMessage/error/Retry and cancellation, remove only the dialog-read count ownership. Keep paired global write safety for Save/domain mutations.

### AUX-06 — P2: Quotation/Master print output lacks the shared flow release and action hiding

Quotation calls `ReportPrintService.print()` at `.../details/details.component.ts:218`; Master at `.../details/details.component.ts:58`. Both use the shared lifecycle correctly and pass **no** Agreement-specific body class. Thus Agreement's old-modal selector/blank-output defect does not apply to these two. Their routed templates still leave Back/Print and the action footer in the output and do not mark bounded page/panel/form/body/scroll layers `sigma-print-flow` (Quotation HTML:1–13,58–63; Master HTML:1–10,19). Shared shell print release (`src/styles.scss:208–224`, `layout/layout.component.scss:24–28`) stops above those retained editor bounds (`styles.scss:3650–3655,3673–3703,4119–4141`); the existing opt-in release is `styles.scss:3997–4002`. Confirmed source gap: non-document actions remain print content and bounded flow is not released according to UI21. Multi-page clipping/actual paper output remains owner-runtime pending. Recommendation: use the existing shared flow/no-print contracts. Tariff exposes no Print action, so it is not added to this finding.

### AUX-07 — P3: editors do not merge saved reference labels into current edit choices

Quotation patches persisted IDs and retains detail label objects (`.../details/details.component.ts:261–266`) but lookup/contact completion replaces the option arrays (`:285–287,306`); the edit Selects consume those arrays directly (HTML:21,25,37,39). Inquiry does the same (`.../details/details.component.ts:403–413,445–448,474`), and Cost Setting retains historical name maps only for view labels (`.../details/details.component.ts:300–308,379–395`) while edit Selects consume raw lookup arrays (HTML:35–37,72–73). An edit opened against a successful source that omits a saved identity can show a blank choice while retaining its ID. Recommendation: reconcile saved selected labels during the finite initial/detail merge and retain selected choices on successful refresh; never change the draft or resurrect previous-context labels. This is a source conformance gap under UI2/16/22; whether the current tenant has such omitted identities remains pending owner verification, not an asserted production occurrence.
