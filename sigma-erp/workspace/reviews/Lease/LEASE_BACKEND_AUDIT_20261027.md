## Confirmed actionable findings

All paths in this section are relative to `F:/My Work/Sigma/SigmaBackend/`.

### BE-01 — P1 — Ordinary Extend removes persisted additional charges from the agreement total

`SiGma.Business/Services/AgreementServices/LeaseAgreementService.cs:821` loads the agreement with BookingCharges only. At `:877` subtotal starts at zero; `:898` accumulates only booking-charge totals; `:903` computes the total and `:915` persists it with `SetTotalChargesExplicit`. Existing AdditionalCharges remain stored but their amounts disappear from the authoritative total after this action.

Example: an open agreement has active additional charges 50, extended booking subtotal 200, zero discount and zero tax. Ordinary Extend writes 200, while the existing Add/Update Additional Charges and extended-rate/Close paths produce 250. This affects displayed balance and downstream consumers of persisted TotalCharges. The source evidence does not require changing tax, discount, rent or invoicing policy: `UpdateAdditionalChargesAsync` at `:2232` includes active additional amounts; the extended-rate action at `:1236` initializes subtotal from active additional amounts; Close also includes them. The earlier owning Additional Charges contract explicitly protects their effect on recalculation. Recommendation: make ordinary Extend retain the same tenant/live/active additional-charge scope and authoritative total contract, with comparable action context/preview behavior. No implementation authorized in this audit.

### BE-02 — P1 — A concurrent quotation edit can overwrite a successful approval

`SiGma.Business/Services/LeaseQuotationService.cs:52` loads the tracked quotation and `:60` checks editability once. After validation and mapping, `:120` marks the **entire root** Modified and `:125` saves. Approval separately uses conditional `ExecuteUpdateAsync` at `:481`, which correctly checks expected statuses, but that status change does not fence the earlier edit.

Interleaving: request A loads Pending/Pending; request B internally approves; request A marks the root Modified and saves its previously loaded Pending statuses, reverting the successful approval and changing the supposedly approved contents. `LeaseQuotationProfiler` ignores incoming approval fields, which protects against client assignment but does not prevent this stale full-row write. `LeaseQuotationConfig` supplies no approval/version token; `SiGmaDbContext.cs:48`–`:56` adds SubscriptionId as the concurrency token, which is unchanged in this same-tenant race. The catch at `:127` therefore does not establish state concurrency protection. Recommendation: use one shared state/version write boundary covering edits and transitions, preserve exact existing transition semantics, and verify concurrent edit/approve ordering. Do not introduce a state schema or migration without its own authorization.

### BE-03 — P1 — Standalone quotation child writes bypass approved-parent guards

`SiGma.ServerAPI/Controller/LeaseQuotationItemController.cs:9` inherits public PUT/DELETE from `SiGmaControllerBase.cs:35` and `:39`. `SiGma.Business/Services/LeaseQuotationItemService.cs:5` has no overrides. Generic Update at `Services/Bases/Service.cs:100` verifies tenant/live row identity and ordinary references, but never reads the owning quotation state; generic Delete at `:942` only finds/deletes the child.

An authenticated caller with a same-tenant item id can update its Units/model or delete it after internal/customer approval, bypassing the parent service's pending/rejected edit guard and minimum-line readiness checks. This can invalidate an approved quotation and a quotation referenced by an existing master. This is a domain-integrity bypass, not an assertion that a new permission system is required. Recommendation: enforce the same aggregate parent/approval boundary on all existing child writers, or retire unused write routes after checking consumers. Parent snapshot updates must remain one aggregate save. Standalone Tariff child services also lack the parent writer's cross-row range-overlap checks; inventory them in that same repair rather than assuming UI nonuse protects the API.

### BE-04 — P2 — Clearing payment instructions prevents re-creation

`LeaseAgreementService.cs:1797`–`:1803` loads only live PaymentInstructions and their live Cheques. Null-method clear at `:1820`–`:1825` removes only the instruction. Later selecting a method sees no live instruction and creates a new row at `:1830`–`:1838`. `SiGma.DataAccess/Configuration/LeaseAgreementPaymentInstructionConfig.cs:24`–`:28` declares an **unfiltered unique** `(SubscriptionId, LeaseAgreementId)` index, also present in the model snapshot at `:3330`. Soft delete leaves that old unique slot occupied, so save/clear/save fails when the declared schema is deployed. The exception is converted into the generic save-failed response at service `:1894`.

The frozen payment-instruction contract explicitly permits null as clear. Recommendation: follow existing BE14 retained one-to-one reconciliation guidance for the reusable slot and preserve historical proof. The current query loads cheques and their configured client cascade may mark them Deleted before the audit conversion; no cheque-orphan defect is asserted from the missing explicit helper alone. No hard delete, financial-history revival or automatic index migration is implied. Runtime confirmation depends on deployed-index parity, which was not inspected.

### BE-05 — P2 — Quotation actions remain hidden after deleting a draft master

`LeaseQuotationService.cs:278`–`:283` calculates CanUnapprove and CanCreateMasterAgreement through raw `Context.LeaseMasterAgreements.Any(...)`, including soft-deleted masters. No global EF query filter is configured in `SiGmaDbContext.OnModelCreating`. In contrast Unapprove at `:368` and `LeaseMasterAgreementService.AddAsync` at `:65` use the repository's live/tenant ExistsAsync boundary. `LeaseMasterAgreementService.RemoveAsync` permits soft deletion of a nonapproved unreferenced master.

Create a master from a customer-approved quotation, then delete that draft master: the server's authoritative operations again allow Unapprove/Create, but the refreshed list flags remain false, preventing the user from reaching either action. Recommendation: compose one repository-scoped live-master predicate for the bounded list flags and retain the write-time rechecks/serializable uniqueness boundary. Raw Any also omits the explicit tenant predicate, although globally unique FK ids mean the soft-delete discrepancy alone is sufficient to prove this finding.

### BE-06 — P2 — Aggregate deletion leaves owned Lease rows active

`LeaseAgreementService.RemoveAsync` at `:331` checks state/external usages then delegates at `:379` to generic `Service.RemoveAsync:942`, which removes only the loaded root. Agreement-owned BookingCharges, Clauses, Provisions, PreTerminationRules, Documents, discounts, additional charges, replacements, payment instructions/cheques and logs are not explicitly loaded/deleted there. Tariff has no Remove override, leaving its four rate collections live as well. Inquiry Remove at `LeaseInquiryService.cs:315` deletes items but does not remove its owned stage histories.

The context converts Deleted EntityBase rows to soft-delete updates (`SiGmaDbContext.cs:508`–`:529`); database cascade therefore cannot clean up untracked children. These rows continue to satisfy direct tenant/live child reads and can block reference deletion or be counted by child-table consumers despite the deleted parent. This is an in-scope occurrence of **existing BE backlog23**, not a new shared defect. Recommendation: enumerate actual owned children, retain legitimate external/history rules and apply the existing aggregate delete owner with nested usage checks. Do not remove the existing business blockers or treat external transaction rows as owned. Historical-retention exceptions require explicit contract evidence.

### BE-07 — P2 — Cost Parameter list has no server page-size bound

`LeaseCostParameterService.cs:23`–`:24` takes PageNo/PageSize verbatim; `:42`–`:43` uses them in Skip/Take. `SiGma.Helpers/Request/ListSmBase.cs:5`–`:6` has no Range annotations; base controller `SiGmaControllerBase.cs:46`–`:48` forwards the bound DTO without clamping. A caller can request PageSize=int.MaxValue and materialize the entire tenant catalog, or send zero/negative paging and obtain invalid count/page arithmetic or query behavior. Other reviewed Lease lists clamp page size to 100/200 and lower-bound PageNo. Recommendation: apply the common bounded paging contract before count/page construction and preserve the complete, separately owned GetSelect lookup response.

### BE-08 — P2 — Cost Setting uniqueness is only a race-prone precheck

`LeaseCostSettingService.cs:136` checks whether MakeAndModelId already exists, then inserts/saves at `:142`–`:143`. Update similarly checks at `:188`. These custom overrides have no serializable/application-lock boundary. `LeaseCostSettingConfig.cs:7` only names the table; the current model snapshot at `:18167` declares a MakeAndModelId FK index, with no tenant/model unique constraint. Two simultaneous creates for one tenant/model can both pass and persist distinct live settings. Cost Parameter name (`LeaseCostParameterService.cs:92`) and Clause Type name (`ClauseTypeService.cs:214`) have the analogous precheck-only problem; both current configs/snapshot lack unique keys, and Name is currently nvarchar(max).

Recommendation: close each confirmed existing uniqueness invariant through its shared guarded writer plus an owner-reviewed tenant/live database constraint. Names require a frozen bounded length matching add/update VMs before they can be indexed. Existing duplicates, nullable IsDeleted semantics and schema deployment must be reviewed first. These are correctness constraints, not performance indexes or permission to run migrations.

### BE-09 — P2 — Cost Setting advanced column rules use a different label from the returned grid

`LeaseCostSettingService.cs:23` applies `ApplyGridFilters`; the actual row projection at `:30`–`:39` returns null for deleted/foreign model references and falls back to the model name when Make is unavailable. `LeaseCostSettingProfiler.cs:19`–`:27`, used by generic `GridFilterProjection` (`Service.cs:864`), checks only navigation nullness and always concatenates a nonnull Make. Thus a deleted Make is included in the filter label while the visible label omits it; a deleted model can match a hidden name although its displayed label is null. Counts/membership disagree with the displayed field and shared column-filter contract.

Recommendation: reuse the actual scalar read projection for both filtering and materialization, preserving the existing live/historical label policy. Inquiry's mapper already repeats its materialized tenant/live label guards; do not alter unrelated historical-label contracts.
