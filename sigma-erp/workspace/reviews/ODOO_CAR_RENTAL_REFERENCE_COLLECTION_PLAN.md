# خطة جمع مرجع Odoo لدورة تأجير السيارات

التاريخ: ٢ نوفمبر ٢٠٢٦. التفويض: طلب المالك جمع وثائق Odoo للتأجير وضمها إلى وثائق سيجما للتحسين وإكمال السلوك الناقص. التنفيذ توثيقي، لا استيراد قواعد مالية أو تشغيل تطبيق/DB/اختبارات أو تعديل تلقائي للشاشات بهذه الحزمة.

المصدر المجمد: المستودع الرسمي `https://github.com/odoo/documentation`، فرع `19.0`، commit `0cc05c25b7614d4d448982fa7d12754ce6462c88`. قرئت بداية LICENSE الرسمي وتؤكد Attribution-ShareAlike 4.0 International؛ تحفظ نسخة الترخيص الكاملة والإسناد، والمصادر المنقولة دون تعديل. لا خلط master/20/SaaS بمصدر 19.0، ولا تضمين وثائق إضافات مدفوعة أو طرف ثالث على أنها Odoo القياسي.

قرار الأولوية النهائي اللاحق: «الاساس سبيد والمفقود ندور عليه فى اودود». سبيد بالدليل والشرح والكود هو الأصل، وOdoo مكمل للمفهوم أو السلوك الناقص أو غير الواضح بعد فحص سبيد. هذا يسود الاقتراح السابق لبدء المتشابه من Odoo، ويُثبت في Master2 والمدخل والمهارة دون تغيير سلطة عقود سيجما.

## الهدف والشكل

إنشاء حزمة مرجعية مؤرخة تحت جذر الوثائق `references/odoo-rental/2026-11-02/`، مع مدخل عربي دائم في `references/odoo-rental/README.md`. تشمل كل صفحات Rental وFleet الرسمية وملفاتها اللازمة، ومراجع رسمية منتقاة صريحة للاقتباسات والعملاء والمخزون/الترقيم والفوترة/الدفع والضرائب والصيانة والتوقيع والمستندات عند ارتباطها بدورة السيارات. كلمة «كامل» تعني تغطية الدورة وحصر النواقص والتقاط كل فروع Rental/Fleet، لا ادعاء أن Odoo العام يثبت نظام سيارات متكاملًا أو كل قواعد سيجما.

## المهام

- [x] جرد شجرة المصدر المحدد والتحقق من كل ملف عبر Git blob SHA-1 وSHA-256، وحفظ الترخيص وتاريخ الجمع. الروابط المحلية مفحوصة؛ روابط التصفح المنشورة مشتقة ومعلنة دون ادعاء فحص HTTP لكل واحدة.
- [x] جمع الملفات الأصلية والوسائط المرتبطة بالفروع المحددة دون بناء وثائق Odoo أو تشغيل أكوادها؛ لا تجاوز روابط مجهولة أو تنزيل التطبيق نفسه.
- [x] إعداد دليل عربي للدورة، وفهرس بالصفحات والروابط المحلية/الرسمية، ومصفوفة تغطية/حدود تفصل المشاهد في الوثائق عن استنتاج سيجما.
- [x] إعداد مصفوفة مواءمة أولية مع ملاك سيجما المعروفين والعقود الجارية، مع تمييز «موثق في Odoo»، «يتطلب مراجعة مصدر سيجما»، «غير مثبت»، وقرارات مالية/صلاحيات تحتاج عقدًا لاحقًا؛ لا ادعاء تدقيق كامل للتطبيق.
- [x] ربط الحزمة بمدخل وثائق سيجما والفهرس المرجعي ومرجع خيارات العملاء والأرقام عند صلتها؛ مراجعة الفروق والبصمات والروابط المحلية، وتقرير قبول/حدود الجمع.

## ملكية العمل والتفويض المتوازي

الجذر يملك الخطة والإصدار والترخيص وملفات الحزمة والجمع والفهرسة والدمج والمراجعة النهائية. باحث أول يقرأ المصادر الرسمية لدورة Rental فقط ويرجع جردًا وتحليلًا بلا كتابة ملفات. باحث ثان يقرأ Fleet والوظائف المساندة الخاصة بدورة السيارات فقط ويرجع جردًا وحدودًا بلا كتابة ملفات. لا تعديل متداخل أو عمل مالي مستقل أو وكلاء إضافيون. تفويض محدود وفق القسم 311 من القواعد الحية ومهارة dispatching-parallel-agents.

## التحقق والقيود

الفحص المسموح: وجود الملفات، JSON/XML/Markdown عند الحاجة، البصمات والروابط، قراءة الفروق المحددة، فحص اتساق الحزم عند استخدامها. لا build/test/lint/DB/migration/browser جديد أو كتابة خارجية/حفظ تطبيق. نشر وثائق Odoo رسميًا لا يثبت وجود هذه الميزات في سيجما أو نجاح تشغيلها، ولا يغير ترتيب سلطة الكتب والعقود. يبقى تعديل عدد الأيام القابل للتحرير وطلب حذف الرسالة شريحة تنفيذ مستقلة من تفويض المالك السابق، ولا يتولاها باحثا التوثيق.
