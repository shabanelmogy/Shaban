# خطة إظهار عنصر القائمة المختار — ٣١ أكتوبر ٢٠٢٦

تعديل لاحق بتاريخ ١ نوفمبر ٢٠٢٦: طلب المالك إبقاء رفع القوائم عند فتح فروعها، مع ثبات التمرير عند اختيار صفحة فرعية. يحل القرار والتنفيذ في SIDEBAR_GROUP_REVEAL_FEATURE_REVIEW.md، قسم «ثبات القائمة عند اختيار صفحة فرعية»، محل جزء محاذاة الورقة وبدء المحاذاة بعد الانتقال أدناه. تبقى بقية الخطة والسجل التاريخي كما هما.

الحالة: Frozen بتوضيح المالك «المفروض القائمة تترفع عشان اظهر العنصر اللى ضغطت عليه». التنفيذ مأذون ضمن إصلاح استمرار المشكلة عند اختيار Driver tracker. المطلوب محاذاة العنصر المختار نحو أعلى viewport القائمة بالقدر المتاح، مع بقاء موقعه ظاهرًا بعد انتقال الشاشة، والحفاظ على الإفصاح/البحث/اللغة/التثبيت ومحتوى الصفحة.

| الأثر | القرار | المالك والدليل |
|---|---|---|
| شجرة القائمة بعد NavigationEnd | Refactor تحديث active على نفس كائنات العناصر وأبنائها؛ لا إعادة بناء عند تغير الشاشة فقط | SidebarMenuComponent؛ toPanelItems ينشئ كائنات جديدة، وPanelMenu المثبت يتتبع هويتها في ngFor |
| العنصر المختار | Extend نفس reveal الموجود للجذر/العنصر الورقي وبعد تغير path؛ Align نحو أعلى القائمة مع clamp | pendingReveal/restoreReveal/frame/ResizeObserver داخل menuScroll فقط |
| route active styling | Keep exact/exclusions/query normalization؛ مسار نشط signal لتحديث القالب المقدم داخل publisher OnPush | isLeafActive مع نفس المقارنة وstyleClass/template |
| المجموعات والبحث/اللغة | Keep الإفصاح الحالي وautoExpand الابتدائي؛ إعادة بناء البحث/اللغة فقط عند سببهما | state.expanded/searchExpanded/filterMenu |
| query/fragment فقط | Keep موضع المستخدم دون إعادة reveal بسبب URL-only state | linkKey path comparison؛ يظل command المباشر قادراً على إظهار العنصر المختار |
| الماوس/اللوحة/Drawer | Keep إلغاء reveal عند تدخل المستخدم أو إلغاء/تدمير الجلسة؛ remount يعيد كشف النشط أو أصله المرئي | shared SidebarMenuComponent وLayout navigationState |
| بيانات/API/خادم/تحميل/كاش/فهارس | Keep دون تغيير | لا request أو query جديد من حركة العرض |

البدائل: تثبيت scrollTop فقط لا يحقق إظهار المختار وفق التوضيح؛ إعادة بناء الشجرة ثم تعويض التمرير تكرر سبب فقد هوية العقد؛ إصلاح خاص بالخريطة/EditorTabs لا يخص مالك القائمة. المختار تحديث هوية مستقرة مع آلية reveal الحالية. لا حقول أو صلاحيات أو مالية/حذف بيانات أو schema/migration.

المراجع: Master1/5/7 وUI1/27/28/29، مهارة Sigma وPrimeNG router ثم audit-troubleshooting، وتقرير SIDEBAR_ACTIVE_ITEM_FEATURE_REVIEW للتشخيص السابق وSIDEBAR_GROUP_REVEAL_FEATURE_REVIEW لمالك محاذاة المجموعة. فحص الحزم الثماني ناجح. هذا سلوك shell خاص بسيجما؛ Speed DriversTracker يثبت رابط الشاشة فقط ولا يحدد حركة القائمة، لذلك لا نسخ تصميم/عقد مالي منه.

التنفيذ محلي متسلسل في مالك واحد مع القالب/الدليل والكتاب والمهارة وتوليد الحزم، دون وكلاء إضافية لصغر الشريحة. الفحص مصدرّي فقط: مراجعة diff وصياغة TS/HTML والدليل وCheck للحزم؛ تشغيل المتصفح/البناء/الاختبارات/DB غير مأذون. القبول المرئي المتبقي: اختيار DriversTracker بعد التمرير، إعادة اختياره، route آخر/query-only/بحث/Back، مجموعة مطوية، الإلغاء اليدوي، الحركة/الارتفاع القصير وRTL/الثيم وDrawer.
