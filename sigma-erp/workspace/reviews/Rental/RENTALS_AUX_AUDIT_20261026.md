## Actionable findings

### AUX-01 — P1: route departure discards the main tariff/card draft without confirmation

`SiGmaAngularFrontEnd/src/app/modules/Rental/RentalTariff/components/list/list.component.ts:65–68` returns true whenever `settingsVisible` is false. The equivalent `TariffCard/components/list/list.component.ts:96–99` checks only `branchSettingsVisible`. Their active route files delegate `canDeactivate` to these methods (`tariff.routes.ts:5–11`, `tariffcard.routes.ts:5–11`). Neither parent queries the mounted main editor's dirty state or close decision.

Trigger: open a tariff or card editor, change an unsaved field/row, then leave the route using navigation/back. The settings dialog is closed, so the feature guard returns true; the child is destroyed and its draft disappears. The child's X/Cancel paths do ask for discard (`RentalTariff/components/details/details.component.ts:658`, `TariffCard/components/details/details.component.ts:167`), but route exit does not call them. The global fallback does not rescue it: `shared/utils/navigation-policy.guard.ts:20–24,33–41` skips `NavigationPolicyService.allowNavigation()` when a feature guard will run. This is a source-supported route/draft gap under UI10/28. Shared `NavigationActivityService` separately blocks pending mutations; this finding does not assert that an in-flight save can be navigated away from.

Recommendation: expose one deferred, identity/busy-safe editor exit decision and have the parent delegate to the actually mounted main editor as well as the settings child; retain one confirmation, canceled draft and disabled-state restoration.

### AUX-02 — P2: planner headers can describe a different date range from the displayed reservations

`RentalPlanner/components/list/list.component.ts:148–150` immediately regenerates slots when the date selection changes. Existing `data` remains from the last search. The template binds the new slots at `list.component.html:159–174,197–205`; its caption also comes from the current mutable filter (`list.component.ts:181–186`). The API deliberately clips each returned interval to the requested range (`SigmaBackend/SiGma.Business/Services/RentalPlannerService.cs:158–172`).

Trigger: successfully search one month, then select another date range before Search. New date columns appear over the old vehicles and clipped reservations. Dates outside the last search become blank cells even where a booking/rental exists. A filter changed during a delayed request can likewise be paired with the old query response (`list.component.ts:108–132` has no query identity comparison; FilterPanel.busy only disables Reset/toggle, not projected controls). This can mislead planning. Preserve a last-successful query/result snapshot for headers and rows, or invalidate/show not-run until the changed query succeeds; fence late results against the active query. Zoom alone can continue to reproject the same successfully loaded interval.

### AUX-03 — P2: required routed lookup bootstrap bypasses the page loader

Two consumers conflict with UI22's 2026-10-26 owner clarification:

- Planner `loadMakes()` at `RentalPlanner/components/list/list.component.ts:236–262` sets only `loadingMakes` and clears it in finalize. It never starts the page count or uses ReferenceLookupStatus. Its filter select instead binds `[loading]="loadingMakes()"` (`list.component.html:60`). The planner data request begins only after this read succeeds, so cold initial make lookup has no page progress and uses an inline filter spinner.
- Time-sheet `loadOptions()` at `DriverTimeSheet/components/list/list.component.ts:395–423` joins agreement options and driver options but sets only `loadingPage`. Its template renders an in-page StateMessage (`list.component.html:10–12`), without contributing to LoadingService. Required bootstrap must use the same global host as routed row/save reads, while retaining disabled/error/Retry state.

All four active routes have no `showPageLoading:false`; only Dashboard's separate root has that explicit policy (`pages/routing.ts:28`). The ordinary shell host is `layout/layout.component.html:38–40`, enabled by `layout.component.ts:48`. Thus the missing page lease is an actual source mismatch, not suppressed metadata. The shared `ReferenceLookupStatus` is the approved presentation seam even for a direct/noncached bootstrap. Runtime visibility and delay acceptance remain pending.

### AUX-04 — P2: tariff-card option bootstrap has no dialog progress at all

`RentalTariff/components/details/details.component.ts:806–826` raises `loadingOptions` for `TariffCard/GetEditorOptions` and releases it on teardown/finalize, but neither starts global loading nor renders a local status for that flag. `details.component.html:25–31` displays loading only for `loadingDetails`. The editor detail request starts after options finishes (`details.component.ts:819,824`), so the option wait is uncovered on initial open and Retry. Row actions are gated by loadingOptions, but the user receives no visible reason. Use one aggregate local dialog bootstrap status under EditorDialog's scope; preserve error/Retry and the current direct option contract. Do not add page/filter spinners or an independent skin.

### AUX-05 — P2: the active branch-settings consumer lacks the approved Branch cache watch/context lifecycle

`shared/components/branch-tariff-settings/branch-tariff-settings.component.ts:84–117` makes a finite `BranchService.getSelectList` read and merges saved labels once into `branchOptions`. The source is opted in (`Administration/Branches/services/branch.service.ts:16`), with root cache owner and `lookup-branches` topic (`shared/service/reference-lookup-cache.service.ts:370`). Successful source writers invalidate through `invalidateSelectOnSuccess`; `deleteBranch` uses inherited delete. However the actual mounted settings child has no `ReferenceLookupBindings`, `watchSelectList`, cache-context reset or separate watch subscription anywhere in its source.

Trigger: keep this dialog open while a branch is renamed/deleted/added or cache context changes. Source invalidation/tenant notifications cannot update/clear the consumer's already-copied options; options stay stale until reopening or manual Retry. Adopt the existing finite bootstrap + separate once-bound watch, preserving selected/saved labels and row drafts, clearing old-context options without merging old labels back, with retained-data refresh silent and failure/Retry + teardown. This affects the existing shared business owner used by two reviewed screens; no new cache source is requested. Successful TariffSetting writes need not invalidate Branch because they do not write branch identities/labels.

### AUX-06 — P2: fresh row CanEdit is ignored in the driver workspace

`DriverTimeSheet/components/list/list.component.ts:123–133,319–322` determines editing and Save eligibility from the agreement options loaded at entry. Fresh per-row `canEdit` from `DriverTimeSheet/GetDriverTimeSheetsByAgreement/{id}` is retained only in `rowData`; neither `createRow` nor those gates consumes it. The backend recalculates it from `agreement.Invoiced` for every row (`SigmaBackend/SiGma.Business/Services/DriverTimeSheetService.cs:92–109`).

Trigger: load options while an agreement is not invoiced, invoice it elsewhere, then select/retry its rows. Fresh rows correctly say canEdit=false, yet working hours/driver editing and Save remain enabled from stale options. Server Save correctly rechecks invoiced and rejects (`DriverTimeSheetService.cs:184–185`), so no bypass of authoritative invoicing protection is claimed; the user can make edits that cannot be saved. Reconcile the fresh operational edit flag before enabling row editing/Save. Do not reference-cache the flag or change the owner's deliberate Save-active-on-invalid/pristine decision.

### AUX-07 — P2: planner render work repeats reservation scans and date parsing per slot

`RentalPlanner/components/list/list.component.html:200–205` calls `reservationStatus(vehicle,slot)` five times per cell. Each call (`list.component.ts:208–219`) filters all reservations, parses both endpoints with new Date, allocates an array and scans for HIR priority. The whole fleet is returned, the default zoom is one hour and the default range is a month: a 31-day month creates 744 slots per vehicle; 100 vehicles creates 74,400 cells and 372,000 reservation scans per evaluation, before additional change-detection passes. No virtual/paged render bound or maximum period exists in `generateTimeSlots()` (`list.component.ts:265–295`).

Precompute parsed ranges and slot status when the successful result/range/zoom changes, then bind one stored result per cell; preserve overlap rules and HIR priority. A date limit, incomplete page or changed fleet scope is not implicitly authorized: those require a separate business/UI decision. Source complexity proves repeated work, not measured milliseconds. Browser CPU/render/memory measurements remain pending.
