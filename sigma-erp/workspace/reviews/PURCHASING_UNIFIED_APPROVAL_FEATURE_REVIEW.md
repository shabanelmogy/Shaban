## Action-state and side-effect matrix

| Action | Source → target | Interaction / read flag | Writer boundary and correction guard | Refresh / failure |
|---|---|---|---|---|
| Approve | Pending → Approved | Shared confirmation, canApprove | Model existing readiness plus exact source/financial/stock guards, same transaction | Reload context and actual owner row/details; no second success toast |
| Reject | Pending → terminal Rejected | Typed reason1..500, canReject | Recheck draft and dependencies; no effective journal/stock survives as if merely rejected | Preserve failed reason, allow retry/refresh, retain history; no reopen |
| UnApprove | Approved → Pending | Typed reason1..500, canUnapprove | Model removes real released effect under source/allocation locks and original financial period; refuses consumed/invalid dependencies | Re-read real canEdit/canDelete and list membership; never merge a fabricated final eligibility |
| Void | Existing eligible released record → canceled | Existing separate typed model workflow | Existing cancellation, stock/period/ledger guards retained | Existing source-owned history, no reversal/reopening invented |
| Log | No state transition | Row action on saved record | Tenant-validated live root/owned child identity from earlier log contract | Shared captured-write viewer; distinct from decision history |

PR has no journal/stock to undo. PO unapproval does not release its PR reservation because a pending order still reserves. GRN unapproval removes stock and cancels only its generated linked pending issues; effective approved/legacy issue or live Bill blocks it, and branch stock cannot become negative. Bill unapproval returns exact source quantities to pending reservation; rejection releases that reservation. Return approval remains financial supplier debit/counter-credit with optional allocations, not physical stock/VAT return. Returned pending financial source retains an unposted journal snapshot; editing does not regenerate/post it, and reapproval rebuilds the same identity. Historical null decisions remain unknown/read-only on new unified UI; the existing legacy Bill approve endpoint compatibility remains explicit and cannot reopen a rejected record. Reasonless legacy Bill unapproval fails.
