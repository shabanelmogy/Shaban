# تسليم مرجع Odoo وإدخال أيام الإيجار

التاريخ: ٢ نوفمبر ٢٠٢٦. الحالة: منفذ ومراجع مصدرّيًا؛ قبول التطبيق التشغيلي
متبقٍ. يغطي هذا التسليم طلب جمع المرجع وتحديد الأولوية، وتعديل Rate للأيام
القابلة للتحرير، وحذف رسالة اختيار النوع، وتصحيح اختفاء بطاقات الإجماليات.

## المرجع والترتيب المعتمد

القرار النهائي: **سبيد بالدليل والشرح والكود هو الأساس؛ المفهوم أو السلوك
الناقص أو غير الواضح يُبحث عنه في Odoo**. هذا يسود اقتراح البدء من Odoo
للأجزاء المتشابهة. نُفذ في Master2 ومدخل وثائق سيجما ومدخل سبيد وAGENTS
والقواعد الحية ومهارة الشاشة مع سجل مراجعتها؛ لا تغيير لحدود التنفيذ أو سلطة
عقود سيجما والمالكين المشتركين.

الحزمة في `F:/My Work/Shaban Documents/Shaban/sigma-erp/references/odoo-rental/`.
مدخل عربي دائم، سياسة أولوية، لقطة مؤرخة ودليل عربي للدورة ومصفوفة مقارنة،
وفهرس وCSV وmanifest وأداة جمع قابلة للتكرار. المصدر الرسمي Odoo19 مثبت عند
`0cc05c25b7614d4d448982fa7d12754ce6462c88`، مع LICENSE والإسناد CC BY-SA4.0.
النسخ الأصلية غير معدلة، والإضافات العربية مميزة وليست ترجمة رسمية أو كود Odoo.

الجرد: **٤١٧ ملفًا أصليًا، ٦٬٨٧٤٬٢٦٥ بايت**: ١١ Rental و٧ Fleet و١٠١ مساند
أي ١١٩ RST؛ ٢٩٧ ملفًا مساعدًا؛ LICENSE واحد. جرد GitHub غير truncated،
وكل ملف يطابق Git blob SHA-1، وفحص الجذر تحقق من SHA-256 المحلي كذلك.
جميع روابط Markdown المحلية داخل الحزمة مفحوصة، وصفر وسائط محلية مفقودة
من التوجيهات الملتقطة. لا فحص HTTP مزعوم لكل رابط نشر، ولا ادعاء جمع كل
إحالات RST الخارجية أو الفيديو، ولا تدقيق دلالي وتشغيلي لكل الصفحات.

قرئت ومُيزت دورة التأجير والأسطول والوظائف المساندة ذات الصلة؛ أوضحت المصفوفة
أن ربط Fleet بصنف Rental، ووقود/كيلومترات العقد، والمخالفات وسالك ودرب، وفحص
السيارة وتحمل التأمين لا تثبتها الوظائف العامة وحدها. استرداد منتج الوديعة
والمقدم والحجز المصرفي ثلاث دورات مختلفة. لا ترحيل مالي أو صلاحيات إلى سيجما
تلقائيًا؛ فحص سيجما الكامل ليس جزءًا من جمع هذه الحزمة.

## خانة الأيام والملخصات

العقد الجاري `RENTAL_RATE_DAYS_INPUT_CONTRACT_FREEZE.md`. بقي صف Rent والعمود
Rate نفسيهما. أصبحت الخانة مدخل عدد صحيح موجب من الأيام، وتتحقق مع النموذج؛
تغيير التواريخ يعيد حسابها. تعديل العدد ثم مغادرة الخانة يغيّر يوم الإرجاع
بالنسبة للبداية ويحفظ وقت الإرجاع السابق. مثال ٢ نوفمبر و٥ أيام ينتج ٧ نوفمبر.
هذه طريقة إدخال لفترة العقد القائمة وليست مدة مالية مخزنة مستقلة أو كتابة
عدد الأيام مكان السعر المالي في DTO. تُحفظ التواريخ ويحسب الخادم المبلغ
بالتعريفة ومالكه الحالي؛ لا هجرة أو نموذج مالي أو قاعدة تسعير جديدة.

اختيار ربط الأيام بالإرجاع يستعمل حقيقة مصدر سيجما القائم، ويتفق مع كون
فترة العقد مصدر المدة في شرح سبيد ووثيقة Odoo19 لإنشاء طلب الإيجار؛ لا يدعي
وجود نفس الخانة في Odoo أو اعتماد حسابه. المصدر المقروء في سبيد هو متحكم
C0530 المؤرخ٢٨ أكتوبر، ودوال التاريخ وحساب الأيام/الساعات؛ اختلافه عن أيام
تقويم سيجما مسجل في المصفوفة ولا يُغيّر ضمن هذا الإصلاح.

التغييرات بالواجهة: محرر Agreement TS/HTML، مستهلك حفظه المضمّن في
MasterAgreement/create HTML، دليل rental-guide، ومفتاح وحدة الأيام في ar/en.
مربعات الملخص الأربعة تبقى مركبة بعد bootstrap وتستخدم قيمتها pending من
SummaryCards القائم بدل اختفاء المربعات. حُذف نص Select a vehicle type...
ومفتاحه، وبقي تحقق الحقول والحفظ وقراءة التعريفة بمالكها القائم.

أضيف calendarDaysBetween إلى مالك date-utils الحالي، دون Date.UTC ذي تحويل
السنوات١–٩٩، واستُخدم في فرق الأيام وحد DateTime. وأضيف opt-out اختياري
mockDataIgnore في المحوّل المشترك حتى يولد المساعد التواريخ الأصلية ولا يكتب
عدد أيام عشوائيًا يغيّرها؛ إدخال المستخدم اليدوي باقٍ. رُقّيت القاعدتان إلى
UI17/UI13 والمهارة وأعيد توليد الحزم بالمالك الرسمي.

المراجعة المستقلة التقطت الحاجة لاستمرار ضغطة Save بعد الحساب؛ أُصلح ذلك
بربط الطلب بإصدار قراءة التعريفة، واستئناف واحد بعد نجاحها فقط. تغيّر المسودة
أو السياق أو إعادة التهيئة أو الإغلاق/الإلغاء/محاولة التنقل يلغي الطلب،
وتُفحص هوية الإصدار وحالة التدمير مجددًا قبل الاستئناف. حُدث زر حفظ الحوار
المضمّن أيضًا. لا حفظ تلقائي على فشل القراءة أو إلغائها.

## التحقق والمراجعات

فحوص صياغة TypeScript والقوالب Angular، تطابق مفاتيح الوحدة تحت rentalAgreement،
اختفاء الرسالة المحذوفة، ومراجعة الفروق المحددة والفراغات. تم فحص API العام
لـInputNumber من metadata الحالية ومثال reactiveforms؛ إسقاط API الخاص بالمكون
صحيح، والخصائص المخصصة للمالك المحلي طوبقت منفصلة مع تصريحاتها الفعلية.
هذا ليس Angular type-check أو build. المرجع: https://primeng.dev/inputnumber

الاستدلال المكمل من وثيقة Odoo19 الأصلية المثبتة والمجمعة؛ رابط التصفح:
https://www.odoo.com/documentation/19.0/applications/sales/rental/rental_orders/create_rental_order.html
الموقع المنشور قد يختلف؛ النص المحلي مصدر اللقطة. تم تجديد recipes بالـgenerator
وفحص الثماني بعد تحديث Master2 وUI13/UI17، دون تعديل مشتق يدويًا.

استُخدم باحثان مستقلان محدودان للقراءة الرسمية: Rental، وFleet/المساند؛ لا
ملكية كتابة متداخلة. راجع مراجع وثائق الجرد والحدود والترخيص وعينات الأصول
وأغلق النطاق دون عيب مؤكد. راجع مراجع UI مستقل الحفظ والإلغاء والسنوات،
وأغلق ملاحظاته مصدرّيًا بعد تصحيحها. النماذج موروثة لأن مسميات النماذج المفضلة
في القواعد غير معروضة بالمعرفات نفسها؛ الجذر احتفظ بالقرار والدمج والفروق.
العمل المتوازي خفض تكرار بحث مجموعتين مستقلتين، ولم يُستخدم وكيل لكل تعديل.

لم تُشغل builds/tests/lint/DB/migrations أو commits/push/deploy أو Graphify/
Sigma MCP. الموافقة السابقة لفحص المتصفح قائمة، لكن الأداة فشلت قبل الوصول
بملف تشغيل مفقود؛ لا معاينة ناجحة أو قياس سرعة مزعوم. لا طلب إضافي للتعريفة
أو فهرس أو cache جديد؛ تبقى القراءة التشغيلية مباشرة وبـdebounce/cancel الحاليين.

## قبول المالك المتبقي

- غيّر التواريخ وتحقق من عدد الأيام في Rate؛ عدّل العدد وغادر الخانة وتحقق
  من الإرجاع مع بقاء وقته، ومن السعر والمبلغ المحسوبين بالخادم بعد الحفظ.
- تحقق من حفظ بنقرة واحدة، فشل/Retry، وإلغاء الطلب المؤجل عند الإغلاق أو
  تغيّر البيانات/الجلسة، في الصفحة وفي النافذة من العقد الرئيسي.
- تحقق من بقاء بطاقات الإجماليات، وأيام صحيحة/ناقصة/مقلوبة/سالبة/كسرية،
  ومدد ضمن سنة١–٩٩ وحدود السنة٩٩٩٩، وView/Print دون تعديل مبالغ محفوظة.
- راجع المراجع المحلية وابدأ أي تحسين جديد بقطعة سبيد ثم السؤال المكمل في
  Odoo؛ هذه الحزمة لا تعني اعتماد كل سلوك البرنامج الخارجي.

لا هجرة إضافية لهذه الشريحة. اقتراح الواجهة فقط:
`fix(rental): edit rental days through return dates and retain summary cards`.
اقتراح الوثائق فقط:

## استكمال معاينة مبلغ الإيجار أثناء كتابة الأيام

بلاغ المالك بتاريخ ٢ نوفمبر ٢٠٢٦: الكتابة في Rate لا تحدث Charges. المسار
المؤكد كان يلتزم بالعدد عند onBlur فقط؛ لا اشتراك لتحديث المعاينة من حقل
الأيام نفسه. أضيف اشتراك valueChanges إلى محرر Agreement الحالي، مع حواجز
التحرير والتعريفة الجاهزة وصحة الأيام والبداية، وإلغاء عند التدمير. يمرر
العدد إلى recalculateChargeTotal القائم بدل تكرار معادلة، فتتحدث الرسوم
والملخصات بالعدد المدخل وسعر التعريفة الحالي دون انتظار blur أو طلب شبكة
لكل ضغطة. التواريخ والتعريفة الرسمية تتجددان عند blur/Save كالسابق، ولا
تغيير للمبلغ المحفوظ بالخادم أو DTO أو تحميل/كاش/فهرس أو هجرة.

حُدث دليل التأجير العربي والإنجليزي في موضعه الحالي، مع توضيح أن تعريفة
بسعر صفر تعطي مبلغًا صفرًا ولا يجوز تخمين السعر. النطاق صغير مترابط؛ لم
تُستخدم وكلاء إضافية. التحقق مصدرّي؛ تجربة إدخال عدة أرقام وتحديث الإجماليات
ثم مغادرة الخانة والحفظ في الصفحة والنافذة المضمنة متبقية لدى المالك.

نتيجة الفحص لهذا الاستكمال: صفر أخطاء صياغة في ملفي المحرر والدليل، وصفر
أخطاء تحليل قالب المحرر، واجتاز git diff --check للملفين. روجعت الفروق
المحددة مع الحفاظ على العمل السابق. هذه ليست نتيجة بناء أو تشغيل أو اختبار؛
لم تُشغّل الأوامر المحظورة. اقتراح الالتزام لهذه الشريحة فقط:
`fix(rental): preview rent charges while editing rental days`.

## توضيح مصدر سعر الإيجار بعد بلاغ استمرار غياب المبلغ

الفحص المصدرّي بتاريخ ٢ نوفمبر ٢٠٢٦: الأيام ليست مصدر السعر. يستدعي محرر
Agreement الدالة getTariffCharges في خدمته، ومنها Tariff/GetBookingCharges
بنوع المركبة والبداية والنهاية. تمرر TariffService.GetBookingChargesAsync
إلى TariffCalculateService.CalculateRentalTariffAsync. الأخير يقرأ تعريفة
نشطة لنوع المركبة والاشتراك الحالي، بشرط Type=Daily وTariffCardId=null،
ويأخذ Rate من RentalRates ويحسب TotalCharge=Rate×أيام التقويم.

الفجوة المؤكدة: المسار لا يستقبل نوع الاتفاقية ويثبت التعريفة اليومية، ولا
يختار الأسبوعية/الشهرية أو بطاقة عميل. هذه حقيقة كود وليست إثباتًا لبيانات
تعريفة المستخدم أو استجابة طلبه. إخفاء السعر المالي من خانة Rate لصالح عدد
الأيام يزيد غموض مصدر المبلغ؛ تعديل المعاينة السابق لم يثبت وصول سعر فعلي.
لم يتغير اختيار التعريفة أو سلوك مالي بهذه الإجابة؛ يلزم تتبع عقد اختيار
النوع والفترة قبل إصلاحه، دون افتراض أن تعريفة المستخدم مفقودة أو تخمين سعر.
