## تحديث التنفيذ المحدود — التنسيق وظهور نتائج البحث

طلب المالك: «حسن تنسيق الشاشة وبعد البحث اسم المكان مش بيظهر الا بعد الاختيار». الحجم S داخل المراجعة الموجودة؛ عقد هذا الجزء Frozen بطلب المالك: تحسين تكوين المحرر وإظهار اسم وعنوان الاقتراح قبل الاختيار، مع إبقاء مدخلات الحفظ الثلاثة وعناوين الخدمة وقواعدها الحالية. الشكل UI01 قائمة بمحرر نافذة، والخلفية BE13 كيان عادي بلا تعديل خادم. التنفيذ محلي متسلسل؛ لا عمل مستقل يبرر تفويضًا جديدًا.

أعيد فحص المهارة والكتل المعنية وPHASE03 بعد نجاح اتساق الحزم الثماني. أدلة التحليل والصورة والتاريخ المقروءة في هذه المراجعة هي مدخل القرار، مع إعادة قراءة مدخل التحليل وشاشة المواقع والمتحكم C0914. الخريطة ونطاق البلد والموفر والتحقق الخلفي والتأكيدات خارج هذا الطلب المحدود، وتبقى نتائجها وقراراتها مدونة أدناه. لا ادعاء تكافؤ كامل مع المرجع.

التغييرات الفعلية في `Location/components/details/details.component.html` وملف TS الموافق، ودليل `UserGuide/content/limousine-guide.ts`:

- أصبح الحوار بعرض780px وارتفاع520px مع حدود viewport التي يملكها EditorDialog، ونقطة ضيقة819px. البحث والاسم والتفاصيل بعرض المحتوى، ومسافات الصفوف من utility المشتركة، والتفاصيل بثمانية صفوف. إطار النافذة وأزرارها وscroll واحد من المالكين الحاليين؛ لا SCSS محلي أو لوحة ألوان جديدة. هذا تكوين مقصود لثلاثة حقول، وليس نسخًا لتصميم الصورة أو استعادة CSS تاريخي.
- استبدلت الخاصية القديمة بـoptionLabel، وأضيف قالب item يعرض shortName ثم longName مع التفاف النص ومظهر مشترك. الاختيار يظل يعبئ النصوص وعلامة الإحداثيات عبر العقد القائم.
- ثبت سبب مصدري إضافي لعدم فتح النتائج: `handleSuggestionsChange()` في المكتبة المثبتة يوقف loading ويفتح/يغلق اللوحة عندما تتغير suggestions خلال بحث جارٍ. نشر مصفوفة فارغة في بداية completeMethod كان ينهي حالة البحث قبل الرد. أزيل هذا النشر من بداية الطلب؛ الرد الناجح/الفاشل وحده ينشر النتيجة، والتغيير اليدوي/الإلغاء ينظف البيانات السابقة قبل بحث المكتبة اللاحق.
- أصبح completeMethod مالك طلب البحث الوحيد؛ debounce300ms وحد أدنى حرفان في AutoComplete. أزيل timer المحلي والطلب من ngModelChange، مع إبقاء إلغاء القراءة السابقة فور تغير النص، وحراس الجاهزية/السياق/الوضع والعمل داخل switchMap. لا نتائج متروكة بين عبارتين ولا اعتماد على كاش تشغيلي.
- إعادة المحاولة تعيد التركيز إلى حقل البحث عبر focusField؛ completeOnFocus يبدأ نفس دورة المكتبة لتظل اللوحة مرتبطة بطلبها، بدل نشر نتائج خارج تلك الدورة. أخطاء الغلاف والنقل تنهي الاقتراحات وتبقي رسالة الخطأ/إعادة المحاولة. تُسجل حالة touched عند مغادرة الحقل ويستخدم invalid حالة FormControl القائمة.
- التحميل المحلي يظل StateMessage واحدًا؛ قالب loadingicon الفارغ يمنع مؤشر المكتبة المرئي الإضافي، وaria-busy باقٍ. تحميل التفاصيل المحلي، حفظ/حذف الصفحة، وحراس السياق الموجودة قبل المهمة محفوظة. الرؤية الفعلية تحتاج معاينة تشغيل.
- حُدث موضوع المواقع في الدليل العربي والإنجليزي ليشرح حد البحث واسم/عنوان الاقتراح والاختيار ومساحة التفاصيل وإعادة المحاولة.

التوثيق الأولي لبرايم: [مكوّن البحث والإكمال](https://primeng.dev/autocomplete)، مورد `primeui://primeng/components/autocomplete.md`، قسم template، والعقد الفعلي المثبت21.1.10. تحقق validate_usage النهائي أعاد valid=true بلا issues لواجهة المكوّن؛ استُبعد من الشفرة المرسلة إلى هذا الفحص Input توجيه Angular المسمى ngModelOptions، وهو موجود صحيحًا في التطبيق مع FormsModule، لأنه ليس Input لبرايم. هذا تحقق metadata فقط، وليس Angular compilation أو تشغيلًا.

المطابقة المصدرية النهائية: نجح تحليل صياغة ملفي TS والقالب عبر TypeScript/Angular parser، ونجح diff --check للنطاق. روجع فرق المحرر الكامل مع تمييز تعديلات السياق السابقة، وفُحصت import/FormsModule وAutoCompleteModule والعقود والحقول والخدمة وعدم بقاء timer/lastSearch. دليل الوحدة يحمل تعديلات أخرى سابقة حُفظت؛ تغير موضوع المواقع فقط بهذه المهمة. لم تتغير الكتب أو الحزم، لذلك لا إعادة توليد مطلوبة؛ فحص الاتساق ناجح.

الأداء والكاش: نفس URL المباشر للبحث والتفاصيل/القائمة، بلا مصدر lookup جديد أو opt-in أو invalidation جديدة. أزيل مسار الطلب والتحفيز الثاني من المصدر، دون أزمنة أو عدد HTTP مقاس. تقييم الفهارس أدناه باقٍ: لا سبب لتغيير فهرس في تنسيق/بحث واجهة، والاستعلام الخلفي لم يتغير. لا بناء أو اختبارات أو lint أو متصفح أو قاعدة بيانات أو ترحيل أو commit؛ التحقق التشغيلي/البصري والتوقيت pending لدى المالك، وبخاصة أول نتيجة قبل الاختيار، الكتابة السريعة/المسح، الاختيار وإعادة البحث، الفشل وإعادة المحاولة، السياق والحفظ، RTL/LTR والثيمين، والعرض819/700px والارتفاعات القصيرة.

## عقود الشاشة والتحميل والكاش

أعمدة القائمة: Actions ثم shortName، searchGoogleLocations، detail. نموذج الواجهة والخادم يحمل id وهذه الحقول؛ الإحداثيات في Detail ولا تُرسل كحقول مستقلة من المحرر الحالي. filter shortName وgrid مع pageNo/pageSize؛ pagination واكتمال response يفحصان بمسارهما الحالي. الإضافة: searchGoogleLocations≤300،shortName≤100،detail≤500؛ التحديث يضيف id؛ لا tenant/audit/number بالحمولة. إجراءات الحالية create/view/edit/delete؛ لا مالية أو طباعة أو تصدير مستقل لهذه الشاشة، ولا permission API؛ AuthGuard مصادقة فقط.

| URL/المستهلك | التصنيف والتحميل | الحياة والفشل/القبول |
|---|---|---|
| `Location`/getLocations | direct operational list؛ LoadingService عالمي | switchMap/start/finalize وtakeUntil context/destroy؛ shell افتراضي showPageLoading فعال. غلاف/HTTP في inline error/Retry، لا claim سرعة. |
| `Location/GetByWithNavigationsId/{id}`/getLocationDetails | direct operational detail؛ StateMessage محلي بحوار body | local flag/finalize/context/destroy؛ لا cache مطلوب لتفاصيل السجل. |
| `Location/SearchPlaces?searchKey=...`/searchPlaces | direct operational provider search؛ لا opt-in | timer/switchMap وlocal StateMessage، خطأ/Retry؛ هناك تحفيز مزدوج، وRetry لا يفحص contextInvalidated بنفسه. searchRequests بعد reset يُفرغ ويُفحص mode/busy فقط؛ يُوصى بحارس جاهزية/سياق موحد. |
| `Location/GetSelect` | لا يستهلكه محرر Location نفسه؛ خدمة المصدر cacheSelect الافتراضيfalse | قراءة مباشرة صحيحة في المستهلكين ذوي العقد الحالي؛ لا اختراع كاش لكل GET. |
| POST/PUT/DELETE Location | كتابة مستقلة؛ عالمي وDialog save progress مالك مشترك | revision يمنع local callback قديم؛ نجاح interceptor مالكه، وفشل الكتابة يحتفظ عادة بالمحرر ويستند إلى interceptor؛ لا inline saveError واضح. |

فحص API/metadata لا يثبت ظهور overlay ولا كامل مساحة الحوار. القالب لا يحدد height، بينما EditorDialog يعطي maxHeight فقط وداخل النموذج flex-fill. يجب قياس ارتفاع/عرض المحتوى المحسوب وscroll في populated/empty/error/loading، عند700/1024 ومجاوراتهما والأحجام البينية والضيقة، مع RTL/LTR والثيمين، وطول اقتراحات كبير. لا يستنتج انضباط الحجم من shared class فقط. تحميل suggestion يملك أكثر من مسار عرض ممكن بين مؤشر مكتبة autocomplete والـStateMessage المضاف؛ الرؤية التشغيلية تحتاج فحصًا قبل اتهام ازدواج مؤكد.

## الأداء والاستعلامات والفهارس

القائمة تنفذ count ثم تحميل الصفحة بترتيب حاسم، والتفاصيل سجل واحد ولا ملاحة مجال تثبت مشكلة graph أو قراءة لكل صف. بحث الموفر محدود بخمس نتائج. لا توجد أزمنة أو أحجام بيانات أو خطط SQL مقاسة؛ المصدر يثبت حدود الطلب فقط. التحفيز المزدوج وتأخير البحث وغياب إلغاء الموفر موضحة كمسارات قابلة للتحسين دون ادعاء سرعة مقاسة.

تهيئة Location تعلن الجدول فقط؛ لقطة النموذج المقروءة11061–11126 تبين PK Id بلا فهرس Location خاص، وهذا لا يثبت الفهارس المنشورة. لا فهرس جديد مبرر الآن. فهرسة ShortName ليست seek مثبتًا لبحث Contains. إذا أثبتت خطة القائمة كلفة تضييق المستأجر/الفرز، يمكن مقارنة `(SubscriptionId, Id DESC)` بفلتر `[IsDeleted]=0` مع التغطية الحالية، دون INCLUDE للنصوص الواسعة افتراضيًا. المنفعة المحتملة تقابل مساحة وكلفة كتابة، والقرار يتوقف على predicates الفعلية والخطة وIO؛ لا تعديل مخطط أو ترحيل من هذه المراجعة.

القياس المتبقي لدى المالك: نفس المستأجر واللغة والبيانات والصفحة، أول فتح وإعادة فتح، أحجام وعدد HTTP/SQL ومدة الموفر والرسم، ثم مقارنة نفس حالات الكتابة/الاختيار والفشل. تبقى رؤية التحميل، سلامة القياسات والمظهر وخطة الاستعلامات pending؛ لا يُستبدل ذلك بفحص مصدر أو كاش.

## الإجراء المقترح وحدود التسليم

الأولوية الأولى إصلاح ربط نص الاقتراحات واستعادة عنوان النتيجة، ثم استعادة توزيع الحقول ومنطقة العرض بما تحققه الصورة والمصدر، داخل المالكين الحاليين. بعدها توحيد مصدر البحث وحياة التأكيد والتحقق من نقطة الموقع. لا استرجاع ملف قديم كاملًا لأنه يلغي إصلاحات الملكية والسياق والحذف/الإحداثيات، ولا إعادة طلاء الشاشة بالـCSS القديم أو إطلاق مزود خرائط خارجي من هذه المراجعة.

لا تغييرات مصدر أو إعداد أو تعليمات أو دليل داخل التطبيق. ملفات المراجعة فقط مسموحة. الدليل الحالي `/UserGuide/limousine` و`limousine-guide.ts` يصف السلوك المنفذ ومسح العلامة/رفضها، ويُقارن بالتفصيل الخلفي أدناه؛ لم يُعدّل في تفويض قراءة فقط.
