الصورة دليل وظيفي لتسعة أعمدة وسبعة مرشحات وإجراءات التقرير وExcel والتحديث. قُرئ README وفهرس المراجعات وشكل UI07، والفصل16 من دليل Speed27 أكتوبر؛ لم يظهر شرح أصلي خاص Sale Report في catalog. قُرئ بعده مستقلًا C1052 من raw/application.js:280441–280666، وشاشة13-sale-report ومسارR0442 بالسطر4786 في لقطة28 أكتوبر. يثبت الفرد/الشركة والأنواع التابعة للفئة ومرشحات الفرع والموظف والملكية والجدول والمخرجات، ولا يثبت قاعدة الإيراد الخلفية. قُرئت rental.rst وcustomer_invoices.rst من Odoo19 المحلي لتوضيح فرق العقد والفوترة، دون تحويلهما لقاعدة Sigma.

المصدر القديم يطلب Report/SaleReport غير الموجود، ويسمي حقول النموذج غير المفاتيح المرسلة، ويقرأ العملاء كموظفين ودفعات مبيعات كفئات اتفاقية، ويزيد التاريخ يومًا ويكرر الصفوف بين البحوث. الخادم الموجود SalesReports/CreateSalesReport يقرأ Rental/Lease حسب بداية العقد، ويعيد Id بدل No، ونوع Rental بدل Daily/Weekly/Monthly، وموعد العودة المتوقع حتى للمغلق، وإجمالي TotalCharges شامل الضريبة تحت Revenue، بلا total في DTO. المصدر يضم المبطل ولا يتحقق من تعارض الفئة والنوع، ويغير الفئة ضمنيًا.

تحتوي الصورة على بدايات عقود قبل الفترة المطبقة، لذلك لا يجوز افتراض أن معيار البداية أو إجمالي العقد يطابق المطلوب. سُئل المالك عن صافي الفواتير أو إيراد الأيام أو قيمة العقود؛ يبقى حساب الخادم المالي معلقًا، ويستمر العمل المستقل على العقد والواجهة.

حسم المالك السؤال لاحقًا باعتماد صافي الفواتير خلال الفترة قبل الضريبة. جُمّد القرار ومصدره الفعلي في SALE_REPORT_FINANCIAL_CONTRACT_FREEZE.md. أثبت المصدر RentalInvoiceGenerationService هوية RentalInvoiceItem ومبلغها، وأثبت InvoiceService:1106–1154 و1202–1270 الربط الصريح الحالي لعقد Lease برقم AgreementNo ونوع الفاتورة، وأثبت InvoiceAccountingService أن القيد RentalInvoice بقيمة Amount قبل VAT وCurrencyId من المصدر. لا يتطلب هذا التقرير كيان ربط تجريبيًا جديدًا أو توافقًا لبيانات قديمة.

مهارة Sigma ومهارات Superpowers متاحة ومستخدمة للتحليل والتشخيص والمراجعة والتحقق، تحت حدود البناء المسموح والمصدر؛ لا اختبارات تشغيل أو متصفح. الجذر يملك الاكتشاف والعقد والربط والحساب والمصالحة. تُفوض الواجهة فقط بعقد النقل المجمد المستقل عن القرار المالي.

أثبتت مراجعة المصدر شروط قيد الفاتورة المولد المعتمد المرحّل غير المبطل ونوعه وتطابق المؤسسة والفرع والتاريخ والعملة. يجمّع SQL بنود Rental لكل فاتورة وعقد، مع فحص الدقة والإشارات لكل بند قبل أن يخفيها الجمع؛ يطابق الخادم جميع المبالغ والضريبة بالرأس ثم ينفذ مرشحات العقد ويجمع العملات بدقة. لا يوزع رأس فاتورة مشتركة على العقود ولا يعتمد لوحة المركبة. يقرأ Lease الربط المحفوظ عبر join رقم العقد في SQL نفسه، حتى لا تختلف مطابقة CLR عن collation القاعدة، ويفحص الرقم المكرر للشركة بقراءة محدودة مستقلة تنتهي قبل query المنشور. تظل الصفوف والمراجع والخيارات تحت QueryReport الطبيعي.

أصبح مالك آخر عودة AgreementReturnReportQueries مشتركًا بين Daily Business وSale؛ يأخذ معرّفات عقود مرشحة ومسموحة، وينفذ probe هوية للشركة فقط ثم يقرأ كل مستهلك الصف الطبيعي حسب الفروع. يحتفظ Daily Business باستبعاد العضوية إذا كانت العودة الأخيرة مخفية/خارج الفترة، بينما يحتفظ Sale بالإيراد المسموح ويفرغ تاريخ العودة غير المتاح. لا استخدام للموعد المتوقع كحدث رجوع. رُوّج هذا التوجيه إلى BE9 ومهارة Sigma، وجُددت الحزم الثماني بالمولد ونجح Check. لا تعديل مباشر للمولّدات ولا schema أو migration أو كتابة بيانات.

## الأداء والاستعلامات

تستبدل القراءة lookup لدفعات المبيعات ودليل العملاء الكامل بخيارات تشغيلية من استعلامين: فروع الفواتير المسموحة وموظفو العقود المسموحون. البحث الكامل حد أقصى9 أوامر: تحقق المندوب إن اختير، رؤوس الفترة، عملاتها، مجاميع بنودها، probe التباس رقمLease عند وجوده، إسقاط العقود، روابطLease، آخر عودة، وقراءة تواريخ العودة المسموحة. تنخفض الأوامر مع النتيجة الفارغة أو غيابLease/المغلق. لا Include لكيانات كاملة أو استعلام لكل سطر أو EF متوازي على DbContext واحد. المجاميع الأولية للبنود فيSQL، والمصالحة والجمع الدقيق النهائي على إسقاطات محدودة بعد النطاق، لا حساب مالي في Angular.

الفهارس القائمة: RentalInvoiceItem له FK InvoiceId ومفتاح (SubscriptionId,RentalAgreementId,InvoiceToDriver,FromDate,ToDate)، وInvoiceBase له FK JournalVoucherId، وCollectionMovement له (SubscriptionId,BranchInId,DateAndTime,Id). لا فهرس تقرير جديد مبرر دون خطة فعلية. مقترحات تقييم خطةSQL: InvoiceBase(SubscriptionId,InvoiceDate,BranchId,Id) مع INCLUDE(CurrencyId,JournalVoucherId)، وLeaseAgreement/Agreement على رقم العقد بحسب TPT/الفهرس الفعلي، والعودة (SubscriptionId,AgreementId,DateAndTime DESC,Id DESC) مع INCLUDE(BranchInId,IsDeleted). تُقارن بالتغطية الحالية والانتقائية وكلفة الكتابة والتخزين قبل أي migration. لا تغيير فهرس في المهمة.

قياس السرعة معلق: نفس tenant وحجم فواتير/بنود، نفس الفترة والفرع والمنح،5 قراءات باردة و5 دافئة مع زمن Options/Read وشكل SQL وlogical reads وحجم الرد ووقت العرض، ثم Print/Excel كاملين. لا يمكن إثبات ترجمة LINQ على SQL Server أو زمن سرعة من نجاح بناء .NET أو نقصان طلبات الواجهة.

## دليل المستخدم والحدود

أُضيف الدليل الإنجليزي والعربي في UserGuide/content/sale-report-topic.ts إلى REPORTS_GUIDE عند /UserGuide/reports. يشرح الفلاتر والإيراد قبل الضريبة ونطاق فرع الفاتورة والعملات والتواتل والمخرجات وحقول العودة والصلاحيات وإعادة المحاولة. بقيت الشاشة خالية من فقرات شرح داخل الجدول.

المصدر الحقيقي لـLease هو رقم عقد محفوظ وليس FK جديدًا؛ تعدد الرقم أو دليل المبالغ/العملة غير الصحيح يعرض فشلًا مختصرًا، دون توافق لبيانات تجريبية غير صالحة. الملكية ومركبة العقد والمندوب مراجع حالية، لا لقطات تاريخية مخترعة. تستبعد العقود المبطلة/غير المسموحة من العضوية، وتظل التواريخ غير المسجلة فارغة. لا يشمل التقرير سندات قبض أو ودائع أو إشعارات ائتمان منفصلة. هذه نتيجة عقد المالك للفواتير قبل الضريبة؛ لا يزعم التقرير صافي نقد أو دورة كاملة للإيراد المحاسبي.
