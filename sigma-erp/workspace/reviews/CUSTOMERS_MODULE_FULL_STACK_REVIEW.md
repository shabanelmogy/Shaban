## بيان المراجعة

شملت المراجعة المسارات الثمانية الموجودة بالفعل تحت مجموعة العملاء في قائمة التطبيق ومجلد الوحدة، وكل حواراتها الحالية وخدماتها ونماذجها وواجهاتها الخلفية المباشرة. لم تُعامل أسماء المجلدات القديمة كشاشات فعلية. استيرادا الأفراد والشركات دخلا فقط باعتبارهما كاتبين مباشرين لمصادر الخيارات؛ لم تُراجع شاشات الاستيراد العامة أو وحدات السندات والودائع كميزات جديدة.

| الشاشة | مسار القائمة الفعلي | شكل الواجهة والخلفية | نتيجة التنفيذ الأساسية |
|---|---|---|---|
| الأفراد | `/IndividualPartner` | نوع ٣، قائمة ومحرر متدرج؛ نمط ٢ | تحديث الكاش السابق محفوظ، وحماية المغادرة وتبديل رقم السجل والملفات والإلغاء والخطأ المركب والحقول المطلوبة استكملت |
| الشركات | `/CompanyPartner` | نوع ٣ وخمس خطوات ومسودة سائق؛ نمط ٢ | متابعة المصادر في القائمة والمحرر والسائق، وحماية السجل والمسودة والملفات وإعادة المحاولة والتحميل |
| كشف الحساب | `/StatementOfAccount` | نوع ٧، استجابة مقطعية كاملة؛ نمط ٥ | توحيد حالة الخيارات وإكمالها الفارغ وحماية الطباعة وعمر العمل المؤجل |
| ملخص الأرصدة | `/BalancesSummary` | نوع ٧ بعقد صفحات موجود وحوار كشف؛ نمط ٥ | إطار التقرير ومرشحاته المتقدمة، متابعة المراجع، تحميل الحوار المحلي، التصفية والتصدير وتجميع قاعدة البيانات |
| أعمار الذمم | `/ReceivableAgeAnalysis` | نوع ٧، خيار كل الصفوف الموجود؛ نمط ٥ | قراءة أولى ذرية ومتابعات مرجعية منفصلة، حفظ الاختيارات، الطباعة المشتركة والإلغاء ومظهر الملخص |
| التنبيهات | `/Alerts` | قائمة تشغيلية مكتملة لصفوف التنبيه | متابعة خيارات العميل وحالة محلية مشتركة، وتضييق قراءات تسميات الاتفاقيات وتجميعها مرة واحدة |
| تحصيل الديون | `/DebtCollection` | تقرير تشغيلي بإجراءات وحوار تاريخ؛ نمط ٥ | تقدم محلي مرئي للتاريخ، تجميد قرارات الإلغاء والطباعة المشتركة، وتحسين مسح القيود وثبات الصفحات وعزل الأب |
| تقرير المتابعة | `/followUpReport` | نوع ٧، تفاصيل وملخص؛ نمط ٥ | متابعة مصدر العملاء مع مصدر مستخدم مباشر، وتجهيز الطباعة المشتركة واستعادة الصفحة |

المسار الحقيقي: جذر مستقل ثم وحدة التخطيط ثم ملف مسارات الصفحات ثم ملف مسارات الشاشة. المسار القديم `details/:id` في الأفراد والشركات يظل عرضًا. لا مسار جديد أو عميل بيانات جديد أو صلاحية جديدة. المصادقة الحالية تبقى مالك الدخول. لم تُعرض صور أو فيديو أو متطلبات حقول جديدة؛ الأدلة مصدر حالي وعقود مجمدة وكتب وحزم معتمدة.

الحجم كبير على مستوى الوحدة؛ قرأ الجذر خطة الصيانة قبل التنفيذ، واختار الأنماط ثم جمد عقود الاستهلاك قبل تفويض الملفات. طُبقت مراحل الاكتشاف والعقود والقراءة والمحررات والإجراءات الموجودة والتكامل والمطابقة. لا إنشاء لدورة مالية أو اعتماد جديدة. بقيت التعديلات السابقة في سندات القبض والودائع والترجمات والمهاجرات واللقطة محفوظة؛ لم يُعدّل هذا المسار أي مهاجرة أو لقطة.

## تقارير الأدلة التفصيلية

- تقرير [الشركات](Customers/COMPANIES_MODULE_REVIEW.md) يتضمن الأعمدة والنماذج والفلاتر وعقد الأطفال وحوار السائق ومصفوفة المصادر والتحميل والمظهر والأداء.
- تقرير [التقارير الأربعة](Customers/REPORTS_MODULE_REVIEW.md) يتضمن لكل شاشة مدخلاتها واستجابتها وأعمدتها وإجمالياتها ونطاق الصفحة والطباعة والتصدير والكاش والتحميل والفهارس.
- تقرير [الخلفية](Customers/BACKEND_MODULE_REVIEW.md) يتضمن الواجهات الثماني وحقولها، وقراءات العدد والصفحة والتفاصيل، ودليل الحفاظ على العلاقات والتاريخ، ومقترحات الفهارس وكلفتها.
- تقرير [الأفراد السابق](INDIVIDUAL_PARTNER_ANGULAR21_FEATURE_REVIEW.md) يثبت عمل أنجولار ٢١ والكاش السابق. هذا السجل اللاحق يضيف تغيرات عمر السجل والخلفية؛ لا يعاد تفسير التاريخ السابق على أنه وصف نهائي لهذه الشريحة.

## قرارات التنفيذ ودليلها

| القرار | الدليل والتطبيق |
|---|---|
| إعادة استخدام المالك الحالي | المكونات الحقيقية للعنوان والتصفية والجدول والخطوات والأقسام والحوارات والحالة المرجعية والطباعة والإلغاء؛ لا غلاف أو كاش أو مكتبة عرض موازية |
| إبقاء المرشح المتقدم للأرصدة داخل إطار التقرير | المالك المشترك الحالي يدعم انهيار نطاق الرصيد وإعادة ضبطه والتحقق؛ تغييره إلى شريط أبسط يفقد قدرة حقيقية. أصلح إطار التقرير وعرض البطاقة دون نسخ المرشحات |
| فصل أول قراءة عن متابعة الخيارات | نجاح الغلاف أولًا ثم ربط واحد بعمر المكون؛ مجموعات نجاح تمنع إعادة قراءة مصدر تحت المتابعة أثناء إعادة محاولة مصدر آخر. الإكمال بلا رد أصبح فشلًا قابلًا للمحاولة |
| حفظ المسودة | دوال المتابعة تستبدل الخيارات فقط، وتقرأ المعرفات الحالية والخيارات الحالية لحفظ التسميات؛ لا ترقيع للنموذج أو حسابات مالية أو إعادة تفاصيل سياق سابق من المتابعة |
| تغيير رقم السجل | تدفق معاملات المسار المميز يلغي قراءة التفاصيل السابقة، ويصفر جاهزية وتفاصيل ومسار مرفقات السجل القديم قبل الجديد؛ لا إعادة تحميل لتغير استعلام الصفحة وحده |
| سلامة المغادرة | حراس المحرر يستعملون تأكيد الإهمال والمالك المشترك لتجميد النموذج وتنظيف الملفات المؤقتة قبل قبول المغادرة. لا تعطيل للمغادرة بسبب قراءة تفاصيل عادية؛ الكتابة والتحقق ورفع الملفات والتنظيف والمسودة الفرعية لها حمايتها المستقلة. الموافقة على خروج صريح تُستهلك مرة واحدة |
| التحميل المرئي | طلب الصفحة له المضيف العام؛ الحوارات التي يغطي قناعها المضيف لها رسالة حالة محلية مع إخفاء قناع الجدول. أعلام الانشغال والتعطيل والأخطاء لا تحذف عند إزالة مؤشر مكرر |
| قراءة التفاصيل | خدمات الأفراد والشركات تحمل رسم المحرر المحدد بعلاقات وقراءات مجزأة بدل المالك العميق العودي. كل حقول التفاصيل والأطفال الأحياء والتسميات التاريخية الحالية محفوظة؛ المصدر القديم لم يطبق مرشحًا إضافيًا على المراجع المنفردة فلا أضيف مرشح يغيرها |
| شروط القيد الأب | أضيف المستأجر الحالي وحذف الأب ليس صحيحًا لتحصيل الديون والأرصدة، وفق الكتلة ١٧ ومصدر كشف الحساب والأعمار. لا تغيير لتاريخ أو حساب أو صيغة مبلغ صحيحة |
| كتابة المتابعة والحظر | حُذفت تجاوزات تكرر الحفظ وتتجاهل نتيجته وتكتب إنجليزية ثابتة؛ المالك العام يتحقق من المرجع ويحفظ ويرد النتيجة المحلية. أزيلت اتجاهات الربط العكسي غير المستهلكة فقط |
| ترقيم الأطفال | محلل واحد لخريطة الأنواع السبعة عشر يسبق قراءة إعدادات الترقيم. الأطفال غير المدعومين يحافظون على الرقم الاحتياطي نفسه دون استعلام سياسة غير مستخدم؛ المستندات المدعومة تحتفظ بقراءة حديثة وبالعداد والسياسة اليدوية والبذور والتزامن. لا كاش سياسة مالية |
| الوصولية | كل استخدام لبطاقات الملخص تحت العملاء يحدد الوصف المطلوب؛ الحقول المطلوبة بالأفراد والشركات تعتمد نمط الوسم المشترك، وحوار السائق يذكر اسم السائق في العنوان الفرعي |
| الترجمة | استعملت الواجهة مفاتيح موجودة. أضيفت ثلاث رسائل فشل مرجع للأرصدة باللغتين في موارد الخلفية، وتستدعيها الخدمة ديناميكيًا. لا طلب خاصية جديدة من ملف مصمم الموارد |

## الأفراد والتنبيهات وتحصيل الديون: الأدلة المملوكة للجذر

| المسار | الأعمدة والنموذج والمرشحات والإجراءات |
|---|---|
| الأفراد | الأعمدة: الرقم والاسم والمجموعة والمحمول ورقم الاتصال المشتق والبريد والفرع والحالة. نموذج القائمة: `id,no,name,mobileNo,phoneHome,phoneWork,email,contactGroupId,contactGroup,branch,isInactive`؛ العرض يضيف `contactNo`. الفلاتر: `branchId,search,agreementStatus,isInactive,grid`، وعدد الصفحة وحجمها وفرزها. الحمولات والتفاصيل والأطفال والمدققون لا تتغير. العرض والتعديل والسجل وتعديل المجموعة والحذف والتصدير تبقى إجراءاتها |
| التنبيهات | أعمدة المصدر: `partnerId,srNo,customerName,agreementNo,company,type,documentType,documentNo,issuedBy,issueDate,expiryDate`؛ حالة ومدة الانتهاء مشتقتان للعرض فقط. فرز وتصفية محليان على الصفوف المكتملة؛ اختيار العميل يرسل للعنوان. التصدير يغطي الصفوف المفلترة المحملة فقط؛ لا تغيير صلاحية المستند |
| تحصيل الديون | `customerId,customerName,customerCode,contactNo,creditPeriod,creditLimit` والشرائح السبع و`subTotal,unAllocated,balance,status,debtCollector,debtCollectorName,nextFollowup,latestNote,promised`. تاريخ التقرير والنوع وحالات الاتفاقية والحظر والوعد والمتابعة والتجاوز تمر بالمفاتيح المجمدة؛ مربع الوعد غير المحدد لا يرسل قيد false. العرض المحلي والطباعة والتصدير يغطيان الصفوف المعادة فقط |
| تاريخ المتابعة | `id,customerId,customerName,dateTime,notes,nextFollowup,isPromised`؛ غلاف `Result` بقائمة كاملة للعميل، وترتيب خادم بالتاريخ والمعرف. الكتابة تحمل حقول المدخلات الحالية فقط. تغيير العميل أو إغلاق الحوار يلغي القراءة؛ الإكمال الفارغ يعرض خطأ، والإلغاء المتعمد عبر استبدال الاشتراك يظل صامتًا |

إجراء الإهمال في مجموعة الفرد والمتابعة والحظر يجمد النموذج خلال القرار ويعيد حالته عند البقاء. الحفظ يحتفظ بالمدخلات عند الفشل. تاريخ الاتفاقيات العام يعرض رسالة تحميل محلية واحدة وخطأ ومحاولة جديدة من المصدر نفسه، ويحمي الطلب من التكرار وينظفه عند تدمير الحوار؛ يرث الأفراد والشركات وبقية مستهلكي المالك هذه المعالجة.

## مصفوفة المصادر والكاش

كل عنوان يبدأ بعنوان البيئة الحالي. الغلاف المرجعي هو `Results<DropDownSelect>` ووضع الخطأ للقراءة الأولى والمتابعة متطابق. جميع العناوين ورموز المستهلكين المفصلة في تقارير الشرائح، وهذه مطابقة موحدة:

| المصدر الفعلي | الشاشات المستهلكة | المالك والكاتب والإبطال والإشعار | المطابقة النهائية |
|---|---|---|---|
| `Customer/GetSelect` عبر خدمة العميل المشتركة | كشف الحساب والأرصدة والأعمار والتقرير المستقل والتنبيهات | الكاش المشترك، كتّاب الأفراد والشركات وتبعيتهما الحالية، والاستيراد عند صفوف محفوظة موجبة؛ الموضوع `lookup-customers` مرتبط بمنتجي الأفراد والشركات | قراءة ناجحة محدودة ثم متابعة مستقلة، إعادة محاولة وحفظ اختيارات وتصفير سياق وتنظيف مثبت بالمصدر |
| `Branch/GetSelect` | قوائم ومحررا الأفراد والشركات والأرصدة والأعمار | خدمة الفرع المشتركة وكتاباتها الناجحة وحذفها الموروث؛ الموضوع `lookup-branches` | مطابقة المصادر المشتركة دون كاش محلي |
| `ContactGroup/GetSelectByType/Customer` | الأفراد والشركات والأعمار | خدمة المجموعة وعامل نجاح كتاباتها؛ الموضوع `lookup-contact-groups`، وتضاف التبعية المؤكدة لكتابات العملاء التي تنشئ المجموعة الافتراضية | الهوية تشمل مسار النوع؛ لا تشارك بيانات نوع آخر |
| `Country/GetSelect` | محررا الأفراد والشركات ومسودة سائق الشركة | خدمة البلد وكتاباتها الناجحة والموضوع `lookup-countries` | تحفظ الجنسية وبلد العنوان الحاليين معًا؛ المتابعة لا تكتب أسماء أو معرفات النموذج |
| `Currency/GetSelect` | محررا الأفراد والشركات والأعمار | خدمة العملة وكتاباتها الناجحة والموضوع `lookup-currencies` | هوية مرجعية فقط؛ لا تخزين أو تحديث سياسة مالية أو أسعار صرف |
| `Staff/GetSelect` | الأفراد والشركات والأرصدة والأعمار | لا اشتراك مصدر في الكاش؛ مصدر مرجعي مباشر موثق | قراءة أولى/إعادة محاولة فقط؛ لا متابعة أو كاش جديد |
| `User/GetSelect` عبر `UserzService` | تقرير المتابعة | خدمة المستخدم الحالية غير مشتركة بالكاش | الاستثناء مباشر؛ لا افتراض أهلية من اسم العنوان |
| `TariffCard/GetSelect` | الأفراد والشركات | مصدر مباشر غير مشترك | لا كاش أو متابعة جديدة |
| عناوين القائمة والتفاصيل والتقارير والتاريخ والتحقق والملفات | الشاشات المعنية | تشغيلية مباشرة؛ مالك التقرير/التحقق/رفع الملفات الحالي | تبقى خارج الكاش المرجعي |

كتابات الأفراد والشركات قد تنشئ مجموعة العميل الافتراضية؛ لذلك تبطِل العائلتين العميل والمجموعة عبر عامل النجاح القائم. استيراداهما يبطلان عائلة المجموعة إضافة إلى العميل عند عدد صفوف محفوظ موجب، بما في ذلك فشل الدفعة الجزئي. الفشل الصفري والنقل لا يبطلان؛ لا مصدر جديد أو مراقب كتابة عالمي أو مقبس جديد.

## مصفوفة التحميل والعمر

| العملية | المالك الفعلي والتوصيل | القبول |
|---|---|---|
| قراءات القوائم والتقارير والتفاصيل وكتاباتها وقراءة التصدير الكامل | `LoadingService` يبدأ عند الاشتراك أو قبل الاشتراك المباشر وينتهي في `finalize` مع النجاح والفشل والإلغاء؛ مضيف التخطيط العام موجود، ولا مسار من الثمانية يخفيه | مطابق مصدريًا؛ الجدول والزر يحتفظان بالانشغال ويخفيان المؤشر عند عمل العام |
| حوار كشف الأرصدة | حالة محلية ورسالة مشتركة داخل قناع الحوار؛ لا عداد عام ولا قناع جدول ثانٍ | مطابق مصدريًا |
| حوار تاريخ المتابعة والاتفاقيات | رسالة حالة محلية، وإعادة محاولة، وإلغاء بعمر/هوية الحوار؛ قناع الجدول مخفي | مطابق مصدريًا |
| تحميل الخيارات الأول | حالة خيارات مشتركة واحدة بجوار الفلاتر أو داخل الحوار الفعلي | مطابق؛ بعض فشل القراءة الأولية الذرية له خطأ الشريحة الحالي إضافة إلى حالة المتابعة، دون مؤشرين للعملية نفسها |
| تحديث خيارات محتفظ بها | صامت بالشاشة، ونشاط الكاش مرئي من مالك الرأس الحالي | لا تعطيل للمسودة أو بدء تقدم عام |
| تحديث استعلام/جزء مرجعي دون تغير مسار | خدمة التحميل المشتركة تقارن شجرة المسار وتتجاهل تغير الاستعلام | الطلب لا يفقد التقدم؛ تغير المسار الفعلي يعيد العداد، والكتابة لها حمايتها المستقلة |
| الطباعة المحلية | جلسة مالك الطباعة المشترك بعمر المكون، تشمل الصفوف المناسبة وتعيد الصفحة والحجم بعد النهاية | مطابق مصدرًا؛ الطباعة والمتصفح لم يشغلا |

## السرعة والاستعلامات والفهارس

الأدلة التفصيلية لكل شاشة في تقرير الخلفية؛ لا يعادل عدد حدود المصدر عدد أوامر قاعدة البيانات المقاسة ولا زمن العرض:

- فتح الأفراد والشركات كان يمر بقارئ عميق يطلب كل علاقة عوديًا؛ أصبح رسمًا محددًا بقراءات مجزأة لعلاقات محررها. عدد الصفوف المطلوب باقٍ وفق عقد التفاصيل، وعدد مسارات الجمع ثابت بدل التوسع مع مراجع غير مرتبطة.
- التنبيهات تقرأ المستندات المطلوبة ثم روابط اتفاقيات تخص معرفاتها، وتبني مجموعتي بحث مرة واحدة بدل مسح الروابط لكل مستند. الحالة والتصدير المحليان لا يرسلان طلبًا جديدًا لكل صف.
- تحصيل الديون يجمع القيود المحملة حسب العميل مرة واحدة، ويحافظ على الحسبة قبل الصفحة وحد الصفوف نفسه، ويضيف المعرف لكسر تعادل ترتيب الاسم.
- ملخص الأرصدة يجمع مبلغ القيد في قاعدة البيانات بدل نقل كل قيد ثم جمعه بالذاكرة. الإجماليات والتصفية والعدد تسبق الصفحة كما في العقد، والتصدير يتبع صفحات مائة بنفس التصفية.
- كشف الحساب والأعمار يحافظان على مصادر التخصيص وتاريخها والإجماليات authoritative؛ لا تغيير صيغة. تقرير المتابعة يحتفظ بالملخص والإجماليات والتفاصيل كقراءات متسلسلة على السياق نفسه. لا تنفيذ متوازٍ لاستعلامين على سياق واحد.
- حفظ أطفال العملاء لم يعد يقرأ إعدادات الترقيم لكل نوع طفل لا يستهلك السياسة؛ المستندات السبعة عشر المدعومة لا تزال تقرأ السياسة حديثًا، ولا يدعي هذا أن كل عمل الحفظ أصبح ثابتًا أو بلا تكلفة لكل طفل.

الفهارس لم تتغير. تقرير الخلفية يفصل تغطية المفاتيح الخارجية القائمة والجدول الفعلي ولقطة الأساس التاريخية، ولا يفترض أن المخطط المنشور يطابقها. المرشحون غير المطبقين: صف القيد بمفاتيح المستأجر والعميل والحساب والأب وتضمين المدين والدائن والحذف؛ تخصيص القيد بمفاتيح المستأجر وصف القيد وتاريخ التخصيص والمعرف؛ تاريخ المتابعة بمفاتيح المستأجر والعميل والتاريخ والمعرف، مع بديل تقوده فترة التقرير إذا أثبتت الخطة الحاجة. لا تضف بديلَي المتابعة معًا افتراضيًا. التضمينات والتداخل وكلفة الكتابة والتخزين في التقرير؛ لا مرشح حذف بالقيمة الصفرية يستبعد القيم الفارغة الحية، ولا فهرس لكل عمود أو تغيير تفرد.

خطة القياس: نفس إصداري الواجهة والخادم والبيانات والمستأجر والفرع واللغة والإعدادات والتصفية والترتيب وحجم الصفحة؛ عينات باردة ودافئة منفصلة مع خمس محاولات دافئة على الأقل. يسجل المالك زمن الطلب وحجم الاستجابة وعدد الأوامر والقراءات والخطة ووقت التصيير. قارن فتح تفاصيل بها صفر وعشرة ومائة طفل، وتنبيهات واسعة وعميل واحد، وصفحات الأرصدة وتصديرها، وتقارير تخصيص جزئي ومستقبلي، ونتائج متابعة متعددة المستخدمين. النتائج قبل/بعد والتوقيت والخطط معلقة؛ لا نسبة تسريع أو زمن إنجاز مثبت هنا.

## قرار حُسم بعد المراجعة — غياب إعداد حسابات الذمم

اعتمد المالك توصية إيقاف تحصيل الديون عند غياب حسابات الذمم بقوله «تمام نفذ» في 2026-10-26، وسُجل تعديل العقد قبل المصدر. أضيفت بوابة في `CustomerService.GetDebtCollectionAsync` بعد قراءة الحسابات وقبل العملاء والقيود: المجموعة الفارغة تعيد `BusinessFailure<List<DebtCollectionResultDto>>` بالمفتاح الموجود `CustomerStatementReceivableAccountsMissing`. أزيل شرط قبول كل الحسابات. يظل المتحكم يعيد `BadRequest(result)`؛ والغلاف والحقول والصيغ وحد المائة محفوظة عند وجود الإعداد.

| المقارنة | الدليل النهائي |
|---|---|
| المرجع والعقد | الخلفية ١٧ تمنع توسيع عضوية الذمم؛ كشف الحساب في الخدمة نفسها يملك رسالة الفشل المترجمة، واعتمد المالك سلوك الإيقاف صراحة |
| المستهلك والفشل | المسار `/DebtCollection` يستورد `DebtCollectionReportComponent`؛ يطلب `DebtCollectionReportService.getReport` عنوان `Customer/DebtCollection` مباشرة مع تجاوز حوار الخطأ العام. يعرض `apiErrorMessage` رسالة الغلاف في خطأ HTTP، ويعرض مسار `!response.isSuccess` الرسالة أيضًا؛ كلاهما يفرغ البيانات. يمنع `print` غياب الصفوف، ولا يصدر `exportToExcel` مصفوفة فارغة؛ `refresh` وSearch يعيدان الطلب بعد تصحيح الإعداد |
| التحميل والكاش | يحتفظ `bindReportQueries` بالبدء داخل `defer` والإفراج في `finalize` وإنهاء الاشتراك مع التدمير، وإعادة تمكين النموذج. المسار لا يعطل `showPageLoading` والمضيف `LayoutComponent` يعرض `StateMessage` العام. التقرير وإعداد ربط الحسابات قراءتان تشغيليتان مباشرتان بلا كاش؛ لا lookup جديد في هذه الشريحة |
| الأداء والفهارس | قبل الإصلاح كانت خريطة الذمم الفارغة تكمل قراءة العملاء والقيود وقد تقبل حسابات أخرى؛ بعدها تنتهي بعد قراءة خريطة الحسابات فقط. عند وجود إعداد لم تضف قراءة أو تغييرًا للصفحات أو الحسابات. لا فهرس إضافي مبرر لفحص قائمة في الذاكرة؛ تظل مرشحات الفهارس السابقة وتكاليفها غير مطبقة. لا ادعاء قياس سرعة |
| دليل المستخدم | أضيف شرط الإعداد وخطوات تصحيحه ثم بحث/تحديث ومنع نتائج الفشل للطباعة والتصدير، بالعربية والإنجليزية في `UserGuide/content/customer-report-topics.ts` ضمن دليل `/UserGuide/customers` الحالي |

التحقق مصدري فقط: روجع الفرق الكامل لملف الخدمة وملف الدليل في مستودعيهما، وتطابق مفتاح الرسالة مع مورد عربي وإنجليزي موجودين، ومرت فحوص المسافات والعلامات. فحص الحزم المولدة نجح دون تعديل كتب أو قوالب؛ طبقت شريحة العقد والفشل ثم المطابقة فقط، ولم تكرر مراحل التحرير والعمليات غير المتأثرة. لا تغيير خرائط أو أنواع أو مراجع مشاريع أو مخطط، ولا ترحيل مطلوب. لم يستخدم وكيل فرعي لصغر الشريحة وتسلسلها، ولم تنفذ أوامر محظورة.

تحقق المالك المعلق: افتح التقرير في مستأجر بلا ربط ذمم، وتأكد من رسالة الإعداد باللغتين دون صفوف أو ملف مطبوع/مصدر؛ كرر بعد نتيجة سابقة ناجحة للتأكد من إفراغها، ثم صحح الربط واضغط بحثًا أو تحديثًا وتحقق من تطابق أرصدة الإعداد الصحيح. قارن نفس البيانات والمرشحات والإصدار في حالتي الربط الفارغ والصحيح، مع عينة باردة وخمس دافئة وسجل HTTP/SQL والخطة؛ التوقيت والتشغيل غير منفذين. رسالة إيداع الخلفية المقترحة فقط: `fix(customers): reject debt collection without receivable accounts`، والواجهة: `docs(customers): explain debt collection setup requirements`.

## القرارات المادية المعلقة

| المسألة | الدليل والحاجة إلى القرار | حالة التنفيذ |
|---|---|---|
| تعريف المبلغ غير المخصص في تحصيل الديون | التعبير الحالي سالب مجموع الائتمانات، بينما التعليق يشير إلى غير المطابق؛ تغييره يغير الأرصدة | بقي كما هو؛ يلزم تحديد مصدر التخصيص والقواعد المحاسبية الدقيقة |
| اكتمال تحصيل الديون بعد مائة عميل | استجابة قائمة بلا عدد كامل، والتصدير والطباعة يغطيان المعاد فقط | لم يُخترع عقد صفحات أو ادعاء اكتمال؛ الدليل داخل التطبيق يذكر الحد |
| أرقام البطاقات الكاملة ورمز الأمان | قرار قديم يتطلب تحديد النموذج البديل ومعالجة البيانات والترحيل | لم تحذف حقول أو بيانات أو تضف بوابة دفع أو ترحيلًا |

وجود هذه المسائل يمنع إغلاق الوحدة ماليًا أو وصف كل العقود بأنها خالية من المخاطر. لا تمنع المسائل المعلقة تطبيق الإصلاحات المستقلة المجمدة.

## دليل المستخدم والوثائق

حدث الجذر موضوعي ملفات العملاء والتقارير باللغتين داخل `UserGuide/content/customer-profile-topics.ts` و`customer-report-topics.ts`. يغطيان الثماني شاشات، وأضيف شرح تحديث الخيارات وحفظ المسودة وإعادة المحاولة وتغير السجل وتنظيف الملفات وتقدم الحوارات وطباعة الصفوف واستعادة الصفحة. القارئ ودليل العملاء ومدخل `/UserGuide/customers` الحاليون أعيد استخدامهم، ولم يُنشأ قارئ أو مسار دليل جديد. راجع النص النهائي تصحيح موقع تقدم خيارات كشف الحساب بجوار الفلاتر، لا داخل القائمة نفسها.

أضيف وصف عام محقق لتقدم تاريخ الاتفاقيات وإعادة المحاولة في الكتلة ١١ للواجهة، وتبعية مجموعة العميل الافتراضية في الكتلة ٢، واستبعاد قراءة إعدادات غير مستخدمة لترقيم الطفل في الكتلة ٧ للخلفية. حدث ملخص المهارة وسجلها في المهمة نفسها، وكل قاعدة تشير إلى مالكها. الحزم الثماني ولدت بالمولد فقط بعد كل تعديل للكتب، وأعيد فحصها؛ راجع الجذر دلاليًا بقاء عقود الكاش والتحميل والعداد وعدم إضافة تفويض مالي أو تشغيل. فحص روابط الكتب نجح، وكان صريحًا أنه لا يفحص مصدر التطبيق دون نطاق مصدر.

## المطابقة النهائية والتحقق

| البوابة | النتيجة |
|---|---|
| العقود والحقول والحسابات | حمولات ونماذج وواجهات الشاشات الحالية محفوظة؛ إصلاح الأب وترجمة الفشل ونتيجة الحفظ حُددت صراحة في العقد |
| الفروق والتعديلات المسبقة | روجعت الفروق حسب مستودعي الواجهة والخلفية، مع فروق المالك المشترك والترجمة والوثائق. تقرير الشرائح يحدد الملفات؛ تغييرات الأفراد السابقة أبقيت وأضيف فوقها. أعمال السندات/الودائع والمهاجرات واللقطة لم تعدل من المهمة |
| الأنواع والواردات والمداخل المطلوبة | لا ملفات تشغيل جديدة تحتاج إضافة للجذور؛ المداخل المطلوبة لبطاقات الملخص موجودة في جميع قوالب العملاء، والرموز المضافة تأتي من مالكيها الفعليين. موارد الفشل الثلاثة موجودة باللغتين؛ موفرات ومراجع طبقات الخلفية الحالية توفر الأنواع المستخدمة |
| الكاش والتحميل والعمر | المقارنات حسب المصدر والمستهلك في هذا السجل والشرائح؛ روجعت حالات القراءة الأولى والفشل الجزئي والتحديث والتصفير والإلغاء والتدمير والخروج. تحقق الشبكة والسياق الحقيقي معلق |
| العرض والاستجابة والإتاحة | المالك العام للمضيف والعرض والتمرير والألوان والاتجاه والثيم محفوظ؛ أزيل تضييق بطاقة الأرصدة ونسخ هندسة ملخص الأعمار. يلزم قبول بصري على الضيق والمتوسط والواسع وجانبي نقاط الفصل وحالات الفراغ والخطأ والتحميل والبيانات وباللغتين والثيمين |
| المسافات والعلامات | فحوص الفروق للمسارات المحددة مرت بلا أخطاء، ولم توجد علامات تعارض في ملفات النطاق. تحذيرات تحويل نهاية السطر ليست نجاح ترجمة ولا عطل مسافات |
| البناء والتشغيل | لم ينفذا؛ لا ادعاء نجاح ترجمة أو تشغيل أو أرقام سرعة أو خطة منشورة |
| المخطط | لا تعديل كيان أو إعداد EF أو مهاجرة أو لقطة من هذا المسار؛ لا يحتاج الإصلاح الحالي ترحيلًا جديدًا. مقترحات الفهارس غير مطبقة |
| الأوامر المحظورة | لم تنفذ بناء أو اختبارات أو تدقيق نمطي أو متصفح أو قاعدة بيانات أو مهاجرات أو إيداع أو رفع أو نشر أو أدوات ممنوعة |

مراجعة الوكلاء: بعد تجميد العقد عمل ثلاثة عمال بالنموذج الموروث وملكية ملفات منفصلة: الشركات، التقارير الأربعة، والخلفية المباشرة. واصل الجذر الأفراد والتنبيهات والتحصيل والمالكين المشتركين والدليل والموارد والوثائق. أنجز عامل الشركات تدقيقًا قرائيًا مقابلًا لحماية مغادرة الفرد، وأنجز عامل التقارير تدقيقًا قرائيًا للتنبيهات والتحصيل وتاريخ الاتفاقيات؛ كشف حالة الإكمال الفارغ وأصلحها الجذر في المصادر المعنية. لم يتداخل تحرير عاملين في ملف، ولم يعلن عامل اكتمال الوحدة. استُخدم التوازي لتقليل تكرار البحث والوقت مع إبقاء القرارات والتكامل والمطابقة عند الجذر.

تحقق المالك التالي: بناء الواجهة والخلفية، ثم رحلة لكل شاشة تشمل قراءة ناجحة وفشل غلاف ونقل وإكمال فارغ وإعادة محاولة؛ تحديث مرجع من جلسة أخرى دون تغير المسودة؛ قائمة فارغة مع تسمية مختارة؛ تغير فرع ولغة وجلسة وإعادة اتصال وتبويب؛ تبديل رقم سجل أثناء قراءة وأثناء مسودة/رفع/تنظيف؛ إلغاء تأكيد الإهمال ثم قبوله؛ خطأ تنظيف بعد حفظ دون تكرار الحفظ؛ حوار تاريخ خلف القناع؛ طباعة متعددة الصفحات واستعادة موضعها؛ تصدير يفشل في صفحة لاحقة؛ مطابقة مبالغ وعدد الصفوف مع مصدرها وخطط الاستعلام. أي مهاجرات سابقة للسندات هي شريحة مستقلة لا يثبت هذا السجل تطبيقها.

رسائل إيداع مقترحة فقط:

- للواجهة: `refactor(customers): reconcile reference lookups, loading and editor lifetimes`.
- للخلفية: `refactor(customers): bound aggregate reads and preserve validated report sources`.
- للوثائق: `docs(sigma): record customer lookup, dialog progress and numbering query contracts`.
