## النطاق والعقد المعتمد

إصلاح تقني محدد للمصدر القائم، بلا تغيير API أو قواعد مالية أو صلاحيات. الشكل استثناء تكامل/مصادقة وخدمات مشتركة، وليس شاشة CRUD جديدة. حافظ الفرع الجديد على تعديلات المالك السابقة دون نقلها أو حذفها أو حفظها في commit.

| النتيجة | قرار التنفيذ المجمد |
|---|---|
| بيانات مستخدم تالفة | قراءة آمنة للتخزين والتحقق من شكل المستخدم؛ السجل غير الصالح لا يسمح بالدخول ولا يفشل التنقل باستثناء |
| وجهة الدخول | يعيد الحارس UrlTree للدخول مع الوجهة الداخلية؛ يستخدم تسجيل الدخول navigateByUrl لحفظ query/fragment؛ الخروج الصريح يحتفظ بعقده |
| استعادة/تسجيل غير موصولين | تعرض المسارات الحالية عدم الإتاحة ورسالة الرجوع للدخول، دون جمع بيانات أو اختراع API |
| سياسة رقمية | تحتفظ الخدمة بالنجاح الصحيح فقط، وتعيد الطلب بعد فشل Result أو HTTP أو إلغاء؛ تبقى المشاركة وإبطال السياق والعملة وخيارات التغذية الراجعة |
| تحميل وتنقل مرفوض | تظل الطلبات مالكة لأعدادها حتى finalize؛ لا يمحو مجرد بدء محاولة التنقل طلبات الصفحة، ولا يمحو انتقال ناجح طلبات الوجهة الجديدة |

## المرجعية والأدلة

قُرئت قواعد العمل الحية ومهارتا Angular وSigma؛ الإصدار المحلي Angular21.2.25. تنطبق Master1/5/7 وUI2/22/26/28 وPHASE05. نجح فحص الحزم الثماني دون توليد تغييرات عند البداية. مداخل سبيد للشرح والكود المؤرخ وOdoo قُرئت في المراجعة السابقة؛ لا شريحة وظيفية من هذه المنتجات تقرر استثناءات التخزين أو Router/RxJS، لذلك تفاصيلها غير منطبقة على هذا الإصلاح.

لم تتوفر Superpowers في الفهارس والمجلدات المفحوصة عند البداية، ثم ظهرت ملفاتها خلال العمل؛ تحقق الجذر منها وقرأ using-superpowers وreceiving-code-review وverification-before-completion وsystematic-debugging وtest-driven-development ومراجعها اللازمة. طُبقت بما يتفق مع حدود Sigma؛ لم تُشغل اختبارات أو أوامر بناء لإرضاء مهارة.

## تحقق مخطط وحدود

فحص المصدر والفروق فقط. تُكتب حالات انحدار ذات معنى لتلف الجلسة والوجهة وإعادة اكتساب السياسة والتنقل المرفوض دون تشغيلها. البناء والاختبارات واللينت والمتصفح وقاعدة البيانات والهجرات وcommit/push والنشر غير مصرح بها. لا تغيير في خادمي HTTP المستثنيين. لا اقتراح فهرس: لا استعلام أو مخطط تغير في هذه المهمة؛ قياس السرعة والقبول التشغيلي معلقان للمالك.

## التنفيذ والمطابقة النهائية

العقد أعلاه جُمّد قبل التنفيذ؛ الحالة الحالية تسجل نتيجة التنفيذ دون تغيير قراراته. لا يوجد قرار مادي مفقود يمنع هذه الشريحة، ولا صور مرفقة تستلزم تصنيفًا.

| الملاحظة | النتيجة ودليل المصدر |
|---|---|
| الثانية: تلف التخزين | تحمي AuthService القراءة والتحليل وتتحقق من الشكل قبل نشر المستخدم. يقبل رقم الاشتراك عددًا صحيحًا موجبًا آمنًا أو نصًا ويطبّع العدد إلى نص، توافقًا مع LoginRm.SubscriptionId واستجابة Console_login بالخلفية |
| الثالثة: فشل السياسة | تحرر FinancialNumberPolicyService مرجع الطلب عند Result فاشل/كيان غائب أو مشوه أو خطأ HTTP أو إكمال بلا قيمة. تحمي مقارنة هوية الطلب المرجع الأحدث من فشل قديم؛ النجاح ومشاركة الطلب والإبطال القائم محفوظة |
| الرابعة: تحميل التنقل | أزيل تصفير عدّاد LoadingService التلقائي مع أحداث Router؛ يحرر كل طلب حصته في finalize. يظل إلغاء القراءات في navigationActivityInterceptor وعمر الكتابة المستقل دون تعديل |
| الخامسة: إجراءات غير موصولة | تعرض RegistrationComponent وForgotPasswordComponent عدم الإتاحة بواسطة StateMessage المشترك مع الرجوع للدخول، بدل نماذج لا ترسل طلبًا حقيقيًا. لا توجد واجهة خلفية جديدة |
| السادسة: وجهة الدخول | يعيد AuthGuard شجرة وجهة الدخول ومعها returnUrl، ويقبل LoginComponent وجهة داخلية سليمة عبر navigateByUrl لحفظ الاستعلام والجزء. الخروج الصريح يحتفظ بعقده |
| الأولى: HTTP | مستثناة بطلب المالك؛ فحص فرق ملفي البيئة أعاد صفرًا، ولم تتغير عناوين الخوادم |

### دليل التطبيق وقبول المالك المتبقي

أُضيفت فقرتان عربيتان/إنجليزيتان إلى `UserGuide/content/shared-screen-guidance.ts`؛ يستهلكهما قارئ الدليل القائم في النظرة العامة للأدلة. المساران القائمان هما `/UserGuide` و`/UserGuide/:sectionId`. تغطيان العودة بعد الدخول والجلسة التالفة وعدم إتاحة الحسابات واستمرار التحميل وإعادة قراءة السياسة، دون قائمة جديدة. مطابقة المصدر مكتملة والمعاينة معلقة.

يلزم عند إتاحة التشغيل:

١. تجربة تخزين تالف/محجوب ثم جلسة صالحة ذات اشتراك عددي بعد إعادة تحميل المتصفح.
٢. فتح سجل محمي مع استعلام وجزء أثناء الخروج، ثم الدخول والتأكد من العودة الكاملة؛ والتحقق من رجوع الوجهة غير الداخلية إلى الجذر.
٣. مراجعة رسالتي التسجيل واستعادة كلمة المرور بالعربية والإنجليزية ورابط الدخول، دون حقول أو نجاح وهمي.
٤. رفض انتقال أو تعذر تحميل مسار أثناء طلب جارٍ، ثم انتقال ناجح يبدأ طلبًا في الوجهة؛ يبقى المؤشر حتى تحرر الطلبات حصصها.
٥. محاكاة فشل/إلغاء قراءة السياسة ثم إعادة فتح المستند، والتحقق من طلب جديد ومن عدم محو نجاح أحدث بسبب فشل طلب أقدم.
٦. تنفيذ بناء الواجهة وحالات الانحدار لدى المالك عند السماح؛ تبقى هذه بوابة القبول التشغيلي.

استُخدم وكيل قائم بملكية منفصلة داخل `auth/**` وبالنموذج الموروث، بينما امتلك الجذر الخدمات واللغة والدليل والوثائق والمراجعة النهائية. الفصل بين مساري المصادقة ودورة الطلب قلل زمن التنفيذ دون تداخل ملفات؛ دُمجت النتيجة ورُوجعت مصدرّيًا من الجذر.
