# مراجعة وتنفيذ الإطفاء

## متابعة رسائل التشغيل — ٢٠٢٦/١٠/٢٦

أرسل المالك خطأ تغيّر ربط الانشغال في الغلاف، وفشل قراءة مصادر الإطفاء بالحالة ٥٠٠، ورسالة ٤٠٩ بلا عنوان طلب أو جسم رد. هذه المتابعة إصلاح مصدر التحميل وتشخيص المصدر الحالي؛ ليست موافقة على تشغيل بناء أو اختبار أو قاعدة بيانات أو تغيير إعدادات مالية لتجاوز التعارض.

أُصلح نشر حالة التحميل في مالكها المشترك، وفق [خطة التحميل وملحقها المجمد](SHARED_LOADING_MAINTENANCE_EVOLUTION_PLAN.md) و[مراجعة المطابقة](SHARED_LOADING_FEATURE_REVIEW.md). بقيت قراءات الشاشة وعملياتها وحواجزها ودليل استخدامها كما هي؛ لا مؤقت أو كشف تغييرات إجباري خاص بالشاشة.

بالنسبة للخادم، تصحيح تركيب استعلام المصادر الموثق في القسم التالي موجود بالفعل قبل هذه الجولة؛ لم يُعدّل مصدر الخلفية الآن. فحص مستقل محدود يؤكد عدم بقاء استدعاء مؤكد غير قابل للترجمة في المسار، مع عدم ادعاء نجاح ترجمة قاعدة البيانات. الدليل المحلي: ملف خدمة الإطفاء عُدّل الساعة ٠٨:٢٣:٢٠، بينما تجميع الأعمال بجوار الملف التنفيذي عُدّل الساعة ٠٧:٣٧:٣٧، والخادم الجاري من ذلك المسار بدأ الساعة ٠٧:٣٩:٤٦ يوم ٢٦ أكتوبر بتوقيت القاهرة. القراءة اقتصرت على معلومات العملية وتواريخ الملفات؛ لم يُوقف الخادم أو يُشغل أو يُتصل بقاعدة البيانات. هذه النسخة المجمعة تسبق التصحيح الحالي؛ يجب إعادة بناء الخادم وتشغيله قبل الحكم على الإصلاح. يظل احتمال تحديث ساخن أو استثناء آخر غير مثبت دون سجل تشغيل.

المعلومات الإضافية التي أرسلها المالك تؤكد عنوان طلب المصادر وحالته فقط، دون نوع الاستثناء أو تشخيصه. ترحيل الجداول موجود في ملفات المصدر تحت اسم إضافة جدول المخصصات وجهات الاتصال بتاريخ ٢٦ أكتوبر؛ لا دليل على تطبيقه على قاعدة المالك. لا يُنشأ ترحيل مكرر ولا تُخفى مشكلة مخطط محتملة بإرجاع قائمة فارغة. إذا استمر الفشل بعد إعادة البناء والتشغيل، يلزم سجل الاستثناء المطابق؛ وعنوان طلب التعارض ونصه لازمان لتحديد رسالة ٤٠٩، ولا يُفترض أنها تخص عملة الأساس أو الفترة أو هذا الطلب.

الدعم المتوازي: أُسند فحص الخلفية للقراءة فقط إلى مستكشف واحد بالموديل الاقتصادي المعتمد، بينما نفذ الجذر إصلاح التحميل في ملفات منفصلة؛ لا تعديلات خلفية أو تضارب ملكية. جميع العقود السابقة باقية؛ لا استعلامات أو كاش أو فهارس جديدة في هذه الجولة، والاختبارات والبناء والتشغيل الفعلي معلقون عند المالك.

## تشخيص خطأ الفتح — ٢٠٢٦/١٠/٢٦

طلب المالك إصلاح رسالة الخطأ غير المتوقع عند فتح شاشة الإطفاء. النطاق إصلاح مصدري محدود لمسار قراءة المصادر وإعادة التحقق الذي يستهلك الاستعلام نفسه؛ العقود المجمدة ومساحة العمل المالية بتبويبات UI1/13، والخلفية المالية BE15، دون تغيير تجاري أو واجهة بيانات جديدة. الحزم الثماني متسقة؛ تطبيق متناسب لحزمة المرحلة١ وBE5/7/10 وMaster1/5/7، مع الرجوع إلى دليل الواجهة والكاش والتحميل السابقين في هذا الملف. لا وكلاء فرعيين لأن تشخيص السبب ثم إصلاح استعلام واحد عمل متتابع لا مساران مستقلان.

| المقارنة قبل التعديل | المرجع والمالك | القرار |
|---|---|---|
| المسار الفعلي | وصلة القائمة → pages/routing → AMORTIZATION_ROUTES → AmortizationWorkspaceComponent.ngOnInit/loadActiveTab/loadSources → GET Amortization/sources → GetSourcesAsync | الفتح الافتراضي يقرأ المصادر مع الفروع وحسابات الترحيل؛ طلب المصادر هو مسار العيب المحدد في المصدر. لا دليل تشغيلي يثبت بعد أنه الاستثناء الفعلي لدى المالك. |
| تركيب الاستعلام | BE7/10؛ Repository.Query يضيف مرشحي المستأجر والحذف؛ AccountSelectionPolicy.Apply يبني أهلية الحساب | توجد استدعاءات Query بلامبدا مرتبطة بصف المصدر داخل Select، واستدعاءات بناء السياسات/المستودع داخل تعبيرات الشروط. تجهيز IQueryable المقيّد خارج اللامبدا ثم تركيب Any/Count/Where/Select القياسية، دون materialization أو تجاوز الأهلية. |
| المستهلكون المرتبطون | GetSourcesAsync، ResolveSourceAsync، EligibleBillSources/EligibleOpeningSources، حجز الجدول في EligibleBills/EligibleOpenings | إصلاح تركيب القراءة وإعادة التحقق معًا حتى لا يعمل العرض ثم يفشل حفظ المصدر. الحفاظ على كل شرط ومبلغ وهوية وترتيب وحد ألفي صف. |

النتيجة: أُصلح تركيب الاستعلام في المصدر؛ مطابقة الاستثناء الفعلي ونجاح الفتح بالتشغيل ما زالا معلقين. رسالة الخادم عامة؛ طُلبت تفاصيل سجل الخطأ اختياريًا لتأكيد المطابقة، ولا يسمح هذا الطلب بتشغيل قاعدة البيانات أو التطبيق. وسيط ErrorLogsMiddleware يحول الاستثناء غير المتوقع إلى هذه الرسالة، ويسجل نوعه وبياناته التشخيصية الآمنة؛ لذلك لا تثبت الرسالة وحدها نوع الخطأ.

### النتيجة والمطابقة المصدرية

- ملف التطبيق المعدل الوحيد: `SigmaBackend/SiGma.Business/Services/VouchersServices/AmortizationService.cs`. الملف كان غير متتبع قبل المهمة؛ حُفظت نسخة قبل التعديل خارج المستودع وقورنت معه كاملة بواسطة Git no-index، بدل اعتبار غياب فرق Git المعتاد دليلًا على عدم التغيير. حُفظت جميع التعديلات السابقة في الطرفين.
- جرى تجهيز مصادر الحسابات والروابط والائتمان والمرتجعات والجداول بوصفها IQueryable مقيدة بالمستأجر والحذف قبل تركيب الشروط. أزيل استدعاء Repository.Query ذي اللامبدا المرتبطة بصف المصدر من إسقاط حساب المصروف في GetSourcesAsync وResolveSourceAsync، واستُبدل بتركيب Where/Select على مصدر الروابط المجهز. بقي الربط واحدًا بالضبط، والحسابان مختلفين وصالحين، والمصدر مرحلًا ومعتمدًا وغير مبطل وبعملة الأساس، دون ائتمان أو مرتجع مؤثر أو جدول حي سابق.
- فحص مقارنة نصية من المصدر بعد توحيد أسماء جذور الاستعلام والمسافات أثبت تطابق شرطَي EligibleBillSources وEligibleOpeningSources قبل/بعد بالكامل. أكدت المقارنة تطابق بقية كتلة الجداول والتجهيز والحفظ والقرارات واليومية والسجل وإعادة التحقق الدفعي حرفيًا؛ التغيير في بناء استعلامات المصادر المستهلكة منها فقط. مراجعة الفرق كاملة وفحص المسافات وعلامات الدمج تمت؛ لا ادعاء نجاح ترجمة EF أو البناء من هذه الفحوص.
- الأداء: قراءة المصادر لا تزال بثلاث حدود materialization: عملة الأساس ثم بنود الفواتير ثم الأرصدة الافتتاحية. المصادر المجهزة خارج اللامبدا لا تنفذ قاعدة البيانات بذاتها. تبقى إسقاطات صغيرة وAsNoTracking وحد إجمالي ٢٠٠٠ مع قراءة صف زائد وفشل صريح، وترتيب Id وتتابع EF على السياق الواحد؛ لا ToList مبكرًا أو استعلام داخل حلقة أو cache تشغيلي. الأثر المقصود صلاحية التركيب الخادمي، دون ادعاء تقليل عدد SQL أو تحسين زمن مقاس. ظروف القياس السابق في قسم الأداء أدناه تظل مطلوبة، مع مقارنة الفتح البارد والدافئ بنفس المستأجر والبيانات والعملات وحجم النتائج وخمس عينات على الأقل، وتسجيل الاستثناء/عدد الطلبات وخطة SQL والقراءات والتوقيت قبل/بعد.
- الفهارس: لا اقتراح جديد لهذا العيب؛ إضافة فهرس لا تصلح تعبيرًا غير قابل للترجمة. فُحص LinkAccountsConfig: بادئة الفهرس المركب الحالية SubscriptionId/Type/Value تخدم الارتباط، مع شروط الفهرس الحي ومحدودية تغطية IsDeleted nullable؛ وفُحص AmortizationScheduleConfig وفهرسا المصدر الفريدان وFK بنود الفاتورة/الأرصدة. لا يُفترض تطابق المنشور مع إعلانات EF؛ خطة التنفيذ والإحصاءات وتغطية الصفوف nullable عند المالك، دون INCLUDE نصي أو كلفة كتابة إضافية أو تعديل EF.
- التحميل والكاش: لم تتغير الواجهة. loadSources → beginRead يملك بداية التحميل العام وfinalize والنهاية وتفريغ الحالة المحلية، وإلغاء الاشتراك السابق والنسخة وDestroyRef، وعرض الخطأ وإعادة المحاولة. مصادر الإطفاء تشغيلية مباشرة، Branch/GetSelect مرجع عبر bootstrap ناجح ثم ReferenceLookupBindings/watch مع حفظ الاختيار والتنظيف، Account/PostingSelect مباشر لأهلية الترحيل، وسياسة العملة مباشرة عند المخصص. تستمر مصفوفة المصدر/الكاتب/الإبطال والظهور أدناه؛ لا تحويل أي مصدر تشغيلي إلى كاش. ظهور المؤشر والتداخل والتوقيت والتحديثات الحية تحقق تشغيلي معلق.
- العقود: لا تغيير DTO/API أو AutoMapper أو حساب أو أثر مالي أو مخطط/فهرس، ولا يلزم ترحيل جديد لهذا الإصلاح. الملف الموجود `20261026042041_AddProvisionScheduleAndContacts` يتضمن بالفعل جداول الإطفاء الأربعة؛ وجوده لا يثبت تطبيقه على قاعدة المالك. ملاحظة إنشاء ترحيل منفصل في التسليم التاريخي أدناه لا تُعاد كتوصية جديدة لهذه المهمة.
- دليل المستخدم: موضوع `modules/UserGuide/content/amortization-topic.ts` المسجل في record-list-topics وتحت دليل السندات المحاسبية يبقى مطابقًا للسلوك؛ الإصلاح خلفي فقط ولا يغير خطوات المستخدم أو يحتاج محتوى جديدًا. فُحصت خطوات مصادر الفاتورة/الرصيد وأهلية المصدر والحفظ والتجهيز، ولا تعديل للواجهة أو دليلها في هذه المتابعة.
- المراحل المطبقة: اكتشاف المسار وتأكيد العقد، إصلاح خلفي محدود، ومطابقة الفرق. تُرك تنفيذ الواجهة والإجراءات والمخطط خارج النطاق. لا builds/tests/lint/browser/application/database/migrations/snapshot/commit/push/deployment/Graphify/Sigma MCP؛ لا تعليمات أو مالك مشترك جديد. اقتراح حفظ الخلفية لهذا الملف فقط دون تنفيذه: `fix(amortization): compose source queries before correlated predicates`.

تحقق المالك: بناء وتشغيل نسخة الخلفية المعدلة ثم فتح الشاشة والتبويبات، والتحقق من الفاتورة والرصيد الافتتاحي ومصدر محجوز وربط مفقود/مكرر ومصدر ائتمان/مرتجع، وأن المصدر المقبول يظل نفسه عند الحفظ والتجهيز. عند استمرار الرسالة، تُطابق تفاصيل آخر خطأ لخدمة Amortization ومسار sources؛ تميَّز أخطاء ترجمة الاستعلام عن أخطاء المخطط أو بيانات الاتصال دون إخفائها أو اعتبارها قائمة فارغة.

## متابعة اتساق العرض — ٢٠٢٦/١٠/٢٦

أوضح المالك أن الصورة الأخيرة تخص عدم اتساق التنسيق؛ نطاق هذه المتابعة عرض الواجهة فقط، وليس تشخيص رسالة الخادم. الصورة دليل على اختلاف خط محاذاة الشهر والأزرار، وعلى ابتعاد إعادة المحاولة عن رسالة الخطأ. إصلاح صغير وفق التناسب؛ العقود المحاسبية والخلفية دون تعديل، ولا حاجة لعقد جديد أو وكلاء فرعيين.

| المقارنة | المالك المرجعي | التصحيح والمطابقة المصدرية |
|---|---|---|
| إطار الشاشة والمسافات | الواجهة١؛ هيكل محرر المستند المشترك | استبدال إطار الصفحة والبطاقة المحليين بالفئتين العامتين للصفحة ولوحة مساحة العمل، وحذف ألوانهما وحوافهما ومسافاتهما المحلية؛ تستمر منطقة المحتوى المرنة والتمرير الداخلي |
| الشهر وإجراءات التحضير والتصدير والإضافة | الواجهة٤؛ قائمة أوامر العمل ومكوّن شريط التصفية | استيراد مالك التصفية وتوجيه الإجراءات من ملفيهما الفعليين، وصف ثابت بعناوين للإجراءات يحاذي الأزرار مع الحقل مستقلًا عن مساحة التحقق؛ الالتفاف والاستجابة واتجاه العرض يملكها المشترك |
| صيغة الشهر | الواجهة١٧؛ منتقي التاريخ وتوجيه التاريخ الحاليان | تمرير صيغة الشهر بربط خاصية صريح بعد إنشاء التوجيه الذي يضبط افتراضي اليوم؛ العرض شهر وسنة، والتحقق والنقل يظلان عبر المحلل المشترك |
| الخطأ وإعادة المحاولة | الواجهة٢٢؛ رسالة الحالة المشتركة | الاحتفاظ برسالة الحالة وزر المحاولة وتجاورهما مع التفافهما عند ضيق المساحة، دون ألوان أو رسالة خطأ بديلة |
| التحميل | الواجهة٢٢؛ خدمة التحميل وهيكل التطبيق | المسار الفعلي يحمّل مكوّن مساحة العمل؛ سياسة الهيكل الافتراضية تظهر التحميل. القراءات الأساسية تبدأ العداد وتنهيه في الإنهاء والإلغاء، وتعطلت أقنعة الجداول المرئية المكررة مع بقاء حالتها المشغولة؛ الحوارات تظل بمالكها المحلي |

أضيفت إعادة الضبط المطلوبة في المالك المشترك: تعيد الشهر الحالي وتمسح المعاينة وتعيد قراءة التبويب النشط؛ ولا تحفظ أو تعتمد دفعة. تحدّث شرحها بالعربية والإنجليزية في موضوع الإطفاء بدليل المستخدم الموجود تحت دليل السندات والقيود. أزرار التجهيز والبحث تتعطل عند شهر غير صالح. لا تغيير للأعمدة أو القيم أو تصدير المعاينة أو إجراءات الدفعات.

بوابة الكاش والأداء: لم تتغير مصادر البيانات؛ مصادر الإطفاء والجداول والدفعات تشغيلية مباشرة، واختيار الحساب والسياسة المالية مباشران للأهلية والدقة، والفروع عبر مصدرها المرجعي المشترك مع قراءة أولى ومراقبة منفصلة ناجحة. إعادة الضبط تعيد استخدام قارئ التبويب القابل للإلغاء. لا استعلامات أو فهارس أو مخطط تخزين جديدة؛ أدلة الأداء السابقة باقية، والقياس الفعلي وخطط قاعدة البيانات عند المالك. لا يُدّعى تحسن سرعة من تعديل التنسيق.

الملفات المعدلة في هذه المتابعة: قالب مساحة العمل ومكوّنها وتنسيقها، وموضوع دليل المستخدم. جرى فحص صياغة المصادر والقالب ومسارات الاستيراد وثنائيات الترجمة: ثمانية ملفات، ٦٢ مفتاحًا لكل لغة، دون أخطاء في الفحص المصدري. فُحصت الواجهات العامة للمالكين المشتركين والفروق والمسافات والملفات الجديدة؛ حُفظت التغييرات السابقة. الحزم الثماني متسقة دون تعديل الكتب أو الحزم. لم يُشغّل بناء أو اختبار أو متصفح أو قاعدة بيانات أو ترحيل أو حفظ للمستودع. التحقق البصري على المقاس المرفق والهاتف وبالاتجاهين والثيمين، وكذلك نجاح طلب الخادم، يظل عند المالك؛ هذه المتابعة لا تدّعي إصلاح رسالة الخادم. اقتراح رسالة حفظ الواجهة دون تنفيذ: `fix(amortization): align workspace filters and shared presentation`.

## الأداء والفهارس: النتيجة القابلة للتحقق

لا baseline تشغيلي سابق لأن الشاشة لم تكن موجودة. لا نتيجة زمنية مقاسة في هذه المهمة. عند البداية التلقائية توجد قراءة مصادر وفروع وحسابات؛ الفروع الدافئة تستخدم مالك الكاش فقط. تجهيز الشهر طلب واحد؛ الجداول تجمع sources/schedules بقراءة مترابطة محددة؛ السندات تجمع نوعي الشهر؛ السياسة تُقرأ عند المخصص. لا طلب بيانات عند فتح تفاصيل الحساب أو التصدير. كل GET كامل محدود بألفي صف مع فشل معلن عند الزيادة؛ قراءة اليومية قد تعرض حتى أربعة آلاف سطر لدفعة من ألفي جدول، وهي حاجة العرض المحاسبي الكاملة.

قراءة المصادر تتابع عملة الأساس ثم استعلام بند الفاتورة ثم الرصيد الافتتاحي؛ mapping predicates/projections داخل الاستعلام ولا materialization لكل سطر. تجهيز/اعتماد الدفعة يعيد تحقق المصدر بدفعات للهوية مع قراءات الفرع والحسابات والعملة والربط؛ لا EF متوازٍ على السياق الواحد. مسار الحفظ يُراجع حتى UnitOfWork.PrepareAddedNumbersAsync، حيث كان الرقم الداخلي الفارغ يجعل CodeCreateService يقرأ إعدادات لكل طفل: أرقام سطور القيد الآن AM-S{schedule.Id} داخليًا، وأرقام RunLine/ApprovalLog ترث رقم الدفعة، ولا تستبدل رقم مستند مستقل. هذه إزالة لنمو مصدر مؤكد في عدد القراءات وليست إثبات سرعة مقاسة. المعاملة الخارجية وحدها تملك Commit/Rollback؛ أزيل فتح معاملة داخلها كان يمنع الحفظ.

| الفهرس المعلن في EF | السبب/التغطية والتكلفة/التحقق |
|---|---|
| Schedule(SubscriptionId,BillDetailId) UNIQUE WHERE IsDeleted=0 AND BillDetailId IS NOT NULL | يمنع جدولين حيين للمصدر، ويساعد seek بمعرف المصدر/المستأجر؛ جدول جديد بلا فهرس مركب قديم متداخل؛ كلفة إدراج/حذف الجدول ومساحة مفتاحين. null IsDeleted غير صادر من هذا الكاتب؛ default=false |

| Run(SubscriptionId,Month,IsCustom) | يطابق ترشيح الشهر والنوع؛ ترتيب Id التنازلي قد يحتاج Sort؛ لا INCLUDE للأوصاف؛ كلفة كتابة كل دفعة. إضافة Id أو INCLUDE للحالة/الإجمالي لا تعتمد إلا بعد خطة فعلية وحجم مبرر |
| ApprovalLog(AmortizationRunId,CreatedAt,Id) | يخدم ترتيب تاريخ الدفعة؛ runId فريد المجال ويحدد المستأجر من صاحب الطلب، مع بقاء مرشح المستأجر؛ كلفة لكل قرار. لا فهرس ثانٍ موازٍ بلا خطة تثبت الحاجة |

هذه إعلانات ضمن الجداول الأربعة الجديدة، وليست فهارس مطبقة. فهارس FK المفردة وإعلانات المصادر الحالية تُراعى في خطة الترحيل، ولا تعدل فهارس الفواتير/الأرصدة الحالية دون دليل SQL. التحقق المطلوب: SQL translation للـcorrelated mapping/anti-reservation، ملاءمة المرشحات nullable مقابل IsDeleted!=true، actual plans/reads/sorts/cardinality، والكلفة عند الاعتماد/الإبطال.

راجع الجذر الملفات الجديدة كاملة ونقاط التسجيل والحماية في الفواتير والأرصدة والائتمان والمرتجعات والتنقل؛ محفوظة تغييرات المستخدم والأعمال المتزامنة خارج النطاق. لم تُعدّل migrations أو model snapshot ولم تُشغّل اختبارات أو بناء أو متصفح أو قاعدة بيانات. فحص الفروق المصدرية وملفات XML والروابط والتسجيلات أجري دون تنفيذ التطبيق.

تحديث الوثائق العام: أضيفت إلى BE7 فقرة Hidden per-row work in aggregate saves وإلى المهارة القاعدة وصف مراجعتها، بنفس المالك المرجعي Master5. جُددت الحزم الثماني عبر المولد، ورُوجعت دلاليًا روابط BE7 والمراجع وشروط حفظ الترقيم والتاريخ؛ فحص -Check ناجح بعدها. لم تُحرر الحزم المولدة يدويًا. هذه قاعدة عامة لمراجعة المسار، أما صيغة الإطفاء واختيار مصدره فتبقيان في عقد هذه الميزة.

المتبقي عند المالك: إنشاء ومراجعة ثم تطبيق ترحيل باسم AddAmortizationWorkspace للجداول الأربعة وعلاقاتها وفهارسها وقيودها، ثم بناء الطرفين والتحقق التشغيلي/المحاسبي. السيناريوهات: سنة كبيسة وتغطية يوم/منتصف شهر ونهاية ديسمبر9999 ودقة0/1/2، مجموع جميع الشهور=الأصل دون catch-up، تزامن حفظين لنفس المصدر والشهر، إعادة التجهيز بعد رفض/إبطال/حذف المسودة، الاحتفاظ بالحجز عند فك الاعتماد، فترات مغلقة وتخصيصات قائمة، مصدر قديم بلا صافي مرحل، ائتمان/مرتجع/تغيير عملة أو ربط، عزل مستأجر آخر، أخطاء وRetry والكاش والتخلي عن النموذج والفتح المباشر للدفعة وعرض كامل/RTL/theme. لا ادعاء أن هذه السيناريوهات اختُبرت بالتشغيل.
