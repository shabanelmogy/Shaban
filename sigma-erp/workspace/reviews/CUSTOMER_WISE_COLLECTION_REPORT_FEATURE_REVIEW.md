## مصدر المتطلبات والقرار

طلب المالك مراجعة وتنفيذ التقرير وفق صورة Customer Wise Collection Report/1.png. تقرأ الصورة ستة أعمدة وثلاثة مرشحات وبحثًا وطباعة وExcel، وصف إجمالي كاملًا. قُرئ شرح Speed فصل ١١، ثم تقريره Reports11 ومتحكمه C0978 ومساره R0421 من لقطة ٢٨ أكتوبر كخطوة مستقلة. يثبت المرجع اختيار Individual/Company، ولا يحدد مصدر حساب الخادم. استُخدم مرجع Odoo19 المحفوظ payments.rst لتوضيح الدفعة المخصصة وغير المخصصة. يستند الحساب إلى مصادر Sigma المالية المجمدة في التقرير الثاني، وقرار المالك السابق بضم Customer Payment وDeposit Refund للمرتجعات.

أثبت المصدر القديم عنوان API غير موجود Report/CustomerWiseCollectionReport، وخطأ إرسال salesPersonId بدل نوع العميل، وتحميل قائمة العملاء لاختيار نوع ثابت، وتحويل التاريخ بزيادة يوم، وتجميع النتائج القديمة في كل بحث. استُبدل المكون والخدمة والنموذج في موضعها بمصادر التقرير الفعلية.

## المطابقة مع المالكين المشتركين

يملك ReportPage/FeatureTitle/ReportActions شكل الصفحة، وDataTable الأعمدة والتصفية والصفحات المحلية وfooterRows. يحتفظ Footer بمكان Total داخل خانة البريد قبل المبالغ، ويظل خارج الصفوف والعدد. يعاد استخدام تصميم التقرير المعتمد UI07 ومرجع StatementOfAccount، وتظهر العملات مستقلة بلا شروحات إضافية داخل الجدول.

استُخرجت دورة القراءة المشتركة createReportReadState من createCollectionReportState مع إبقاء واجهة المالك السابق ونموذجه ومرشحاته للمستهلكين الثلاثة. يمرر كل تقرير حقوله وقراءة الفلتر وإعادة تهيئته. يستخدم تقرير العميل ثلاثة حقول حقيقية مستقلة. يحمي المالك الجلسة ونطاق الفروع وإصدار الصلاحيات والقراءات والمخرجات المؤجلة، ويمسك LoadingService بزوج start/finalize. لا تخزين مالي أو مصادر lookup اختارت reference cache هنا. Options قراءة تشغيلية مباشرة وفقط branch choices، والنوع ثابت مترجم محليًا.

تُستهلك CustomerCollectionReports/Read وOptions وPrint وExport. يعتمد مسار الواجهة على Read، وتحتاج المخرجات الإجراء والقراءة. تضع PermissionCatalogAction هذه الإجراءات في الكتالوج، وتعيد PermissionPrerequisites Read، ويصنف BranchOperationRules التقرير EffectReads مع QueryReport. يتكفل اكتشاف الخدمات القائم بربط الواجهة بتنفيذها. دليل الشاشة داخل UserGuide/content/customer-collection-report-topic.ts ضمن /UserGuide/reports.

## الأداء ونطاق الفروع

يُستخرج مالك صرف العميل من تقرير التفاصيل إلى CollectionReportSourceQueries ليستخدمه القارئان بالشروط نفسها. تكتمل فحوص الهوية المستبعدة على مستوى الشركة في استعلامات مستقلة، وتبقى الاستعلامات المنشورة وخياراتها تحت مرشحات الفروع. لا IgnoreQueryFilters داخل الاستعلام المنشور أو الخيارات. تحفظ قراءات تقرير العميل صلاحية فرع السند، وتعيد بيانات العميل المرتبط بحركة مالية مسموحة فقط، دون تحميل دليل عملاء عام.

تعتمد القراءة على ثلاثة فحوص هويات ثم تحقق SQL قبل التجميع ثم استعلام تجميع كامل. الخيارات ثلاثة فحوص ثم استعلام فروع واحد. لا استعلام لكل عميل، ولا تحميل تفاصيل التخصيص أو فواتير الإيجار التي لا يحتاجها هذا الملخص. التوقيت وخطة SQL الفعلية معلقة. راجعت المهمة السابقة فهارس نفس المصادر على sql5106/db_a82a9c_sigmaoperations1، وتغطي المفاتيح الخارجية وسجل ردود الودائع الفترة/الفرع/الشركة. يبقى اقتراح تقييم فهرس (SubscriptionId,Date,Id) لسندي القبض والصرف مع INCLUDE للحالة والفرع بحسب خطة التنفيذ وحجم الكتابة. لا فهرس جديد في نطاق هذه المهمة دون دليل قياس الحاجة.

## مراجعة المصدر النهائية

أكدت المراجعة المستقلة سلامة قيمة Individual الصفرية، والنوع غير المختار، وحدود التاريخ، والتجميع بهوية العميل وعملته، وصفوف المرتجعات فقط والصافي الصفري، وإجماليات النتيجة الكاملة. راجعت شجرة المصدر بحيث تبقى استبعادات الشركة في استعلامات معرّفات منفصلة، مع بقاء مرشحات الفروع على الصفوف والخيارات. بقيت دورة التحميل وإبطال السياق والصلاحيات والمخرجات المؤجلة للمستهلكين الثلاثة السابقين في المالك المستخرج.

أضيفت الفترة المطبقة إلى رأس الطباعة فقط، وتظل الشاشة بنفس أعمدة الصورة. يتضمن Excel ستة أعمدة صريحة، مع بيانات الفترة والعملة في صفوف تحت الأعمدة النصية القائمة. أكد فحص المصدر مطابقة خصائص DTO وصف Angular وتطابق مفاتيح الترجمة ووجود ستة أسماء أعمدة مختلفة باللغتين.

تضم مواصفات الخادم أربع حالات ذات معنى، تشمل تشابه أسماء العملاء، والمرتجعات فقط والصافي الصفري، ونوع العميل صفر وحدود الفترة قبل فحص الدليل المالي، وحجب الفروع غير المسموحة في التقرير والخيارات، وفصل العملات بدقتين ومنع تكرار استعمال الوديعة مع ردها. مواصفات الواجهة الجديدة تغطي إرسال النوع صفر في القراءة والطباعة والتصدير، وإبطال القراءة عند تغيير النوع وإغلاق مؤشر التحميل. جُمعت معها مواصفات مستهلكي Collection وCollectionAndRefunds للتأكد من بقاء عقود المالك المشترك.

تعطل بناء الواجهة الأول بسبب توقف خدمة esbuild الفرعية. أُعيد بعامل واحد ونجح بناء Angular development في ١٤٢٫١٧٥ ثانية، بالسجل .codex-build/customer-collection-angular-build-final.log والمخرج .codex-build/customer-collection-web. نجح تجميع قوالب التقرير ومواصفات الواجهة والمستهلكين السابقين عبر ngc --noEmit بإعداد معزول .codex-build/customer-collection-specs.json. لم تُنفذ اختبارات سلوك أو متصفح.

رُوّج مالك دورة القراءة إلى UI20 ومهارة Sigma مع سجل المراجعة، وجدد المولد حزم PLAN-00 وPHASE-00 حتى PHASE-06. نجح فحص الاتساق بعد التجديد. لا تغيير مخطط أو بيانات أو هجرة في هذه المهمة، ولا commit أو push أو نشر. قبول SQL Server والاستعلامات المتزامنة وتوقيت الصفحة والطباعة وExcel الفعلي وRTL والثيمين معلّق بعد تشغيل API المحدث.
