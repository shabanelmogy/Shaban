## الواقع والأدلة

المسار المستورد فعليًا VehicleProfitAndLossByChasisNoComponent. القارئ الأمامي يطلب Report/VehicleProfitAndLossByChasisNoReport غير الموجود، ويفترض accounts/children ويعرض6 حقول فقط، ويغير التاريخ بإضافة يوم ويراكم files عند إعادة القراءة ولا يعالج الخطأ/finalize. الخادم يملك VehiclesProfitAndLoseByChassisNo بالفعل لكن يقرأ Invoices بنص PlateNo وNormalizePlate داخل Where غير القابل للترجمة، وBillDetails بمطابقة شاسيه نصية، دون استعمال QueryReport وحدود الفروع والترحيل المشتركة؛ يختار رأس أول مركبة رغم إمكانية عدة مطابقات ويعيد أرقام JSON غير دقيقة نقديًا.

الصورة1 دليل المحتوى، وSpeed23/06/R0401/C1097 بتاريخ2026-10-28 دليل الحقول/voucher/account/debit-credit والتصدير؛ راجع فصل16 ثم شرح الشاشة ثم كودها، وأكمل بـOdoo19 fleet/cost_analysis.rst ضمن حدوده. عقد الربحية العام القائم حسم مصدر القيود؛ العقد المجمد لهذه الشريحة يعيد استعماله دون تعديله أو إنشاء معادلة منافسة. ## نتيجة التنفيذ والمصالحة

أصبحت الواجهة جدولًا مسطحًا بالأعمدة الأحد عشر وبترتيب الصورة، مع الفترة والشاسيه وExcel والتحديث في صف التحكم المشترك؛ لا شجرة أو بطاقات أو شرح إضافي. يعرض التذييل إجمالي الإيراد والمصروف القادمين من الخادم للمجموعة كاملة. تتغير دقة المال حسب عملة الأساس وتبقى القيم decimal-string، وتبقى الهويات والترقيم أعدادًا صحيحة.

صُحح عنوان HTTP إلى مالك VehicleReports الفعلي، واستُبدل قارئ الفواتير/اللوحة القديم بمحول إلى CreateVehicleProfitAndLossDetailReport القائم؛ لم يتغير القارئ العام أو عقده المالي. تعاد المجموعة الكاملة وتستبدل نتيجة البحث السابق، وتُنقل أيام التقويم كما هي دون إضافة يوم. أزيلت DTOs القارئ القديم غير المستهلكة. طريقة الدفع تبقى غير متاحة عند غياب رابط موثوق في القيد، كما في مالك التفاصيل القائم، دون تخمين.

أضيف تصدير مستقل بنفس القارئ، ومنحته مرتبطة بمنحة قراءة تقرير الشاسيه وبنطاق ReportReads؛ لا يتطلب منح تفاصيل التقرير العام ولا يمنح الوصول تلقائيًا. سُجلت سياسة المسار وترجمات الإجراءين. يحمي مالك النتيجة هوية المستخدم/الشركة/نطاق الفروع وإصدار الصلاحيات، وتبطل تعديلات الفلاتر أو تغير السياق النتائج وتلغي الطلبات وتمنع ردًا أو تنزيلًا منتهي الصلاحية. أُضيف موضوع الدليل باللغتين إلى /UserGuide/reports.

## الأداء وحدود SQL

يستعمل التقرير قارئ التفاصيل المشترك: قراءة عملة الأساس، إعدادات الاستبعاد، حل الحسابات عند وجود أكواد، ثم إسقاط قيود واحد مرتب بتاريخ القيد وهويتي المستند والسطر. لا استعلام داخل كل صف ولا قراءة lookups إضافية. البحث بالشاسيه Contains من ثلاثة أحرف؛ ليس وعدًا باستعمال index seek عادي. لا تغيير schema/index أو اقتراح فهرس بلا خطة SQL. العدد الفعلي للاستعلامات والترجمة والخطة وقراءات SQL والتوقيت قبل/بعد وتغطية الفهارس والحجوم الكبيرة تبقى قبولًا تشغيليًا غير منفذ؛ لا ادعاء سرعة مقاسة.

جرى فحص scoped diff وgit diff --check في المستودعين، ومراجعة القالب والخدمة والمالكين المشتركين وسياسات HTTP/الفروع، والبحث عن مستهلكي DTOs المحذوفة وعن المسار الأمامي القديم. أكد فحص AST وجود مفاتيح الأعمدة الأحد عشر في الترجمتين العربية والإنجليزية. حُفظت التعديلات غير المتعلقة بالمهمة. لا قاعدة بيانات أو migration أو منح تجريبية أو lint أو اختبار تشغيل أو متصفح أو commit أو نشر.
