# عقد تبني وصول قائمة ومحرر الإيصالات

| البند | القيمة |
|---|---|
| Status | Frozen |
| Owner verification pending | yes |
| التاريخ | ٢٠٢٦-١١-٠٧ |
| النطاق | `/Receipt` القائمة، create/view/edit، وإجراءات القائمة والإيصال المستقل |
| المستثنى | مسارات الاستيراد غير المنفذة، سياسات مالية جديدة، schema، وReceipt المدمج الذي يستهلك عقده الخاص |

## متطلبات الوصول

| السطح | المتطلب |
|---|---|
| القائمة والقراءة والطباعة والتقرير والتصدير | `Receipt.View` |
| إنشاء | `Receipt.Create`؛ القراءات التابعة تبقى حراسة مستقلة حسب نوع الإيصال |
| تعديل | `Receipt.View + Receipt.Update` |
| حذف | `Receipt.View + Receipt.Delete` |
| سجل الاعتماد قراءة | `Receipt.View` لفتح النافذة، و`Receipt.ManageApproval` لأحداث القرار |
| سجل اليومية | `Receipt.View + Receipt.Journal` |
| سجل الأحداث | `Receipt.View + Receipt.Log` |
| إبطال | `Receipt.View + Receipt.Void` |
| فروع القائمة | `Branch.Lookup`؛ غيابها يخفي الفلتر ولا يرسل `branchId` من اختيار مخفي |
| طرق الدفع القائمة | `PaymentMethod.Lookup`؛ غيابها يخفي الفلتر |
| أطراف الإيصال القائمة | `Receipt.Parties`؛ غيابها يخفي فلتر الطرف ويوقف القراءة فقط |
| سياق عرض السعر/العقد | `Receipt.QuotationContext` أو `Receipt.SalesAgreementContext` مع متطلب الإنشاء عند إنشاء إيصال مدمج |
| التخصيصات | `Receipt.Receivables`؛ لا تُقرأ في سياق عقد البيع المدمج |

## دورة القراءة والكتابة

كل قراءة قائمة أو فلتر أو تقرير أو سجل تربط `denied$` بمتطلبها وسياق الوصول،
وتُلغى عند تبديل actor أو المستأجر أو الفرع أو سحب المنحة. تعاد bootstrap
للقراءات الممنوحة بعد regrant دون GET مكرر، ويُمسح الخيار المخفي وقيمته من
الطلب. الكتابات المرسلة (حفظ/حذف/إبطال/قرار اعتماد) تستمر حتى النتيجة ولا
يعاد إرسالها، لكن التأكيد المفتوح يعاد فحصه قبل الإرسال.

المحرر يميز بين View وEdit؛ لا تُقرأ اختيارات التحرير في View، ولا يفتح زر
الحفظ أو تحديث أو حذف بلا المتطلب الفعلي. التقرير والطباعة والتصدير قراءات
مشتقة من `Receipt.View` ولا تمنح عملية جديدة.

## الأدلة والحدود

المرجع الوظيفي Speed Receipts بتاريخ ٢٨ أكتوبر هو شاشة `tenant.crs_receipts`
ومتحكميها C1424 وC1419 وC1431؛ يثبت وجود القائمة والتحصيل والتخصيص والطباعة
والاعتماد، ولا يثبت قواعد خادم Sigma. المصدر الحالي هو `ReceiptController`
و`ReceiptService` ومكونات القائمة والمحرر وكتالوج `PermissionEndpointResolver`.
لا تغيير DTO/EF أو حسابات العملة والتخصيص؛ قبول المظهر والبيانات والتشغيل يبقى
تحقق مالك منفصلًا.

## استكمال المحرر والمصالحة — ٧ نوفمبر، مصدر فقط

تبقى مفاتيح المسارات الأساسية كما هي: View للقراءة، Create للإنشاء، وView
مع Update للتعديل. قراءات الحقول مستقلة حسب النوع والمصدر؛ لا تُحجب قراءة
إيصال محفوظ بافتقاد قراءات التحرير. متطلب المحرر الفعلي يتبع وضعه الحالي
بما فيه الانتقال إلى Edit من View، ويضم مفتاح سياق المصدر عند الإنشاء منه.

كل قراءة تابعة تستلزم متطلب المحرر ومفتاح endpoint الفعلي؛ لا يكفي إيقاف
الزر دون حراسة handler/stream. تظل مصادر الفروع وطرق الدفع وسياسة العملة
وتفاصيل الطريقة شروط جاهزية للحفظ، مع Receipt.Parties للطرف المستقل غير العام
أو Account.GetPostingSelect للإيصال العام. سياقات المصدر المثبتة تجبر طرفها
ولا تحتاج lookup بديلًا له. يحتاج مصدر LeaseAgreement إلى LeaseAgreement.View
ومصدر RentalAgreement إلى RentalAgreement.View، طبقًا لمسار GetByWithNavigationsId.
Bank.Lookup شرط اختيار البنك عند طريقة التحويل فقط، وRentalAgreement.Lookup
شرط اختيار اتفاق مستقل فقط. SettingsCommonModel.GetMySetting قراءة اختيارية
لتسميات مبلغ الكلمات، ولا تُستبدل بها سياسة الأرقام المالية.

لا تجلب View اختيارات التحرير أو الأطراف أو المرشحين للتخصيص أو تفاصيل طريقة
الدفع أو settings/policy؛ تستخدم قيم DTO المحفوظة وsnapshot للطباعة والعرض.
سحب منحة داخل السياق نفسه يحجب سطحها وportals ويحتفظ record/draft/عملة/صفوف
المرفقات والتخصيص؛ regrant يعيد فقط القراءة المفقودة/الملغاة والأهلية دون
استبدال edits أو تكرار detail GET مكتمل. تبقى outer triggers حية وتثبت
validators/القيم المشتقة المحلية حتى إذا بدأ المحرر بلا grant ثم استعادها.

لا يستطيع Save اعتماد اختيار أو تخصيص من مصدر مطلوب لم يعد ممنوحًا أو
جاهزًا؛ ولا تُسقط تخصيصات أو مرفقات أو معرفات مسودة بصمت لتجاوز نقص المنحة.
أفعال التخصيص المحلي تحتاج منحة Receivables ووضع الكتابة، وحوارها/تبويبها
المحجوب يحتفظ المسودة. حذف صف مرفق يحمل مسارًا يحتاج Media.DeleteMedia؛
إزالة صف فارغ تعديل محلي. hydration المرفقات المحفوظة ليست أمر إضافة مستخدم
ولا تُمنع بشرط editable الخاص به.

تغير actor/tenant/branch-access أو working context ينهي جلسة المحرر نهائيًا،
يلغي reads/confirm/print، ويمسح بياناته؛ لا إعادة إحياء عبر revision لاحقة.
تستمر كل كتابة/تنظيف أُرسلت حتى نتيجتها؛ نتيجة السياق القديم لا تحدث الجديد.
يُفحص الحذف بعد تأكيد مشترك كسول ثم يُرسل مستقلاً؛ لا يوضع denied$ على
delete/save/approval/void بعد الإرسال. dirty exit لا يتخطى المسودة أو pending
write عند denial، ويلغى قراره المفتوح بـfalse، ويظل discard محلي جديد ممكنًا.

تتبنى قائمة وتفاصيل Receipt مدخلات DocumentApprovalCycle الثلاثة الموجودة
لقراءة View وقرار View+ManageApproval وحجب انتهاء السياق. يدير المالك نفسه
revision recovery وحوار السبب. تبقى القراءة في list modal محلية فوق قناعه؛
القائمة تحتفظ بالموافقات/الإبطال أثناء منع منحة فقط، وتمنع مغادرتها أثناء
قرار/سبب/كتابة معلقة. سجلات القراءة واليومية والتقارير disposable ويمكن
إغلاقها عند سحب متطلبها؛ تُلغى طباعتها ومخرجاتها القديمة. تُخفى وتصبح inert
السطوح المحمية، وتغلق Select/DatePicker overlays عند تغير الوصول.

الأدلة الإضافية: الشرح الأصلي S075 (توليد إيصال مقدم عقد الإيجار ثم ظهوره
في قائمة المقبوضات وطباعته)، وشرح شاشة 04-receipts المؤرخ٢٨أكتوبر. قُرئ
بصورة منفصلة كود C1419 ومدخله ومفاتيحه ووظائفه في الدفعة الحالية؛ وفهرس
C1424/C1431 ومساراتها مثبتان في عقد الدفعة السابقة. مرجع Speed يصف دورة
تحصيل/تخصيص/طباعة، ولا يمنح أي مفاتيح Sigma أو قاعدة خادم مالية. الشكل هو
screen08 مستند مالي مع قائمة screen02؛ لا إعادة تصميم أو حسابات جديدة.
