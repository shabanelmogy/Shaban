## العقد والقرار

طُبق [العقد المجمد](LIMO_QUOTATION_ACCESS_CONTRACT_FREEZE.md). القائمة والعرض
والطباعة وإكسل بمنحة العرض. إنشاء العرض مستقل عن العرض، مع مصادر المحرر
الستة. التعديل يحتاج العرض والتعديل والمصادر نفسها. فلتر العميل اختياري؛
يبدأ الجدول بلا انتظاره، ولا يؤدي فشله إلى منع البحث العام.

| العملية | المنح المطلوبة |
|---|---|
| القائمة والتفاصيل والطباعة والتصدير | LimoQuotation.View |
| فلتر العميل | العرض مع Customer.Lookup |
| الإنشاء | LimoQuotation.Create مع مصادر المحرر |
| التعديل | العرض مع LimoQuotation.Update ومصادر المحرر |
| الحذف | العرض مع LimoQuotation.Delete؛ الحالة Pending |
| الاعتماد والرفض الداخليان | العرض مع InternallyApprove أو InternallyReject على المورد نفسه؛ الحالة Pending |
| اعتماد العميل ورفضه | العرض مع ApproveByCustomer أو RejectByCustomer؛ الحالة InternallyApproved |
| إعادة المراجعة | العرض مع LimoQuotation.Revise؛ الحالة InternallyApproved، والنتيجة Pending |

مصادر المحرر: Customer.Lookup وTripType.Lookup وLocation.Lookup
وTariffGroup.Lookup وSettingsCommonModel.GetMySetting
وCurrency.GetFinancialNumberPolicy. لا نفرض هذه المصادر كشرط على API
الكتابة نفسه؛ هي حزمة دخول المحرر الذي يستهلكها. يعلن الخادم اعتماديات
العرض للعمليات المحفوظة من PermissionPrerequisites، ويقرأها المرشح
والكتالوج معًا. أضيفت العمليات المخصصة الخمس إلى ReviewedPermissionOperations.
التفعيل غير مدعوم ويعيد 405، ولا يُعرض كمنحة قابلة للإسناد.

العرض التجاري مشترك داخل الشركة؛ لا يوجد له BranchId. موقعا الاستلام
والتسليم تعريفات Location وليسا فرعي حركة. تبقى هوية الشركة والصفوف الحية
محكومة بمصدر Repository.Query. لا نشتق فرعًا من الموقع ولا من الفرع الحالي.
تبقى القيود العامة لوصول الجلسة وإسنادات الفروع على حالها.

## المطابقة من المصدر

| الوجه | دليل المصدر والنتيجة |
|---|---|
| المسار | routing.ts:303 إلى limoquotation.routes.ts؛ القائمة والإنشاء والعرض والتعديل والتفاصيل مرتبطة بـ limo-quotation-access.ts في RouteAccessPolicyRegistry |
| أعمدة الجدول | No وCreatedAt وCustomerName وحالتا الاعتماد المشتقتان من Status |
| نموذج القائمة | LimoQuotationListVM: Id وNo وCreatedAt وCustomerId وCustomerName وStatus؛ الهوية والعميل والحالة تخدم الأفعال والمرشحات |
| المرشحات | quotationNo وcustomerId وfromDate وtoDate وinternalApproval وcustomerApproval وgrid؛ تقابل ApplyListFilters وApplyGridFilters |
| الحفظ | مصادر المحرر الفعلية وحمولته باقية، وملكية الضريبة والتحقق المالي في الخادم؛ لا تغيير في معادلات المبالغ أو AutoMapper |
| قراءات الخلفية | تفاصيل عادية وبالتنقلات تستخدم الإسقاط نفسه؛ GetAllWithNavigations يستخدم إسقاط القائمة، وGetManyWithNavigations يعيد مسار التصفية والصفحات نفسه |
| حالات الكتابة | الفحص والحفظ/الحذف/تغيير الحالة تحت ExecuteUniqueWriteAsync بمفتاح الشركة ونوع الكيان ومعاملة Serializable على المزود العلائقي؛ لا نتائج فحص قديمة بين طلبين مشاركين |
| الفشل | قراءات القائمة والمحرر تحوي قناتي فشل النقل وIsSuccess؛ أخطاء الكتابة تمر بالمعترض العام مع CAN_PRESENT_API_OUTCOME مقيد بمالك النتيجة |
| الترجمة | أعيد استخدام مفاتيح الرسائل والحالات الموجودة كاملةً؛ لا مفتاح مركب جديد |

تمنع الواجهة أفعال الصف غير الموجود في النتيجة الحالية أو المكتمل بالفعل.
تُلغى التأكيدات والقراءات والإخراج المعلق عند سحب الوصول، وتغلق القوائم
الملحقة بالجسم. يحتفظ المحرر بالمسودة عند سحب المنحة مؤقتًا في الجلسة
نفسها، ويعيد قراءة الحالة والمصادر قبل إعادة التمكين دون استبدال المدخلات
المعدلة. تبديل الحساب أو الشركة أو نطاق الفروع أو بدء جلسة دخول جديدة
ينهي السياق السابق؛ تجديد التوكن ضمن الجلسة نفسها لا ينهيه.

الكتابة المرسلة تستقر مستقلة عن إلغاء القراءة وعن تدمير المكوّن. تُحجب
رسالتها والتنقل عنها بعد انتهاء الملكية أو سحب الوصول، مع ختم النجاح لمنع
إعادة إرسال المسودة أو الصف القديم. إعادة المراجعة تفتح محرر التعديل بعد
قراءة الصف الجديد فقط إذا توافرت حزمة التعديل كاملة؛ خلاف ذلك تبقى بالقائمة.
يدعم محرر الإنشاء المستقل الرجوع إلى مسار مسموح بدل إجباره على قائمة محجوبة.

## المرجع الوظيفي والمالكون المشتركون

قورنت شاشة سبيد المؤرخة 2026-10-28، القسم 16-limousine، الشاشة
05-quotations، مع متحكم القائمة C0906 ومتحكم الإنشاء والتعديل C0905.
المطابق هنا القائمة والحقول الحالية والتصفية وحالات الاعتماد والرفض وإعادة
المراجعة والإخراج. تحويل العرض إلى رحلة وسبب الرفض وبقية تفاصيل سبيد الأوسع
تبقى فجوات وظيفية منفصلة عن تبني صلاحيات المسارات الحالية؛ لا نضيف لها منحًا
أو API غير موجودين ولا نزعم التكافؤ الوظيفي الكامل. لا قرار غامض في هذه
الشريحة يستدعي الرجوع التكميلي إلى أودو. لا صور جديدة مرفقة لهذه الشريحة.

الشكل المستخدم قائمة بمحرر مستند موجه بسبب الإجماليات والاعتماد، وفق UI13.
المالكون: FeatureTitle وFilterPanel وDataTable وFormSection وSummaryCards
وConfirmationDialogService وPrintSession وAccessViewPolicyService
وReferenceLookupBindings. طُبقت حراسة UI26 وعمر UI28؛ لا تعديل للأنماط
المرجعية أو غلاف الصفحة أو الحسابات المشتركة.

## المصادر والتحميل والأداء

| المصدر | التصنيف والعمر |
|---|---|
| Customer/GetSelect | ذاكرة المرجع المشتركة باختيار CustomerService؛ bootstrap محدود ثم watch منفصل، وكتابات المصدر الناجحة تنشر إبطال المصدر. تُحفظ تسمية الاختيار للمسودة داخل سياقها ويُزال الربط عند المنع أو التدمير |
| TripType/GetSelect وLocation/GetSelect وTariffGroup/GetSelect | مراجع مباشرة بلا cacheSelect opt-in؛ تُقرأ في تحميل المحرر، ولا ندعي اشتراكها في ذاكرة غير مفعلة |
| SettingsCommonModel/GetMySetting | استثناء إعدادات مشترك تستهلكه TaxSettingsService من CommonSettingsService؛ إعادة تحميل صريحة وتحديث المصدر يبطل مفتاحه |
| Currency/GetFinancialNumberPolicy | قراءة سياسة تشغيلية مباشرة ضمن التحميل الإلزامي، دون تحويلها إلى مرجع مخزن محليًا |
| القائمة والتفاصيل والإجراءات | بيانات تشغيلية مباشرة، لا تخزين نتائج عقود أو إجراءات كمرجع |

تحميل القائمة والخيارات الأولية والمحرر والحفظ والتصدير يستخدم مالك تقدم
الصفحة الموجود مع finalize متوازن. تحديث ذاكرة العميل المحتفظ ببياناتها
يبقى لدى مالكها المشترك. لا نافذة قراءة محلية إضافية. رؤية المؤشر والتوقيت
الفعلية تحتاج قبول التشغيل. يطلب المحرر مصادره بالتوازي، وتصدير القائمة
يمر بالصفحات حتى النهاية مع شرط الوصول على التركيب كله؛ لا استعلام لكل صف.
الاستعلامات/الإسقاطات تحت نطاق الشركة والسجلات الحية. لم تُقَس سرعة SQL أو
تُقرأ خطة تنفيذ. لا فهرس جديد مُقر؛ يلزم قياس مرشحات الشركة/العميل/التاريخ
مع الفهارس الحالية قبل اقتراح تغيير مخطط. لا هجرة مطلوبة من هذه الشريحة.

## أدلة التحقق والقبول المتبقي

مر فحص النحو لـ15 ملفًا وقالبًا، مع189 مسار استيراد محلي و241 اسمًا
مستوردًا بلا findings، باستخدام TypeScript createSourceFile وAngular
parseTemplate دون typecheck. مر تحليل نحو6 ملفات C# باستخدام Roslyn
المحمّل في بيئة الأدوات، وتحليل XML لثلاثة مشاريع، وفحص الحزم الثماني.
رُوجعت الفروق المحصورة في المستودعين والملفات الجديدة ومطابقة المنح
ومساراتها. فحص JSON وروابط هذا التسليم وعد الجرد ضمن الفحص النهائي.

أضيفت مواصفات مصدرية للقائمة والمحرر وشروط المسار وكتالوج الخلفية: دخول
بالعرض دون خيارات العميل، إلغاء تأكيد الاعتماد، استقرار كتابة مرسلة دون
إعادة، الاحتفاظ بمسودة create-only، استقلال الإنشاء عن العرض، وشرط العرض
للعمليات المحفوظة واستبعاد التفعيل. هذه المواصفات لم تُنفذ. لم يُشغّل بناء
أو اختبارات أو lint أو متصفح أو قاعدة بيانات أو هجرة أو commit أو نشر.
محاولتا التفويض السابقتان توقفتا بحد الاستخدام دون إنتاج ملفات؛ التنفيذ
والدمج والمراجعة المباشرة للجذر، ولا يوجد ادعاء مراجعة مستقلة مكتملة.

التجربة المجمعة المطلوبة:

- جرّب العرض فقط مع القائمة والطباعة وإكسل دون تحميل خيارات العميل.
- جرّب الإنشاء بمصادره دون العرض، ثم الرجوع إلى مسار مسموح.
- اسحب كل منحة إجراء أثناء التأكيد وتحقق من عدم إرسال الطلب.
- أرسل الحفظ أو الاعتماد ثم اسحب المنحة؛ تحقق من استقرار الطلب مرة واحدة
  دون نشر النتيجة أو إعادة الإرسال، ثم اقرأ الحالة الجديدة بعد استعادة الوصول.
- احتفظ بمسودة محرر ثم اسحب مصدرًا وأعده؛ راجع المدخلات والتسميات وحالة العرض.
- بدّل الحساب والجلسة والشركة/نطاق الفروع أثناء القراءة والطباعة والحفظ؛
  تحقق من عدم نشر نتائج السياق السابق. بدّل اللغة دون فقد المسودة.
- حاول عمليتي تعديل واعتماد متداخلتين؛ يُعاد التحقق من الحالة داخل القفل.
- جرّب API مباشرة بمنحة الإجراء دون View ثم بمنحتهما، وراجع رسالة الاعتمادية.
