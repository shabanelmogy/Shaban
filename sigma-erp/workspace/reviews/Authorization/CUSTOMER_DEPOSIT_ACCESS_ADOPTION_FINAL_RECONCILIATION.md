## ما نُفذ

- أضيفت سياسة المسار وقائمة البداية لـ`CustomerDeposit` مع متطلبي العرض والبحث
  الفعليين من `CustomerDepositController`.
- رُبطت القائمة والتقرير والتصدير والبحث بصلاحية العرض/البحث، وربطت قراءات
  العملاء والأنواع بالمفاتيح المستقلة مع إلغاء المراقبات عند سحب الصلاحية.
- رُبطت أفعال التمديد والتحويل بمتطلبات `GetActionContext` و`ExtendDeposit`
  أو `GetTransferAgreements` و`TransferDeposit`، مع إبقاء حالة الصف الخلفية
  جزءًا من قرار الإتاحة.
- أضيفت حراسة حوار الإجراء: إلغاء القراءات والتأكيدات عند تغير السياق، تعطيل
  المحتوى عند سحب المنحة، وإبقاء الكتابة المرسلة مستقلة مع منع الاستجابة القديمة
  من تحديث السياق الجديد.
- أضيفت اختبارات سياسة المسار وحياة القائمة وحوار الإجراء، وربطت المفاتيح
  بعقد الشاشة ودليل Speed. شملت تغطية التحويل المصدرية اشتراط اختيار الاتفاقيات،
  إلغاء القراءة المعلقة، حفظ الاختيار عند إعادة المنح، رفض اختيار فقد أهليته،
  واستمرار محاولة التحويل المرسلة بعد سحب المنحة.

## التعديل الخلفي والقرارات

صُحح تصنيف أربع عمليات في `BranchOperationRules`:
`SearchDeposits` و`GetTypes` و`GetActionContext` و`GetTransferAgreements`.
أسماؤها المخصصة كانت تجعلها تسجيل حركات؛ أصبحت قراءات WholeDocument تحتاج
استعراض فروع المستند كاملة. يظل `ExtendDeposit` و`TransferDeposit` تسجيلًا،
مع مفاتيح العملية وحالة المستند وفحص الخادم. أضيفت ست حالات Theory إلى
`tests/SiGma.BranchAccess.Tests/BranchOperationRulesTests.cs` دون تشغيل.
تطابق namespace الخاص بالمنتج والمستهلك ومراجع المشروع وإدراج المصدر المفصول
في مشروع الاختبارات فُحصت مصدرًا.

لم تتغير DTO أو mapping أو الحسابات أو المخطط. تبقى عمليات الاستخدام والرد
فجوة وظيفية معلومة؛ البحث المحدد في واجهة التطبيق لم يجد لها مستهلكًا حاليًا.
اعتمادها يحتاج دفعتها المالكة ولا يستنتج من وجود endpoints فقط.

## المطابقة والأدلة

| الاهتمام | المالك والمرجع | نتيجة المصدر |
|---|---|---|
| الشكل | قائمة مخصصة وخوار إجراء؛ screen01 وscreen08، وUI7/13/26/28 | سياسات فعلية للعمليات، وحارس exact لمسار القائمة دون فتح مسار غير معروف |
| الإظهار | AccessViewPolicyService وActionList وEditorDialog | السطح المحجوب hidden/inert؛ يغلق Select/DatePicker portals مع الاحتفاظ بالمحرر عند منع منحة فقط |
| عمر المسودة | contextReady وbootstrapNeeded وcontextInvalid | إعادة المنح تقرأ الأهلية وتحفظ edits؛ تغير سياق البيانات ينهي الحوار نهائيًا |
| التأكيد والكتابة | defer/defaultIfEmpty وcontextEnded | قرار discard كسول ينتهي بـfalse عند الإبطال؛ notifier لا يقطع كتابة أرسلت |
| المرجع الوظيفي | دليل Speed وقسم `2026-10-28/sidebar/18-vouchers/screens/05-deposits.md`؛ كود C1294 وC1299 قُرئ منفصلًا في الاكتشاف | البحث والتقرير والتصدير والتمديد والتحويل matched؛ الاستخدام والرد missing في الواجهة؛ لا استنتاج لصلاحيات الخادم من المرجع |
| المرجع المكمل | مدخل Odoo المحلي قُرئ | لا غموض وظيفي إضافي في هذه الدفعة يستلزم قراءة تفصيلية؛ لا ادعاء مطابقة Odoo |

أعمدة القائمة تقابل خصائص ListVM التالية دون تعديل:
`DepositNo, PaymentMethod, Date, ExpiryDays, Customer, CustomerCode, AgreementNo,
Status, Amount, UsedAmount, RefundedAmount, AvailableAmount`، مع `Id` للهوية
و`IsVoided/CanExtend/CanTransfer` لحالة الإجراء. الأرقام المالية تحت عقدها
القائم، وExpiryDays عدد صحيح، ولم تضف الدفعة حسابًا في الواجهة.

## الطلبات والتحميل والذاكرة

| الطلب الفعلي | التصنيف والمالك | الإبطال والتحميل |
|---|---|---|
| `Customer/GetSelect` عبر CustomerService | مصدر reference مشترك opted-in؛ BaseService + ReferenceLookupCacheService | bootstrap محدود ثم ReferenceLookupBindings.watch منفصل؛ writers الناجحة تبطل مصدر العميل وrefreshSelectList يبطل العملات التابعة أيضًا؛ إعادة revision تعيد التحقق دون cache محلية |
| `CustomerDeposit/Types` | قراءة تشغيلية مباشرة بلا opt-in | نجاح التحميل يحتفظ بالأنواع في القائمة؛ context أو سحب منحته يمسحها؛ فشل/Retry صريحان |
| `CustomerDeposit/Search` للقائمة | قراءة تشغيلية مباشرة | latest query عبر switchMap؛ denied$/accessChanged يلغي القراءة؛ start/end داخل defer/finalize |
| `CustomerDeposit/Search` لكل صفحات التقرير وإكسل | قراءة تشغيلية مباشرة، صفحات متسلسلة من ١٠٠ | مالك الصفحة العالمي نفسه؛ إلغاء كامل السلسلة عند سحب العرض أو تغير السياق؛ report/retry/print pending يمسحها المالك |
| `ActionContext/{id}` و`TransferAgreements/{id}` | سياق وأهلية مباشرة غير مخزنة في cache | forkJoin داخل الحوار؛ StateMessage المحلي؛ إلغاء القراءات القديمة وإعادة الأهلية عند المنح |
| `Extend/{id}` و`Transfer/{id}` | كتابة مستقلة داخل مالك الحوار | busy/disabled وبدء/إنهاء مالك الصفحة؛ لا denied$ بعد الإرسال؛ النتيجة تخص السياق الذي أرسلها فقط |

مسار القائمة يحمل `showPageLoading: true`، وReferenceLookupStatus يجمع bootstrap
العميل والأنواع ومراقبات المرجع في مالك الصفحة. حوار الإجراء يستخدم نطاقه
المحلي لقراءات bootstrap. يغلق المالك الاختيارات الملحقة بالجسم عند تغير
الوصول؛ ويحذف العميل والنوع غير الممنوحين من draft/applied filters والطلب
والتقرير والتصدير. فحص المصدر لا يثبت رؤية loader أو زمنه على التطبيق.

## الاستعلامات والأداء والفهارس

القراءة الحالية تحسب العدد ثم تعرض projection مرتبة تنازليًا بالهوية؛
pageSize مقيد بين ١٠ و١٠٠. التقرير وإكسل يجمعان الصفحات بحجم١٠٠، وحوار
التحويل يجمع السياق والاختيارات بصورة مستقلة. لا طلب لكل صف أضيف في هذه
الدفعة، ولا مقارنة زمنية منفذة.

يوجد فهرس `(SubscriptionId, BookingId)` وفهرس فريد مفلتر
`(SubscriptionId, OpeningBalanceDepositId)`، وعلاقة usage بالوديعة في مالك EF.
لم يظهر من توصيل المنح وحده احتياج مثبت لفهرس جديد. لا تغيير مخطط أو تكلفة
كتابة إضافية مقترحة. قبول المالك للأداء يحتاج قاعدة وحجم بيانات وفلاتر
متطابقة، وعدد الطلبات وSQL plans وزمن البارد/المحتفظ به؛ يظل ذلك pending.

## دليل التطبيق والمراجعة

حُدث `UserGuide/content/customer-deposits-topic.ts` بالعربية والإنجليزية،
ويصل إليه قارئ الدليل الموجود من مجموعة السندات ثم القبض والدفع
`vouchers-cash` عبر `invoice-guide.ts`. يشمل فصل العرض عن الفعل واختيارات
الفلاتر والفروع واستعادة المسودة وانتهاء سياقها.

راجع الجذر scoped diff لملفات الواجهة، وقرأ ملفات specs الجديدة مباشرة
لأنها untracked. ملفا الخلفية untracked أيضًا، ففُحص محتواهما مباشرة بدل
ادعاء diff غير موجود. المراجعة المستقلة قراءة فقط لم تجد finding محددًا
في CustomerDeposit؛ نبهت إلى ضعف تغطية transfer فأضيفت الحالات الثلاث أعلاه.
الوثائق محلية خارج المستودعين ولا يُدعى لها Git diff.

## الحدود والتحقق

لم تُشغّل build أو tests أو browser أو قاعدة بيانات وفق حدود Sigma الحالية.
يلزم تحقق المالك من مستخدم يملك العرض فقط، ومستخدم يملك التمديد، ومستخدم يملك
التحويل، وسحب المنحة أثناء الحوار، وتجربة فشل القراءة والـ Retry.

لا تحتاج هذه الدفعة إلى migration. العبارة السابقة «لا تعديل Backend»
كانت أوسع من النتيجة؛ التعديل الخلفي المحدود هو تصنيف القراءات أعلاه فقط.
مفاتيح الكتالوج والعقد المالي والمخطط ثابتة.

اقتراح رسالة الواجهة: `fix: adopt customer deposit access and dialog lifetimes`.
اقتراح رسالة الخلفية: `fix: classify customer deposit reads for branch viewing`.
لا commit أو push أو أوامر تشغيل أو قاعدة بيانات أو migration نُفذت في الدفعة.

نتيجة التحقق المصدرّي النهائي: scoped diff الواجهة فُحص كاملًا، والأنواع
والـtemplates والمسار ودليل الشاشة والمراجع المباشرة متوافقة ضمن العقد.
فحص whitespace للملفات المتتبعة خرج صفرًا مع تنبيهات تحويل LF/CRLF فقط؛
الـspecs وملفات Backend الجديدة فُحصت مباشرة لعدم وجود diff متتبع لها.
فحص الوصفات النهائي أعاد OK للحزم الثماني. لا build/tests/lint/browser/DB
نفذت، ولا تُنقل نتائج تشغيل دفعة سابقة إلى قبول هذه الدفعة.
