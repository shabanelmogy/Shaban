## المطابقة

| الجزء | التنفيذ |
|---|---|
| route | سياسة `/MonthlyPosting` تتطلب `MonthlyPosting.Prepare` ومسار دخول أولي |
| prepare | حراسة الزر و`prepare()`، وإلغاء القراءة عند سحب المنحة أو تغير السياق |
| post | حراسة التأكيد والطلب بمتطلب Prepare + Post، مع الحفاظ على الكتابة المرسلة |
| export/retry | التصدير وإعادة المحاولة لا يعملان دون القراءة؛ السطح محجوب عند فقد الوصول |
| الخلفية | `MonthlyPostingController` يحمل metadata صريحة لـ Prepare وPost |
| الدليل والجرد | أضيفت خطوات الصلاحيات ودخل المسار إلى دليل الاستخدام والجرد |

## التحقق والحدود

لا تغيير query/schema/index أو حساب مالي. أُجريت فحوص المصدر والـJSON والوصفات
والوثائق و`diff --check` وmerge markers؛ لم تُشغّل الاختبارات أو build أو lint
أو browser أو DB أو migrations.

رسالة واجهة مقترحة:

`feat(authorization): adopt monthly posting access guards`

## تصحيح ٨ نوفمبر

تستبعد الخدمة القالب المرتبط بقيد أساس وتولّد القيد الشهري دون فرع على الرأس
أو السطور. لذلك يخضع المسار والتحضير والترحيل لسياسة مدير الشركة في الواجهة
والخادم. مفاتيح العمليات تبقى للتعريف في الكود، وتُستبعد من المنح القابلة للإسناد.
تغير المستخدم أو نطاق الفروع يلغي التأكيد أو القراءة. تعيد الموافقة فحص السياق
والمنحة قبل بدء الترحيل، ويظل الطلب المرسل مستقلًا عن إلغاء التأكيد.
