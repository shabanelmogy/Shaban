## نتيجة المصدر بعد الدمج

اكتملت الشريحة الموجودة في المصدر، وانتهت مراجعة الجذر وتدقيق الخلفية
المستقل وتبادل تدقيق المحررين دون ملاحظة تنفيذ مؤكدة باقية. رُقي صف
MasterAgreement وحده؛ لا ادعاء بقبول تشغيل أو إقفال عقود الإيجار العامة.

| المسار | المنح والمالكون | الدليل الحالي |
|---|---|---|
| القائمة والتفاصيل والتصدير | RentalMasterAgreement.View | [تسليم القائمة](RENTAL_MASTER_AGREEMENT_LIST_HANDOFF.md)، وسجل المسارات ومتحكم الخادم |
| إنشاء الماستر | RentalMasterAgreement.Create + RentalQuotation.View | لا يشترط View للماستر؛ مصدر عرض معتمد وعميل مطابق ومنع تكرار |
| الاعتماد | View + ManageApproval | حالة غير معتمد وقراءة المصدر والعميل ضمن الشركة |
| الحذف | View + Delete | حالة غير معتمدة وفحص وجود توابع مستقل عن نطاق إخراجها |
| تحديث API والتفعيل | View + Update؛ التفعيل405 وغير قابل للإسناد | لا يضاف مسار تعديل واجهة غير موجود |
| إنشاء عقد من البند | منحة RentalAgreement.Create وعرض الماستر ومصادر المحرر | مدخلات عمر المصدر والمنحة اختيارية في محرر العقد الحالي، دون ترقية وحدة العقود العامة |

## المراجع والتوافق

قُرئ مدخل الوثائق وفهرس المراجعات ومهارة Sigma والكتاب الرئيسي وكتل
UI26/28/2/7/13/22/29 وكتالوج02 ومرجع Workshop/Job للقائمة. قُرئ شرح
S269 من نص المكتبة، ودليل دورة الإيجار وملف شاشة الماستر ومتحكم C0950
بتاريخ28أكتوبر. يطابق فصل العرض والاعتماد والتصدير وفتح العقد من الماستر
المسار الحالي. طباعة الماستر والتسليم ومصفوفة فتراته موثقة كفجوات وظيفية
مرجعية خارج إضافة صلاحيات لوظائف قائمة؛ لا ادعاء أنها نُفذت أو حُذفت.
مدخل Odoo متاح؛ لا غموض جديد يحتاجه لتحديد منح محلية.

الأعمدة الفعلية: رقم الماستر والتاريخ والعميل وكوده ومرجع العرض والحالة.
عقد الخادم: id/no/date/customerName/customerCode/quotationNo/approvalStatus؛
masterAgreementNo مشتق في الواجهة فقط. لا تغيير مالي أو سياسة تسعير أو
توزيع أو حجز وحدات مرقمة، ولا مخطط جديد أو هجرة مطلوبة.

## الملاحظات التي أُقفلت في التكامل

- فحص الحذف يتجاوز مرشح الفرع للوجود البنيوي فقط، مع قيد صريح للشركة
  والحذف والماستر؛ يمنع التابع الحي الحذف دون إخراج بياناته. صُحح النظير
  المؤكد في Lease أيضًا في [تقرير مستقل](LEASE_MASTER_AGREEMENT_DELETE_SCOPE_REPAIR.md).
- ربط عقد الإيجار الفردي أو الحمولة الجماعية المطبّعة يحتاج قراءة الماستر
  وحالته النشطة والمعتمدة والعميل المطابق. لا مخطط بند جديد أو استهلاك وحدة.
- هوية عرض السعر المحجوب لا تتسرب من QuotationId الخام؛ GetView يعيدهاnull
  عند غياب المصدر المقروء، والتفاصيل العامة تسقطها من المصدر المقيد نفسه.
- مصدر الطفل لا ينشر أثناء انتظار إعادة تحقق الأب بعد سحب View وإعادتها؛
  تبقى المسودة المركبة، ويتحقق الطفل من Approved في القراءة الجديدة.
- يعود مستخدم Create-only إلى عروض الإيجار عند غياب View للماستر؛ لا
  تسريب لمعلمات جلسة منتهية في مسار العودة. يمكن تجاهل مسودة محلية جديدة
  بعد انتهاء الممثل/المصدر دون تمكين الكتابة، ويُلغى أي قرار سابق للانتهاء.
- يثبت نجاح الحفظ المرسل قبل حجب النتيجة، ولا يكرر الإنشاء عند إعادة المنح.
  لا تدمير للحوار بسبب سحب منحة مؤقتة، ولا إعادة تعرفة مكتملة فوق المسودة.

ناقش التدقيق وضع رأس الماستر المشترك؛ ثُبت قراره صراحة في ملحق العقد.
وسُحبت ملاحظة افتراضية عن تصنيف الاعتماد بعد إثبات مالكه الأساسي
DocumentApprovalEndpointRules. لا metadata إضافية أو فرع مفترض للرأس.

## التحميل والكاش والأداء

القائمة والتصدير والأفعال وصفحة الأب تستخدم مالك التحميل العام وفواصل
finalize؛ خيارات مرشح العملاء عبر ReferenceLookupStatus، وقراءات الطفل
تحت نطاق EditorDialog المحلي. تُغلق البوابات المؤجلة عند انتهاء الوصول.
اختيارات العملاء والبلدان تستخدم مالكي الكاش الحاليين مع finite bootstrap
ثم watch وunbinding وإعادة محاولة؛ الإعدادات تحت مالكها الحالي والتعرفة
والسعة والمصدر التشغيلي قراءات مباشرة، دون كاش جديد أو HTTP للصلاحية لكل صف.
تفاصيل الطلبات ودورة الإلغاء والإبطال في التسليمات الثلاثة.

القائمة Count ثم projection صفحي بحد200 وترتيب ثانوي ثابت؛ المصدر المجمع
بعدد قراءات محدود وأسماء داخل الاستعلامات، لا استدعاء لكل بند. بقيت فهارس
العلاقات الحالية؛ لا اقتراح فهرس جديد دون خطة SQL وأحجام واقعية. لم تُقاس
السرعة أو حركة الشبكة؛ مقارنة cold/warm وخطة التنفيذ وIO للمالك.

## التحقق والملفات والدليل

شمل فحص النحو19ملفًا/قالبًا في النطاق، و226مسار استيراد محلي و287اسمًا
مستوردًا مقابل المنتج، دون تشخيصات. هذه قراءة/تحليل مصدر لا typecheck
أو تشغيل compiler للتطبيق. فُحص JSON الإعداد والجرد، وXML مشروعات
Helpers/DataAccess/Business/ViewModels/ServerAPI/BranchAccess.Tests، ومراجع
namespaces والأنواع والخرائط والقالب، وscoped diff في المستودعين وملفات
untracked ذات الملكية. حزم الوصفات الثماني سليمة؛ لا markers أو whitespace
مؤكدة في النطاق. المواصفات Angular وxUnit مكتوبة وغير منفذة.

أضيف الملفان التشغيليان الجديدان إلى files الصريحة في tsconfig.app.json،
دون تضمين الاختبارات أو include واسع. دليل المستخدم العربي والإنجليزي في
UserGuide/content/rental-guide.ts تحت موضوع Master agreements ورابط
MasterAgreement في دليل وحدة الإيجار الحالي. يشرح المنح والفروع والمسودة
والعودة وإنشاء العقد؛ لا حاجة لمسار دليل جديد. الواجهة والبصرية لم تُختبرا.

ملفات التنفيذ: قائمة الماستر ومحرر الأب والمسارات والخدمة والمتطلبات؛ محرر
عقد الإيجار المضمّن وخدمته ومتطلبات فتحه؛ سجل سياسة المسار وtsconfig ودليل
التطبيق؛ خدمة/متحكم/خرائط/DTOs الماستر ومواضع التصنيف والحراسة، وموضع
تحقق ربط الماستر في خدمة عقد الإيجار؛ وفحص حذف الماستر المحدود في Lease.
تسجل التسليمات أسماء الملفات والمواصفات كاملة. لم تُعدل تغييرات المستخدم
والزملاء غير المرتبطة أو snapshot أو migrations في هذه الشريحة.

استُخدم ثلاثة وكلاء بملكيات مستقلة للخلفية والأب والطفل وفق قواعد Sigma،
باستخدام النموذج gpt-5.6-sol؛ استفادت مراجعة المصدر من التوازي بعد تجميد
العقد، وبقيت القائمة والتكامل والتوثيق والقرار النهائي عند الجذر. تبادل
الأب والطفل التدقيق، ودقق الطفل الخلفية، وراجع الجذر الفروق والنتائج.

لا Add-Migration مطلوب. رسالتا commit مقترحتان فقط:
`feat(rental-master-agreement): enforce scoped access and source lifecycle`
للخلفية، و`feat(rental): complete master agreement access adoption` للأمامية.
لا commits أو push أو نشر نُفذت.

## الجرد ونقطة الاستكمال

الجرد١٣١مؤكدًا و٧١محدد المورد و٥٧قيد التحقق وبندان للسياق وبندان بديلان
=٢٦٣؛ المتقاعد التاريخي٧ ضمنbaseline. رُقي MasterAgreement فقط، ولا توجد
ترقية لقائمة RentalAgreement أو حواراتها العامة من إدماج إنشائها هنا.
التالي: عقود الإيجار العامة بقائمتها ومحررها وحواراتها، وفق طلبات كل عملية.

## القبول التشغيلي الباقي للمالك

جرّب بحساب مدير الشركة ثم حساب عرض فقط، وإنشاء ماستر من عرض فقط دون
عرض الماستر، وحساب له منح الاعتماد والحذف كل على حدة. تحقق من غياب
الخيارات غير المسندة، وحفظ الفروع، ومنع الطلب المباشر بلا منحته. أثناء
فتح المحررين اسحب منحة مطلوبة وأعدها، ثم بدّل الممثل أو المصدر، وتأكد من
حفظ المسودة عند السحب المؤقت وحجب السياق المنتهي. أرسل حفظًا واسحب المنحة
أو غادر؛ يجب ألا يتكرر الحفظ أو تنشر نتيجته في سياق مستخدم آخر.

التشغيل والاختبارات والبناء والقياس المرئي/الشبكي/SQL باقية؛ لا تساوي
فحوص النحو والاستيرادات والـdiff قبولًا تشغيليًا. لا DB أو migrations أو
commits/push/deploy في شريحة الصلاحيات الحالية.
