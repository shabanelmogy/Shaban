# عقد تبني وصول قائمة ومحرر المدفوعات

| البند | القيمة |
|---|---|
| Status | Frozen |
| Owner verification pending | yes |
| التاريخ | ٢٠٢٦-١١-٠٧ |
| النطاق | `/Payment` القائمة، `create` و`view` و`edit`، والمحرر المالي وإجراءات الاعتماد والسجل والحذف والإبطال |
| المستثنى | `PaymentDetail` القديم غير المرتبط بمسار القائمة، schema، migrations، واختبارات التشغيل |

## متطلبات الوصول

| السطح | المتطلب |
|---|---|
| القائمة والقراءة وفتح المستند وسجل الاعتماد والسجل | `Payment.View` |
| الإنشاء | `Payment.Create` مع `Branch.Lookup` و`Customer.Lookup` و`Supplier.Lookup` و`PaymentMethod.Lookup` للمحرر |
| التعديل | `Payment.View + Payment.Update` مع اختيارات المحرر |
| الحذف | `Payment.View + Payment.Delete` |
| قرارات الاعتماد | `Payment.View + Payment.ManageApproval` |
| الإبطال | `Payment.View + Payment.Void` |
| فتح القيد المرتبط | `JournalVoucher.View`؛ زر الرابط لا يظهر بدونه |
| رفع/حذف المرفق | صلاحية السطح الحالي مع `Media.UploadMedia` و`Media.DeleteMedia` عبر المالك المشترك |
| العملة | متطلبات العملة التشغيلية الحالية عبر `DocumentCurrencyComponent`؛ لا قراءة مستقلة خارج مالكها المشترك |

## دورة القراءة والكتابة

تتوقف قراءة القائمة والمحرر والاختيارات والسجل والاعتماد عند سحب المتطلب أو
تبديل actor/المستأجر/سياق الفرع، وتمسح النتائج القديمة وتعيد bootstrap عند
إعادة المنح. لا تطبق حراسة الوصول على كتابة أُرسلت بالفعل؛ يعاد فحص المنح بعد
التأكيد وقبل الحذف أو الإبطال أو قرار الاعتماد. يظل فحص الفرع وسياق المستند
على الخادم هو المصدر الحاكم.

## الأدلة والحدود

مرجع Speed المدفوعات في تحليل الورشة والتمويل بتاريخ ٢٨ أكتوبر يثبت دورة
الإنشاء والتخصيص والاعتماد والسجل، ويحدد متحكمات `payments.viewModal` و
`payments.createOrEditModal` وواجهات `getPaymentForView` و`getPaymentForEdit`
و`createOrUpdatePayment` و`approvePayment`. قورنت هذه الأدلة مع
`PaymentController` و`PaymentService` وكتالوج الصلاحيات الحالي ومكونات
القائمة والمحرر في Sigma. المرجع لا يثبت قواعد خادم Sigma التفصيلية أو
المطابقة التشغيلية؛ لذلك تبقى هذه خارج ادعاء التحقق.

## تعديل التدقيق المصدرّي — ٧ نوفمبر

ثبت من المحرر الحالي أن سياسة الأرقام المالية شرط للإنشاء والتعديل، بالإضافة
إلى اختيارات الفروع والعملاء والموردين وطرق الدفع. لذلك تتطابق متطلبات أزرار
القائمة وحارس المسار ومتطلب المحرر: الإنشاء يحتاج `Payment.Create` مع المفاتيح
الأربعة و`Currency.GetFinancialNumberPolicy`؛ والتعديل يحتاج `Payment.View`
و`Payment.Update` مع المجموعة نفسها. تبقى فلاتر القائمة اختيارية، ولا تضاف
هذه المفاتيح إلى قراءة مستند محفوظ فقط.

عند سحب عرض القائمة يُخفى سطحها ويصبح inert مع الاحتفاظ بالحالة داخل مالكه،
وتُغلق بوابات الاختيارات والتاريخ الملحقة بالجسم عند تغير الوصول. لا تبقى
خيارات مصدر غير ممنوح معروضة، وتُصفى هوياته من الطلب التالي. يحتفظ المحرر
بالمسودة والمستند والعملة عند سحب منحة داخل السياق نفسه، ويعيد bootstrap
المطلوب عند إعادتها؛ أما تغير المستخدم أو الشركة أو سياق الفرع فينهي عمره.

رابط القيد أو الشيك يحتاج صلاحية القراءة **وموافقة سجل سياسات مسار الوجهة**.
حُذف فتح مسار اليومية العام؛ تبني القراءة وحدها لا يفتح مسارات الإنشاء أو
التعديل. تظل الوجهات غير المتبناة مغلقة للمستخدم العادي حتى دفعتها الكاملة.
هذا التعديل يصحح توصيل المتطلبات والعمر، ولا يغير قاعدة مالية أو صلاحية خلفية.

## تكملة مالك الاعتماد المشترك في الدفعة نفسها

تتبع السبب بيّن أن إلغاء adapter لقراءة الاعتماد لا يغير هوية مدخلات
`DocumentApprovalCycleComponent`؛ لذلك لا تعود القراءة المركبة تلقائيًا بعد
إعادة المنح أو revision. كما أن حوار سبب الرفض/إلغاء الاعتماد ملحق بالجسم
ولا يرث حجب الأب. تمتد الدفعة إلى هذا المالك المشترك لحل السبب فيه، مع
الإبقاء على توافق مستهلكيه غير المتبنين.

العقد: مدخل اختياري لمتطلب القراءة `accessRequirement`، وآخر لمتطلب القرار
`decisionRequirement`، ومدخل حجب دائم من الأب `accessBlocked` عند انتهاء سياقه.
تحافظ القيم الافتراضية على سلوك المستهلك غير المتبني. المستهلك المتبني يمرر
مفاتيحه الفعلية؛ لا يستنتج المالك resource أو فعلًا من اسم الشاشة.

تُلغي القراءة المحدودة عند سحب منحتها أو تغير سياق البيانات. يؤدي تغير
revision داخل السياق إلى إبطال القراءة واستعادتها عبر مالك الاعتماد نفسه
بمجرد أن يسمح الوصول وينتهي انشغال القرار، مع منع تكرار GET بعد استقرار
النتيجة. حجب القراءة يخفي ويجعل السطح inert؛ وحجب القرار يحجب حوار السبب
مع الاحتفاظ بالمسودة في السياق نفسه. تنتهي التأكيدات المفتوحة عند سحب
متطلبها، ويظل discard محلي جديد ممكنًا بعد denial.

يُفحص القرار بعد التأكيد وقبل الإرسال، ولا تُلغى كتابة أُرسلت بسبب سحب
منحة. نتيجتها صالحة فقط لهوية المستند وسياق الإرسال؛ تغيير سياق المستخدم
أو الشركة أو الفروع ينهي النسخة المركبة ولا تعيدها revision لاحقة. رابط
مساحة عمل الموافقات يتبع سجل سياسات الوجهة للمستهلك المتبني. حوار القائمة
يستخدم `localReadProgress` لأن overlay يحجب loader الصفحة. لا API أو مفتاح
صلاحية أو حساب أو مخطط جديد من هذا التصحيح.
