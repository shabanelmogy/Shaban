## النتيجة المصدرية

| الاهتمام | النتيجة |
|---|---|
| متطلب المسار | Create يستهلك Create واللوكات والإعداد والتعريفة المجمدة؛ View يستهلك View فقط؛ Edit يستهلك View وUpdate ولوكات التحرير وتعريفة الحجز التي يستدعيها تغيير المركبة/الفترة فعليًا، دون مفتاح الإعداد غير المقروء في Edit. المصدر المضمّن يحتفظ بمتطلب الأب الدقيق ولا يُخفض إلى متطلب المسار العام. |
| عمر الممثل والمستند | تُلتقط هوية الممثل ووضع/هوية المستند عند التركيب. تبدل الممثل أو هوية المستند ينهي الجلسة نهائيًا؛ A→B→A لا يعيدها. |
| السحب وإعادة المنح | سحب نفس الممثل يلغي قراءات التفاصيل واللوكات والتعريفة والتركيز والتوليد والقرارات المعلقة، ويغلق portals ويعطّل النموذج. إعادة المنح تعيد القراءة المطلوبة؛ Edit/Create يحتفظان بالمسودة والاختيارات الحالية. |
| View | لا يطلب لوكات المركبات أو الطرازات أو العملاء أو السائقين أو الموظفين أو أنواع البنود أو إعداد الضريبة. تسميات العرض تأتي من Detail DTO وتُدمج كخيارات محفوظة معطلة. |
| الانتقال إلى Edit | زر Edit لا يظهر ولا ينفذ إلا عند تحقق متطلب Edit الكامل، مع بقاء حارس المسار العام عند مالكه في registry. |
| الحفظ | Create وUpdate يمران `HttpContext` يحمل `CAN_PRESENT_API_OUTCOME`. الطلب المرسل مستقل عن destroy/denial، ونجاحه يُثبّت `saveCompleted` قبل محاولة النشر، فيمنع الإعادة بعد استعادة المنحة. النتيجة المحلية والعامة لا تنشر بعد انتهاء الممثل/المستند/المنحة. |
| MockData والتركيز | متطلب المحرر العام، ودالة السماح، وإشارة الإلغاء تمر إلى MockData؛ `focusField` يستخدم نفس العمر. |
| الصفوف والتأكيدات | قرارات إزالة الصفوف وقرار تجاهل المسودة قابلة للإلغاء عند انتهاء الوصول. يبقى تجاهل المسودة المحلي متاحًا بعد المنع، وقبوله ينهي جلسة المحرر. قواعد منع مخصصات المصدر المضمّن بقيت كما هي. |
| الطباعة | الطباعة وطلب `?print=true` لا ينشران بعد سحب View أو تبدل السياق؛ View لا ينتظر لوكات تحرير. |
| المسارات المغلقة | أضيف حارس الخروج المتسخ لمساري `view/:id` و`details/:id` في القائمة المغلقة؛ المسارات النشطة كانت تملكه بالفعل. |

## أدلة UI2 وUI22 وUI29

- تستخدم لوكات Create/Edit مالكي المصدر الحاليين و`ReferenceLookupBindings`؛
  إعادة المنح تعيد bootstrap وتحافظ على الخيار المحفوظ والمسودة. View لا يتبنى
  أي lookup، لذلك لا يوجد طلب أو watch أو cache خاص به.
- قراءات الصفحة والتعريفة والحفظ غير المضمّن تبقى تحت عداد الصفحة الحالي،
  وتُفرج في `finalize`. المصدر المضمّن يحتفظ بمالك حالته المحلي. لا تمتلك
  الشاشة loader جديدًا أو مسارًا صامتًا جديدًا.
- لم يتغير عدد الطلبات الطبيعي لـ Create/Edit. خُفض View مصدرًا بإزالة كامل
  bootstrap التحرير غير اللازم. هذا دليل حدود طلب فقط وليس قياس أداء.
  القياس الشبكي والزمني التشغيلي معلق للمالك.
- هذا النطاق الأمامي لا يغير استعلامًا خلفيًا أو مخططًا؛ لا يوجد اقتراح index
  مصدره تغيير المحرر، وتبقى مراجعة SQL plan غير منطبقة هنا.

## المواصفات المصدرية غير المنفذة

وُسعت مواصفات `master-agreement-source-access.spec.ts` لتغطي:

- المفاتيح الدقيقة لـ Create/View/Edit مع بقاء عقد المصدر المضمّن؛
- View بلا لوكات تحرير وإلغاء قراءة التفاصيل عند السحب؛
- استعادة لوكات Create لنفس الممثل مع بقاء المسودة؛
- الانتهاء النهائي في A→B→A.

وتحتفظ المواصفات القائمة بتغطية المصدر المضمّن للتعريفة أثناء debounce،
MockData، تأكيد الصف، تجاهل المسودة، وحراسة نتيجة Create المرسلة. حُدث إعداد
`details.component.spec.ts` ليمنح متطلب Create الصريح بدل الاعتماد على bypass.
لم تُشغّل المواصفات أو فحص الأنواع وفق الحد المصدري.

## فحص الفرق والمعلقات

- روجع فرق Git المحدد داخل مستودع Angular فقط، وشُغّل `git diff --check`
  على الملفات المملوكة دون أخطاء؛ التحذير الوحيد هو تحويل LF إلى CRLF لاحقًا.
- طُوبق توقيع `LeaseAgreementService.update(payload, context?)` الموجود مع
  الاستهلاك الجديد، وفُحصت المسارات والاستيرادات وعلامات الدمج ضمن النطاق.
- لم تُشغّل build أو tests أو typecheck أو lint أو متصفح أو قاعدة بيانات أو
  migrations أو commit/push/deploy.
- يلزم قبول المالك المجمع: سحب/إعادة منح حي في Create/View/Edit، تبدل الحساب
  والـid على route مع reuse، تراكب loader، إلغاء MockData والتركيز والـportal،
  ونجاح/فشل Create وUpdate المرسلين بعد السحب.
- لا تغيير مخطط ولا حاجة إلى Migration. لا يعلن هذا التسليم اكتمال وحدة
  اتفاقيات الإيجار أو التطبيق؛ الدمج والدليل والجرد وبقية الحوارات عند الجذر.
