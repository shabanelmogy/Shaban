# عقد صلاحيات أنواع المركبات وترتيب مجموعاتها

| البند | القيمة |
|---|---|
| Status | Frozen |
| Owner verification pending | yes |
| التاريخ | ٩ نوفمبر ٢٠٢٦ |
| النطاق | `/FleetVehicleType` والقائمة ومحرر النوع وحوار ترتيب المجموعات والصورة |

الشكل قائمة مرقمة بمحرر حواري ذي حقول وتبويبات، وحوار مستقل لحفظ أرقام
ترتيب المجموعات. الخلفية تعريف عادي داخل الشركة، وليست حركة فرع.
تطبق حدود الفرع العامة للجلسة، ولا تُنشأ صلاحية فرع على تعريف مشترك.

| السطح أو الطلب | المتطلب |
|---|---|
| القائمة والرابط والبحث والمرشحات والصفحات وتفاصيل النوع | `VehicleType.View` |
| الإنشاء | العرض و`VehicleType.Create` |
| التعديل والانتقال من العرض إلى التعديل | العرض و`VehicleType.Update` |
| الحذف | العرض و`VehicleType.Delete` وشروط الاستخدام الخلفية |
| فتح المجموعات وقراءتها | العرض و`VehicleType.GetGroups` |
| تعديل أرقام الترتيب وحفظ المجموعة | قراءة المجموعات و`VehicleType.UpdateGroupNo` |
| رفع صورة جديدة | متطلب محرر النوع و`Media.UploadMedia` و`Media.DeleteMedia` عبر مالك الرفع القائم |
| إزالة صورة أو بدء تنظيفها | متطلب المحرر للإزالة المحلية، ومنحة `Media.DeleteMedia` لكل DELETE فعلي جديد |

يحمل الخادم منح CRUD الموروثة، وعمليتا المجموعات مثبتتان في
`ReviewedPermissionOperations` والـcontroller والخدمة. لا يحتوي طلب
إنشاء النوع أو تعديله `GroupNo`؛ لا يوجد مسار تعديل خفي لأرقام الترتيب
داخل حفظ النوع. تبقى حقول حالة الحجز وعدم النشاط ضمن عقد حفظ النوع
القائم، ولا تُخترع منح حقول منفصلة. لا هجرة أو حساب أو رد جديد.

الأرقام والسعات أعداد صحيحة وفق عقدها الحالي. تعدادات التصنيف والرسوم
المخططية محلية؛ لا طلب اختيارات خارجي لازم لمحرر النوع. قراءة القائمة
والتفاصيل والمجموعات تشغيلية مباشرة، دون توسيع مخبأ مرجعي جديد.
تظل خدمات التعرفة المستهلكة لـFleetVehicleTypeService بعقودها القائمة؛
تمرير سياق HTTP للكتابات اختياري ويحافظ على كل المستهلكين.

يُحفظ المحرر مركبًا عند سحب الوصول مع حجب المضيف والمنافذ المنفصلة.
تُلغى القراءات والتأكيدات المنتهية وتُعاد القراءات الأولية الناقصة عند
إعادة المنح دون الكتابة فوق مسودة. حوار المجموعات يدعم العرض فقط.
يُمنع الحفظ قبل تحميل التفاصيل أو المجموعة، وتُراجع هوية الصف بعد
التأكيد وداخل المعالج. تغادر القائمة عبر CanDeactivate للمحرر المفتوح.

يبقى الحفظ والحذف المرسلان مستقلين مع سياج نشر محلي وعالمي بسياق HTTP.
تظل نتيجة الحفظ الناجح مثبتة لمنع إعادة الإرسال ولو حُجبت رسالتها.
يستخدم المرفق DocumentUploadTracker وFileField ومدخل permission القائم؛
لا تُلغى كتابة بسبب سحب صلاحية العرض، ولا يُحذف ملف من حساب بديل.
كل تنظيف جديد يحتاج منحته الحالية، ويحفظ الفشل لإعادة المحاولة دون
ادعاء نجاحه. يُتاح التخلص المحلي من المسودة بعد الرفض مع إلغاء أي
قرار قديم عند انتهاء سياقه. لا يتكرر حفظ عند إعادة محاولة التنظيف.

الأدلة المقروءة: شرح سبيد الأصلي `S053`، وشاشة
`08-fleet/02-vehicle-types` والمتحكمان `C1217/C1218` من لقطة ٢٨ أكتوبر،
ومصدر سيجما ومساره وخدمته ونماذج طلباته. يتتبع عامل المحرر أيضًا
`C1216` لحدود تبويباته. يدعم المرجع التصنيف والرسوم وترتيب المجموعات؛
لا يقرر مفاتيح سيجما أو حقولًا مفقودة أو تحقق خادمها. قوائم الفحص
والصور الإضافية التي لا يملكها عقد سيجما الحالي فجوات وظيفية مستقلة،
وليست أفعالًا جديدة تُنشأ ضمن تبني الصلاحيات. لا فجوة مفاهيمية تستدعي
تغيير العقد بأودو بعد هذا الفحص.

الجذر يملك القائمة والمسار والخدمة المشتركة وخريطة المنح والجرد والدليل
والتكامل. عامل أول يملك ملفات details فقط، وعامل ثان ملفات manage-groups
فقط. الجرد والتسليم النهائي عند الجذر. الفحص مصدري؛ لا بناء أو اختبار
أو lint أو متصفح أو قاعدة بيانات أو هجرة أو commit أو نشر.

## توضيح تكامل مالك التنظيف — ٩ نوفمبر

أثبتت مراجعة المصدر وجود إلغاء teardown بعد `switchMap(work)` داخل
DocumentUploadTracker.cleanup، مما يلغي DELETE أُرسل بالفعل. يصححه
الجذر في المالك المشترك: ينتهي انتظار الرفع عند هدم المحرر، ولا يبدأ
عمل تنظيف جديد بعد الهدم، بينما يظل DELETE المرسل مستقلًا حتى نتيجته.
تُحجب callbacks الواجهة القديمة عند المستهلك. عمر POST الخاص بالرفع
نفسه يبقى عند هدم tracker وفق UI18؛ لا يتغير إلى طابور دائم أو تنظيف
من حساب بديل. يُوثق الفرق في UI18 والمهارة مع مواصفتي المصدر، دون
ادعاء تشغيلهما أو تغيير منح Media ونطاق حذفها.
