## العقود المستهلكة

تستمر ملكية فروع المستندات وفق العقود المجمدة. التحويل البنكي يمكن أن يضم مصادر من عدة فروع، ويحتاج عرض كل فروعه وحق التسجيل على كل فروع أثره. يحافظ الإيداع النقدي على المسودة داخل جلسة الحساب الأصلية، ويؤكد قراءة السجل الحالية قبل إعادة عرض بيانات محفوظة.

أُقفل اختلاف النقل في ودائع العملاء بربط وسائل القراءة المدعومة بمنحتي العرض والبحث، وتصنيفها قراءات فروع عرض. اختيار وجهة تحويل الوديعة يتقاطع مع فروع التسجيل. يعتمد التحقق من الحقول المقبولة على حدود القوائم الفعلية، ويمنع خصائص الكيانات الداخلية والعلاقات غير المعتمدة في المرشحات والفرز.

تحتاج مرشحات حالة الاتفاقية في ملف العميل، وحالة أو نوع الاتفاقية في التحصيل، عرض عقود الإيجار والتأجير معًا. يعيد سجل الاتفاقيات الأنواع المسموح بها، وتؤدي خسارة إحدى منح النوع إلى إعادة بناء النافذة وقراءة نطاقها الحالي. فحص الفريدية الاستباقي اختياري حسب المنحة، مع استمرار الفحص الملزم عند الحفظ. تغيير مجموعة الاتصال داخل التعديل العام يخضع لمنحة تغيير المجموعة.

تستخدم المرفقات والصورة تخزينًا خاصًا. فتح ملف محفوظ يحتاج منحة وسائط العملاء الخاصة ومنحة عرض نوع العميل وفرعه. يرتبط الملف غير المحفوظ برافعه، ويحتفظ الملف المستبدل أو المحذوف من النموذج بمطالبته التاريخية. تحفظ سجلات البطاقة آخر أربعة أرقام، وتخلو عقود القراءة والكتابة من الرقم الكامل ورمز التحقق.

أصبح تقرير التحصيل يعيد عقد القوائم `Results<DebtCollectionResultDto>` مع الصفحات والعدد والإجمالي، وتجمع الواجهة كل الصفحات عبر المالك المشترك قبل نشر التقرير. هذا تعديل متعمد للـtransport في الطلب المعالج، مع تحديث المستهلك الحالي. يجب نشر الواجهة والخادم المتوافقين معًا.

## مطابقة التنفيذ

| البنود | المعالجة في المصدر |
|---|---|
| ١٧١ | فحص مراجع البنك على مستوى المستأجر داخل قفل الحذف. يفرض مالك الحفظ تحققًا حديثًا من مراجع البنك الفعلية والمنطقية، وفق ترتيب أقفال العملة ثم البنك. أضيف اعتماد العرض لفحص الفريدية، وحماية المسودات ونتائج الطلبات. |
| ١٧٢ | تسلسل انتقالات الشيكات الواردة المتعارضة داخل معاملة الكتابة، مع شروط منافسة للحالة والمرجع المالي. تشمل الحراسة التعديل والحذف والاستحقاق الفردي والجماعي والارتداد وإعادة التقديم. |
| ١٧٣ | حدود المرشحات والفرز، وملكية نتيجة الطلب المرسل. يحتفظ إنشاء CSV باستثنائه المعتمد ومصدر الفرع المتحقق منه. |
| ١٧٤ | نطاق المستند الكامل يتبع الرأس ومصادر السطور المحفوظة. ترجع القائمة والتفاصيل أهلية التسجيل، وتستهلكها إجراءات الصف. أُغلق التفعيل الموروث غير المدعوم في الكتالوج والخدمة. |
| ١٧٥ | يستمر رابط التفاصيل القديم في التحويل إلى القائمة المحمية. |
| ١٧٦ | ربط القراءات الموروثة بمنح البحث والعرض وفروع العرض، وتوحيد مرشحات البحث، وحراسة وجهة التحويل، وتنقيح عنوان الحوار، وربط التقرير والطباعة والمنح باستعلام الإنتاج. |
| ١٧٧ | إعادة تأكيد نطاق السجل قبل إظهار التفاصيل المحتفظ بها عند رجوع المنحة. تبقى البيانات محجوبة عند الرفض مع إعادة المحاولة. |
| ١٧٨–١٧٩ | مرفقات وصور خاصة، وبطاقات بآخر أربعة أرقام، ومنح موحدة للتاريخ والمجموعة والفريدية. تنتهي ملكية الواجهة عند استبدال جلسة الحساب، وتُحجب الإشعارات والنتائج القديمة. |
| ١٨٠ | تطابق إنشاء المتابعة مع قراءة السجل، وتنقيح نص آخر متابعة حسب المنحة، وتصحيح قيم الحظر واعتماد آخر حالة محفوظة، وتجميع صفحات التقرير كاملة. |

## التحميل والمصادر والأداء

| السطح | المصدر والعمر | الحراسة |
|---|---|---|
| قوائم البنوك والشيكات والتحويلات والإيداعات | قراءة تشغيلية مباشرة لكل استعلام مطبق | إلغاء القراءة وتقييد نشر النتيجة بمالكها وصلاحيات المرشحات |
| خيارات المحررات | مالكو الخيارات الحاليون، دون مخزن مرجعي جديد | يستمر تحديث الخيارات وحقول المسودة وفق عقود الوحدات |
| مرفقات العملاء | قراءة ملف خاصة مباشرة بلا تخزين مشترك، واستجابة `no-store` | المستأجر وصاحب السجل والفرع والمنحة، مع تحرير blob عند انتهاء الوصول |
| تقرير التحصيل | صفحات تشغيلية مجمعة باستعلام واحد في الواجهة | إلغاء السلسلة عند إبطال الاستعلام، ونشر النتائج بعد اكتمالها |
| الكتابة المرسلة | عمر مستقل عن اشتراك القراءة | تسوية النتيجة الأصلية ومنع الإعادة، ونشر مشروط بالجلسة والمنحة |

لم تُقَس مدة استعلامات SQL أو خطط التنفيذ أو أداء القوائم الكبيرة في بيئة تشغيل. بقي تقرير التحصيل يجمع الحسابات والأرصدة قبل تقطيع الصفحة في الخادم، وتحتاج كلفته التشغيلية إلى القياس. صحة البناء أو اختبارات الذاكرة لا تثبت سرعة الخادم أو ترتيب أقفال SQL Server تحت حمل متزامن.

## التحقق والقبول

تم التحقق النهائي في ١٤ نوفمبر ٢٠٢٦.

| الفحص المنفذ | النتيجة |
|---|---|
| وصفات المشروع | ٨/٨ صحيحة |
| بناء خادم API ومراجع المشروع | نجح؛ شمل البناء النهائي مشروع اختبارات الفروع واعتمادياته |
| بناء Angular development | نجح بعد آخر تعديلات الواجهة والترجمة، بخرج `dist/sigma` |
| الاختبارات المركزة | ٦١ ناجحًا، صفر فشل أو تخطٍّ |
| فروق المصدر والموارد | نجح فحص المسافات في المستودعين، وموارد XML صحيحة دون مفاتيح مكررة |
| جرد المسارات | حُدّث دليل ٩ شاشات، مع بقاء ٢٦٣ مدخلًا وتصنيف الرابط ١٧٥ السابق |

شغّل التحقق المحدد مشروع `tests/SiGma.BranchAccess.Tests/SiGma.BranchAccess.Tests.csproj` مع عائلات
`Authorization171180EndpointTests` و`CustomerPartnerReadScope171180Tests` و`BankReferenceWriteBoundaryTests`
و`CustomerProfileMediaAccessTests` و`CardSettlementAggregateWriteScopeTests`،
وحالة قراءة التحويل في `BranchRelationalReadTests` واختبار اكتمال اعتماديات الكتالوج ومنع دوراتها.
تستخدم هذه الأدلة EF InMemory وSQLite في الذاكرة وملفات مؤقتة مملوكة للاختبار. لا تتصل بقاعدة التطبيق.
اختبارات الوسائط تعزل تهيئة البيانات عن حراسة SQL، وتستدعي منطق المطالبات والتوفيق والتدقيق الحقيقي.
بقيت تحذيرات تحليل الاختبارات في ملفات سابقة خارج الإصلاحات، ولم يمنع أي منها البناء.

كشفت المحاولات الأولى خطأ ترتيب متغير في محرر الفرد، وحقول تدقيق ونطاق فرع ناقصة في تجهيز الاختبارات،
واستخدام مرشحات السياق الإنتاجي على سياق تهيئة خام. صُححت هذه الحالات، ثم أعيدت المجموعة على المصدر النهائي ونجحت ٦١/٦١.

تظل تجربة HTTP والمتصفح والطباعة الحية وتزامن SQL Server على قاعدة التطبيق معلقة. لم تتغير قاعدة بيانات التطبيق في هذه الجولة. احتُفظ بالأعمدة الموجودة للبطاقة مع منع حفظ أسرار جديدة أو إرجاعها، وتبقى إزالة القيم التاريخية المخزنة عمل بيانات منفصلًا. الملفات القديمة تحتاج إعادة رفع عبر التخزين الخاص عند استخدامها؛ لا توجد إعادة نشر عامة.

## حدود النطاق

تظل موارد `Partner` و`MemberPartner` والعمليات العامة المجاورة في `Customer` ضمن سجلها السابق خارج هذه الشاشات. احتُفظ بتعديلات المستخدمين الأخرى في المستودعين. جرى توزيع التنفيذ على مالكي البنوك والإيداعات والعملاء، ثم مراجعة الدمج واختبارات الانحدار في هذه الجولة.
