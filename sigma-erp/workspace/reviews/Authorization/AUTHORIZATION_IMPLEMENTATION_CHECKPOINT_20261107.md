## معالجة مراجعة140–144 — 12نوفمبر

فلاتر موظفNRM، ومراقبة منحة اتفاقية العهدة، وتأمين ملفات حركة الورشة
بمنفذ خاص وحجب الممر العام التاريخي. لا هجرة أو نقل/حذف بيانات. لا ترقية
جرد جديدة؛ قبول البناء والتشغيل والاختبارات ضمن مراجعة المالك المجمعة.
هذه معالجة للملاحظات ولا تعني بدء وحدة أخرى أو قبول عمل جلسات متوازية.

### متابعة فشل هجرة الفروع

تحديث أحدث: وافق المالك على تجهيز البيانات القديمة بأي فرع مناسب بدل الحذف.
نُفّذ البناء وتطبيق الهجرة المحددة على الهوست بنجاح؛ أُسندت ١٩ حركة أعمال ورشة،
و٤ سجلات تشحيم و١٨ حركة خدمة إلى الفرع 2 داخل الاشتراك 1007، وبقيت الحوادث فارغة.
تحققت قراءات القاعدة من عدم وجود فروع غير صالحة وإلزام الأعمدة الأربعة وغياب
القيم الافتراضية وتفعيل القيود، دون حذف أو تغيير مبالغ الحركات المرتبطة. هذا استثناء
تهيئة تجريبية لمرة واحدة وليس تغييرًا لسلوك الحركات الجديدة. لا تعديل لملف
ModelSnapshot ولا عمل واجهة جديد أو ترقية للجرد. التفصيل في
[تقرير التصحيح](WORKSHOP_REQUIRED_BRANCH_MIGRATION_REPAIR.md).
الفقرة التالية تسجل المرحلة المصدرية السابقة قبل قرار المالك وإتمام التنفيذ.

بناء على سجل فشل FK عند تحويل BranchId إلى0، فوّض المالك تعديل الهجرة
المحددة مع أولوية المنطق الصحيح واعتبار البيانات تجريبية. صُححت الهجرة
20261110173039_update-auth بإزالة افتراضات0 للفروع الأربعة وإضافة preflight
يفحص تجهيز البيانات وملكية الفرع داخل الشركة قبل أي تعديل مخطط.
[تفاصيل التصحيح والتجهيز](WORKSHOP_REQUIRED_BRANCH_MIGRATION_REPAIR.md).
لم تُشغّل migration/DB ولا تُمسح بيانات أو تُعدل snapshots. نجاح التطبيق
يتطلب تجهيز بيانات التجربة؛ لا فرع عشوائي ولا تخفيف للإلزام. لا ترقية جديدة للجرد.

وفحص whitespace دون أخطاء. لم يُشغّل build/test؛ إعادة بناء المالك معلقة.

### متابعة أخطاء بناء Angular التي أرسلها المالك

عولجت أسباب الأخطاء الستة المرسلة دون تغيير تصميم الصلاحيات أو المفاتيح:
وُسع توقيع AdministrativeDefinitionSession.denied$ ليطابق المالك الداخلي
AccessViewPolicyService ويقبل requirement ثابتًا أو factory ديناميكية. بقي
تقييم factory عند الاشتراك وكل access change لدى المالك الأصلي، لا تحويلها
إلى snapshot قديم داخل المستهلك. يغطي الإصلاح Location وTripTypes وقرار
حذف صف إعداد تعريفة الفرع. أضيفت ثلاث مواصفات مصدرية للـfactory والسحب
والهوية والمتطلب الثابت، ولم تُشغّل.

أُتيحت branchTariffRead كخاصية readonly في TariffCards للقالب. صُححت رسالتا
منع عروض الإيجار وخطأ المخصص المحفوظ إلى kind=error من عقد StateMessage
القائم (loading/empty/error)، دون توسيع المكوّن أو إضافة تنسيق موازٍ.

الفحص المنفذ: parsing لتسعة ملفات/قوالب محددة ومطابقة قيم kind بتعريف المالك
ومراجعة المصدر/الفروق وwhitespace بلا أخطاء. لم يُشغّل build أو typecheck أو
test runner وفق حد المصدر؛ يلزم إعادة بناء Angular عند المالك لتأكيد زوال
رسائل المترجم، ولا تعد هذه المتابعة قبولًا تشغيليًا للوحدات أو ترقية جديدة للجرد.

### أحدث إقفال — عقود التأجير العامة وتوابعها

اكتملت [مطابقة عقود التأجير](LEASE_AGREEMENT_ACCESS_RECONCILIATION.md)
للقائمة النشطة والمغلقة والمحرر العام والأفعال والحوارات الأربعة عشر.
فُصلت منح العرض/الكتابة/الخيارات، وحُفظت جلسة المصدر المضمّن. تنتهي
هوية الممثل والمستند نهائيًا، وتستعيد نفس الجلسة القراءات دون مسح المسودة،
وتبقى الكتابة المرسلة ونجاحها مستقلين عن denial/destroy. التصدير من
المرشحات المطبقة وكل الصفحات، والقرارات والتركيز والطباعة والبوابات محروسة.

الخلفية تحرس المراجع الحية والشركة وتقلص DTO، والوثائق خاصة بقفل ربط/حذف
وفحص وجود، وسجل الفوترة يشترط استعراض كل فروع المقبوض قبل التجميع. حُسمت
ملاحظات read-only hydration وinitial-denied وbusy recovery وتأكيد تجاهل
dirty وتبديل الصف أثناء رفع الوثيقة، وتثبيت savedPaths قبل حجب نتيجة التأمين.
انتهت مراجعات مستقلة محددة دون finding مؤكدة متبقية؛ الدليل الثنائي محدث.

التحقق الأخير: نحو٦٨ ملفًا وقالبًا و٥٣٩ استيرادًا محليًا و٣٨٧ مفتاحًا
ثنائي اللغة بلا مشاكل، XML لخمسة مشاريع وملفي موارد، وفروق محددة وحزم
ثماني سليمة. المواصفات مصدرية غير منفذة؛ لا build/tests/typecheck/browser/DB.
رُقي صفا العقود والقائمة المغلقة فقط: الجرد١٢٩/٧٣/٥٧/٢/٢=٢٦٣ والمتقاعد٧.
لا مخطط أو migration جديد. المصدر وحده لا يثبت runtime أو race acceptance.

نقطة الاستكمال التالية: دورة الإيجار Rental، بدءًا بعرض السعر وتوابعه
طبقًا للجرد والعقود ومراجع Speed، دون إعادة وحدات Lease المقفلة. هذه
الفقرة تتقدم على نقاط الاستكمال التاريخية أدناه؛ هدف التطبيق العام لم
يكتمل ومراجعة المالك مجمعة للنهاية.

## ما تغير في الاستكمال الأخير

أُصلح duplicate detail GET عند دخول view/edit بلا Create مع HTTP معلقة؛
وأُلغي تأكيد الحذف عند سحب grant أو تغير السياق في القائمة والتفاصيل، مع
إعادة فحص id/Available قبل DELETE. إعادة منح فلتر اختياري أثناء bootstrap
تستبدل القراءة القديمة ثم تحمل المصادر الممنوحة الفعلية. استعادة Media.Delete
تستأنف cleanup معلقة داخل نفس السياق حتى خلف route محرر محجوبة، دون Save
ثانٍ أو loop على فشلHTTP أو busy/revision غير مرتبط.

يلغى قرار الخروج المفتوح عند السحب ويصدر false؛ قرار discard محلي جديد
بعد denial القائم يظل متاحًا. فتح التأكيد lazy؛ notifier للقرار فقط ولا
يقطع cleanup أرسلت. ترقى هذا النمط فيUI28 والمهارة، وأعيدت الحزم الثماني
بالمولد وCheck كلهاOK. دليل sales-guide ثنائي اللغة محدث في قارئ التطبيق.

حد orphan محفوظ: لا discard تلقائي بعد تبديل actor/link/branch-access
context لأنه قد يحذف ملفًا حفظه Save قديم. الضمان المحلي ضمن عمر tracker؛
انتهاء orphan على الخادم/التنظيف best-effort منفصل حسبUI18.

اكتمل تبني قائمة ومحرر SalesAgreement وأفعال الحوارات والإيصال المدمج ضمن
هذه الشريحة، مع سياسات route صريحة. جرد مفاتيحه وتبعيات الإيصال موجود في
[خطة وصول الواجهة](FRONTEND_ACCESS_MAINTENANCE_EVOLUTION_PLAN.md).
اكتمل تبني Receipt standalone مصدرّيًا، وتبقى بقية مسارات جرد٢٦٢ مطلوبة قبل
إغلاق الهدف.
ابدأ الشريحة التالية من المسارات غير المتبناة بحسب تتبعها الفعلي وعقدها
المجمد؛ اكتملت اليومية وقيد اليومية الآن وفق المفاتيح في مصالحتها، وتبقى
بقية الشاشات مطلوبة. لا تغيّر القرار المالي المعتمد أو تكرر سؤاله.

## دفعة Receipt الحالية — ٧ نوفمبر

بدأ تبني قائمة Receipt: أضيفت سياسات المسار وReceipt إلى مسار البداية، وربطت
أفعال العرض والتعديل والاعتماد واليومية والسجل والإبطال والحذف بمفاتيحها، مع
حراسة الفلاتر والقراءات الاختيارية وسياق الوصول. نجحت مجموعة القائمة وسياسة
المسار ١٧/١٧. ما زال محرر Receipt المستقل وكل قراءاته وكتاباته يحتاج دفعة
منفصلة قبل اعتبار Receipt مكتملًا.

اكتملت حراسة محرر Receipt نفسه: متطلبات View/Create/Update/Delete، قراءات الأطراف
والتخصيص والسياقات والاختيارات، وأزرار الحفظ والتعديل والحذف والاعتماد والمرفقات.
أضيفت مصالحة مصدرية نهائية للقائمة والمحرر ومالك الاعتماد المشترك؛ لم تُشغّل
اختبارات أو build أو lint أو browser أو DB في هذه الدفعة. قبول runtime والواجهة
والبيانات والفروع ما زال تحقق مالك منفصلًا.

## المعلّق الذي لا يوقف العمل المستقل

سؤالا التحصيل عبر الفروع وتفويض مخطط AddAssetAndSalesBranchOwnership
مرسلان سابقًا دون جواب؛ لا تكررهما. المخطط model-only ب١٢عملية غير مطبق،
ولا تجربة posting جديد قبله. تفويض الهجرة السابق يخص إسنادات الفروع فقط
وطُبّق AddUserBranchAccessPermissions. لا تبنِ سياسة تحصيل/قيد موازن بالحدس.
القبول المرئي للاتجاه والثيمين والموبايل ورؤية loaders على التطبيق معلق.

آخر ملكيات اليومية انتهت: branch_access_admin للمحرر، branch_ui_final_review
للقائمة والتخصيص، sales_details_adoption للتدقيق المستقل؛ استلم الجذر كل
المصدر للتكامل. أي دفعة جديدة تحتاج تجميدًا وملكية محددة قبل إعادة الإسناد.
الجذر يملك العقود/shared/route/docs والدليل والتكامل والتحقق. لا وكيل يكتب
ملفًا يملكه آخر. لا تعاد
اختبارات ناجحة إلا عند تغيير أو قلق محدد، ولا يُستعمل Sigma MCP أو Graphify.
