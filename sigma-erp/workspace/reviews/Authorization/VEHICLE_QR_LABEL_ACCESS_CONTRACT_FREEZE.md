## السطوح والمنح

المسار الرئيسي تقرير ملصقات كامل بلا ترقيم، وليس قائمة CRUD رغم اسم
مكوّنه list. تُحفظ طريقة عرض بطاقات QR وطباعة المجموعة الكاملة، ولا يحولها
تبني الصلاحيات إلى جدول. محرر السجل القائم حقول فقط وله مسارات مستقلة؛
إعادة تصميم شكل المحرر خارج شريحة الصلاحيات، وتبقى حراسة مغادرته قائمة.

| السطح أو الطلب الفعلي | المتطلب |
|---|---|
| القائمة والرابط الرئيسي وتهيئة المرشحات | VehicleQRLabel.Generate مع VehicleQRLabel.GetFilterOptions |
| توليد الملصقات وطباعة النتيجة الحالية | متطلب التقرير نفسه، ونجاح الاختيارات؛ لا طلب طباعة خادمي أو Print grant مخترع |
| عرض سجل محفوظ | VehicleQRLabel.View فقط |
| إنشاء سجل | العرض مع VehicleQRLabel.Create وBranch.Lookup وTariffGroup.Lookup |
| تعديل سجل | العرض مع VehicleQRLabel.Update والاختيارات نفسها |
| حذف السجل من المحرر | العرض مع VehicleQRLabel.Delete وشروط السجل/الفرع الحالية |
| المسار القديم details/:id | تحويل إلى view/:id بالهوية نفسها ومتطلب العرض نفسه |

ترجع تفاصيل السجل اسمي الفرع ومجموعة التعرفة مع هويتيهما، كي لا تتطلب
قراءة سجل محفوظ إذن قراءة قوائم اختيار أوسع. يُضاف BranchName وTariffGroupName
إلى DTO القراءة فقط، مع projection داخل DetailAsync يحافظ على فلاتر الشركة
والفرع والحذف. لا تُقبل الأسماء في DTO الحفظ ولا يُغير الكيان أو المخطط.

## نطاق الشركة والفروع

VehicleQRLabel مسجل فعلًا في BranchScopeRegistry كمالك مباشر لـBranchId.
التقرير ومرشحاته والتفاصيل يقرأون نطاق العرض، والكتابات تمر بحارس SaveChanges
وبنطاق التسجيل على الفرع الأصلي والمطلوب. السجل بلا فرع يظل ضمن حدود المدير
القائمة؛ لا يوسع المستخدم العادي قراءته أو كتابته. يستهلك المحرر خيارات فروع
التسجيل الفعلية من سياق الفروع، مع بقاء الخادم مرجع القرار. تعديل فرع سجل
ملصق ليس نقل مركبة، ولا تضاف له منحة تحويل مخترعة. لا حركة مالية أو ترحيل.

## دورة الوصول والقراءة والكتابة

تُلغى قراءات التوليد والمرشحات والتفاصيل والاختيارات عند انتهاء المنحة أو
السياق. تُمسح نتائج التقرير ومرشحاته السابقة ومنافذ Select وتُلغى تهيئة
الطباعة المؤجلة. لا يعاد تقرير تلقائيًا بعد إعادة المنح، وتُستعاد فقط
الاختيارات الأولية الناقصة. فشل القراءة العادي يحتفظ بـRetry دون حلقة طلبات.

المحرر مرتبط بمالك افتتاحه، ويبقى مركبًا بمسودته عند الرفض. تتبع الأزرار
والمعالجات وMockData المتطلب نفسه. تُلغى قرارات الحذف والمغادرة المنتهية،
ويظل التخلص المحلي الصريح متاحًا بعد الرفض. الحفظ والحذف المرسلان مستقلان
عن إلغاء القراءة مع trackWrite وسياج النشر المحلي والعالمي، ونتيجة نجاح
مثبتة تمنع إعادة الإرسال بعد إعادة المنح.

## مصادر الاختيارات والتقدم والأداء

Generate وFilterOptions وGetById قراءات تشغيلية مباشرة بلا مخبأ جديد.
Branch/GetSelect مصدر مرجعي متبنٍ للمخبأ: bootstrap محدود ثم watch عبر
ReferenceLookupBindings، مع حفظ تسميات الاختيار دون تغيير المسودة وإبطال
مصدر Branch القائم. TariffGroup/GetSelect مباشر دون cacheSelect opt-in.
العرض لا يبدأ أيًا منهما. مطلوب محمل الصفحة لتهيئة التقرير وقراءة تفاصيل
المحرر واختياراته وكتباته، مع خطأ وRetry وaria-busy دون مؤشر مرئي مكرر.

Generate يقرأ كل السجلات المطابقة من استعلام مرتب واحد؛ FilterOptions ينفذ
أربع قراءات distinct متتابعة على DbContext نفسه. لا طلب لكل صف. لا تغيير
schema أو index ضمن شريحة الوصول. تُقاس الأحجام وخطة SQL وزمن توليد وطباعة
عدد الملصقات نفسه لاحقًا؛ المصدر وحده لا يثبت السرعة.

## الأدلة والتوزيع

قُرئ شرح سبيد الأصلي S097 (Vehicles QR Codes Generation)، ثم شاشة
08-fleet/04-vehicle-qr-labels ومتحكم C1642 من لقطة ٢٨ أكتوبر: يثبت اختيار
المركبة والموديل والفرع والسنة والمجموعة والتوليد ونوعي الملصق. سيجما يخزن
سجل ملصق مستقلًا ويقرأ قيم QR منه، بينما المرجع يبحث المركبات نفسها؛ هذه
فجوة مصدر وظيفي مسجلة، ولا تغير شريحة الصلاحيات هوية الملصق أو تخترع ربط
VehicleId. اختلاف مقاسات الإخراج المرجعية يحتاج شريحة عرض مستقلة. لا يثبت
كود المرجع تحقق الخادم أو يمنح مفاتيح سيجما. لا فجوة إذن تستدعي أودو بعده.

الجذر يملك التقرير وملف المنح والمسارات والخدمة وDTO القراءة الخلفي/الأمامي
وprojection والتوثيق والجرد والدليل. عامل مستقل يملك components/details/**
فقط، ويستهلك العقد المجمد. لا تداخل ملفات ولا مسح للحل. الفحص مصدري فقط؛
لا build/tests/lint/browser/DB/migrations/snapshots/commit/push/deploy.
