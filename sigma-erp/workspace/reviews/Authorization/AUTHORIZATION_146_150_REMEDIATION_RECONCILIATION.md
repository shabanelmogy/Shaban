## الإصلاحات المنفذة

| الملاحظة | الإصلاح المصدري | سيناريو القبول المتبقي |
|---|---|---|
| F1 — عزل مراجع سجل الحركات | طبق `CollectionMovementService.GetMovements` إسقاطات مراجع المورد في Workshop والعميل في Delivery من `VisibleSuppliers/VisiblePartners`. تحققت NRM وAgreement من فرع الموظف/العميل عبر `CanShowPartner` قبل إظهار الاسم أو الكود. أصبح `contactId` يتحقق من `VisiblePartners` في الأنواع المعنية. بقيت الحركة التاريخية مرئية وفق فرع جذرها، وتعمل قواعد grid على DTO المحجوب بعد الإسقاط وقبل Count/Excel/Report | مستخدم يستطيع قراءة حركة في فرع أ، ومرجعها انتقل إلى ب: تظهر الحركة، بينما الاسم/الكود محجوبان في القائمة والمرشحات وExcel والتقرير |
| F2 — تعارض تعريف المتغير | عُرّف `tenant` مرة واحدة في `EquipmentMasterAgreementService.SaveSaleOrdersAsync` ويُعاد استخدامه لفحص الفروع والروابط. صُححت أيضًا ثلاثة معاملات lambda كانت تحمل أسماء `quotation` و`agreement` المتطابقة مع متغيراتها الخارجية، لتجنب تعارض CS0136 في الخدمة | تجميع Business واختبار كتابة كل أوامر البيع ضمن فروع مسموحة؛ مرفوض خارجها |
| F3 — تعليق المحرر بعد إلغاء سياق الكاش | صُفرت أعلام طلبات القراءة الملغاة صراحة بعد إبطال أجيالها في `EquipmentQuotation/details` و`EquipmentMasterAgreement/details`؛ تُلغى قراءات ومراقبات المصدر مع بقاء حالة الكتابة المرسلة مستقلة | تغيير `ReferenceLookupCache.contextChanges` أثناء تحميل التفاصيل أو الخيارات ثم إغلاق المحرر دون تعلق |
| F4 — تدمير حوارات المالية وأوامر البيع عند سحب المنحة | قائمة الاتفاقيات تحتفظ بمكونات الحوار المفتوح عند revoke، و`EditorDialog` يحجب المحتوى/التفاعل بحارس صلاحية مستقل ويترك الإغلاق والتجاهل متاحين. تحفظ حوارات finance/sales-orders المسودة، وتعيد قراءة الخيارات المطلوبة بعد regrant وتستهلك نجاح الكتابة المرسلة دون إعادة إرسال. عند تغير الحساب/الفرع/الجلسة تُنهى جلسات الحوار القديمة من الأب صراحة | سحب/إعادة `FinancialStatus/GetSaleOrders/UpdateSaleOrders` أثناء مسودة، طلب قراءة، قرار تجاهل أو POST مرسل؛ لا ضياع ولا تكرار ولا حارس خروج عالق |
| F5 — استعادة مسودة محرر الاتفاقيات | عند سحب المنحة والعودة لنفس المالك يحتفظ محرر `EquipmentMasterAgreement/details` بالمسودة والاتفاقية المعلّقة ويعيد تمكين النموذج ومصادره دون `initialize` لمسودة متسخة؛ نجاح الحفظ المرسل يظل مستهلكًا. زر Retry الذي قد يستبدل مسودة متسخة يطلب قرار تجاهل أولًا | إنشاء/تحرير Dirty ثم سحب المنحة وإعادتها ثم Retry أو Save؛ تبقى البيانات الأصلية ولا تحدث كتابة ثانية |
| F6 — فشل عروض الأسعار الاختيارية | فصل محرر الاتفاقيات `Customer/Equipment` الإلزاميين عن تحميل صفحات `Quotation.View` الاختياري في طلب مستقل؛ له خطأ/تحميل وإلغاء عند سحب المنحة أو تغير السياق. يسمح بإزالة عرض مختار غير قابل للقراءة، ويمنع حفظ مرجع عرض بلا منحة، لكنه لا يمنع حفظ اتفاقية مستقلة ذات `quotationId=null` | فشل المصدر الاختياري أو سحبه أثناء الصفحات مع نجاح المصدرين الإلزاميين: حفظ مستقل ناجح، ولا تتابع طلبات العرض القديمة |
| F7 — عرض سند تسليم تاريخي | يفصل `EquipmentRentalOrder/details.prepareOrView` رابط قراءة `deliveryId` الموجود عن حالة `Confirmed` أو إلغاء السطر؛ يتحقق من منحة الطلب وعضوية السطر والسياق الحالي. أضيف `DeliveryNote.GetDetailById` إلى متطلب الرابط إلى جانب `DeliveryNote.View` لأنه المتطلب الفعلي لحوار التفاصيل داخل الوجهة؛ الخادم يظل مالك تحقق الفرع | أمر ملغى أو ملغى الباقي وله سند محفوظ: يفتح رابط القراءة مع منحتي قائمة/تفاصيل الوجهة؛ لا زر أو انتقال مع View وحدها |

## حدود الإصلاح والعقود

العقود الحاكمة دون تعديل: `LOGS_MOVEMENT_ACCESS_CONTRACT_FREEZE.md`،
`EQUIPMENT_QUOTATION_ACCESS_CONTRACT_FREEZE.md`،
`EQUIPMENT_RENTAL_ORDER_ACCESS_CONTRACT_FREEZE.md`،
`EQUIPMENT_MASTER_AGREEMENT_ACCESS_CONTRACT_FREEZE.md`. لم يظهر عيب جديد
مؤكد في البند ١٥٠ ضمن تقرير المصدر، ولذلك لم تتغير عقود البيع أو مصدره.

بقيت `Quotation.View` منحة مستقلة، و`Customer.Lookup/Equipment.Lookup`
إلزاميين عند الإنشاء/التحرير؛ لا فتح لـ`Quotation.GetSelect` المتقاعد أو
للكتابات المتقاعدة في `EquipmentRentalOrder`. ملكية الفرع التاريخي لكل جذر
وقواعد `BranchScopeRegistry` لم تُوسّع. لا حاجة مثبتة إلى هجرة أو تعديل مخطط.
يظل استعلام سجل الحركات تسلسليًا وخاضعًا لتجميع الذاكرة؛ لم يُدّع تسارع مقاس
أو إنشاء فهرس بناء على إصلاح الحجب.

اُستهلك تقرير المراجعة الأصلي وشروحه المؤرخة لسبيد ٢٧ و٢٨ أكتوبر، بما فيها
شاشة اتفاقيات المعدات ومصادر سجل الحركات، والعقود المجمدة. لا توجد قاعدة
صلاحيات أو قرار أعمال إضافي يُطلب استنتاجه من أودو. دليل التطبيق القائم
للمعدات والحركات يصف المنح والاستعادة بالفعل؛ هذه الإصلاحات تعيد المصدر
للسلوك الموثق فيه دون إضافة وظيفة جديدة أو تغيير نص الدليل.

## التحقق وحدود التسليم

فحص المصدر والمسارات المتأثرة و`git diff --check` على نطاق الملفات المتغيرة
هو حد التحقق المتاح لهذه الشريحة. لم تُشغّل أو تُنفّذ builds أو tests أو
typecheck أو lint أو browser أو HTTP أو SQL Server أو migrations أو snapshot
أو commits أو push أو نشر. الفحص النحوي وحده لا يثبت ترجمة EF ولا صحة
المكونات في وقت التشغيل. يجب أن يشمل قبول المالك سيناريوهات F1–F7 في الجدول،
وتجربة إلغاء الطلبات واستعادة الوصول ضمن نفس الحساب، مع حساب/فرع مختلف.

تم الحفاظ على بقية تعديلات مساحة العمل، وعلى تقرير المراجعة الأصلي باعتباره
دليلًا تاريخيًا سابقًا للإصلاح. لا تُغيّر هذه المطابقة `150/263` أو
تصنيف صفوف الوحدات المنفذة؛ القبول التشغيلي والبناء والاختبارات مجمعة عند المالك.
