# عقد صلاحيات حواري فوترة وتسليم عقد البيع

| البند | القيمة |
|---|---|
| Status | Frozen |
| Owner verification pending | yes |
| التاريخ | ٢٠٢٦-١١-٠٧ |
| النطاق | SalesAgreementActionDialogComponent فقط واختباراته والدليل؛ جزء من هدف الصلاحيات النشط |
| التفويض | استمرار التنفيذ والبناء والاختبار في مسار الوصول الحالي |
| المستثنى | فتح route عقد البيع قبل تبني كل أحداثه؛ الإيصال المدمج ومخطط البيع والتحصيل عبر الفروع |

هذه شريحة UI09 من العقد الذاتي CURRENT_ACCESS_IMPLEMENTATION_CONTRACT_FREEZE؛
لا تغير الأرقام أو الضريبة أو التوزيع أو حالات الفوترة والتسليم أو عقد HTTP.
اعتماد المالك للفاتورة الواحدة وتوزيع فروع البيع محفوظ في عقد الفروع السابق.
تفويض مخطط AddAssetAndSalesBranchOwnership وقرار التحصيل ما زالا معلقين.

## المتطلبات المجمدة

| العملية | المتطلب والسلوك |
|---|---|
| فتح حوار الفوترة/قراءته/Retry | SalesAgreement.View مع SalesAgreement.Invoice؛ تفصيل GET يحتاج View فعلًا، وInvoice يحدد إتاحة سير هذا الإجراء |
| فتح حوار التسليم/قراءته/Retry | SalesAgreement.View مع SalesAgreement.Deliver |
| الإرسال | المتطلب نفسه يُعاد فحصه داخل submit قبل بناء/إرسال الطلب، مع جميع حراس الحالة والاختيارات الحالية |
| قراءات GET | denied$ على القراءة الداخلية فقط؛ إبطال dataContext يلغيها ويزيل بيانات السياق القديم، ويترك trigger قابلًا لإعادة القراءة |
| سحب منحة | يخفي EditorDialog عبر accessRequirement دون هدم المالك أو المسودة؛ يغلق منتقي التاريخ والاختيار والمتعدد التابعة للناشر |
| إعادة المنحة | تعيد قراءة اختيارات المصدر عند الحاجة دون reset لمسودة الحقول أو تكرار mutation مرسلة |
| تغير actor/branch context | يبطل الجلسة الحالية حتى فتح target جديد؛ لا تكفي مساواة id أو بقاء نفس grants لقبول callback قديم |
| كتابة مرسلة | تستمر حتى نتيجتها وfinalize، دون denied$؛ لا تعيد الإرسال ولا تنشر نجاح جلسة/target قديم في جلسة أخرى |
| إغلاق مسودة | يحافظ على التأكيد المشترك والـbusy؛ فحص سياق/target بعد التأكيد قبل الإغلاق أو إعادة تمكين نموذج مختلف |
| بيانات تجريبية | المالك المشترك MockData يفحص مفاتيحه الاختيارية؛ لا تصبح متطلبات للدخول أو الفوترة |

## المراجع والأثر

الكتب: Master1/4/5/7، UI7/13/22/26/28 والشكل UI09. الحزمة04 بعد Check
للحزم الثماني (كلها OK). المرجع الشكلي الفعلي Workshop/Job/close-job يثبت
EditorDialog وملكية typed form والقراءة والكتابة المستقلتين؛ لا ينقل قواعده.
قُرئ مدخل Speed ودليل شاشة Sales Agreement من لقطة٢٨أكتوبر، ثم كود C0786
بصورة مستقلة (٦٥–٩٠)؛ يثبت فصل منح الأفعال والحالة، ولا يثبت قواعد خادم
Sigma. لا شرح أصلي محدد لفوترة/تسليم بيع المعدات في دليل٢٧أكتوبر/فهرس الشرح؛
يبقى قيدًا مرجعيًا لا دعوة لاختراع قاعدة مالية. مدخل Odoo19 المحلي متاح؛
لا غموض مرجعي في مجرد تبني مفاتيح Sigma المثبتة يحتاج سلوكًا جديدًا منه.

الدليل الفعلي: SalesAgreementService.getDetail/invoice/deliver ومسارات
SalesAgreementController الحالية وكتالوج التنفيذ السابق. GET تشغيلي مباشر
غير مخزن؛ لا lookups إضافية أو watch/cache جديد ولا HTTP لكل زر. التحميل
المحلي الحالي عبر ReferenceLookupStatus/EditorDialog؛ كتابة الحفظ لها مالكها
الحالي. لا EF/DTO/AutoMapper أو فهارس أو schema جديدة؛ قياس السرعة ورؤية
التحميل على التطبيق يبقيان قبولًا منفصلًا، ولا تجربة posting قبل المخطط.

الجذر يملك العقد والتكامل وتشغيل الاختبارات والدليل والمصالحة. العامل يملك
ملف action-dialog.component.ts واختباراته فقط؛ يبدأ باختبارات سلوكية ثم
ينتظر نتيجة RED من الجذر قبل تعديل المصدر. لا مالك آخر يكتب هذه الملفات.
الاختبارات: denied initial؛ View دون grant الإجراء؛ استقلال Invoice/Deliver؛
إلغاء read عند سحب View/الإجراء؛ revoke/regrant مع بقاء draft؛ stale context
رغم نفس المنح؛ سحب grant أثناء كتابة مرسلة؛ dirty close من target قديم.
لا تغيير route registry أو عدادات التبني الكامل من هذه الشريحة وحدها.
