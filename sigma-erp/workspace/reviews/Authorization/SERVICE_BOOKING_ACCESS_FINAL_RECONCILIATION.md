## العمليات والمنح النهائية

| السطح والطلب الحقيقي | الواجهة والخادم والفرع |
|---|---|
| القائمة `/FleetServiceBookings` وGET VehicleServiceBooking | العرض `VehicleServiceBooking.View` في خريطة الوصول المشتركة والقائمة والبحث والفرز والترقيم. نفس الخريطة ترشح القائمة الجانبية والروابط؛ لا مسار مستقل للإنشاء أو بديل محرر مخترع. |
| GET GetById/{id} | العرض، ويستخدمه محرر التعديل فقط ضمن متطلبه المركب. يتأكد المحرر من الهوية وPending قبل قبول التفاصيل. |
| POST/PUT VehicleServiceBooking | العرض مع Create/Update واختيارات `VehicleServiceBooking.AgreementOptions` و`ServiceItem.Lookup`. حراسة الخادم تفرض مفتاح الكتابة، وتثبت وجود الاتفاق والشركة ونشاطه والبنود والتكرار والحالة. |
| GET AgreementOptions وServiceItem/GetSelect | طلبان مستقلان بالمفتاح الحقيقي لكل منهما. الاتفاق تشغيلي مباشر يتبع فروع التسجيل لأنه يزود حفظًا؛ بنود الخدمة مرجعية مشتركة مباشرة بلا opt-in للمخبأ. |
| PATCH {id}/Confirm | العرض مع Confirm وعضوية الصف الحالي وPending/canConfirm، قبل الإقرار وبعده؛ يفك انتظار القرار قبل الفحص الثاني كي يصل الطلب فعليًا. الخادم يتحقق من الحالة والتسجيل على الفرع. |
| PATCH {id}/Close | العرض مع Close وعضوية الصف وConfirmed/canClose قبل الإقرار وبعده؛ الحالة Closed نهائية في الانتقالات الحالية. |
| GET {id}/History | العرض مع History؛ لا يحتاج التعديل. مصنف WholeDocumentRead لدى BranchOperationRules، وتثبت الخدمة الرأس المقروء ثم تكرر شرطه داخل استعلام التاريخ. |
| GET Export | العرض مع Export؛ كامل النتائج المطابقة للمرشح المطبق والفرز ومرشح الأعمدة. مصنف WholeDocumentRead فلا يشترط تسجيل الفرع. يمسح العميل غير المسموح متزامنًا قبل الالتقاط، ويلغي التصدير المحمل بعميل عند سحب صلاحية اختياره. |
| GET Customer/GetSelect | Customer.Lookup اختياري؛ غيابه لا يحجب القائمة. يمسح العميل الخام والمطبق، ويحرر المراقبة القديمة؛ تعاد تهيئة القراءة الملغاة عند إعادة المنحة، بما في ذلك السحب والإعادة خلال دورة عرض واحدة. |

الإجراءات الموروثة الأخرى في المتحكم العام تبقى تحت مفاتيحها الحقيقية
عند الخادم وحراسة الفرع؛ لا تدعي هذه المطابقة وجود أزرار حذف/تفعيل/اختيار
حجز في واجهة لا تستهلكها. لم ينشأ endpoint أو إذن جديد أو تغيير DTO.

## ملكية البيانات والحفظ

أضيف رأس VehicleServiceBooking إلى BranchScopeRegistry بمسار
Vehicle.BranchId. يتبع الحجز المركبة المحفوظة عليه وفرعها الحالي، وليس
لقطة بيع تاريخية أو مستند تنفيذ ورشة. القراءة والتصدير والسجل تتبع فروع
الاستعراض؛ الحفظ والاعتماد والإغلاق تتبع التسجيل. عند إعادة الإسناد
تفحص الحراسة VehicleId الأصلي والجديد وفرعيهما؛ تغيير الاتفاق ليس تحويل
مركبة فلا تُطلب له منحة التحويل. يظل العزل المؤجّر والشركة عند المستودع
وفلتر EF، ولا توجد متحكمات مستقلة للأطفال أو التاريخ في المصدر الحالي.

يتجاوز فحص التكرار وتوليد الرقم فلتر الفرع مع SubscriptionId صريح؛
فحص التكرار يحتفظ بشرط الحذف الذي أضافه المستودع، والترقيم يشمل المحذوف
عمدًا. يحمي الفهرسان الفريدان القائمان رقم الشركة والاتفاق/موعد الخدمة.
أصبحت Status concurrency token لمنع كتابة انتقال قديم فوق حالة أحدث؛
يلتقط مالك الخدمة التعارض. هذا metadata لشروط UPDATE بلا عمود أو DDL
جديد؛ لا هجرة مطلوبة لهذه الشريحة، ولم يُمس snapshot.

الحفظ يشمل الرأس وبنود الخدمة والتاريخ في SaveChanges واحد بمعاملة EF
الضمنية. لا AutoMapper جديد أو حساب مالي أو توزيع أو أثر محاسبي جديد.
تبقى قواعد الوقت والأطوال والعداد وأسماء الحقول من العقود القائمة.

## العقود والمالكون المشتركون

أعمدة القائمة: رقم الحجز، العميل، الاتفاق، اللوحة، الماركة والموديل،
الموعد، الملاحظات، سبب الإلغاء والحالة. تقابل BookingNo/CustomerName/
AgreementNo/PlateNo/MakeAndModel/ServiceDateTime/Notes/CancellationReason/
Status في ListVM، مع Id وCanEdit/CanConfirm/CanClose اللازمة للأفعال.
تطابق PlateNo/CustomerId/Statuses/DateFrom/DateTo وFilters[grid] بين
التسلسل والخادم؛ العد قبل Skip/Take والتصدير غير مرقم بالمرشح نفسه.
العميل والمركبة مشتقان من الاتفاق في الخادم ولا يقبلهما طلب الحفظ.

الشكل قائمة بمحرر modal لرأس ومجموعة صغيرة واحدة؛ تستخدم FilterPanel،
DataTable، FeatureTitle، EditorDialog، EditableCollectionTable وMockData
والحراسة والجلسة الحالية. ليس تقريرًا عامًا ولا مستندًا ماليًا. مرجع
الشكل UI01 ومراجع Workshop/Job وEditorDialog كما يحدد كتالوج الشاشات؛
تبقى تفاصيل المجال وعمر الكتابة عند مالك الحجز. لا wrapper أو استخراج
مشترك جديد؛ أُعيد استخدام ReferenceLookupStatus وReferenceLookupBindings.

| الطلب أو العملية | ملكية التحميل والعمر والاستعادة |
|---|---|
| القائمة | محمل الصفحة؛ start/finalize مع switchMap لكل قراءة. يستمر trigger بعد إلغاء القراءة، وتُمسح النتائج عند انتهاء سياقها. |
| تهيئة العميل | ReferenceLookupStatus بمالك الصفحة، دون spinner داخل Select؛ bootstrap محدود ناجح ثم watch مستقل. فشل bootstrap أو watch يظهر مع Retry. التحديث ذو البيانات المحتفظ بها صامت. |
| تهيئة محرر الحجز والتفاصيل | forkJoin مستقل للطلبات وStateMessage محلي داخل body dialog وaria-busy؛ إلغاء بالمنح والسياق، وإعادة تهيئة القراءة الملغاة فقط. لا إعادة محاولة تلقائية لفشل أعمال أو نقل. |
| قراءة السجل | StateMessage محلي واحد وRetry، بلا قناع جدول أو محمل صفحة مكرر. إغلاقه المحلي متاح بعد الرفض. |
| الحفظ والاعتماد والإغلاق | محمل الكتابة القائم، وللحوار تقدمه المشترك؛ الطلب المرسل مستقل عن قراءة المنح والتدمير، مع trackWrite/HttpContext لسياج النشر المحلي والعالمي. يثبت النجاح قبل سياج النشر ولا يعاد تلقائيًا. |
| التصدير | محمل الصفحة وفصل exporting، start/finalize عند النجاح والفشل والإلغاء؛ لا يعاد تلقائيًا. |
| الحوارات والقرارات | يحمي interactionBusy من حوار ثانٍ أو تغيير مدخلات محرر مركب. يحتفظ المحرر بمسودته عند الحجب، ويستدعي CanDeactivate المتخلص المحلي بعد الرفض. تغلق منافذ Select/DatePicker/MultiSelect عند انتهاء الوصول والتدمير. |

تسميات العميل المحدد يحتفظ بها مالك merge القائم أثناء تحديث المصدر.
مخبأ Customer مصدر cacheSelect المعتمد بمالكه وإبطاله الحاليين؛ لا مخبأ
حجز أو اتفاق تشغيلي جديد. ترتبط المراقبة بالمنحة والسياق ويُعاد ربطها
بعد انتهاء صلاحيتها، ولا يعيد تغيير إذن غير متعلق تحميل الاختيارات.
تربط علامة نجاح الانتقال بالسياق والفعل والهوية حتى لا تمنع مستخدمًا
آخر ذا رقم سجل مماثل، وتمنع تكرار إرسال نجاح سابق من صف قديم.

## الأدلة المرجعية والأداء

سبيد أولًا: شاشة 08-fleet/16-service-bookings بتاريخ ٢٨ أكتوبر، ثم
C1205 للمحرر وC1206 للقائمة وC1207 للسجل. توجد أدلة المرشحات والإنشاء
والتعديل والاعتماد والإغلاق والسجل والتصدير؛ مصدر الواجهة لا يثبت
قواعد خادم خارجي. لم يوجد شرح أصلي مستقل للحجز في catalog ٢٧ أكتوبر؛
لا يستبدل بشرح تعريف الخدمة أو سجل تنفيذها. بعده قُرئت وثيقة Odoo19
المحلية Fleet/service.rst لفصل الموعد المخطط عن الخدمة المنفذة فقط.

الفجوات الوظيفية المرجعية: حذف/إلغاء الحجز وتعديل الملاحظات المستقل
والبحث المرجعي المتخصص وتخطيط الفني والطاقة ليست وظائف قائمة في واجهة
سيجما المتبناة. تُسجل كفجوات مجال، ولا تنشئ شريحة الصلاحيات قواعدها أو
endpoints أو آثارها المالية. ليست صلاحيات موجودة تُترك بلا حراسة.

مسار البحث ينفذ count ثم projection مرقمًا، دون طلب لكل صف. التفاصيل
تقرأ بنود التجميع، والسجل يتحقق من الرأس ثم يقرأ التاريخ بشرط الرأس.
توليد الرقم الحالي يقرأ أرقام الشركة في الذاكرة؛ توسعة النطاق من الفرع
إلى الشركة لازمة للصحة، وتبقى كلفة نمو التسلسل مرشحة لتحسين مالك ترقيم
مستقل دون اختراع تسلسل أو تغيير contract في هذه الشريحة. AgreementOptions
وServiceItem خيارات غير مرقمة حاليًا؛ قياس حجمها وزمنها عند المالك.

لا فهرس جديد في هذه الشريحة: فهارس SubscriptionId/No وSubscriptionId/
AgreementId/ServiceDateTime القائمة تغطي التفرد، وفهرس التاريخ المركب
SubscriptionId/VehicleServiceBookingId/CreatedAt يخدم استعلام السجل،
وFKs القائمة تربط المركبة والرأس. قبل إضافة فهرس فلترة المركبة/الموعد يجب قياس
SQL الفعلي وانتقائية الاستعراض والفرز مقابل كلفة الكتابة والتداخل؛
لا تكفي قلة الطلبات أو سلامة المصدر لإثبات سرعة. القياس قبل/بعد وخطة
SQL وحجم المخرجات والظهور المرئي تبقى عند المالك بنفس الشركة والفروع
والمرشحات وحالة cache الباردة والدافئة، ولا تُجرى هنا أوامر قاعدة بيانات.

## التحقق والتسليم

دليل المستخدم: موضوع sideMenu.fleets.serviceBookings في
`src/app/modules/UserGuide/content/fleet-guide.ts` عبر `/UserGuide/fleet`
وقائمة دليل الأسطول القائمة. وُضح الاشتقاق من الاتفاق والحالات والمنح
المستقلة ونطاق الفرع والتصدير واستعادة المسودة والتخلص بعد الرفض.
الرسائل الجديدة تستخدم مفاتيح مشتركة قائمة بالعربية والإنجليزية.

مواصفات المصدر غير المنفذة: ١١ حالة للقائمة، و٦ للمحرر، وحالة للسجل،
و٤ لحراسة الفروع/التزامن، و٥ صفوف theory لتصنيف قراءات/كتابات الحجز.
تشمل نجاح Confirm/Close فعليًا، وإلغاء القرار، والتصدير المحمل بعميل،
والإسناد الأصلي ورفض حفظ صاحب العرض فقط وعدم نشر/تكرار الكتابة المرسلة.
تحقق source parsing/import-existence موثق عبر
`verify-service-booking-source.mjs`؛ ليس type checking أو build أو tests.
أعطى تحليل ١٩ ملفًا وقالبًا صفر أخطاء صياغة وصفر imports محلية مفقودة.

استُخدم العاملان القائمان للقائمة/السجل والمحرر بملكية ملفات منفصلة بعد
تجميد العقد، ثم مراجعتان قراءة فقط وتدقيق خلفية مستقل لتقليل إعادة اكتشاف
السياق. استلم الجذر المخرجات وأصلح الحراسة والتحميل وتصنيف History/Export،
وراجع الفروق والملفات الجديدة وتولى التكامل والتوثيق والجرد. لا يعلن أي
عامل اكتمال التبني العام. [تسليم القائمة](SERVICE_BOOKING_LIST_HISTORY_ACCESS_HANDOFF.md)
و[تسليم المحرر](SERVICE_BOOKING_EDITOR_ACCESS_HANDOFF.md).

القبول النهائي للمالك: افتح القائمة بالمدير ثم مستخدم عرض فقط؛ امنع الرابط
وGET المباشر بلا View. أضف History وExport مع استعراض فرع دون التسجيل
وتحقق من تطابق نتائج القائمة والسجل والتصدير. اسند إنشاء/تعديل مع
الاختيارات والتسجيل، واختبر pending ثم confirm ثم close مع المنحة
المستقلة لكل انتقال. جرّب فرعًا غير مسند وشركة أخرى وإعادة الإسناد
بين فرعين؛ اسحب منحة أثناء قراءة وقرار ومسودة وحفظ مرسل ثم أعدها.
جرّب فشل نقل/أعمال وRetry وعدم تكرار الحفظ الناجح، وإغلاق الحوار بعد
الرفض والتجاهل المحلي. قارن كامل التصدير بالمرشحات والعداد والصفحات.

لا build/tests/lint/browser/DB/migration/snapshot/commit/push/deploy في
هذه الشريحة. قبول المالك التجميعي والتشغيل والقياسات معلقة؛ اكتمال
هذه الوحدة لا يعني اكتمال بقية التطبيق.
وصف تغيير الواجهة المقترح: `fix(service-bookings): enforce operation access and request ownership`.
وصف تغيير الخلفية المقترح: `fix(service-bookings): scope reads and transitions to authorized vehicle branches`.
