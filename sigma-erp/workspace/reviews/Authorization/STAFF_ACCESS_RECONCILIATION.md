## النتيجة والعقود

تتبّع المسار الفعلي `/Staff` إلى `Staff/Staff/staff.routes.ts` وقائمته ومحرره. تستهلك الواجهة مصدر المفاتيح الواحد `staff-access.ts` في شروط المسارات والقائمة والمحرر. يعرض كتالوج الخادم المتطلبات الثابتة والشرطية من `PermissionPrerequisites` نفسه الذي يفحص الطلب، مع مفاتيح ترجمة كاملة ثابتة لشروط الموظف التسعة.

| السطح | الشرط المطبق |
|---|---|
| القائمة والبحث والتفاصيل وExcel الكامل | `Staff.View` |
| الإنشاء المباشر | `Staff.Create` + `Branch.Lookup`، مستقل عن View |
| التعديل | `Staff.View` + `Staff.Update` + `Branch.Lookup` |
| الحذف | `Staff.View` + `Staff.Delete` مع تأكيد الصف وقيود الارتباطات القائمة |
| قراءة حزمة الراتب | `Staff.View` + `Staff.GetSalaryRevision` |
| حفظ تعديل الراتب | القراءة السابقة + `Staff.ReviseSalary`؛ لا تتطلب Staff.Update |
| حزمة راتب أولية | `Staff.ReviseSalary` شرطية فقط عند إرسال SalaryPackage في Create |
| التحقق الاستباقي من التكرار | `Staff.Validate` اختيارية؛ لا تُعطّل تحقق الخادم الإلزامي |
| البلد والجنسية والقسم والوردية والمسمى والكفالة والمسؤول ونوع الإجازة | Lookup الخاص بالمصدر عند الإسناد أو التغيير؛ إبقاء المرجع المحفوظ لا يحتاج تحميل قائمته |
| مرجع الدور داخل ملف الموظف | `Staff.GetRoleOptions`؛ إسقاط Id/Name داخل الاشتراك من العلاقة RoleId الحالية |
| فتح تقرير القائمة | `Staff.GetStaffBalancesSummary` من مالك وجهة `/StaffBalancesSummary` الموجود؛ لا يمنحه Staff.View |
| فتح مرفق محفوظ | `Staff.View` + `Media.ReadStaffDocument` مع ملكية وثيقة الموظف |
| رفع مرفق | `Media.UploadMedia` مع حق إنشاء/تعديل الموظف؛ الملف الجديد يثبت رافعه ووجوده |
| تنظيف رفع غير مسند | `Media.DeleteMedia` للممثل والجلسة الأصليين والرافع نفسه؛ يمنع الحذف بعد أي مطالبة تاريخية |

الأصل Staff تعريف مشترك داخل الشركة وفق النموذج الموجود، بلا إضافة Branch query filter إلى جذره. يبقى BranchId إلزاميًا في المحرر ويخضع للتحقق الحالي، وتبقى الحركات والتقارير ونطاق فروعها تحت ملاكها المستقلين. لا يؤدي اختيار RoleId إلى إنشاء مستخدم أو منحه دور دخول؛ بقي RoleController محصورًا في TenantAdmin. لم تُحوَّل العلاقة إلى StaffRole ولم يتغير المخطط.

## تغطية الوظيفة والمرجع

المرجع الوظيفي المقروء: دليل سبيد المحلي بتاريخ ٢٧ أكتوبر في سجل الموظف والموارد البشرية، ثم الشاشة المؤرخة `06-staff/screens/01-staff.md` بتاريخ ٢٨ أكتوبر وتعريف R0362 ووحدات C1113/C1112/C1116. المقارنة مصدرية، وليست مشاهدة تشغيل. لم تُقدم صور جديدة لهذه الشريحة. لم يبق غموض وظيفي في نطاق تبني الصلاحيات يحتاج وثائق Odoo المكملة؛ لا استحداث لسياسة راتب أو دورة موارد بشرية جديدة.

| تفصيل المرجع | مصدر سيجما النهائي | المطابقة |
|---|---|---|
| قائمة الموظفين والبحث والمخرجات وأفعال الصف | list.component وStaffListVM والخدمة | مطابق في النطاق؛ لا أعمدة أو حسابات جديدة |
| ملف بيانات ووثائق وحسابات بنكية وأهلية | تفاصيل الخطوات وDTOs القائمة | مطابق في النطاق؛ حماية المراجع والأطفال دون إعادة تصميم الملف |
| فصل عرض الراتب عن تعديله | GetSalaryRevision/ReviseSalary والحوار | مطابق؛ عرض بلا تحرير عند غياب منحة التعديل |
| إدارة حسابات الدخول | User/Role الحاليان | خارج ملف الموظف؛ الفصل موضح في الدليل |
| الاستيراد وكشف الحساب وبقية الرواتب | مساراتها المستقلة | خارج اعتماد هذا الصف؛ لا ترقية ضمنية |

الأعمدة الفعلية: `no / displayName / mobileNo / email / designationLabel`.
خصائص ListVM المستهلكة: `id / no / firstName / middleName / lastName / mobileNo / email / staffDesignation`؛ تُركّب تسميتا العرض من هذه الخصائص. لا راتب ولا مخزن ملفات في القائمة. يتطابق Add/Update مع المدخلات، وتبقى قيم الراتب والإجمالي والحسابات تحت مالك الخادم القائم. لم تضف هذه الشريحة AutoMapper جديدًا؛ تستعمل الخرائط الحالية مع reconcile صريح للوثائق.

## أعمار الوصول والمسودة والكتابة

- تُلغى قراءات القائمة والتفاصيل والراتب وExcel والقرارات القديمة عند فقد حقها أو تغير السياق أو الجلسة، وتُحجب البيانات والـportals. لا يُعد snapshot مطابق إبطالًا دلاليًا.
- يحافظ محرر الموظف على مسودة Edit المحملة عند سحب المنحة وإعادتها داخل الجلسة نفسها؛ لا يُعاد fill فوقها. تتحمل القراءات الأولية الملغاة إعادة المحاولة، وتبقى بيانات راتب موجود منفصلة عن حزمة الإنشاء المدخلة.
- تُعطَّل حقول المرجع المفقود مع إبقاء معرفاتها وتسمياتها المختارة؛ يتحقق Save من كل مرجع تغيّر ومن الحزمة الأولية قبل POST، دون حذف المدخلات صامتًا.
- عند سحب منحة الحزمة الأولية بعد إدخالها يبقى اختيار «تضمين حزمة الراتب» متاحًا لإلغائه صراحةً، فتستمر مسودة الموظف دون إرسال الحزمة؛ لا تصفير للمدخلات المحلية ولا حذف صامت من payload.
- تمنع هوية الجلسة الثابتة إعادة فتح محرر منتهي السياق بمجرد العودة إلى الممثل السابق. يُتاح قرار تجاهل محلي جديد بعد السحب، ويُلغى التأكيد الذي بدأ قبل تغير الوصول.
- لا يُلغى POST/PUT/DELETE المرسل بسبب إلغاء قراءة أو تدمير المكوّن. يستهلك نجاح الحفظ مسودته حتى لو لم يُسمح بعرض النتيجة؛ لا يعيد منح الصلاحية إرسال Create أو تعديل الراتب مرة أخرى. تقيد `CAN_PRESENT_API_OUTCOME` عرض النتيجة بجلسة المرسل ومتطلبات العملية الفعلية.
- يستقل تنظيف الملفات المؤكد عن عمر قرار التأكيد والاشتراك في التنقل. لا يبدأ تحت حساب/جلسة بديلة. لا يلزم حق الحذف لتسوية tracker فارغ، ولا يُحبس الملف المحفوظ خلف حق تنظيف سُحب بعد الحفظ. تبقى الملفات غير المسندة التي تعذر تنظيفها لصيانة المالك؛ لا ادعاء بوجود مهمة آلية لانتهاء الأيتام.
- ينتهي Create-only إلى أول وجهة مسموحة عبر سجل المسارات، دون افتراض حق فتح قائمة الموظفين.

## تحميل المصادر والكاش والمالكون المشتركون

| المصدر الفعلي | التصنيف والمالك | دورة المصدر والتغذية الراجعة |
|---|---|---|
| GET Staff وGetByWithNavigationsId وSalaryPackage | قراءة تشغيلية مباشرة، StaffService | القائمة والتفاصيل بمؤشر الصفحة؛ GET الراتب داخل الحوار برسالة محلية، وداخل المحرر بمؤشر الصفحة؛ أخطاء القناة وisSuccess/Retry |
| كامل نتائج Excel | طلبات الترقيم القائمة، fetchAllPages | نفس Staff.View؛ إلغاء وتحقق السياق قبل إنشاء الملف؛ لا تصدير للصفحة الحالية فقط |
| Branch/GetSelect وCountry/GetSelect | opted-in reference cache بالخدمتين وReferenceLookupBindings | bootstrap محدود ثم watch منفصل؛ إلغاء binding/علامة bootstrap عند السحب وإعادته عند المنح؛ حفظ الاختيارات والمسودة، تنظيف السياق وRetry |
| Department/Shift/StaffDesignation/SponserShip/LeaveType/Staff GetSelect | مصادر مباشرة بلا opt-in للكاش في خدماتها | لا طلب بلا المنحة؛ استبدال القراءات عند revision دلالي، حفظ التسميات المختارة، وتجديد دون مسح المدخلات |
| Staff/role-options | مرجع محدود مباشر جديد | لا طلب Role/GetSelect ولا فتح إدارة الصلاحيات؛ منحة المرجع مستقلة |
| Staff/CheckUnique | تحقق استباقي مباشر | لا طلب بلا Validate؛ تحقق الحفظ الخادمي يبقى مستقلًا |
| Media وFileLink | مالكو FileStore/FileField/DocumentUploadTracker/FileLink الحاليون | ملف خاص مع قراءة authenticated؛ الرفع والقراءة والنشر والتنظيف لكل منها عمره وشرطه |

تهيئة الاختيارات المطلوبة لها مالك الصفحة `ReferenceLookupStatus`، وتجديد الاختيارات المحتفظ ببياناتها صامت مع حالة busy وRetry. أحداث كتابة المصادر وإبطالها تبقى تحت خدمات المرجع الحالية وReferenceLookupCache؛ لا نسخة كاش جديدة ولا cache عابر للمستخدمين. الشروط الدلالية تلغي القراءات السابقة وتعاد مراجع الصفحة دون الكتابة فوق المسودة. الجدول والخطوات والحقول والصفوف والتأكيدات تستخدم DataTable/StepForm/EditableRows/ConfirmationDialog القائمة؛ لا CSS أو wrapper بديل.

## الوثائق الخاصة والخادم

تُرفع الوثائق الجديدة إلى `staff-documents` خارج wwwroot، باستخدام `StaffDocumentPath` المبني على `PrivateUploadPath`. يعيد GET `Media/staff-document` ملفًا بلا تخزين عميل (`no-store` و`nosniff`) بعد التحقق من اشتراك المستخدم ومنحة العرض ومالك CustomerDocument.PartnerId والموظف الحي والصف الحي. يمنع مشاركة المسار مع طفل غير مسند أو مع مالك آخر، حتى لو كانت المطالبة محذوفة منطقيًا. يسمح إعادة استخدام مسار خاص محجوز سابقًا للموظف نفسه فقط إذا كانت كل مطالبه له.

تسبق فحوص المسار والملكية mapping والحفظ. يستبدل تعديل المسار صف الوثيقة مع إبقاء المطالبة القديمة المحذوفة منطقيًا، ولا يؤدي فصل الوثيقة أو حذف الموظف إلى حذف الملف الخاص مباشرة. يستخدم حفظ المطالبات وتنظيفها مالك قفل CustomerDocument نفسه ومعاملة Serializable عند التخزين العلائقي، مع حدود وحدة العمل الحالية. يمنع static المجلد الخاص ويمنع المسارات العامة القديمة التابعة فعليًا للموظف، بما فيها مجلد staff القديم والمجلد المشترك CustomerDocuments. لا fallback عامًا عند فشل القراءة الخاصة، ولا ترحيل أو حذف أو backfill للملفات التجريبية.

يحيل GetById العام إلى إسقاط التفاصيل المراجع نفسه؛ لا مسار graph بديل لقراءة SalaryPackages. تبقى Lookup وValidate الحقيقيتان مستقلتين. عمليات Activate/GetAllWithNavigations/bulk غير المستخدمة ترجع 405 ولا تصلح للإسناد، بدل عرض صلاحيات لوظائف وهمية.

## الأداء والفهارس

لم يُضف استعلام لكل صف في القائمة أو مرجع الأدوار: إسقاط Id/Name مباشر ومحدود بالاشتراك. تفاصيل الموظف تستعمل إسقاطها الحالي وقراءات الأطفال المحدودة بملف واحد؛ لم تُعد صياغة حساب الراتب. يقارن حارس المراجع snapshot واحدًا مخزنًا بعمر الطلب فقط عند غياب منحة مطلوبة لتحديد هل المرجع تغيّر، مع AsNoTracking/AsSplitQuery؛ لا cache بيانات مشترك.

تحتاج مطالبات الملفات فحص المسار والمالك الحي/التاريخي. لا فهرس صريح للمسار مثبت في النطاق الحالي. يُقترح تقييم فهرس `(SubscriptionId, DocumentPath)` مع تضمين `PartnerId, IsDeleted` بعد قياس SQL plan/cardinality، مع كلفة كتابة ومساحة وفحص طول نوع العمود وتداخل الفهارس؛ لا تطبيق فهرس أو هجرة هنا. لا ادعاء بتحسن زمن أو استهلاك SQL من مقارنة المصدر. قبول الترجمة والـDI وخطط SQL والتزامن والتحميل المرئي مؤجل للمالك.

## التحقق والتسليم

تمت مراجعة الفروق المحصورة في مستودعي Angular وBackend مع الملفات الجديدة واستيرادها وnamespace ومراجع المشاريع وإدراج runtime file في tsconfig.app.json، دون إدراج specs في تطبيق الإنتاج. أضيفت مواصفات مصدرية لشروط المسارات والمراجع والراتب وأعمار الشاشة والملفات وكتالوج الخادم؛ **لم تُنفذ**. فحص الصياغة لا يثبت نجاح البناء أو الاختبارات.

نتائج الفحوص المصدرية: صياغة ١٩ ملف C# و١٦ ملف TypeScript/Angular، وصحة JSONC لإعداد التطبيق، وصحة XML لملفي الموارد دون مفاتيح مكررة. فحص فرق whitespace في النطاقين انتهى برمز 0، مع تحذيرات LF/CRLF الاعتيادية فقط. فحص حزم الوثائق الثماني انتهى 8/8 OK. لا توجد نتيجة اختبار أو بناء ضمن هذه الأدلة.

دليل التطبيق: `src/app/modules/UserGuide/content/staff-guide.ts`، من رابط `/UserGuide/staff` الموجود بقائمة الموظفين. حُدث موضوع ملف الموظف باللغتين لشرح فصل المستخدم والدور المرجعي والراتب والميديا والإسناد المشروط والمسودة والخروج. لا إنشاء قارئ أو مدخل دليل منافس.

لا تغيير مخطط ولا حاجة Add-Migration لهذه الشريحة. البيانات الحالية تجريبية؛ تجهيز وثائق خاصة جديدة من الشاشة هو مسار القبول الصحيح للملفات القديمة، دون workaround أو نقل بيانات. لم تُشغّل builds/tests/typecheck/lint/browser/HTTP/DB/migrations/snapshots/commits/push/deploy أو Sigma MCP/Graphify.

شارك عاملان بنموذج gpt-5.6-terra للقائمة والمحرر وعامل gpt-5.6-sol للخادم تحت ملكيات مستقلة بعد التجميد؛ تولى الجذر المفاتيح والاعتماديات والربط واللغة والدليل ومراجعة التكامل وإصلاح حوافها. خفّض التوازي زمن الملفات المستقلة، وبقي قرار العقد والترقية والتسليم عند الجذر.

قبول المالك المطلوب: إنشاء موظف بحساب يملك Create دون View، وعرض دون تعديل، وقراءة راتب دون تعديله، وسحب/استعادة منحة اختيار أثناء مسودة، وتبديل الجلسة أثناء GET وحفظ مرسل، وقراءة/استبدال مرفق خاص ومحاولة حذفه بعد الإسناد، والتأكد من حجب رابط staff العام القديم. تشمل التجربة الفروع وtenant آخر ورفض إسناد path يخص غير الموظف، مع اختبار 405 للمنافذ غير المدعومة وخطة استعلامات حقيقية.

رسالتا commit المقترحتان، دون تنفيذ: `feat(staff): apply employee permissions and private document lifecycle` للواجهة، و`feat(staff): enforce employee grants and private document ownership` للخادم.

التالي بحسب ترتيب الجرد هو `/Alerts` **تنبيهات العملاء** بعد تجاوز StaffStatement المؤكد سابقًا؛ لا يُخلط مع `/staffAlerts`. يبدأ بعقده المستقل ولا يرث صلاحيات الموظفين.
