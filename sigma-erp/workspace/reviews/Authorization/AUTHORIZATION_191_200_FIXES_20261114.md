## خطة الإصلاح وحدودها

١. استبعاد الفروع المحذوفة من شرط اكتمال نطاق قراءة تشغيلات الإضافي. يبقى نقص فرع حي مانعًا. لا تغيير لسياسة الفروع غير النشطة أو تاريخ المسير.

٢. إصلاح الخروج من إنشاء الإضافي إلى وجهة مسموحة، وربط قرارات تجاهل مسودة المعالجة بعمر سياقها، وتطبيق حارس النتيجة نفسه على فشلي الأعمال وHTTP.

٣. فصل هوية المسودة الأصلية والجلسة عن إصدار حجب الإشعار عند تسوية حفظ الحضور والإضافي. إكمال الحفظ المرسل لا يعيد إرساله ولا يستهلك مسودة حساب أو محرر بديل. يتاح الانتقال/التحديث المسموحان بعد استعادة المنحة.

٤. إضافة حالات رجوع موجهة، والتحقق من التجميع والتشغيل المحدد، ثم مراجعة الفروق وتحديث دليل الاستخدام والفهرس وحالة الملاحظات. القبول داخل التطبيق وقاعدة SQL الفعلية منفصلان.

لا هجرة أو تعديل منح أو مالية. لا يتغير قرارا ملكية سجلات الخصومات والإجازات المؤجلان. مالك الواجهة المفوض يقتصر على محرر ومعالجة الإضافي ومواصفاتهما؛ الجذر يملك الحضور وخدمة الإضافي واختبارها والدمج والتوثيق.

## التحقق المنفذ

- نجح فحص الوصفات 8/8؛ لم تُعدّل كتب أو قوالب أو ملفات مولدة.
- أعاد اختبار خدمة تشغيلات الإضافي إنتاج العيب قبل الإصلاح: 1 فشل و1 نجاح. بعد إصلاح الشرط نجحت حزمة الخادم `27/27`، وتشمل اختباري النطاق، وحالات البنود 191–200 واعتماديات الكتالوج. بُنيت مشاريع الخادم ومشروع الاختبار ضمن نفس الأمر بمخرجات معزولة؛ لم يستبعد أي اختبار مصدر خارجي من التجميع.
- أعادت مواصفات الحضور إنتاج العيب قبل الإصلاح: 4 فشل و3 نجاح. وأعادت مواصفات الإضافي إنتاج عيوبه: 16 فشل و8 نجاح. بعد الإصلاح نجح تشغيل Chrome Headless/Karma المجمع `34/34` في مواصفات محرر الحضور ومحرر الإضافي ونافذة المعالجة. أضيفت بعض حالات الحماية الإضافية بعد دورة RED، فلا يُدّعى أنها اجتازت دورة RED منفردة.
- نجح فحص TypeScript المحدد لمواصفات الإضافي. نجح بناء Angular الكامل بإعداد development ومخرجات مؤقتة معزولة (exit 0) بعد اكتمال تعديلات المصدر والدليل.
- راجع الجذر المصدر المتكامل والفروق المحددة في مستودعي التطبيق. فحص whitespace المحدد ناجح؛ التحذيرات السابقة المتعلقة بنهايات الأسطر وأدوات الاختبار لا تعني فشل الحالات.
- المحاولة الأولى لتجميع اختبارات الحضور توقفت بسبب تمرير مسار إعداد مطلق إلى Angular CLI؛ أُعيدت بمسار إعداد نسبي وأثبتت الإخفاقات الأربعة المطلوبة، ثم نجحت الحزمة النهائية. ملفات إعداد الاختبار المؤقتة أزيلت بعد كل تشغيل، ولم يتغير إعداد المشروع الدائم.

## مطابقة التحميل والمراجع والدليل

يحافظ الإصلاح على مالك تحميل القائمة وقراءات المحرر ومعالجة POST. لا تُلحق إشارة إلغاء القراءة بالكتابة المرسلة؛ ينهي كل طلب busy/loader في finalize. تُحدّث القائمة المسموح بها من مسار إغلاق المحرر أو إعادة دخول القائمة، دون إعادة POST؛ ومستخدم الإنشاء فقط يتجه إلى صفحة أخرى مسموحة. لم تُضف ذاكرة منح أو طلبات صلاحيات أو lookup جديدة. تعديل الخادم يضيف شرطًا لنفس استعلام الوجود، ولا يضيف رحلة SQL. لا تغيير فهارس أو مخطط، ولا ادعاء بقياس سرعة أو خطة SQL.

استُكملت معالجة ضمن العقود والمراجع التي جُمعت في مراجعة المصدر: كتب Sigma وUI26/UI28 وBE8/BE9، وشرح سبيد S132 وخريطة الحضور/الإضافي المؤرخة وكود C1577، دون استنباط سياسة أعمال جديدة. لا غموض يحتاج Odoo في هذا الإصلاح.

دليل التطبيق: `SiGmaAngularFrontEnd/src/app/modules/UserGuide/content/hrm-guide.ts`، موضوعا `/Attendance` و`/Overtime` في قارئ UserGuide القائم. أُضيف وصف الحفظ المرسل واستعادة الوصول والخروج لمستخدم الإنشاء فقط وإلغاء قرار التجاهل القديم، وحدود الفروع غير المحذوفة.

استُخدم وكيل واحد لمحرر ومعالجة الإضافي ومواصفاتهما (بالنموذج الموروث) لتوازي ملفاته المستقلة مع الحضور والخادم؛ بقي الجذر مالك الدمج والتوثيق. لم تُستخدم قاعدة التطبيق أو HTTP حي أو أتمتة واجهة التطبيق أو هجرات أو commit/push/deploy. اقتراحا commit فقط: `fix: reconcile attendance and overtime access lifecycles` للواجهة، و`fix: ignore deleted branches in overtime run read scope` للخادم.
