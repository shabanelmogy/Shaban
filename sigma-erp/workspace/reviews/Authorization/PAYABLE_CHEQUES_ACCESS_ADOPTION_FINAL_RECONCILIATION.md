# مطابقة صلاحيات الشيكات الصادرة

| البند | القيمة |
|---|---|
| Status | Implemented — source + scoped build/filter checks; runtime pending |
| Owner verification pending | yes |
| العقد | [صلاحيات الشيكات الصادرة](PAYABLE_CHEQUES_ACCESS_ADOPTION_CONTRACT_FREEZE.md) |

| الإجراء | الصلاحية المطلوبة بالإضافة إلى العرض |
|---|---|
| القائمة والتفاصيل والتقرير والطباعة والتصدير | العرض `PDCPayable.View` يكفي للقراءة الأساسية |
| اختيار مرشح الطرف والفرع | `Partner.Lookup` أو `Branch.Lookup` بحسب المرشح |
| محرر الإضافة والتعديل | `PDCPayable.Create` أو `PDCPayable.Update` مع اختيارات المورد والعميل والطرف والفرع والبنك |
| القيد وطباعته | `PDCPayable.GetVoucherDetails` |
| الصرف الفردي | `PDCPayable.MatureSingle` و`PDCPayable.GetDefaultBankAccountId` و`Account.GetPostingSelect` |
| الصرف الجماعي | `PDCPayable.MatureBulk` |
| الإلغاء والحذف | `PDCPayable.Cancel` أو `PDCPayable.Delete` |
| الاستيراد | `PDCPayable.Create` و`PDCPayable.View` و`Partner.Lookup` و`Bank.Lookup`؛ يشترط `Supplier.Lookup` أو `Customer.Lookup` عند إرسال المعرّف المقابل |

في HTTP تتطلب `Create` العرض والطرف والبنك؛ `Supplier.Lookup`
و`Customer.Lookup` شرطيتان في حمولة `PDCPayableAddVM`، بينما
`Update` يحتاج مصادر المحرر الأوسع. ويُفحص `Partner.Lookup` أو
`Branch.Lookup` عند طلب مرشح `contactId` أو `branchId`، وتحتاج
`MatureSingle` إلى `GetDefaultBankAccountId` و`Account.GetPostingSelect`
بالإضافة إلى العرض والصرف الفردي؛ لا تنشئ هذه الاعتماديات منحًا تلقائية.

تتبنى القائمة الحوارات المملوكة لمسارها. يرجع معرّف الفرع في السجل
لتقييد الأزرار واختيار الشيكات المعلقة. يتحقق الخادم من الفروع عند الكتابة.
تُقرأ تفاصيل القيد المرتبط ضمن نطاق عرض المستند الكامل، ويحتفظ تحضير
الصرف الفردي بنطاق التسجيل. يستخدم الصرف الجماعي الربط البنكي الحالي.

تُلغى قراءات القائمة والحوارات وتأكيدات الإلغاء والحذف عند فقد الوصول.
تُحفظ المسودة في مالكها وتُحجب عن السياق الجديد. تكتمل الكتابة
المرسلة بعمرها المستقل. يتوقف تسلسل الاستيراد قبل إرسال أي صف جديد
عند فقد الوصول. يُثبت فرع العمل في الحوار، وتحتفظ الدفعة بنتائج الصفوف
المؤكدة. يتطلب الرد الملتبس مراجعة السجل قبل إعادة الاستيراد.

تحميل السجل واختيارات مرشحاته للصفحة. يُراقب الفرع في القائمة، ويُراقب
المورد والعميل والفرع في المحرر باستخدام مالك ذاكرة الاختيارات.
يقرأ الطرف والبنك مباشرة. يملك الحوار تحميل خيارات الصرف والاستيراد
والتقرير والقيد. حُدّث دليل البنوك داخل التطبيق.

تطابق عمليات السجل والصرف والإلغاء شاشة سبيد 03 في لقطة ٢٨ أكتوبر
والمتحكمات `C0617` و`C0618` و`C0619` و`C0614`.
الأفعال ومفاتيحها موثقة من نقاط Sigma الفعلية. لا تغيير في المخطط أو
ترحيل القيد أو سياسة الحساب البنكي للصرف.

يشمل القبول المعلق تجربة صلاحية عرض فقط، وقيد في فرع عرض دون تسجيل،
وصرف فردي دون جماعي والعكس، وإلغاء الصلاحية وسط صفوف الاستيراد، ومراجعة
نتيجة استيراد ملتبسة دون إعادة إرسال الصف. في جولة البنود 171–180 بتاريخ
13 نوفمبر نجح بناء ServerAPI وAngular development وفحص TypeScript،
ونجحت 13/13 حالة محددة لمرشح HTTP وشجرة الاعتماديات، لا تشمل قبول كل
سيناريوهات الاستيراد والصرف. يظل HTTP الحي والمتصفح وEF relational
والطباعة/التصدير الفعلي معلقًا.
