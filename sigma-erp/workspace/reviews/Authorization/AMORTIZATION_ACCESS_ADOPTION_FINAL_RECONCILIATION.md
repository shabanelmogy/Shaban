## المطابقة

| الجزء | التنفيذ |
|---|---|
| route والتبويبات | سياسة `/Amortization` تفتح فقط لشريحة قابلة للاستخدام؛ التبويبات غير الممنوحة لا تظهر، والتبويب الحالي يعاد إلى أول شريحة متاحة |
| التحضير والتشغيلات | `beginRead` يملك متطلبًا صريحًا ويلغي القراءة عند سحب المنحة؛ الحفظ يحتاج Prepare + SaveRun |
| الجداول | مصادر الجداول وبياناتها تحت Sources + Schedules؛ الإنشاء يحرس Branch/Account lookup وAddSchedule، والحذف يحرس DeleteSchedule |
| الاعتماد والقيد والسجل | أفعال الصفوف والحوار تمر عبر View/ManageApproval/Journal/Log مع مدخلات الحراسة في `DocumentApprovalCycle` |
| الإلغاء والحذف والتصدير | Void/DeleteRun منفصلان عن القراءة؛ التصدير لا يعمل دون Prepare؛ أفعال الصف لا تظهر عند غياب المنحة |
| الخلفية | كل endpoint في `AmortizationController` يحمل `PermissionCatalogAction` مطابقًا للـresolver وكتالوج الاعتماد |
| العمر والسياق | revoke/regrant يلغي القراءات، ينظف مراقبات الاختيارات والنوافذ، ويحافظ على نتيجة الكتابة المرسلة دون إعادة |

## الأداء والحدود

لم يتغير query أو schema أو index، ولا يوجد قياس سرعة أو SQL plan أو قبول بصري
ضمن source-only.

## التحقق

أضيف اختبار عقد route مصدرّي، وحُدث جرد المسارات. ستُجرى فحوص الوصفات والوثائق
وJSON و`diff --check` وmerge markers فقط. لم تُشغّل الاختبارات أو build أو lint
أو browser أو DB أو migrations.

رسالة واجهة مقترحة:

`feat(authorization): adopt amortization workspace access guards`

تحديث ٨ نوفمبر: يفلتر الخادم الدفعة قبل إسقاط إجماليها. تفحص القراءة كل فروع
السطور المحفوظة واتساقها مع مالك الجدول. تحتاج إجراءات الدفعة إلى تسجيل الحركات
في كل تلك الفروع. أضيف حارس لتأكيد الحذف والرابط المباشر للاعتماد وخيارات التبويب.

لا هجرة أو DTO/AutoMapper أو تغيير مالي مطلوب. قبول المالك المعلق: حساب تحضير،
حساب تشغيلات، حساب جداول، سحب/إعادة منح أثناء lookup والاعتماد والكتابة، مع تحقق
RTL والثيمين وظهور loader.
