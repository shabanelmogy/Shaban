## تصحيح السجل الأولي

كانت هذه المصالحة قد أعلنت التبني قبل اكتمال مراجعة جميع الأحداث. حل هذا
التدقيق محل الوصف الأولي: تفاصيل التسليم تستخدم GetDetailById، واعتماد
الفاتورة يستخدم ManageApproval؛ لم نضف Approve إلى كتالوج العمليات. لا
تُستخدم أعداد الاختبارات والبناء التاريخية كدليل لهذه الدفعة. ترقية الجرد
هنا مصدرية فقط بعد إصلاح findings المراجعة، وليست قبول تشغيل أو قبولًا ماليًا.

## المطابقة النهائية للمفاتيح والمسارات

| المستهلك | المتطلب المثبت من خدمة الواجهة وcontroller/resolver |
|---|---|

| تعديل التسليم | GetDetailById + Update + OperationalSources + Branch.Lookup؛ تظل هوية الاتفاقية والمعدة والفرع مقفلة بعد initial denial/regrant وView→Edit |
| حذف تجهيز التسليم | View + Delete، وحالة canDelete وهوية الصف والتأكيد وإعادة الفحص |
| فلاتر العميل والفرع | Lookup اختياري لكل منهما؛ يُنظف النموذج والطلب والتصدير فور السحب وقبل الإرسال |

| القبض والروابط | Finance+Receipt.Create لإنشائه؛ Finance ومنحة الوجهة وسياسة مسارها لروابط القبض/اليومية؛ اليومية غير المتبناة تظل مغلقة للعادي |
| محرر الفاتورة القديم | Create للإنشاء الداخلي وView+Update للتعديل؛ الفواتير المولدة تبقى للقراءة فقط. مسار create القديم يعيد إلى التسليم ولا يفتح قائمة جديدة |
| قائمة/تفاصيل/تصدير/تقرير كشف التشغيل | TimeSheet.View؛ قراءة الاعتماد View أيضًا |

| إسناد مسار التفاصيل القديم | TimeSheet/details/:id يدخل edit فعليًا، لذلك يحمل متطلب التعديل الكامل؛ view/:id للعرض فقط |
| حذف كشف التشغيل | View+Delete مع فحص حالة الاعتماد والفوترة قبل التأكيد وقبل الإرسال |
| الإدخال اليومي | SaveBatch + مفتاحي مصدر التسليم، دون منح Create/Update ضمنية |
| قرار اعتماد كشف التشغيل | View+ManageApproval في المالك المشترك، مع فصل حجب السياق عن سحب المنحة |
| مرفقات كشوف التشغيل | متطلب المحرر في FileField؛ Upload+Delete للرفع وDelete للتنظيف في DocumentUploadTracker، وإزالة صف بمرفق تحتاج Delete أيضًا |

لم تتغير حقول القوائم أو ListVM أو عقود Add/Update أو AutoMapper أو الحسابات
في هذه الدفعة. احتُفظ بتوافق المال النصي والدقة الموجودين في نموذج مالية
الفاتورة مع CurrencyAmountJsonConverter الخلفي؛ لا سياسة مالية جديدة.

## عمر القراءة والمسودة والكتابة

- أُلغي كل finite read/export ومراقبة اختيار محمية عند سحب منحته أو انتهاء
  سياقه، مع إبقاء outer query triggers حية. لا revision غير متعلق يعيد GET
  تشغيليًا؛ تعود القراءة الناقصة مرة واحدة بعد إعادة المنح.
- يحتفظ سحب المنحة داخل السياق نفسه بالمسودة والسجل والمعاينة وسبب الإبطال.
  تُحجب الأسطح وSelect/DatePicker وMockData portals بمتطلب محررها الفعلي.
- يعيد restoreReads/lookupsReady اختيارات المحرر ومصدر التسليم الناقص، حتى
  إذا جاءت إعادة المنح أثناء Save ثم فشلت الكتابة؛ لا يعاد إرسال Save.
- انتهاء actor/token/tenant/working context يحجب الجلسة القديمة ويمسح outputs
  القديمة. لا يهدم والد الحوار محررًا يملك كتابة مرسلة؛ يبقى حتى ينتهي أو
  يغلق محليًا. تستبقي المرفقات مالكها حتى بعد هدم FileField داخليًا.
- التأكيدات كسولة، مع إلغاء القرار القديم إلى false وفحص المنحة والحالة
  والسياق قبل الإرسال. discard محلي جديد بعد denial/انتهاء السياق متاح؛
  لا يحذف ملفات السياق القديم. الكتابة والتنظيف المرسلان مستقلان عن notifier
  القراءة، وتُحجب ردودهما عن سياق جديد.
- بقي Receipt المضمن mounted تحت EditorDialog. close/escape يفوضان إلى
  مالكه الفعلي مع operationBusyForExit، بدل حظر الإغلاق دائمًا أو هدمه بالسحب.
- أُلغيت طباعة كشف التشغيل المؤجلة عند سحب View، حتى بعد انتهاء GET وقبل
  animation frame. نافذة طباعة فُتحت فعلًا تبقى مملوكة للمتصفح.

## الخلفية والفروع

ثبت من مسار الخدمات أن DeliveryNote.GetDetailById وOperationalSources و
EquipmentRentalInvoice.Preview وFinance لا تكتب بيانات. أضيفت إلى
WholeDocumentReads في BranchOperationRules: عرض كل فروع المستند، دون
عرض جزئي لمستند متعدد الفروع. تظل Generate وManageApproval وVoid تحت
تسجيل الحركات. أضيفت حالات مصدرية إلى BranchOperationRulesTests للقراءتين
من كل controller ولثلاث عمليات كتابة مضادة. لا schema أو migration مطلوب
لهذا التصنيف؛ القرارات المالية والمخطط المعلقة في checkpoint مستقلة.

## التحميل والكاش والأداء

| المسار | المالك والمطابقة المصدرية |
|---|---|
| قائمة/تصدير التسليم وكشف التشغيل | LoadingService الصفحة مع start/finalize؛ switchMap للقائمة وإلغاء التصدير المركب |
| bootstrap فلاتر التسليم | ReferenceLookupStatus بمالك الصفحة؛ Branch/Customer مصادر opted-in فعلًا عبر cacheSelect=true |
| اختيارات الفروع والعملاء | finite bootstrap ثم ReferenceLookupBindings/watch؛ invalidation عند الكتابة/الموضوعات وعند access revision عبر مالك الكاش، مع مسح السياق وRetry |
| اختيار التسليم لكشف التشغيل | GET DeliveryNote/GetSelect مباشر، دون cache opt-in؛ لا watch إضافي مصطنع |
| مصدر التسليم/OperationalSources وتفاصيل الفواتير/Finance/Preview | قراءات تشغيلية مباشرة غير مخزنة؛ تقدم الحوار المحلي وحالة الخطأ/Retry القائمة |
| قراءات الاعتماد | DocumentApprovalCycle مع localReadProgress داخل الحوار؛ نفس المالك المشترك للقراءة والقرار |
| الحفظ والتوليد والقرارات والحذف | busy/saving في المالك الحالي وLoadingService، مع finalize واستقلال الإرسال |

أُزيل تكرار القراءات من revisions غير المؤثرة؛ هذا دليل مصدر، وليس قياس
سرعة. التوقيت والحجم وخطط SQL لم تُقَس. لا استعلام مجال أو predicate/join/order
تغير، لذلك لا فهرس جديد مقترح لهذه الدفعة؛ يظل قياس الأداء والتصدير الحقيقي
مع المالك. effective loader visibility والطبقات والثيمان والموبايل لم تُقبل
على تطبيق عامل.

مباشر لهاتين الشاشتين؛ لم يُدَّع قراءته أو قراءة بقية كودهما. مرجع Odoo
المحلي متاح كمكمل؛ لا يحدد مفاتيح Sigma أو عمر سياستها ولا يلزم مفهوم مجال
جديد لتوصيل هذه الدفعة. الأدلة الخارجية لا تثبت إنفاذ الخادم.

## التحقق والحدود والجرد

- فُحص scoped diff منفصلًا في مستودعي الواجهة والخلفية، والملفات الجديدة
  untracked مباشرة؛ فُحصت namespaces ومراجع المشروع وإدراج spec.
- نجح git diff --check في النطاق، بتحذيرات EOL فقط، ولم تُرصد merge markers.
- فحص الوصفات الثماني -Check: كلها OK. لم تُعدل أي وصفة مولدة.
- أضيفت/وسعت مواصفات سلوكية للتسليم، الفوترة، تاريخ الفواتير، مالية الفاتورة،
  تفاصيلها، كشوف التشغيل ومصادرها ودفعتها، وسياسة المسار وتصنيف الفرع.
  لم تُشغّل هذه المواصفات. اختبارات قوالب مبسطة لا تثبت DOM؛ اختبار والد
  Receipt يستخدم طفلًا بديلًا يملك اشتراكًا، وليس قبولًا لـReceipt الحقيقي.
- الجرد الآن١٩operation-confirmed و١٣٧resource-only و١٠٢unknown و٢context-only
  و٢alias بإجمالي٢٦٢بندًا. يوجد٢٥٩اسم مسار مميز؛ تكرارات BillDetail وProvision
  وProvisionDetail سابقة لهذه الدفعة ومحفوظة كمتابعة جرد، وكلها خارج الشرائح
  المؤكدة. إنه دليل تبنٍّ مصدري؛ بقية الهدف ما زالت active.
- لم تُشغّل builds أو tests أو lint أو browser أو DB أو migrations/snapshots
  أو commits/push/deploy. لا ترقية لنتائج التشغيل التاريخية إلى هذه الدفعة.

قبول المالك المطلوب: البناء وتشغيل المواصفات، وتجربة مدير وعادي بمنح
جزئية، وإسنادات الفروع، وسحب وإعادة المنح مع محرر/سبب/Receipt/رفع/حفظ
معلق، وقرار خروج مفتوح، وتقرير اكتمل قبل الطباعة، وروابط قديمة، وloaders
والاتجاه والثيمين والموبايل. لا Add-Migration لهذه التعديلات.

استُخدم العاملان الحاليان بملكيات منفصلة للفواتير وكشف التشغيل، ومراجع
مصدر مستقل؛ الجذر جمّد العقد وراجع الفروق ودمج التصحيحات النهائية والخلفية
والمسارات والجرد والدليل. استُخدموا لتوازي مسارات مستقلة دون نسخ اكتشاف
الحل؛ لم تُنشأ عوامل جديدة أو تتداخل ملكية الكتابة، والنماذج موروثة.
