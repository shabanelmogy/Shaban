## المصدر والقرارات

القائمة الفعلية: مسار MasterAgreement ومكوّن MasterAgreement/components/list.
تتبع خدمة MasterAgreementService نقطة RentalMasterAgreement، وليس
AgreementController العام. الشكل UI02 وفق الكتالوج، ومرجع قائمة Workshop/Job
للعنوان والمرشحات والجدول، مع مالكي ActionList/DataTable/ReferenceLookupStatus
الحاليين. تطبيق LeaseMasterAgreement مرجع تبنٍّ للمنح ودورة القراءة وليس
بديلًا عن الكتب. قُرئ شرح S269 والمتحكم المؤرخ C0950؛ تفاصيل الطباعة
والتسليم المرجعية غير الموجودة ليست عمليات تمت إضافتها في هذه الشريحة.

الأعمدة: masterAgreementNo المحسوب من no/id، date، customerName، customerCode،
quotationNo، approvalStatus. عقد ListDTO: id، no، date، approvalStatus،
customerName، customerCode، quotationNo. لا بيانات إضافية للسرية في القائمة.
مرشحات الرأس: الرقم والحالة ومرجع العرض والفترة والعميل، مع grid filters
والصفحات والترتيب من المصدر المطبق لا قيم نموذج لم يُبحث بها بعد.

## المطابقة المصدرية

| المجال | المالك والدليل | النتيجة |
|---|---|---|
| العرض والمسار | rental-master-agreement-access، RouteAccessPolicyRegistry | View للقائمة والتفاصيل، Create مع RentalQuotation.View فقط؛ أضيف الماستر لبدائل صفحة الدخول |
| الأفعال | ActionList<MasterAgreementGridRow>، canAct | المنحة مع حالة الصف وعضويته الفعلية وعدم الانشغال؛ إعادة فحص بعد التأكيد |
| قراءة القائمة | listRequests/switchMap ثم denied$ داخل الطلب | يبقى المحفز حيًا، وتلغى القراءة القديمة؛ هوية الممثل والتسلسل تحرسان النشر |
| سحب وإعادة المنحة | مراقب denied$ دائم حتى أول سحب مع interrupted/recoveryPending | رصد السحب والإعادة في نفس tick، إخفاء وإخماد المحتوى وغلق بوابات الاختيار والتاريخ |
| التحميل | LoadingService للقائمة والتصدير والكتابة، ReferenceLookupStatus لخيارات العملاء | مالك صفحة مرئي واحد؛ تحرير كل قراءة بمالكها، والتحديث المحتفظ به صامت |
| الكاش | CustomerService/BaseService وخيار الشركة opted-in، ReferenceLookupBindings | bootstrap محدود ثم watch منفصل، unbind عند المنع وتحديث المرجع، الاحتفاظ باسم المختار لنفس الممثل فقط |
| التصدير | getAllList/fetchAllPages مع صورة المرشحات المطبقة | جميع الصفحات؛ إلغاء التركيب كاملًا قبل إخراج الملف عند المنع/المغادرة |
| التأكيد | defer/denied$/destroy/finalize | لا نافذة جديدة بلا المنحة، ولا كتابة بعد انتهاء التأكيد، وإطلاق busy عند الإلغاء |
| الكتابة المرسلة | trackWrite وHttpContext CAN_PRESENT_API_OUTCOME | لا إلغاء بواسطة denied$/destroy؛ تقفل نتيجة السياق القديم فقط، ويُثبت النجاح قبل حجبه |
| منع التكرار | WeakSet مكتمل للأفعال على كائن الصف الفعلي | لا يعاد فعل ناجح على نفس الصف عند سحب المنحة وإعادتها |
| المسارات | MasterAgreementRoutes وسجل السياسة | create-only لا يفتح View، وView لا يحتاج قراءة عرض السعر المصدر المحفوظ |

لا lookup HTTP لكل صف أو قرار صلاحية HTTP إضافي. لا كاش تشغيلي جديد ولا
حساب مالي أو مخطط جديد. قراءة العملاء اختيارية ومفصولة عن قدرة قراءة
القائمة؛ عند غيابها لا تُطلب خيارات العملاء. لا مؤشر أداء مقاس أو فهرس
جديد؛ مصدر الطلب والحد الأقصى للصفحات الحالي محفوظ، وقياس الشبكة/SQL للمالك.

## دليل التطبيق والتحقق

أُضيفت إرشادات عربية وإنجليزية إلى موضوع Master agreements في
UserGuide/content/rental-guide.ts، وصُححت ملاحظة كانت تنفي الاعتماد رغم وجوده
في القائمة. يبقى دليل الوحدة الحالي تحت UserGuide ومسار MasterAgreement؛
لا route أو عنصر قائمة دليل جديد.

كُتبت مواصفات لسحب/إعادة المنحة في نفس tick، ومنع فتح التأكيد بلا منحة،
وإلغاء القرار دون replay، واستمرار الطلب المرسل بعد destroy مع حجب النتيجة.
وتوجد مواصفات فصل Create عن View وصفحة الدخول لمستخدم يملك View فقط.
لم تُنفذ المواصفات. فحص النحو والاستيرادات المحلية الأولي شمل12ملفًا دون
تشخيصات، وليس typecheck أو build أو قبول واجهة. المراجعة النهائية بعد دمج
الخلفية والأب والطفل باقية في تقرير المطابقة العام؛ لا ترقية للجرد في هذا التسليم.

الملفات ذات الملكية: قائمة الماستر ومواصفاتها، ملف المتطلبات، المسارات،
خدمة الماستر لتمرير HttpContext للأفعال، السجل والدليل. لا تعديل لملفات
الطفل أو الخلفية من الجذر أثناء عمل الزملاء. لا اختبارات أو بناء أو متصفح
أو DB أو هجرات أو commits/push/deploy نُفذت في شريحة الصلاحيات الحالية.
