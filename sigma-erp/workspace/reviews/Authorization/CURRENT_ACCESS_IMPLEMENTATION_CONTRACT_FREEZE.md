## القرارات

١. مدير الشركة هو صاحب claim Admin/SuperAdmin الموقّع مع ربط ERP نشط مطابق
داخل الاشتراك؛ اسم دور ERP لا يصنع مديرًا. يظل الخادم مالك رفض أي عملية
مجال غير صحيحة أو خارج المستأجر. المستخدم العادي محكوم باتحاد منح الأدوار
النشطة والمنح المباشرة؛ لا توريث تلقائي بين CRUD ولا Deny جديد.

٢. واجهة ذاتية جديدة `GET /Authorization/me` تحتاج JWT وتقرأ صاحب الطلب
فقط؛ لا userId/subscriptionId مدخلان. لا توضع تحت سياسة TenantAdmin الخاصة
بمتحكم الإدارة. DTO النجاح، ضمن Result المعتاد:

```typescript
interface CurrentAccess {
  identityUserId: string;
  subscriptionId: number;
  erpUserId: number;
  isTenantAdmin: boolean;
  permissionKeys: string[];
  revision: string;
}
```

يرجع401 لغياب/بطلان الجلسة، و403 مع Result.errors يحتوي كودًا ثابتًا عند
فشل الرابط أو النشاط: AuthorizationIdentityNotLinked، AuthorizationActorUnavailable،
AuthorizationIdentityMismatch. لا مفاتيح أعمال عند الفشل. لا API إدارية أو
snapshot مستخدم آخر بديلًا عن هذه القراءة.

٣. قارئ المنح مشترك بين التقييم ولقطة الجلسة ومعاينة الإدارة حيث يلزم؛
يحافظ على SubscriptionId والحذف ونشاط الدور ومطابقة Module/Action/Key.
تُصفّى اللقطة بالكتالوج القابل للإسناد. revision مشتق بلا مخطط جديد.

٤. يضاف Self access إلى الاستثناء الذاتي المتحقق داخليًا. وبعد التحقق
من ربط ERP، تكون CurrentBranch وLanguage.Options وLocalization.Runtime
تهيئة سياق/لغة ذاتية لا تمنح إدارة اللغات أو تعديل الترجمة أو بيانات شركة
أخرى. تُستبعد استثناءات الهيكل من مفاتيح المنح القابلة للإسناد. لا استثناء
عام لكل Lookup أو كل GET. لا يمنح MockData.Settings تلقائيًا للمستخدم العادي.

٥. Angular يملك CurrentAccessService واحدة للجلسة؛ تخلي اللقطة عند تغير
المستخدم/الاشتراك، وتمنع أثر رد متأخر، وتشارك الطلب الجاري. لا HTTP لكل
زر، ولا تخزين المنح في JWT/localStorage كقرار دائم. لا عرض محمي حتى ready.
قراءة السياسة تفشل مغلقة مع Retry؛ غياب الرابط له رسالة واحدة مستقلة.

٦. حارس وخرائط صريحة مشتركة للقوائم والمسارات والاختصارات. لا استنباط
permission من النص أو اسم الزر أو طريقة HTTP. تعالج aliases وعمليات
التقارير والإعدادات بعقد المصدر الفعلي. المسار المجهول محجوب للعادي؛
الدور/المستخدم محميان بإدارة TenantAdmin القائمة. UserGuide والإرشادات
المحلية وصفحة عدم الصلاحية سياق معلن. dashboard يشترط Dashboard.Snapshot؛
عند غيابه يبدأ المستخدم بوظيفة مسموحة أو صفحة لا وظائف، ولا يطلب dashboard.

٧. مالكو ActionList وButtonModel والأزرار المشتركة يضاف لهم شرط permission
صريح مع استمرار visible/disabled الخاصين بحالة السجل. موجه shared للإظهار
يستهلك نفس القرار. تبني الشاشة يجب أن يربط المفتاح الحقيقي لكل فعل؛
المفتاح المجهول لا يمنح للعادي. لا يكفي إضافة الموجه دون تبني المستهلكين.
يحافظ canDeactivate وعمر الكتابات المرسلة على عقدهما؛ لا تجاوز خروج قسري.

٨. تحديث الجلسة بعد حفظ مؤثر محليًا، وعند عودة التركيز، ومرة واحدة بعد403،
وبحد تحديث٦٠ ثانية أثناء نشاط التطبيق. الخادم يطبق المنع في كل طلب؛ عرض
الواجهة قد يتأخر حتى التحديث. 403 لا يعني انتهاء الدخول ولا يعاد إرسال
الكتابات تلقائيًا. تحديث policy لا يفتح المستخدم التالي من لقطة السابق.

٩. الحساب القديم الظاهر في الصورة غير مربوط؛ لا ربط بالبريد ولا إنشاء
ملف ERP أو إسناد دور أو تغيير كلمة مرور ضمن هذا العقد. الحسابات المرتبطة
التجريبية السابقة تستخدم لاختبار المدير والعادي والعزل.

١٠. لا صلاحيات حقول حساسة/نطاق فروع جديدة دون عقد المجال، ولا أهلية خطة
اشتراكات ضمنية. يبقى ذلك في التصور الأوسع. لا migrations أو snapshots
أو commit/push/deploy. البناء والاختبار والمتصفح والبيانات التجريبية ضمن
تفويض المالك المستمر لهذا المسار. يضاف دليل الشاشة وتحديث الكتب/المهارة
والحزم بعد تحقق السلوك المشترك.

## خطة التنفيذ والملكية

- عمل الخلفية: قارئ الوصول الحالي وDTO والمتحكم وحارس الطلب والكتالوج؛
  اختبارات HTTP تبدأ بإثبات غياب المسار/القراءة، ثم قيود الربط والمنح والسحب.
- عمل الواجهة: خدمة وguard وموجه وخريطة ونقاط التنقل والمالكون المشتركون
  وحالات البداية والخطأ والدليل؛ اختبارات قبل المصدر للتقييم والجلسة
  والخرائط/الحراس، ثم قبول متصفح للمدير والعادي ومنح العرض فقط.
- عمل التكامل للجذر: مقارنة خرائط المستهلكين بالمنتجين، مراجعة الفروق
  المنفصلة، بناء وقبول تشغيل، وتقرير تبنٍّ صريح وقرارات غير مشمولة.

يجوز فصل الخلفية والواجهة بعد هذا العقد بملكية ملفات غير متداخلة. لا تعديل
كتاب أو مهارة أو أثر مراجعة بواسطة العامل؛ الجذر يملك المصادر المشتركة
والتوثيق والتكامل. تحفظ كل تغييرات المستخدم/النظير السابقة في المستودعين.
