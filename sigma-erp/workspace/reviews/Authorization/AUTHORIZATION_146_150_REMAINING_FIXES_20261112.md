## عقد المعالجة المعتمد

- قرار التجاهل في محرر اتفاقية المعدات وحوار أوامرها مستقل عن نسخة قراءة البيانات. سحب الصلاحية أو انتهاء السياق يلغي القرار المفتوح ويعيد false ويحرر حالة الانتظار. يظل طلب تجاهل محلي جديد أثناء المنع ممكنًا؛ لا يُلغى حفظ أُرسل للخادم.
- تُغلق قوائم Select المفتوحة عند فقد حق الكتابة وتغير الهوية وإغلاق حوار الأوامر؛ تبقى المسودة ومالكتها مركبتين. يُستخدم hide من API الحزمة المثبتة، دون تغيير المكتبة أو مالك الحوارات المشترك.
- فلتر contactId مصدره Customer.Lookup؛ حركات الورشة التي لا تحمل علاقة عميل لا تطابقه. تُستبعد عند وجوده، دون مطابقة SupplierId بالعميل أو تغيير عزل الفرع أو الحجب أو Count/Excel/Report.
- لا تغيير لمنح أو DTO أو قواعد مالية أو مخطط قاعدة البيانات. تُكتب مواصفات سلوكية للمسارات المهمة دون تنفيذها، وتُفحص الصياغة والاستيرادات والفروق فقط. لا يُدّعى RED/GREEN.

## الملكية وخطوات التنفيذ

الجذر يملك محرر الاتفاقية والدليل والتكامل والمطابقة. مسار مستقل للخادم يملك شرط الورشة ومواصفاته فقط؛ ومسار مستقل للواجهة يملك حوار أوامر البيع ومواصفاته فقط. لا تداخل ملفات. العقود المجمدة السابقة وUI26/28 ومالكو القرار والنموذج وSelect الحاليون هم المرجع؛ لا تصميم أو قرار جديد لإعادة اعتماده.

بعد الدمج يُراجع الجذر الفروق في المستودعين ويتتبع السيناريوهات الثلاثة، ثم يُحدّث هذا السجل بنتيجة التحقق والقبول المتبقي. دليل سبيد وكوده المؤرخ وشكل UI02/UI09 قرئت في المراجعة الأصلية؛ الإصلاح يعيد التنفيذ إلى العقد نفسه ولا يوسع دورة الأعمال.

API المثبت محليًا في PrimeNG 21.1.10 يعلن `hide(isFocus?: any): void` في `types/primeng-select.d.ts:703`؛ هذه هي بينة الاستدعاء، وقبول المتصفح مستقل.

## نتيجة التحقق النهائي

أُغلقت R1 وR2 وR3 في المصدر، وانتهى التدقيق المستقل دون ملاحظة مؤكدة باقية في نطاق هذه الإصلاحات. في حوار الأوامر أُضيف أيضًا شرط ملكية كامل قبل استعادة النموذج: الاتفاقية والفاعل والجلسة والمكوّن الحي؛ تبديل الاتفاقية يلغي القرار السابق ويمسح صفوف مسودته قبل تحميل الاتفاقية الجديدة. رجوع الصلاحية أثناء قرار محلي بدأ في حالة المنع لا يفك تجميد النموذج قبل حسمه، ثم تستعاد قابلية الكتابة والخيارات عند إلغاء القرار. طلبات الحفظ المرسلة تظل مستقلة.

الفحوص المنفذة بعد آخر تعديل:

- تحليل صياغة TypeScript وقوالب Angular والاستيرادات المحلية على ٨ ملفات: ٧٩ مسار import و٩٣ اسمًا محليًا، دون issues. ليس typecheck أو بناء.
- تحليل Roslyn نحوي لملفي خدمة سجل الحركات ومواصفاته، دون أخطاء syntax؛ لا تجميع دلالي أو EF/SQL acceptance.
- فحص XML لمشروع الاختبارات وتضمين مصادره الافتراضي. ملفا مواصفات Angular الجديدان تحت نمط tsconfig.spec، وغير مضافين لقائمة ملفات التطبيق الصريحة.
- مراجعة الفروق المحصورة في المستودعين والملفات الجديدة غير المتعقبة؛ فحص المسافات وmerge markers سليم، مع تحذيرات LF/CRLF المعتادة فقط. تغييرات HTML الموجودة قبل هذه الشريحة حُفظت ولم تُكتب ضمنها.
- كتابة ١٢ حالة سلوكية جديدة دون تشغيل: ٦ لقرار محرر الاتفاقية، و٥ لحوار الأوامر ومنتقيه وتبديل هويته، وحالة للخدمة الفعلية تثبت ظهور حركة الورشة دون فلتر العميل واختفاءها معه من الصفوف والعد. لا ادعاء RED/GREEN أو نجاح تنفيذ.
- الحزم الثماني: OK. لا تغيير كتب أو تعليمات أو حزم مولدة في هذه الشريحة.

لم تُشغّل builds/tests/typecheck/lint/browser/HTTP/DB/migrations/snapshots/commit/push/deploy، ولا Sigma MCP أو Graphify. لم تتغير أعداد الجرد أو بيانات التجربة. لا هجرة مطلوبة، ولا قرار مالي أو API مؤجل يمنع إكمال هذه التعديلات المصدرية. بقي قبول البناء والتشغيل والتنفيذ الفعلي للمواصفات عند المالك.

## قبول المالك المتبقي

1. مسودة متسخة، ثم قرار تجاهل، ثم سحب صلاحية القراءة: يُغلق التأكيد ويُحرر الانتظار، وتظل المسودة. أعد المنحة، وجرّب تجاهلًا محليًا بدأ أثناء المنع ثم رجعت الصلاحية قبل حسمه؛ يبقى النموذج مجمدًا حتى الحسم.
2. قائمة اختيار أمر بيع مفتوحة، ثم سحب UpdateSaleOrders وحدها: تُغلق فورًا ولا يغيّر اختيار قديم المسودة. لا يُمنع اكتمال كتابة سبق إرسالها.
3. قرار مفتوح على اتفاقية، ثم استبدال هوية الحوار باتفاقية أخرى: لا صفوف من القديمة ولا أثر لإجابة التأكيد القديمة.
4. سجل الحركات مع حركة ورشة مسموحة: تظهر دون عميل محدد، وتُستبعد عند تحديد عميل من النتائج والعد والتقرير وExcel.
