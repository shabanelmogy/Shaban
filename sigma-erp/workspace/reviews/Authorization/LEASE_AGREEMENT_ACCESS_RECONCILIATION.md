## عقد التنفيذ والتوزيع

المرجع [العقد المجمد](LEASE_AGREEMENT_ACCESS_CONTRACT_FREEZE.md).
الجذر يدمج القائمة والمنح والخدمة وregistry والدليل والجرد، وعامل مستقل
للخلفية، وآخر للمحرر ومساراته، وثالث للحوارات. الملكيات غير متداخلة
والعمل في checkout القائم للحفاظ على التغييرات السابقة. استُخدمت أدوار
sol_worker الثلاثة لأن الوحدة تضم محررًا كبيرًا و١٤ حوارًا ومسارات خلفية
مستقلة بعد تجميد العقود؛ التدقيق والدمج النهائي عند الجذر. لم تُشغّل
أوامر التنفيذ المحظورة، ولا تُعد نتائج العاملين وحدها إثبات إقفال.

## حدود التحقق

الفحص المسموح parsing/import existence/XML/scoped diff فقط؛ المواصفات
تُكتب ولا تُشغّل. تبقى اختبارات التنفيذ والبناء وفحص الأنواع والواجهة
وقاعدة البيانات والملفات والسباقات عند المالك. فحص الحزم الثماني الأول
سليم؛ لا صيانة كتب مشتركة أو تغيير schema مقصود. نتائج الدفعة النهائية
وتفاصيل إصلاح findings وتحديث الجرد تُثبت هنا بعد انتهاء التدقيق.

دفعة الجذر المحددة قبل دمج الحوارات: فُحص نحو١١ ملفًا وقالبًا و١٣٩
استيرادًا محليًا بلا مشاكل، وطُوبق٦٧ مفتاح ترجمة من قائمة العقود في
الإنجليزية والعربية بلا مفتاح مفقود. لا typecheck أو template binding
compilation أو test runner؛ parsing وحده لا يثبتها.

## النتيجة النهائية والقرارات

اكتمل تبني العمليات الفعلية للقائمة النشطة والمغلقة ومحرر العقد العام
وحواراته الأربعة عشر، مع إبقاء عقد المصدر المضمّن المقفل سابقًا.
فُصلت منح القراءة والكتابة والخيارات والأفعال في ملف واحد مستهلك من
القائمة والمحرر والـregistry؛ Create مستقل عن View، وView لا يطلب
لوكات الكتابة. Edit يضيف مصدر التعريفة المستهلك فعلًا. التأمين يضيف
تفاصيل طريقة الدفع وسياسة العملة المستهلكتين، والمرفقات بمنح Media
الاختيارية ومتعقب الرفع القائم. Activate مرفوض405 وغير قابل للإسناد.

الحوارات مثبتة عند المنع، مع حجب محتواها وعنوان السجل، وبقاء التجاهل
المحلي. تنتهي هوية الممثل/المستند نهائيًا، وتلغى القراءات والقرارات
والبوابات والتوليد والتركيز والطباعة؛ استعادة نفس الممثل تحفظ المسودة
وتعيد السياق والخيارات المطلوبة بعد busy tail. الحفظ المرسل مستقل
عن destroy/denial، ونجاحه يثبت قبل نشر النتيجة. التأمين يحتفظ بمجموعة
ملفاته المحفوظة حتى لو حُجبت نتيجة السند؛ لا discard لها ولا سند ثانٍ.
يمكن رفع أكثر من وثيقة صراحة، وتبقى controls مرتبطة بالصف الصحيح حتى
إذا فشل تحديث metadata، مع Retry يدوي بلا حلقة إعادة طلب.

الخلفية تحرس المراجع الحية والشركة في القائمة والبحث والترتيب والتفاصيل
والسياقات، والتفاصيل أصبحت NumberedDetailBaseVm دون حقول tenant/audit.
إسقاط AutoMapper للقائمة بقي اتجاه قراءة واحدًا مع حراسات مرجعية؛
الحفظ وحساب الأموال عند مالكهما الحالي، ولم تُغير صيغة الحساب.
سجل الفوترة يشترط استعراض كل فروع إيصالاته قبل التجميع الكامل، فلا
يُعرض Received/Due محسوبًا من مجموعة إيصالات جزئية.

وثائق العقد تحفظ خارج wwwroot، والمسار العام القديم محجوب. ربط الملف
يتحقق من وجوده ورافعه وtenant تحت قفل مشترك مع الحذف. تمنع Media حذف
أي path claimed، ويتولى cleanup داخلي إزالة الملف المستبدل غير المطالب
به حتى لو كان رافعه مستخدمًا آخر. لا endpoint قراءة مخترع ولا migration.
القفل مصدرّي؛ اختبار السباق الفعلي والتخزين والـDI ما زال عند المالك.

## التحقق النهائي وحدود الأداء

فُحص نحو٦٨ ملفًا/قالبًا و٥٣٩ استيرادًا محليًا بلا مشاكل، و٣٨٧ مفتاحًا
ثنائي اللغة بلا مفقود. نُفذ XML parsing لخمسة مشاريع وملفي موارد، وفحص
الحزم الثماني سليم. روجعت الفروق المحددة في المستودعين، وفحص whitespace
بلا أخطاء؛ التحذيرات LF/CRLF فقط. الملفات الجديدة غير المتتبعة قُرئت
وفُحصت مباشرة؛ لا اعتماد على git diff لإثبات محتواها.

المواصفات المصدرية موجودة ولم تُشغّل:٢١ حالة قائمة،٩ وثائق،٧ تأمين،
٦routes،٧helper،٤logs،٣٠مصدر/محرر مشتركة، وحالات نقل سياق mutation
معلّمة١٥ في loop واحد، مع المواصفات الخلفية الخمس. الأخيرة الخاصة
بـstorage contract reflection-only، ولا تدعي اختبار filesystem أوDI أو
claim/delete. لا اختبارات RED/GREEN أو build/typecheck/runtime ناجحة مُدعاة.

المسارات العادية bounded count+page projection وAsNoTracking، ولا
enrichment per-row جديد. إلغاء لوكات View غير المطلوبة وإبقاء refresh
المرجعي لدى المالك المشترك دليل طلبات مصدرية فقط. لا قياس سرعة/SQLplans
أو IO؛ يلزم مقارنة نفس tenant والمرشحات وحجم البيانات وcold/warm cache
وقياس initial usable/settled load ثم paging/detail/export. لا index
جديد مبرر من المصدر وحده؛ تحقق الخطة/التداخل والكلفة قبل schema.

## الدليل والجرد وقبول المالك

حُدث دليل التطبيق الثنائي:
`SiGmaAngularFrontEnd/src/app/modules/UserGuide/content/lease-guide.ts`.
يستهلكه GuideReader كـLEASE_GUIDE، id=lease، عبر مسار UserGuide القائم؛
موضوعا العقود والقائمة المغلقة يشرحان الإسناد والفروع والسحب/الإعادة
والملفات والإجراءات. لا reader/menu جديد.

رُقي صفا LeaseAgreement وclosedLeaseAgreements فقط. أصبح الجرد
١٢٩ operation-confirmed /٧٣ resource-only /٥٧ unknown /٢context-only
/٢alias=٢٦٣baseline، والمتقاعد٧. لا اكتمال عام للتطبيق. الاستكمال التالي
هو دورة الإيجار Rental، بدءًا بعرض السعر وتوابعه حسب الجرد، دون إعادة
الوحدات المقفلة. مراجعة المالك مجمعة في النهاية.

قبول المالك يشمل إسناد كل read/write منفردة، الحساب الإداري والعادي،
كل فروع المستند والتحويل، initial-denied وrevoke/regrant سريع ومتكرر،
تبديل الحساب/id مع route reuse، الحفظ/رفع الملفات بعد السحب والهدم،
Metadata failure ثم رفع ثانٍ وRetry، وحفظ التأمين ثم سحب الوصول والتجاهل.
تُفحص الأخطاء/التحميل/لوكات الاختيار وRTL/theme/keyboard والبوابات والطباعة.
إذا سُحبت منحة تنظيف المرفقات يبقى الخروج المحلي متاحًا دون حذف؛ قد
تترك رفعات غير مرتبطة تحتاج تنظيفًا من مالك التخزين. لا توجد آلية انتهاء
تلقائي جديدة مُدعاة في هذه الشريحة، ولا يتعرض ملف السند المحفوظ للحذف.
لا schema جديد ولا Add-Migration مطلوب في هذه الشريحة. لم تُشغّل أوامر
بناء أو tests أو lint أو typecheck أو browser أو DB أو migrations أو
commit/push/deploy، ولا Sigma MCP أو Graphify أو full-solution scan.
