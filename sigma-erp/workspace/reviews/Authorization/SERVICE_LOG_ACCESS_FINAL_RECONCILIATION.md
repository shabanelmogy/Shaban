# مطابقة صلاحيات سجل الخدمة وفرع التنفيذ

تحديث ٩ نوفمبر: صيانة [إلزام فرع التنفيذ](WORKSHOP_REQUIRED_EXECUTION_BRANCH_CONTRACT_FREEZE.md)
تستبدل توافق nullable للبيانات التجريبية المسجل أدناه. راجع مطابقة الصيانة
قبل إعداد مخطط التشغيل؛ لا backfill تخميني أو استثناء سجل بلا فرع للمدير.

## العمليات الفعلية

المتحكم ServiceLogController مخصص؛ مفتاح القائمة والرابط والبحث والفرز
والترقيم `ServiceLog.Search`، ومفتاح POST `ServiceLog.Add`. لا يستعمل
المتحكم العام ليُسمى View/Create. الإنشاء في الواجهة يحتاج أيضًا البحث
واختيار المركبة Vehicle.Lookup. Workshop.Lookup وVehicleService.Lookup
للاختيارات الاختيارية فقط، لا يمنع غيابهما إنشاء سجل بلا تلك القيم.
عرض الصف من لقطة DTO الحالية ولا يبدأ تفاصيل أو lookup؛ يثبت الوالد
عضوية الصف وهويته وسياقه قبل فتح الحوار. ليس هناك Edit/Delete/Print/
Export في هذه الشاشة؛ منفذ GetAllWithNavigations القديم له منحة مستقلة
وتصنيف قراءة صريح بالخادم، ولا يحول إلى bypass لقائمة المستخدم.

يتم تصنيف Search وGetAllWithNavigations كقراءة مستند كامل، وAdd كتابة.
يظل PermissionEndpointResolver/ReviewedPermissionOperations مالك المنح
الخادم، وBranchOperationRules مالك read/transaction context. لا مخبأ
صلاحيات جديد ولا أدوار حرفية في الشاشة.

## قرار الفرع والمنتجون

اعتمد المالك حفظ فرع التنفيذ وقت التسجيل. يضاف BranchId nullable إلى
WorkshopMovement للاحتفاظ بالسجلات القديمة بلا تخمين. كل سجل جديد
يتطلب فرعًا نشطًا من نطاق التسجيل؛ لا يغيره انتقال المركبة ولا UpdateVM.
يختار المستخدم من CurrentBranchService.options المسندة للتسجيل، مع
افتراضي صالح فقط، ولا طلب اختيار Branch أو منحة Branch.Lookup جديدة.
يحتاج تحديث عداد المركبة أيضًا صلاحية تسجيل فرع المركبة الحالي.

المنتجون المباشرون: ServiceLogService.Add، وWorkshopMovementService.Add،
وFleetAlertsService.CompleteVehicleService. تشمل الشريحة هذه الحدود وDTOs
وحقول اختيار الفرع في واجهة حركة الورشة وإتمام التنبيه، وList/Detail
BranchId/BranchName المحفوظين. لا يعني ذلك اكتمال تبني كل أفعال وحدتي
حركات الورشة أو التنبيهات؛ لهما صفوف مستقلة غير مرقاة في الجرد.
يُسجل تدقيق باقي قراءات root وbypasses في تسليم الخلفية.

تخزين مطلوب من المالك: هجرة مقترحة `AddWorkshopMovementExecutionBranch`
لحقل nullable وFK Restrict مع Branch وفهرس SubscriptionId/BranchId/DateOf.
لا backfill بفرع المركبة الحالي؛ تبقى السجلات غير المثبتة للمدير إلى
إسناد مالك البيانات الصريح. لا تُشغّل المسارات الجديدة قبل تطبيق مخططها.
لم تُنشأ هجرة أو يعدل snapshot أو تنفذ DB commands في هذا العمل.

## المصدر والتحميل والمرجع

قائمة مباشرة بمالك الصفحة وswitchMap، وتفاصيل modal create/view تستخدم
EditorDialog وملكية القراءة المحلية. الحفظ المرسل مستقل مع trackWrite
وسياج النشر المحلي والعالمي، ونجاحه latch قبل النشر. CanDeactivate من
المسار عبر الوالد للمحرر؛ الإغلاق والتخلص المحلي بعد الرفض متاحان.
يخفي المضيف المحمي دون هدم المسودة، وتغلق منافذ Select وDatePicker.

مصادر الاختيارات: Vehicle/GetSelect متبنٍ cacheSelect بمالكه، bootstrap
محدود ثم watch منفصل وإبطال Vehicle الحالي. Workshop/GetSelect
وVehicleService/GetSelect مباشران بلا cache opt-in. مرشح الورشة
اختياري يزيل raw/applied ID عند سحب المنحة ويلغي القائمة المحملة به؛
تهيئته تستخدم ReferenceLookupStatus بمالك الصفحة بلا مؤشر Select مكرر.
فشل القراءة له feedback/Retry ولا يدور تلقائيًا، والتحديث المحتفظ
بقيمه صامت. التفاصيل المحلية لا تستدعي مصادر الاختيار في وضع العرض.

الأدلة: شرح سبيد S253 المحلي بتاريخ ٢٧ أكتوبر، ثم شاشة
08-fleet/10-service-log وC1190 وC1164 وC1201 بتاريخ ٢٨ أكتوبر. يثبت
المرجع المرشحات والعرض والتسجيل ويقترح طباعة/تقرير وتعديل/روابط تعريف
الخدمة؛ غير الموجود منها في واجهة سيجما فجوات مجال، لا منح مخترعة.
قُرئت Odoo19 Fleet/service.rst المحلية بعد سبيد للتفرقة بين الموعد
والتنفيذ ومفهوم تسجيل خدمة المركبة فقط، دون استنتاج منحة أو أثر مالي.

الدليل الداخلي محدث في fleet-guide.ts لموضوع سجل الخدمة وإتمام التنبيه،
وmovements-guide.ts لحقل فرع حركة الورشة المحفوظ، عبر قارئ الدليل الحالي.
تسجيل مبلغ وعداد يظل بعقوده الحالية، ولا فاتورة أو قيد مالي تلقائي جديد.

## المطابقة المصدرية والتحقق

راجعت الفروق المقيدة لكل مستودع والملفات الجديدة يدويًا؛ أكدت استيرادات
الأنواع ومراجع المشاريع وSDK source inclusion، واتساق branchId/BranchId
المطلوب للإنشاء وBranchName/BranchId nullable في القراءة وعدم قبول
UpdateVM فرعًا متغيرًا. فحص frontend/backend scoped diff نظيف عدا
تنبيه LF/CRLF. تحليل ٤٩ ملفًا وقالبًا أعطى صفر أخطاء صياغة وصفر imports
محلية مفقودة؛ ليس type checking. الحزم الثماني Check سليمة. لم تُشغّل
المواصفات أو build أو التطبيق أو SQL. قبول التشغيل والمخطط عند المالك.

تطابق أعمدة القائمة مع ListVM: اللوحة والماركة/الموديل وفرع التنفيذ
والاستحقاق التاريخي/العدادي وتاريخ/عداد التنفيذ وأمر الشراء والخدمة
والملاحظات وبنود الخدمة/المنفذ والمبلغ والنوع؛ تقابل PlateNo/MakeAndModel/
BranchName/DueDate/DueKMs/PerformedDate/PerformedKMs/PoNo/Service/Notes/
ServiceItems/PerformedItems/Amount/WorkTypes، مع Id وBranchId للهوية
وسياق العرض. أضيف branchName للفرز والمرشح في الطرفين، وبقي العد قبل
الترقيم وتجميع البنود للصفحة نفسها. الحقول الحالية ونوع العمل والمال
والعداد لا تتغير معادلاتها ضمن هذه الشريحة.

مواصفات المصدر غير المنفذة: خمس للقائمة وتسع للمحرر، وست لحراسة
WorkshopMovement/immutable snapshot، وثلاثة صفوف theory لتصنيف
ServiceLog.Search/GetAllWithNavigations/Add، بالإضافة لمواصفة خريطة
المسار والاختيارات الاختيارية. لا توصف نتائجها بأنها passing؛ فُحصت
مصدريًا فقط. راجعت الشريحة مستقلاً قراءة فقط بعد إصلاحات الجذر، ولم
توجد finding مثبتة إضافية في عمر مصادر الاختيار والكتابة. المخرجات
الجزئية الأولى لم تُعتمد قبل إصلاح العرض وRetry والإغلاق والمنح.

استُخدم عامل القائمة ثم استُكمل محرر details بواسطة الجذر بعد تسليم
جزئي، وعامل backend بملكية مستقلة، ثم مراجعة قراءة فقط للمحرر. يملك
الجذر كل التكامل والفروق والجرد والدليل؛ لا تفويض متداخل أو إغلاق
عام من عامل. تسليمات [القائمة](SOURCE_LOG_LIST_ACCESS_HANDOFF.md)
و[المحرر](SERVICE_LOG_EDITOR_ACCESS_HANDOFF.md)
و[الخلفية](SERVICE_LOG_BACKEND_ACCESS_HANDOFF.md) تحفظ الدليل والحدود.

القراءة التاريخية تبقى تابعة لفرع التنفيذ حتى بعد نقل المركبة. بيانات
المركبة المرتبطة حاليًا لا تتحول إلى نسخة تاريخية: قد تُحجب تسمياتها
والبحث بلوحتها إذا لم يعد المستخدم يقرأ فرع المركبة الحالي، بينما يبقى
رأس سجل التنفيذ مقروءًا بفرعه. لم يُلغَ فلتر المركبة لتسريب بياناتها
الجديدة ولم تُخترع لقطة لوحة/ماركة تاريخية غير معتمدة. هذا حد بيانات
مرجعية موثق، وليس منحًا ضمنية لفرع المركبة الجديد. أي طلب لتثبيت تسميات
تاريخية يحتاج شريحة بيانات مستقلة؛ لا تُدعى مطابقة وظيفية كاملة لسبيد.

الأداء: ينفذ البحث إعدادًا واحدًا ثم count ثم projection للصفحة وقراءتين
مجمعتين لبنود الخدمات وأوامر الشراء، بلا طلب لكل صف. الفهرس الجديد
SubscriptionId/BranchId/DateOf يخدم فلترة التنفيذ/الفترة، مقابل كلفة
كتابة وفهرس إضافي؛ يبقى SubscriptionId/DateOf مناسبًا لقراءة المدير
لكامل الشركة، وSubscriptionId/VehicleId/DateOf/Id لآخر حركة مركبة؛ لا
يحذف فهرس قائم دون SQL plans. يلزم المالك قياس نفس النطاق/الفترة/حجم
المخرجات والكاش البارد/الدافئ قبل وبعد، وخطة استعلام root وlabels
المحجوبة. الفحص المصدري لا يثبت سرعة ولا ظهور التقدم المرئي.

طُبقت مراحل المنح والعمر والكتابة والتكامل والمصالحة والدليل؛ لم تُنفذ
هجرة أو snapshot أو أثر مالي. التغيير المقترح للواجهة:
`fix(service-log): enforce access and retain execution branch ownership`.
التغيير المقترح للخلفية:
`fix(workshop-movements): persist and guard execution branch snapshots`.

سيناريوهات القبول النهائي: مدير ثم مستخدم Search فقط؛ Add مع Vehicle.Lookup
وتسجيل على فرع التنفيذ والمركبة؛ منع إنشاء دون فرع أو بفرع شركة أخرى؛
نقل المركبة ثم قراءة السجل من فرع التنفيذ القديم؛ منع تعديل BranchId؛
حماية legacy null؛ سحب المنحة أثناء القراءة وقرار التخلص والحفظ المرسل؛
منح اختيارات الورشة والخدمة وإزالتها وإعادة منحها دون فقد باقي المسودة؛
نجاح/فشل الحفظ وعدم تكرار النجاح؛ تطبيق الفرع من حركة الورشة والتنبيه.
