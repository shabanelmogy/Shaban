# مطابقة إلزام فرع التنفيذ وإزالة توافق بيانات التجربة

متابعة أحدث ١٠ نوفمبر: غيّر المالك قرار التجهيز إلى إسناد البيانات التجريبية لأي
فرع مناسب بدل الحذف. طُبّقت تهيئة ٤١ سجلًا للفرع 2 داخل الاشتراك 1007 ونجحت
الهجرة على الهوست. الفروع الأربعة إلزامية بلا default وقيودها مفعلة؛ لم تُحذف
حركات أو توابع. هذا استثناء تهيئة لمرة واحدة، ولا يغيّر ثبات فرع الحركات الجديدة.
تفاصيل القبول الفعلية في [تقرير التصحيح](WORKSHOP_REQUIRED_BRANCH_MIGRATION_REPAIR.md).
تبقى مطابقة الشاشات الأوسع ومراجعتها التشغيلية ضمن حدودها المبينة أدناه.

متابعة سابقة ١٠ نوفمبر: أظهر تطبيق هجرة update-auth قيمة افتراضية0 مخالفة للعقد.
بعد تفويض المالك المحدد أزيلت الافتراضات الأربع وأضيف فحص تجهيز قبل تعديل
المخطط؛ [تقرير التصحيح وحدود التنفيذ](WORKSHOP_REQUIRED_BRANCH_MIGRATION_REPAIR.md).
لم تُشغّل الهجرة أو تُحذف بيانات، ولا يثبت هذا قبول المخطط على قاعدة المالك.

## النتيجة

أزيل الاحتفاظ بفرع فارغ على WorkshopMovement وJob وLubricationJob؛ أصبح
BranchId من نوع int وعلاقته مطلوبة مع Restrict. هذه المواضع الثلاثة كانت
تحفظ بيانات التجربة فقط، وفق العقود السابقة وحصر المصدر. لا default أو
backfill أو تخمين فرع مركبة، ولا تحويل سجلات بلا فرع إلى استثناء للمدير.

أُضيف invariant للثلاثة قبل خروج !BranchScopeEnforced؛ يشمل الحفظ للمدير
والعادي وغير HTTP وdetached updates. يرفض الفرع غير الموجب، ويقرأ الأصل
المادي دفعياً ويمنع نقله إلى فرع آخر حتى لو كان الفرعان مسموحين، ويثبت
OriginalValue للحفاظ على شرط concurrency الحالي. لا يعتمد على قيمة أصلية
يزودها العميل. لم تتغير حراسة الشركة والمنح والمراجع التي تأتي بعده.

## المنتجون والمخرجات

| المسار | المطابقة |
|---|---|
| إنشاء حركة ورشة مباشرة | WorkshopMovementAddVM مطلوب والخدمة تتحقق من فرع نشط؛ mapping يحمل القيمة الصحيحة |
| تسجيل خدمة مركبة | ServiceLogService.Add يحمل الفرع المطلوب؛ بيانات القائمة وإسقاطها أصبحت int |
| إتمام خدمة من التنبيهات | FleetAlertsService.CompleteVehicleService يتحقق من الفرع قبل إنشاء الحركة |
| إنشاء شغل | JobAddVM.BranchId يبقى nullable عند الحد لتوريد فرع WorkOrder من الخادم؛ يتحقق JobService من الفرع قبل إسناد Value للكيان |
| تحويل التقدير | معامل اختياري عند الحد؛ يعيد التحويل المحفوظ وفق العقد قبل التحقق من فرع إنشاء جديد، والإنشاء يسند Value بعد التحقق |
| إنشاء تشحيم | Required/Range عند حد الطلب، ثم تحقق مرجع الفرع وإسناد Value للكيان المطلوب |
| التعديل | نماذج update لا تعرض الفرع، والخريطة/التحديث الصريح يحافظان عليه؛ الحارس يشمل الكتابة المباشرة |
| المخرجات | تفاصيل/قائمة/قائمة كاملة لحركة الورشة، تفاصيل الشغل وشبكته المختلطة، تفاصيل التشحيم، سجل الخدمة وإسقاطه كلها تحمل int |
| التقارير | العمالة تتبع visibleJobIds، واليومي يتبع Job المحكوم؛ لا صيغة مالية أو output جديد |

تطابق ستة نماذج قراءة أمامية مخرجات الخادم بقيمة number مطلوبة: حركة الورشة
تفاصيل/قائمة، الشغل تفاصيل/شبكة، التشحيم تفاصيل، وسجل الخدمة قائمة. تبقى
فلاتر «كل الفروع المسموحة» ونموذج الاختيار قبل إدخال المستخدم اختيارية.
تبقى BranchName nullable للتسمية غير المحملة/المحجوبة؛ لا FK فارغ مستنتج منها.

لا تغيير لأعمدة الجداول أو حقول المستخدم أو الطلبات أو منح endpoint أو
شكل الشاشة أو المعادلات. الخرائط تطابق BranchId بالاسم ولا تحتاج مالكًا
منافسًا أو ReverseMap جديدًا. لا يشمل العمل أي nullable لمرجع آخر له معنى أعمال.

## المراجع والدليل والمالكون

هذه صيانة Tier S لقرار المالك بالتجريبية وفرع التنفيذ الثابت. مراجع سبيد
ودليلها وكودها مسجلة في عقود سجل الخدمة والورشة والتشحيم السابقة؛ لا قرار
وظيفي جديد يحتاج تفسيرًا من Odoo ولا تغيير شاشة قائم على شكل مرجعي جديد.
قُرئت الكيانات وEF والخدمات وDTOs والخرائط والتقارير والحراسة والمالكون
الأماميون المحددون. لا تعد مصدرًا مقروءًا صفحةً لمجرد وجود رابطها.

دليل التطبيق الثنائي اللغة محدث في fleet-guide وmovements-guide وworkshop-guide
تحت /UserGuide/fleet و/UserGuide/movements و/UserGuide/workshop ومدخل كل وحدة
القائم. أُزيلت جملة «السجلات القديمة بلا فرع للمدير»، ووُضح إلزام الفرع
وثباته والشغل المرتبط بأمر. لا مكون دليل أو عنصر قائمة أو UI جديد.

وُضعت إحالات التغيير على العقود والمطابقات السابقة مع الحفاظ على نصها
التاريخي. يمتد قرار Master1 العام للبداية النظيفة إلى هذه الشريحة دون
قاعدة مشتركة إضافية؛ الحزم الحالية اجتازت drift check ولا تعديل مولد يدويًا.

## الأداء والمخطط والتحقق

تظل الفهارس الحالية للشركة/الفرع/التاريخ لكل نوع؛ لا فهرس إضافي مبرر.
الحراسة تضيف قراءة أصول دفعية للأنواع المتغيرة فقط، ولا استعلامًا لكل صف.
يبقى query shape للقراءات والتحميل والكاش والطباعة كما هو؛ لا قياس زمن
أو SQL plan أو نتائج concurrency فعلية في هذه الشريحة.

يلزم المالك مخطط RequireWorkshopExecutionBranches، أو دمج required في
هجرات إضافة الفروع التي لم تُجهز بعد. يشمل الأعمدة الثلاثة المطلوبة وFKs
Restrict والفهارس المصدرية. لا default/backfill أو reset من الوكيل؛ تجهيز
البداية التجريبية النظيفة عند المالك. لا تشغيل على مخطط لا يطابق المصدر.

كتب عامل الخلفية ثماني theories/٣٩ حالة مصدرية غير منفذة. تشمل missing/zero/
negative، ثبات ordinary/admin/nonHTTP وdetached وOriginalValue ورفض فرع
الاستعراض وقبول التسجيل. أزيل فقط اختبار/صف توافق الحركة القديمة بلا فرع.
لا ادعاء RED/GREEN. تحليل TS/HTML/import existence المقيّد شمل١١٢ ملفًا
وقالبًا وأعاد problems:[]؛ ليس type checking أو نجاح بناء.

اكتملت المطابقة وتدقيق مستقل للملفات التسعة عشر ومنتجي الحركة وخرائطها
وحراسة SaveChanges المتزامنة وغير المتزامنة، بلا finding مؤكد متبقٍّ في
النطاق. روجع الديف المقيّد في المستودعين، وnamespace imports ومراجع SDK،
وفحص whitespace سليم مع تحذير LF/CRLF فقط. لا تُرقى مسارات
Job/Workshop بالكامل بسبب هذا الإصلاح؛ يبقى إجمالي الجرد١١٦/٢٦٣. قائمة
المالك النهائية تشمل الإنشاء من المنتجات الستة، رفض missing/zero وتبديل
الفرع لكل أنواع الحسابات والكتابة الداخلية، وقراءة الشبكة/المستند/التقرير
بعد نقل المركبة. التشغيل والفروع وSQL/المرئي يظلون قبول مالك معلقًا.

رسالة مقترحة للخلفية دون تنفيذ:
`fix(auth): require immutable workshop execution branches for every writer`

رسالة مقترحة للواجهة دون تنفيذ:
`fix(workshop): align saved execution branch contracts and screen guides`

استخدم عامل خلفية واحد لإسنادات متصلة وتدقيق مستقل قراءة فقط؛ الجذر يملك
التجميد والواجهة والتوثيق والدمج. لا builds/tests/lint/browser/DB أو
migrations/snapshots/commits/push/deployment أو مسح بيانات نُفذت.
