# مطابقة صلاحيات الشيكات الواردة

| البند | القيمة |
|---|---|
| Status | Implemented — source + scoped build/filter checks; runtime pending |
| Owner verification pending | yes |
| العقد | [صلاحيات الشيكات الواردة](RECEIVABLE_CHEQUES_ACCESS_ADOPTION_CONTRACT_FREEZE.md) |

| الإجراء | الصلاحية المطلوبة بالإضافة إلى العرض |
|---|---|
| السجل وتفاصيل الشيك والتقرير والطباعة والتصدير | العرض `PDCReceivable.View` يكفي للقراءة الأساسية |
| اختيار مرشح العميل أو الفرع | `Customer.Lookup` أو `Branch.Lookup` |
| محرر الإضافة والتعديل | `PDCReceivable.Create` أو `PDCReceivable.Update` مع اختيارات العميل وجهة الاتصال والاتفاقية والفرع |
| التحصيل الفردي والجماعي | `PDCReceivable.MatureSingle` أو `PDCReceivable.MatureBulk` مع `Bank.Lookup` |
| الارتداد وإعادة التقديم | `PDCReceivable.ReturnCheque` أو `PDCReceivable.Resubmit` |
| الحذف | `PDCReceivable.Delete` |
| الاستيراد | `PDCReceivable.Import` |

طبقة HTTP تفرض أيضًا `PDCReceivable.View` كاعتماد لعمليات
`Create/Update/MatureSingle/MatureBulk/Delete/Activate/Import/Resubmit/ReturnCheque`.
عند استعمال `customerId` أو `branchId` في طلب القائمة تُفحص
`Customer.Lookup` أو `Branch.Lookup` بصورة مشروطة في
`PermissionPrerequisites`، لا بمجرد ظهور عنصر المرشح على الشاشة.

تطابق المسارات النشطة القائمة ومحررها ومسار التفاصيل المتوافق. تتوقف
القراءات والطباعة المنتظرة عند فقد صلاحيتها أو تغير سياقها. يعزل المحرر
وحوارات التحصيل والاستيراد محتواها عند فقد الوصول، ويحافظ المالك على
المسودة والطلب المرسل. تُمنع إعادة إرسال دفعة الاستيراد إذا لزم التحقق
من نتيجة الإرسال السابق.

يرجع سجل الشيك معرّف فرعه لربط أفعال الصف واختيار التحصيل بصلاحية التسجيل.
يطبق الخادم حارس فروعه المشترك على الكتابة. يُرسل الاستيراد معرّف فرع
العمل المثبت عند فتح الحوار لكل الصفوف. يتحقق الخادم من وجود الفرع
ونشاطه عند إرساله، ثم يسند الفرع للشيكات ويحفظها بالدفعة الذرية الحالية.
يمر رفض نطاق الفرع عبر معالج الصلاحيات إلى الواجهة بحالة 403.
الامتداد في عقد الطلب والعرض يستخدم حقل الفرع الموجود في الكيان.

تحميل السجل ومصادر مرشحاته في الصفحة. يراقب المرشحان مصدرَي العميل والفرع
عبر مالك ذاكرة الاختيارات. يراقب المحرر نفس المصدرين داخل الحوار ويقرأ
جهة الاتصال والاتفاقية مباشرة. تحميل التقرير واختيارات التحصيل في الحوار.
حُدّث دليل البنوك داخل التطبيق.

مرجع سبيد يطابق فصل السجل عن التحصيل والارتداد في شاشة 02 المؤرخة
والمتحكمات `C0631` و`C0632` و`C0638` و`C0626`. تحدد نقاط Sigma
المنح الفعلية وأفعال الحالة. تحويل نوع الشيك خارج سطح Sigma الحالي.

يشمل القبول المعلق تجربة دور للعرض فقط، وسحب كل منحة أثناء القراءة،
واختبار التحصيل على فرع عرض فقط، واستيراد دفعة في فرع التسجيل المختار
ومحاولة إرسال فرع غير مسند. في جولة البنود 171–180 بتاريخ 13 نوفمبر
نجح بناء ServerAPI وAngular development وفحص TypeScript، ونجحت 13/13
حالة محددة لمرشح HTTP وشجرة الاعتماديات؛ ليست هذه تغطية تشغيلية لكل
سيناريوهات الشيكات. يظل قبول HTTP الحي والمتصفح وEF relational
والطباعة/التصدير الفعلي معلقًا.
