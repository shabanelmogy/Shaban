## المتطلبات المعتمدة

الأصل Staff تعريف داخل الاشتراك وفق المصدر الحالي؛ ليس قيدًا أو حركة مالية. يحفظ BranchId الحالي دون إدخال نطاق فرع جديد على جذر تعريف لم تتبنه BranchScopeRegistry. تبقى الحركات والتقارير ونطاقها الحالي مستقلة. لا تعني ترقية Staff ترقية بقية شاشات الرواتب أو الاستيراد أو كشف الحساب.

| السطح | المنحة |
|---|---|
| القائمة والتفاصيل وExcel الموجود | Staff.View |
| إنشاء مباشر مستقل عن القائمة | Staff.Create + Branch.Lookup |
| تعديل | Staff.View + Staff.Update + Branch.Lookup |
| حذف | Staff.View + Staff.Delete |
| قراءة حزمة الراتب المحفوظة | Staff.View + Staff.GetSalaryRevision |
| تعديل الراتب | Staff.View + Staff.GetSalaryRevision + Staff.ReviseSalary |
| حزمة أولية عند Create | Staff.Create + Staff.ReviseSalary عندما SalaryPackage ليست null؛ لا يشترط عرض حزمة موظف موجود |
| التحقق الاستباقي من التكرار | Staff.Validate عند منحها فقط؛ يبقى تحقق الخادم إلزاميًا عند الحفظ |
| فتح تقرير من القائمة | منحة وجهة StaffPerformanceReport الفعلية بعد تتبعها، وإلا يحجب الرابط؛ لا تُمنح من Staff.View |

مصادر الحقول الاختيارية Country.Lookup وDepartment.Lookup وShift.Lookup وStaffDesignation.Lookup وSponserShip.Lookup وLeaveType.Lookup وStaff.Lookup؛ تُحمّل عند منحها فقط. عدم المنحة يبقي الحقل المحفوظ للعرض/دون تعديل، ولا يمسح معرفًا محفوظًا من payload. تتطلب Create المنحة عند إرسال المرجع، وUpdate عند تغييره مقارنة بالمحفوظ؛ Branch.Lookup مطلوب للمحرر لأنه حقل إلزامي. تغييرات أهلية LeaveType تتبع المنحة عند إضافة/تغيير المرجع، لا عند إبقاء الصف نفسه. يمتنع Save مع مدخل اختياري تغير وفقدت منحة مصدره، ولا يسقطه صامتًا.

مصدر Role الحالي هو RoleController المحصور في TenantAdmin، وليس StaffRole، وعلاقة Staff.RoleId الحالية تشير Role. لا تُوسّع إدارة أدوار المستخدمين لتشغيل ملف الموظف ولا تُغيّر العلاقة/المخطط هنا. يضاف GET Staff/role-options بمنحة مستقلة Staff.GetRoleOptions يعيد Id/Name للخيارات الحية داخل الاشتراك فقط. اختيار RoleId أو تغييره يحتاج هذه المنحة، ولا ينتج عنه إسناد دور إلى مستخدم أو تغيير أي منحة. بقية ملفات الإدارة لا تدخل النطاق.

تعلن PermissionPrerequisites المتطلبات الثابتة والشرطية من مالكها الواحد. لا مقارنة بأسماء مترجمة أو grant جديد في الواجهة وحدها. العمليات الموروثة بلا مستهلك مؤكد مثل GetAllWithNavigations/Activate/bulk ممنوعة 405 وغير قابلة للإسناد؛ Lookup وValidate يظلان مستقلين للمستهلكين الحقيقيين.

## أعمار الواجهة

استخدام AccessViewPolicy/AuthSession/dataContext والإصدار الدلالي، دون اعتبار تجديد snapshot مطابق إلغاءً. لا GET أو lookup أو راتب أو export بلا متطلبه. تبقى triggers حية لإعادة المنحة؛ تتوقف القراءات والقرارات السابقة وتخفى البيانات والـportals عند السحب. يحتفظ المحرر ومسودة تعديل الراتب بحالتهما داخل الممثل نفسه، ويظل التجاهل المحلي والمغادرة ممكنين بعد السحب. الكتابة المرسلة مستقلة عن teardown؛ CAN_PRESENT_API_OUTCOME وختم المسودة يمنعان نشر نتيجة لجلسة أخرى أو إعادة Save بعد نجاح تحت السحب. لا تُنشأ حزمة راتب افتراضية إن غابت منحة إدخالها.

Branch/Country مصادر مرجعية ذات finite bootstrap ثم watch الحاليين؛ بقية lookups مباشرة ما لم يثبت opt-in في المصدر. تهيئة المحرر والفلاتر بمالك الصفحة، وقراءة حوار الراتب محلية، والتجديد المحتفظ ببياناته صامت. يحتفظ View بتسميات DTO ولا يجلب قوائم التحرير. FileField/Tracker/EditableRows/StepForm/shared confirmation مالكون قائمون لا تُنشأ بدائل لهم.

## وثائق الموظف الخاصة

الملفات الجديدة في مجلد staff-documents الخاص خارج wwwroot؛ يعرّف StaffDocumentPath مسارًا مطابقًا لمالك PrivateUploadPath الموجود. Upload يحتاج Media.UploadMedia وStaff.Create أو Staff.Update. قراءة GET Media/staff-document تحتاج Media.ReadStaffDocument وStaff.View، مع ملكية CustomerDocument.PartnerId لموظف حي في نفس الاشتراك. حذف مسودة غير مسندة يحتاج Media.DeleteMedia ورافعها نفسه؛ الملف المسند يبقى في المخزن بعد إزالة صفه ولا يسمح حذفه المباشر. يمنع ربط مسار شخص آخر أو مسار خاص بمالك آخر، أو تمريره عبر طفل مشترك إلى مستند آخر. يعتمد التحقق على المسار والمالك الحي/التاريخي، مع تثبيت tenant في استعلامات IgnoreQueryFilters.

تحجب استضافة static المسار الخاص وأي مسار staff عام مثبت الارتباط بوثيقة موظف، دون نقل أو حذف بيانات. البيانات الحالية تجريبية؛ لا backfill أو fallback عام أو هجرة هنا. المسارات العامة القديمة لا تُعرض كرابط مباشر ولا يقبل الحفظ إعادة إسنادها؛ تجهيز/رفع ملفات تجريبية خاصة جديدة إجراء قبول مالك.
