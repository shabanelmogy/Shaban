## القرارات ومطابقة الطلبات

| السطح | المنح والمطابقة |
|---|---|
| القائمة والرابط والبديل الأول بعد الدخول | أي SearchInsurance/SearchRegistration/SearchMileage/SearchWarranty/SearchServices تحت FleetAlerts؛ لا View مخترع. يفتح أول نوع مسموح، والقائمة الجانبية وAuthGuard يستهلكان registry نفسه. لا محرر routed مستقل أو بديل create قائم. |
| مرشحات الفرع والماركة والموديل | GetFilterOptions اختياري. طلب مجمع مباشر، لا Branch.Lookup أو CarMake.Lookup إضافي. غياب المنحة ينقح raw/applied IDs؛ تغير actor/company/working-branch يمسحها وخياراتها حتى لو بقيت المنح نفسها. |
| الطباعة والتصدير | Search النوع نفسه غير مرقم، مع المرشح المطبق وgrid؛ لا منح Export/Print أو endpoint مستقل قائم. إلغاء القراءة والإخراج المؤجل عند انتهاء الوصول أو السياق. |
| تجديد التأمين | SearchInsurance + RenewInsurance في الواجهة؛ الخادم يفحص العملية الفعلية والتسجيل على المركبات المحددة كلها. |
| إتمام الخدمة | SearchServices + CompleteVehicleService؛ فرع تنفيذ من options القابلة للتسجيل، مع التحقق الخلفي من فرع التنفيذ والمركبة وتعريف الخدمة، وحفظ الفرع على WorkshopMovement وتحديث العداد في نفس الحفظ. |
| التذكير | SearchServices + SendServiceReminders؛ عضوية الصفوف الحالية وإعادة فحص القرار قبل الإرسال. الخادم يرفض أي هوية مركبة غير متاحة في نطاق الكتابة، ثم يختار آخر عقد مفتوح ويقرأ جهة اتصاله من النطاق المسموح. لا إرسال لعقد أقدم عندما يغيب بريد الأحدث أو يُحجب. |

المفاتيح موحدة في fleet-alerts-access. العمليات التسع موجودة في
FleetAlertsController وReviewedPermissionOperations؛ يطبق مرشح الخادم
فحص المنحة. القراءات الست WholeDocument في BranchOperationRules؛
الكتابات الثلاث transaction mode. المدير يظل داخل اشتراكه وقواعد العملية.

## أحدث مصدر ونطاق الفروع

كان اختيار الأحدث بعد فلترة الفروع يستبدل أحدث حركة محجوبة بحركة أقدم
أو بتاريخ إنشاء المركبة، فينتج استنتاجًا خاطئًا. نُفذ في FleetAlertsService:

- تُحصر أدلة الوجود في IDs المركبات المسموح بها أصلًا، مع SubscriptionId
  وIsDeleted صريحين عند كل IgnoreQueryFilters. لا تُستخرج labels أو
  جهات اتصال أو KMs من هذا النطاق؛ لا يُدمج bypass داخل قراءة التفاصيل.
- يجمع العداد max(date) من مصادره الخمسة في النطاق المرئي، ويقارنه بأحدث
  تاريخ داخل الشركة. لا يُعرض تنبيه إذا كان التاريخ الفعلي أحدث من المتاح
  للمستخدم أو لا توجد قراءة مرئية مع وجود قراءة فعلية. تساوي التاريخ كافٍ
  هنا لأن المصدر المستهلك تاريخ فقط، والعداد المعروض يأتي من المركبة.
- تختار الخدمة أحدث هوية DateOf ثم Id للمركبة ولكل مركبة/خدمة أولًا؛ ثم
  تُحمّل KMs والتاريخ بقراءة منفصلة محكومة بالفروع. إذا لم تُقرأ هوية لازمة
  لأي خدمة نشطة، يُحجب ملخص المركبة كله؛ لا تُعرض خدمة أخرى على أنها الأشد
  استحقاقًا بمقارنة ناقصة. المصدر العالمي لا يُطلب إذا كانت الخدمة لها
  baseline خاصة قابلة للقراءة. يبقى fallback الشراء/الإنشاء للحالة التي
  لا يوجد لها تاريخ فعلي، ويظل المدير قادرًا على التاريخ غير المسند.
- يحدد سياق العميل والتذكير آخر عقد مفتوح بهويته داخل الشركة، ثم يقرأ
  بياناته عبر مرشح المستند الكامل. لا استبدال بعقد أقدم محجوبًا أو بلا بريد.
  VehicleStatus مصدر tenant-bounded مربوط بمجموعة المركبات المرئية؛ لا
  تغيير لحدود حالته الحالية. بيانات الشركاء مشتركة وفق العقد المعتمد.

النتائج/count/page والطباعة والتصدير كلها تُشتق بعد حراسة المصدر نفسها.
لا تسرب لتفاصيل السجل المحجوب ولا توسيع لمنح الفروع. الدليل يوضح أن
القائمة لا تثبت خلو الشركة كلها من مستحقات إذا كان تاريخها غير متاح للمستخدم.

## العمر والتحميل والمصادر

القائمة والإخراج يبدآن LoadingService وينهيانه في finalize عند النجاح
والفشل والإلغاء. ReferenceLookupStatus يملك bootstrap المرشحات بمالك
الصفحة، مع Error/Retry لقناتي الأعمال والنقل. مصدر المرشحات مباشر
تشغيلي دون opt-in cache؛ البحث والإخراج قراءات تشغيلية مباشرة. لا lookups
في الحوارين؛ فرع التنفيذ من CurrentBranchService الموجود. لا cache جديد.

القراءات مربوطة بالمنحة وdataContext ومراقبة بعد اكتمال الطلب. تمسح النتائج
وselection وprintData وتغلق Select portals عند الانتهاء؛ لا إخراج queued
قديم بعد تغيير النوع/السياق. ReportPrintSession يملك انتظار العرض والإلغاء.
يحمي busy تغييرات النوع/الصف/الإخراج أثناء الحوار؛ لا callbacks قديمة تعيد
تحميل سياق مختلف. يشترك المسار فعليًا في canDeactivate المفوض للحوار.

يستخدم الحواران EditorDialog/MockData بمتطلب الوصول؛ تبقى المسودة mounted
خارج مضيف القائمة المحجوب. كتابة أرسلت تستمر مستقلة عبر trackWrite وHttpContext؛
يثبت النجاح قبل حجب النشر ويمتنع replay. قرار التخلص كسول ويلغى عند انتهاء
سياقه؛ يظل التخلص المحلي الصريح بعد الرفض ممكنًا. تنظف منافذ Select/DatePicker.

## الأداء والمخطط

يحافظ البحثان التجميعيان على تجميع التاريخ قبل المقارنة وحساب العدد والصفحة
في الذاكرة؛ لا قراءة لكل صف أو خدمة، ولا عمليات EF متوازية على السياق نفسه.
العداد صار ١٠ قراءات تجميع محدودة بالمركبات بدل ٥، وسياق الاتصال زاد قراءة
هوية واحدة؛ الخدمة زادت قراءة payload واحدة وسياق الاتصال زاد قراءة هوية.
هذه تكلفة إثبات أحدث مصدر، وليست ادعاء تحسين سرعة. القراءة غير المرقمة
والبيانات المرشحة الكثيرة لها تكلفة مستقلة؛ قياس SQL والترجمة والزمن معلق.

الفهرس القائم WorkshopMovement(SubscriptionId,VehicleId,DateOf DESC,Id DESC)
يشمل Type/IsDeleted ويخدم أحدث مصدر عام؛ فهرس branch/date الجديد مملوك
لهجرة سجل الخدمة. مرشح تحسين عند ثبوت الحاجة بخطة التنفيذ:
(SubscriptionId,VehicleId,VehicleServiceId,DateOf DESC,Id DESC)
مع INCLUDE(BranchId,KMs,IsDeleted)، لتجميع الخدمة؛ يتداخل جزئيًا مع
فهرس المركبة العام ويضيف كلفة كتابة وتخزين، فلا يُطبق دون قياس المالك.
لم تتغير إعدادات الفهارس في هذه الدفعة.

يلزم قبل التشغيل مخطط المالك المسجل مسبقًا:
AddWorkshopMovementExecutionBranch. لا هجرة جديدة لهذه الخوارزمية؛
لم تُنشأ/تشغّل هجرة أو يُعدّل snapshot أو backfill.

## التحقق والتسليم

نُفذ تحليل صياغة TypeScript/Angular ووجود imports محلية في ٦١ ملفًا وقالبًا
بلا مشاكل، وفحص drift للحزم الثماني سليم. روجعت الفروق المحددة في مستودعي
الواجهة والخلفية، وقرئت الملفات untracked مباشرة بدل اعتبار diff فارغ دليلًا.
فحص whitespace سليم مع تحذيرات LF/CRLF فقط. تُفحص ملفات resx كـXML.
هذا ليس type checking أو build أو tests أو إثباتًا للتشغيل أو سرعة SQL.

أضيفت مواصفات غير منفذة: أربعة للقائمة (بما فيها تغيير الحساب بنفس المنح)،
ومواصفة route any-of وفصل الإجراءات، ومواصفات الحوارين، وتسعة صفوف endpoint
mode، وأربعة عشر سيناريو خلفي لأحدث التاريخ والفروع والـfallback والتذكير.
لا تُدعى RED/GREEN أو نجاحة runtime. لا build/tests/lint/browser/DB/
SMTP/migration/snapshot/commit/push/deploy في هذه الدفعة.

الدليل: src/app/modules/UserGuide/content/fleet-guide.ts، موضوع FleetAlerts
داخل قارئ UserGuide الحالي. حُذفت عبارة authentication-only القديمة؛ يغطي
الدليل الأنواع والمنح والإخراج وفرع التنفيذ وحدود التاريخ والتذكير والمسودة.

استخدم الجذر مدقق UI مستقلًا بلا كتابة، بعقد مجمد وملكية منفصلة عن إصلاح
الخلفية، لتقليل زمن المراجعة. اكتشف مسح context الناقص وأصلحه الجذر، الذي
أضاف guard المسار وراجع التكامل. لا تفويض لقرارات الفروع أو قبول الوحدة.

تجربة المالك النهائية: مدير الشركة ثم مستخدم services-only؛ سحب/إعادة منح
القراءة والمرشحات والإجراء أثناء lookup/dialog/export؛ تبديل الحساب بنفس
المنح؛ رفض التنفيذ بفرع غير قابل للتسجيل؛ انتقال المركبة بعد سجل تنفيذ؛
أحدث سجل محجوب وآخر مرئي؛ tie-date بهوية أحدث؛ أحدث عقد بلا بريد؛ رفض هوية
مركبة غير متاحة. تُجرب رسائل فعلية فقط بإعداد وتجهيز المالك، لا بواسطة الوكيل.

رسالتا commit مقترحتان فقط:
- للواجهة: feat(auth): complete fleet alert route, action and output permissions
- للخلفية: fix(auth): preserve authoritative fleet alert history across branch scopes

التطبيق كله ما زال قيد الاستكمال. ترقية FleetAlerts تخص هذه الوحدة فقط،
والقبول بالتشغيل مؤجل للتجربة المجمعة في نهاية الهدف.
