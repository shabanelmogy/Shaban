## التنفيذ

تصدّر daily-service-logs-access.ts المفتاح الفعلي DailyServiceLogReport.Get.
تستخدم الشاشة AccessViewPolicyService المشترك، وتخفي مضيف ReportPage
وتجعله inert عند غياب المنحة. حراسة البحث والتبويبات والطباعة وExcel
فورية داخل handlers، مع ملكية صريحة لنتيجة التقرير بتاريخ البحث وسياق
actor/tenant/branchAccessRevision. لا مفاتيح قراءة داخلية مخترعة ولا كتابة.

تفصل دورة الوصول عن busy/form effects: مراقبة access/context وحدها تمسح
النتيجة والأقسام والأخطاء والهوية وتلغي الطباعة المؤجلة وتغلق DatePicker.
تظل النتيجة الناجحة محفوظة بعد finalize. الاشتراك المستمر في denied$
يلغي مخرجات مكتملة أيضًا، ويسجل interruption يمنع استعادة نتيجة قديمة
بعد revoke/regrant سريع، ثم يبدأ طلبًا جديدًا واحدًا عند الاستعادة. فشل
الأعمال أو النقل يبقى قابلًا للمحاولة الصريحة دون حلقة إعادة تلقائية.

تُلغى القراءة الفردية عند denial/context/date change/destroy، مع سياج
sequence/context/date قبل النشر. LoadingService يملك قراءة الصفحة، ويحرر
finalize عداده لكل نهاية. تعطيل مرشح التاريخ وإعادته عبر reactive-form API
بحسب المنحة والتحميل والطباعة؛ لا CSS أو مالك تحميل منافس.

التركيز المؤجل للتاريخ غير الصالح يتحقق من access/context ومراجعة التركيز
وعمر المكوّن. تستخدم الطباعة ReportPrintSession مع denied notifier، فلا
تعود frame ملغاة بعد إعادة المنحة. الهوية المعروضة تُلتقط فقط مع نتيجة
ناجحة عندما تتطابق identityUserId وSubscriptionId مع حساب Auth الحالي؛
يُحذف الكود عند غياب التطابق أو كونه غير نصي، ويُمسح مع انتهاء النتيجة.

## المطابقة والعقد المحتفظ به

الشكل UI07/BE17: مرشح date واحد، أربعة تبويبات، الأقسام الثمانية كلها
من الاستجابة الكاملة الحالية، والطباعة لكل الأقسام. بقي Excel مقصورًا
على serviceRows وبأعمدة serviceColumns نفسها. لم تتغير الحقول أو الحسابات
أو proxy أو paging أو API أو طبقة mapping أو النموذج أو CSS.

المصدر التشغيلي الوحيد GET DailyServiceLogReport بقي مباشرًا دون cache
opt-in أو lookups. لا حاجة إلى bootstrap/cache watcher آخر. الجذر يملك
تحديث route registry والقائمة والبديل الأول والدليل والجرد والخلفية؛
لم تُمس هذه الملفات في هذا التسليم. لا حارس مغادرة جديد لتقرير بلا مسودة
أو كتابة مرسلة. لا schema أو migration في شريحة الواجهة.

## الملفات والأدلة

تغيّر report.component.ts وreport.component.html، وأضيف ملف المفاتيح
وملف report-access.spec.ts. راجعت scoped diff للملفين المتتبعين كاملًا
ومحتوى الملفين الجديدين. فحص TS/HTML parsing ووجود local imports عبر
المصدر شمل ٧ ملفات بالوحدة وأعاد problems:[]؛ وgit diff --check نظيف.
هذه الفحوص ليست type checking أو build أو tests أو قبول تشغيل.

أضيفت ١٣ مواصفة سلوكية بالمصدر، غير منفذة: غياب المنحة؛
احتفاظ finalize بالنتيجة؛ revoke/regrant؛ إلغاء نتيجة قراءة قديمة بعد
regrant سريع؛ تبديل actor/company بنفس المنحة؛ رفض كود حساب غير مطابق؛
فشل الأعمال ومحاولة صريحة؛ تغيير التاريخ وإلغاء القراءة؛ فشل النقل بلا
حلقة؛ إلغاء تركيز مؤجل بعد denial؛ وإلغاء queued print دائمًا؛ واستعادة
قراءة واحدة بعد انتهاء active print إثر تغيير السياق؛ وبقاء فشل استعادة
ما بعد الطباعة لمحاولة صريحة دون حلقة. لم نَدّعِ
RED/GREEN لأن قواعد المشروع تمنع تشغيل الاختبارات في هذه الدفعة.

أصلح تدقيق الجذر مسار استعادة مؤجلة: لا يمكن إلغاء حوار طباعة فتحه
المتصفح بالفعل، لذلك تحتفظ recoveryPending بطلب استعادة الوصول حتى
انتهاء printing/loading. تأثير مستقل يستهلك الاستعادة عبر search مرة
واحدة، ولا يمسح output عند تغيّر busy. تستهلك محاولة البحث الإشارة قبل
التحقق أو الطلب، فيظل فشل الأعمال/النقل وتاريخ غير صالح بلا إعادة تلقائية.
تُلغى نية الاستعادة السابقة عند denial وتُنشأ نية حالية عند regrant/context.

استُخدمت المهارات Sigma وAngular؛ الإصدار المثبت من package.json هو
Angular21.2.25 وPrimeNG21.1.10. قُرئت UI20/UI26/UI28 ومالكو الوصول
والطباعة والتحميل والمضيف وAuth الفعليون. أدلة Speed/Odoo والقرارات
الخلفية مسجلة في العقد المجمد الذي سلّمه الجذر؛ لا ادعاء بقياس تحميل
أو تحقق بصري في هذه الشريحة. الأداء المصدرّي بقي طلبًا واحدًا كاملًا
لكل بحث، دون طلب إضافي للمنح أو للهوية ودون قراءة لكل صف.
