## مصادر الحكم وحدود المراجعة

استُهلك [العقد المجمد](SALES_QUOTATION_ACCESS_CONTRACT_FREEZE.md)، و[الاكتشاف](SALES_QUOTATION_ACCESS_DISCOVERY.md)، و[المطابقة](SALES_QUOTATION_ACCESS_RECONCILIATION.md)، وعقد الإيصال المستقل عند تتبع المصدر المدمج. البند ١٥١ هو ترتيب ترقية SalesQuotation، وليس ترتيب صف JSON. الاختيار Tier M وشكل UI02: قائمة بمحرر مستند موجّه. شملت المراجعة المسارات والقراءة والمحرر والقرارات والتكامل؛ لم يُنفذ أي إصلاح أو ترقية جرد جديدة.

قُرئت تعليمات AGENTS والمرافق الحي، ومهارة Sigma، ومهارتا Angular والتحقق قبل الإكمال المتاحتان محليًا، مع Master1 ومراجع UI26/28/10 وقواعد الخدمة BE5. فحص اتساق الحزم أعاد OK للحزم الثماني. عولج النطاق في الجذر دون وكلاء جدد لترابط مساراته. حُفظت تعديلات المستخدم/الزملاء الموجودة في المستودعين.

مرجع الوظيفة هو دليل التحليل Speed_Analysis_Guide.md، فصل الاستفسارات والعروض المتاح، ثم شريحة القائمة المؤرخة 2026-10-28: `07-sales/screens/02-sales-quotation.md`، وR0365 وC0812. الشرح العام لا يثبت قواعد خادم عروض البيع؛ الكود المؤرخ يثبت وجود الفلاتر والعرض والإنشاء والاعتماد الداخلي واعتماد العميل والمراجعة والسند. العقود والخادم الحاليان يحكمان منح Sigma. لم تستدعِ العيوب المؤكدة قاعدة مالية أو وظيفية مجهولة تحتاج مكمّل Odoo، ولا يُنسب إليه تحقق لم يُنفذ.

شملت القراءة ملفات الوحدة النشطة وخدمة SalesQuotation وواجهتها ومتحكمها وDTOs والخرائط، وPermissionPrerequisites وPermissionEndpointResolver، ومالكي CurrentAccess وAccessViewPolicy وTaxSettings، والقراءات المتصلة من Receipt، ودليل sales-guide. أصل العرض مشترك داخل المستأجر؛ لا تغيّر هذه المراجعة عقد الفروع أو اعتماد المستندات العام.

## الملاحظات المؤكدة

### F1 — أولوية P2: تحديث الصلاحيات العادي يمسح الحوارات ومسوداتها

الموضع: `SalesQuotation/components/list/list.component.ts:262–273`، مع حراسة النتائج في `674–680` وقالب حواري السبب والإيصال في `list.component.html`.

تعتبر القائمة اختلاف مرجع كائن `snapshot` تغييرًا في الوصول، حتى إذا لم يتغير `revision` أو المستخدم أو الفروع أو المفاتيح. مالك `CurrentAccessService` ينفذ تحديثًا عند العودة للتبويب وكل ٦٠ ثانية (`69–71`)، وينشر كائن وصول جديدًا لكل نتيجة سليمة (`95–98`, `169–172`). لذلك يدخل الفرع هنا في التحديث العادي أيضًا: يلغي القراءات ويمسح الجدول ويجعل `rejectionRow` و`receiptQuotationId` فارغين. وبسبب @if يُهدم حوار السبب أو الإيصال وتضيع مدخلاته غير المحفوظة دون قرار تجاهل. يصبح ختم نتيجة الكتابة السابقة غير صالح أيضًا بمجرد تجديد مطابق، فتُحجب نتيجة فعل مرسل وإعادة تحميله رغم بقاء الجلسة والصلاحية نفسيهما.

مثال تحقق: افتح سند مقدم من العرض واكتب بيانات، ثم بدّل التبويب وعد إليه أو انتظر دورة التحديث دون تغيير أي منح؛ يمسح مسار effect هوية الحوار. المطلوب التمييز بين إعادة التحقق المطابقة وبين تغير صلاحيات/سياق فعلي باستخدام الهوية والإصدار الدلاليين؛ ومع السحب المؤقت الحقيقي يُحجب الحوار ذو الحالة مع حفظ مسودته وعمر الكتابة المرسلة بدل هدمه. لا يُحل العيب بإيقاف تحديث الصلاحيات المركزي.

المواصفات الحالية للقائمة تُنشئ المالك عبر `Object.create` وتهيئ حالته يدويًا؛ تغطي منع الإرسال والنتائج القديمة، لكنها لا تشغّل effect الخاص بالمكون، فلا تثبت سلامة هذه الدورة.

### F2 — أولوية P2: غياب منحة معاينة الضريبة يمنع الحفظ عند نسبة غير افتراضية

الموضع: `SalesQuotation/components/details/details.component.ts:391–393, 592–598, 848`؛ المالك الخادمي `SalesQuotationService.cs:84–89`، و`TaxPolicyService.cs:57–68`، وعقد بند الإدخال `SalesQuotationItemAddVM.TaxPercentage` غير القابل للقيمة الفارغة.

العقد يعتبر `SettingsCommonModel.GetMySetting` اختياريًا للمعاينة، ويجيز الإنشاء دون هذه المنحة. لكن عدم منحها يترك السطر الجديد بنسبة الواجهة الافتراضية ٥٪، ثم يرسل save هذه النسبة كاختيار صريح. الخادم يقبل النسبة المضبوطة على الشركة فقط، أو صفرًا عند السماح به. إذا كانت النسبة المضبوطة مثلًا ١٠٪، يفتح المستخدم المحرر بكل منح إنشائه ثم يُرفض حفظه؛ النسبة الافتراضية هنا ليست معاينة فقط كما يوحي العقد. ينطبق الأمر على بند جديد أثناء التعديل أيضًا.

المطلوب فصل قيمة المعاينة عن اختيار ضريبي صريح: عند غياب اختيار معلوم تعتمد السياسة الخادمية النسبة الفعلية، مع عقد إدخال قادر على التعبير عن ذلك، والحفاظ على الاختيار الصفري المقصود إن كان مسموحًا. لا تُوسّع منحة قراءة الإعدادات الكاملة كعلاج ضمني، ولا تُضعف تحقق النسبة الخادمي. لا يتطلب إثبات العيب افتراض نسبة قانونية؛ ٥ و١٠ مجرد قيم إعداد للاختبار.

### F3 — أولوية P2: المسودة تحبس المستخدم بعد انتهاء سياق المحرر

الموضع: `SalesQuotation/components/details/details.component.ts:665–688`، مع `expireContext()` في `373–382` وتسجيل canDeactivate في ملف routes.

عند اختلاف الحساب/الجلسة أو سياق الوصول، يضبط `expireContext` العلم `validContext` إلى false نهائيًا لهذا المكون، مع بقاء form.dirty. بعدها تعيد `canDeactivate` قيمة false قبل عرض قرار تجاهل المسودة بسبب شرط `!this.validContext()` في 672، كما ترفض نتيجة القرار في 687 بالشرط نفسه. إذا لم يكن هناك حفظ ناجح سابق، فلا مسار يغير العلم أو يتيح التخلص المحلي من المسودة؛ يبقى أي انتقال Router مرفوضًا، بينما القالب المحجوب لا يعرض زر خروج.

مثال تحقق: اكتب مسودة ثم غيّر سياق الفرع/الوصول الذي يطلق expireContext، وحاول فتح شاشة مسموحة أو الرجوع. المطلوب إتاحة قرار تجاهل محلي مرتبط بهوية المسودة المنتهية والخروج بعده، دون إعادة تفعيل قراءة أو كتابة السياق السابق، مع استمرار منع المغادرة غير الآمنة إذا بقيت كتابة مرسلة. الإخفاء الأمني وحده لا يستلزم رفض المغادرة إلى الأبد.

## ما تأكد في المصدر دون ملاحظة إضافية مسجلة

- توافق متطلبات المسارات مع المورد الفعلي؛ إنشاء العرض المباشر لا يشترط View، وEdit يضيف View/Update ومصادر الاختيار. يوجد specification للمسار يؤكد هذا الفصل لكنه لم يُشغّل.
- استقلال المنح الست للقرارات مع View وحراسة handler والحالة الخادمية؛ الطباعة وExcel تستهلكان View. الكتابات المرسلة لا تستخدم إلغاء قراءات المكون.
- حماية فلتر العميل وgrid وفرز حقوله بمنحة Customer.Lookup في الواجهة وPermissionPrerequisites، مع إسقاط مراجع العملاء والاتفاقيات بحسب نطاق القراءة. لا يُفهم من ذلك منع عرض الاسم التاريخي المسموح به في DTO التفاصيل وفق العقد.
- استخدام فحص ارتباط الإيصالات الحية مع تثبيت المستأجر والحذف/الإبطال عبر الفروع، وعدم نشر هوية السند المخفي؛ ومسار سياق الإيصال يحجب عميلًا خارج نطاق القراءة قبل نشر سياقه.
- استبعاد متحكم البنود كجذر مستقل، وإرجاع 405 لمسارات التوافق غير المدعومة. لم تُغيّر مراجعة ١٥١ عقد الإيصال المستقل الذي يمنح سياق المصدر عبر Receipt.QuotationContext؛ لا يُصنَّف اختلاف صلاحيات مساره عن زر التهيئة داخل العرض وحده ثغرة مؤكدة دون تغيير عقده.
- وجود موضوع الدليل العربي والإنجليزي في `UserGuide/content/sales-guide.ts` على `/SalesQuotation`. نص الاحتفاظ بمسودة المحرر لا يغلق عيب حوارات القائمة F1 أو عيب المغادرة F3.

## الأداء والتحقق والقبول المتبقي

فحوص المصدر المنفذة: تحليل صياغة ١٢ ملف TypeScript/Angular للوحدة بلا diagnostics، وتحليل صياغة Roslyn لثمانية ملفات C# مرتبطة بلا أخطاء صياغة، وفحص فروق المستودعين والمسافات بلا أخطاء whitespace مع تحذيرات LF/CRLF. هذه ليست typecheck أو build أو اختبارات؛ لا إثبات لترجمة EF أو نتائج HTTP أو أداء مقاس. لوحظ في F1 إعادة تحميل القائمة والعملاء مع تجديد مطابق، وهي كلفة مصدرية مثبتة لا قياس سرعة. لا اقتراح فهرس أو هجرة لهذا الخلل، ولا تغيير SQL أو AutoMapper أو مخطط في المراجعة.

قبول الإصلاحات لاحقًا يحتاج مواصفات سلوكية للمالكين الحقيقيين، ثم تشغيلًا عند المالك: تحديث مطابق أثناء reason/receipt/قرار مرسل، وسحب/استعادة حقيقية مع حفظ المسودة؛ إنشاء بلا منحة إعدادات مع نسبة مضبوطة مختلفة؛ ومسودة dirty بعد انتهاء السياق تسمح بالتجاهل والمغادرة دون إرسال. تبقى اختبارات سحب View أثناء GET/Excel والطباعة، وCreate-only، وعزل المستأجر والفروع، و405 والحالات والتزامن مطلوبة ضمن القبول التشغيلي المعتاد.

لم تُنفذ build/tests/typecheck/lint/browser/HTTP/DB/migration/snapshot/commit/push/deploy، ولا Sigma MCP أو Graphify. لم تتغير ملفات التطبيق أو الإعداد أو قواعد التعليمات أو الجرد. لا ادعاء بإغلاق الملاحظات الثلاث أو نجاح تشغيل الوحدة؛ إغلاق الحالة أعلاه يخص انتهاء هذه المراجعة فقط.
