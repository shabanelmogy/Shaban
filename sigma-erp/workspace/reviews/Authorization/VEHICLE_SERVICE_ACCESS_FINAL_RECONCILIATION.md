# مطابقة صلاحيات تعريف خدمات المركبات

| البند | القيمة |
|---|---|
| Status | Implemented — source-only |
| Owner verification pending | yes |
| التاريخ | ٩ نوفمبر ٢٠٢٦ |
| العقد | [تعريف خدمات المركبات](VEHICLE_SERVICE_ACCESS_CONTRACT_FREEZE.md) |

القائمة ومسار العرض والتفاصيل تحتاج `VehicleService.View`. الإنشاء
يحتاج Create مع العرض، والتعديل Update مع العرض؛ يلزم المحرر أيضًا
ServiceItem.Lookup وItem.Lookup، ولا يطلبهما وضع العرض. الحذف يحتاج
Delete مع العرض وتحقق الاستخدام في الخدمة. روابط create/view/edit
مستقلة ومثبتة في خريطة الوصول مع متطلبات المحرر الفعلية، والقائمة
والتنقل وأفعال الصف تعيد فحص المنح والعضوية والسياق قبل التنفيذ.

التعريف رأس وثلاث مجموعات أطفال، وليس حجز خدمة أو تسجيل صيانة
فعليًا. تتبع تغييرات الأطفال واختيار البنود وإزالتها منحة حفظ التجميع؛
لا تُنشأ منح حذف مسودة مستقلة. تعتمد الخلفية CRUD الموروث مع ملكية
الأطفال والمراجع في VehicleServiceService؛ لا نقاط خدمة أو مخطط أو
حسابات جديدة. التعريف مشترك داخل الشركة وفق نطاق المستودع.

أعمدة القائمة الاسم وحد الكيلومترات والأشهر تقابل Name/DueAtKMs/OrMonths
مع Id للأفعال. تبقى العقود الرقمية كما هي. مرشحات القائمة وفرزها
وترقيمها محفوظة في المسار. لا إخراج طباعة أو تصدير قائم في هذه الشاشة
يُضاف أو يُدعى اكتماله من اسم الإجراء المرجعي.

## العمر والمصادر

طُوبقت في التكامل دورة حجب المحرر المركب والاختيارات المنفصلة وحوار
اختيار البنود عند سحب الوصول. تُلغى القراءات والتأكيدات المنتهية،
ويُتاح التخلص المحلي الصريح بعد الرفض. يحتفظ الحفظ والحذف المرسلان
بعمرهما مع سياج نشر محلي وعالمي؛ يثبت نجاح الحفظ قبل حجب نشره فلا
تؤدي إعادة المنح إلى تكراره. تُستعاد الاختيارات الأولية الملغاة دون
استبدال المسودة أو إعادة القراءة عند نهاية مؤشر تحميل فقط.

القائمة والتفاصيل تشغيلية مباشرة. مصدر ServiceItem/GetSelect مباشر
بلا opt-in للمخبأ؛ مصدر Item/GetSelect يستخدم مخبأ Item ومراقبته
وإبطاله القائمين، مع الاحتفاظ بتسميات الاختيارات المحفوظة. لا مخبأ
تشغيلي جديد. يملك محمل الصفحة القائمة والتفاصيل والحفظ وتهيئة
اختيارات المحرر المطلوبة. حوار اختيار البنود يستهلك ما حُمّل ولا
يبدأ شبكة جديدة. يبقى فشل القراءة وإعادة المحاولة ظاهرين.

تقرأ القائمة count ثم projection مرقمًا، وتقرأ التفاصيل مجموعاتها
بمالكها الحالي. لا تضيف الصلاحيات طلبًا لكل صف. يوجد فهرس الاسم
والاشتراك بمرشح الحذف اللين؛ لا اقتراح فهرس جديد في شريحة الحراسة.
قياس الزمن وحجم مجموعات التفاصيل وخطة SQL معلق للمالك بشروط بيانات
متطابقة قبل وبعد، ولا تثبت السرعة من قلة استدعاءات المصدر وحدها.

الأدلة المرجعية المقروءة: شرح سبيد S229، وشاشة الخدمات
08-fleet/08-services والمتحكم C1165 بتاريخ ٢٨ أكتوبر. النسخ والاستيراد
والتخصيص بحسب الماركة والموديل في المرجع فجوات وظيفية خارج عقد الشاشة
القائم؛ لا تُخترع لها منح أو طلبات. لم يستدع هذا التبني مثال أودو
لتغيير عقد محلي مثبت. [تسليم المحرر](VEHICLE_SERVICE_EDITOR_ACCESS_HANDOFF.md).
حُدّث موضوع الخدمات في `fleet-guide.ts` عبر قارئ دليل الأسطول القائم.

## المطابقة النهائية والتحقق المصدري

| المسار أو العملية | دليل المطابقة النهائي |
|---|---|
| القائمة والرابط وعرض التفاصيل | سياسة القائمة View، وسياسات create/view/edit مستقلة؛ عرض التفاصيل لا يبدأ اختيار البنود أو القطع. |
| الإنشاء والتعديل | يجتمع العرض ومنحة الحفظ مع اختياري البنود والقطع في المسار والزر والمعالج؛ الخادم يفرض CRUD، ومصادر الاختيار تفرض Lookup الخاصة بها. |
| الأطفال وحوار الاختيار | الإضافة والإزالة تتبعان محرر التجميع؛ انتظار أي إقرار يمنع الحفظ والتغييرات الأخرى. القرار يراجع snapshot الاختيار وعضوية الصف بعد الإقرار. |
| الحذف | منحة Delete مع العرض وعضوية الصف، وإلغاء القرار المنتهي؛ DELETE المرسل مستقل مع سياج النشر، وتظل شروط الاستخدام عند الخدمة. |
| إعادة المنح | تُستعاد الاختيارات الناقصة مع المسودة؛ Item مراقب عبر مالكه وServiceItem مباشر. الفشل ينتظر Retry، ولا يتحول finalize إلى trigger لإعادة القراءة. |
| التحميل | التفاصيل والاختيارات المطلوبة وRetry المراقب تتبع مالك الصفحة؛ أزيل مؤشر تفاصيل محلي مكرر، وبقي aria-busy والخطأ وإعادة المحاولة. |

أُصلح في التكامل ظهور زر التعديل في وضع العرض ليستهلك متطلب المحرر
نفسه. تمت مراجعة مستقلة قراءة فقط من عامل المحرر الآخر شملت ملفات
الوحدة والعقد والجلسة والاختيارات والخلفية؛ لم يجد خللًا مؤكدًا بعد الإصلاح.
تظل مسؤولية التكامل والتوثيق والجرد عند الجذر. استُخدم العامل القائم لتجنب
إعادة اكتشاف السياق، مع ملكية قراءة فقط وعدم تداخل مع تعديل الجذر.

فُحصت الفروق المقيدة للواجهة وملفاتها الجديدة والخريطة والمسارات والدليل؛
لم تتغير ملفات الخلفية الخاصة بالوحدة في هذه الدفعة، وفُحص ربطها الحالي.
أعطى تحليل ٣٢ ملفًا وقالبًا للوحدتين والمالكين المباشرين صفر أخطاء صياغة
وصفر imports محلية مفقودة. فحص الفروق المقيد بلا أخطاء، وفحص الحزم
الثماني سليم. لم يشمل ذلك type checking أو تشغيل مواصفات المحرر الست.
طُبقت مراحل التنفيذ والتكامل والمطابقة وفق العقد المجمد؛ لا هجرة أو حساب
أو تغيير AutoMapper. لا صور جديدة، والمرجع الوظيفي لا يثبت سلوك خادم خارجي.
موضوع خدمات المركبات ضمن /UserGuide/fleet وقائمة دليل الأسطول القائمة.

## تجربة المالك النهائية

١. افتح القائمة وروابط العرض والإنشاء والتعديل بالمدير ثم مستخدم عرض
فقط. تحقق من عدم طلب اختيارات المحرر في العرض ومن رفض الكتابة المباشرة.
٢. اسند الإضافة أو التعديل مع الاختيارات، وجرّب الرأس والبنود والقطع
والعمالة والحفظ. امنع منح اختيار مطلوبة وتحقق من الحجب المفهوم.
٣. افتح اختيار البنود، وأزل صفًا محفوظًا بإقرار ثم بإلغاء؛ اسحب الوصول
أثناء القرار وتحقق من بقاء المسودة ومنع تنفيذ القرار المنتهي.
٤. جرّب حفظًا أو حذفًا مرسلًا مع سحب المنحة قبل النتيجة، ثم أعدها؛
تحقق من عدم تكرار الطلب أو نشر نتيجة تخص مستخدمًا سابقًا.
٥. افشل تفاصيل أو اختيارًا ثم أعد المحاولة، وغيّر صلاحياته أثناء
مسودة؛ تحقق من استعادة الاختيارات دون استبدال المدخلات أو حلقة طلبات.

البناء والاختبارات والمتصفح والبيانات وقبول المالك معلقة. لا هجرة جديدة.
وصف تغيير الواجهة المقترح: `fix(vehicle-services): enforce definition access lifetimes`.
وصف الوثائق المقترح: `docs(authorization): reconcile vehicle type and service access`.
