# مراجعة اختفاء صورة الدخول بعد النشر — ٢٠٢٦-١٠-٣١

الطلب سؤال تشخيصي، لذلك المراجعة مصدرية فقط دون تعديل التطبيق أو إعدادات النشر. الفئة S، الشكل غلاف الدخول AuthComponent عبر app.routes/auth/auth-routing، ولا عقد خلفي أو قائمة أو نموذج أعمال جديد. استُخدمت مهارة الشاشة وMaster1/5/7 وUI1/25 والحزمة PHASE05 بتناسب بعد Check ناجح للحزم الثماني. مدخل تحليل Speed المقروء في المهمة مستمر؛ هوية صورة Sigma وتقديم ملفها في النشر غير منطبقين على دورات الأعمال المرجعية.

الدليل المؤكد: auth.component.html:211 يستعمل ./assets/media/misc/auth-fleet-operations.webp. الملف متعقب وموجود في src/assets وحجمه 100828 بايت، وموجود أيضًا في dist/sigma/assets/media/misc الحالي دون تشغيل build أو الزعم بأنه نفس المرفوع على السيرفر. angular.json ينسخ src/assets إلى المخرج المسطح، وbaseHref نسبي وwithHashLocation فعلي في app.config؛ لا غياب مثبت من إعدادات نسخ الأصول.

السبب المرئي المثبت في المصدر: auth.component.scss:780–805 يخفي auth-product-preview بواسطة display:none لكل عرض <=1100px. القاعدة الضيقة اللاحقة تخفيه أيضًا. لذلك اختلاف عرض نافذة المتصفح أو التكبير بعد النشر يكفي لاختفاء الصورة حتى مع نجاح طلب الملف. لم تُلغ هذه القاعدة ضمن سؤال السبب.

احتمال يحتاج دليل نشر: الصورة WebP، وweb.config يضيف webmanifest فقط دون خريطة WebP صريحة؛ قد تعتمد خدمتها على إعداد static MIME الموروث من IIS. غياب الإضافة المحلية لا يثبت خطأ السيرفر، فلا يجزم بوجود 404.3 دون استجابة الطلب. يجب التمييز بين ملف 200 لكنه مخفي بالتصميم، و404/404.3 أو استجابة HTML/نوع غير صحيح من النشر. لم يُستدعَ موقع خارجي أو API أو متصفح.

ملاحظة منفصلة: الخلفية التزيينية في auth.component.scss:537 تستعمل /assets/media/misc/auth-bg.png من جذر النطاق؛ قد تفشل عند النشر تحت مجلد فرعي، لكنها ليست صورة معاينة الأسطول. لا يخلط التشخيص المصدرين.

الأداء والتحميل والكاش: أصلان ثابتان بلا استعلامات أو تحميل بيانات أو source-cache lookup جديد؛ service worker app-assets يشمل /assets/** بحسب الإعداد المحلي. لا تغيير لسياسات الجلسة أو اللودر أو فهرس أو مخطط، ولا قياس قبل/بعد. تحقق المالك المطلوب هو عرض أكبر من 1100px ثم نتيجة طلب ملف المعاينة نفسه على النشر، إن ظل مختفيًا. لا تعديل دليل تطبيق لعدم تنفيذ تغيير؛ لا وكلاء لأن التشخيص محدود ومتسلسل. لم تُشغل اختبارات أو بناء أو lint أو قاعدة بيانات أو migration أو نشر أو commit.

## استكمال التشخيص بعد توضيح المالك — ٢٠٢٦-١٠-٣١

أفاد المالك أن الاختفاء يحصل على جميع مقاسات الشاشات؛ لذلك قاعدة <=1100px لا تفسر العطل العام، ولا يُعلن أنها سبب حالة النشر. عُرض ملف WebP المحلي وفُحص بصريًا وهو سليم. تتطابق بصمة SHA256 لنسختي src وdist الحاليين: 21A97B46DBE6941975B28ACD43E0B17891F9C0A4FA05F4D224A0448FCCC73791. سجل ngsw.json الحالي يحتوي الملف في قائمة الموارد وبصماتها؛ هذا يثبت إدراجه في المخرج المحلي لا وصوله إلى السيرفر. ما فوق 1100px ليس مخفيًا بالقاعدة المصدرية الحالية، وobject-fit/max-height لا يثبتان اختفاءه العام.

لا توجد نتيجة HTTP من النشر أو رابط نشر يتيح تحديد عنوان الملف المعني في السياق الحالي. فشل خدمة WebP أو نقص الملفات المرفوعة/اختلاف نسخة النشر يظلان فرضيتين، وإعداد MIME المحلي غير الصريح لا يثبت انعدام الإعداد الموروث في IIS. طلب رابط التطبيق سؤال تشخيصي لإكمال الأدلة، وليس طلب إذن لتعديل إعدادات. لم تتغير ملفات التطبيق أو web.config أو المخرج المبني، ولم يُجرَ تشغيل أو اتصال نشر. تُراجع الاستجابة ونوع المحتوى ومطابقة الملف قبل اعتماد تصحيح نشر بعينه.
