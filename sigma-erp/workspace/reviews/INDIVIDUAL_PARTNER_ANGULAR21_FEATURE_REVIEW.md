## النتيجة

### متابعة تشخيص استجابة ٤٠٤ — ١٥ نوفمبر ٢٠٢٦

| البيان | القيمة |
|---|---|
| الحالة | Closed |
| قبول المالك معلق | no — اكتمل التشخيص المصدري فقط، لا تنفيذ أو قبول تشغيلي |
| النطاق | تحديد سبب فشل GET لقائمة الأفراد مع المستخدم والمدير؛ لا تعديل مصدر |

أبلغ المالك عن 404 للمسار
`GET https://localhost:7178/IndividualPartner?pageNo=1&pageSize=15`، وأكد أن
المدير يتأثر أيضًا. الواجهة ترسل المسار الصحيح من
`IndividualPartnerService.getList`، والمتحكم ما زال يرث GetListAsync ذي
HttpGet والجذر `[controller]` من SiGmaControllerBase. لا فرق حالي في هذين
المتحكمين يزيل المسار.

السبب المثبت من ترتيب المصدر: Program.cs يستدعي
CustomerProfileMediaPath.IsBlockedStaticRequest قبل المصادقة والتفويض
واستدعاء المتحكم. مالك المسار يمرر LegacyPhotoFolder بقيمة
`individualPartner` إلى PrivateUploadPath.IsStaticRequest؛ والأخير يفك
الترميز ثم يطابق أي مقطع من المسار دون حساسية لحالة الأحرف. لذلك يصنف
`/IndividualPartner` نفسه مسار صورة قديمة، ويُرجع middleware استجابة 404
وينهي الطلب. يشمل ذلك جذر القائمة وأبناء مسار المتحكم بصرف النظر عن هوية
المدير أو منح المستخدم. معاملات الصفحة لا تؤثر لأن المطابقة على Request.Path.

أثبت git blame أن الاستدعاء وقاعدة الصور أضيفا في التغيير
`b91a7a99c66484c12affb62c57091dc24427bfa2` بتاريخ ٢٠٢٦-١١-١٥ الساعة
٠٨:٤٣:٢٨ بتوقيت القاهرة. هذا نطاق مختلف عن إصلاح معامل مسار User identity
السابق. الاختبارات المصدرية الموجودة تغطي منع صورة قديمة مشفرة ومجلدات
الحفظ الجديدة، ولا تغطي مرور مسارات API ذات الاسم المتصادم.

الإصلاح الموصى به: تمييز مسار صورة قديمة ذي بنية مجلد الشركة والملف عن
مسارات API، مع الحفاظ على رفض ملفات الصور الخاصة وتطبيع الترميز والفواصل.
يجب أن يغطي التحقق مرور جذر الأفراد والتفاصيل والاختيارات والإجراءات، وبقاء
حظر مسارات الصور المباشرة والمشفرة. لا يُوصى بإلغاء حماية الملفات أو تغيير
اسم المسار العام أو إضافة منح للمدير لعلاج هذا التصادم.

التشخيص Tier S وفق Master1 وBE6 ومهارتي Sigma والتشخيص المنهجي المتاحتين؛
لم تتغير العقود، لذلك لا مقارنة وظيفية جديدة مع شرح سبيد أو كوده ولا فجوة
تحتاج Odoo. لا تغيير تحميل/cache/query/index/schema أو دليل المستخدم، ولا
قياس أداء أو تنفيذ HTTP حي أو متصفح أو بناء أو اختبارات أو قاعدة بيانات
أو commit/push. لا وكلاء فرعيون لصغر العمل. تعديل التنفيذ وقبوله التشغيلي
لم يُنفذا ضمن سؤال المالك عن السبب.

### تنفيذ إصلاح مسار الأفراد — ١٥ نوفمبر ٢٠٢٦

| البيان | القيمة |
|---|---|
| الحالة | Implemented — source-only |
| قبول المالك معلق | yes |
| التفويض | طلب المالك «ظبط الاصلاح» بعد التشخيص السابق |

نُفّذ إصلاح Tier S في PrivateUploadPath وCustomerProfileMediaPath. أصبحت
مطابقة مجلد الصور القديم عبر IsNestedStaticRequest، فتتجاهل مقطع الجذر
وحده وتبقي حظر كل ظهور متداخل للمجلد؛ بذلك لا يُحجب جذر API للأفراد أو
أبناؤه. تحليل المقاطع داخل المالك نفسه يحتفظ بفك الترميز حتى أربع مرات
وتوحيد الفواصل وتجاهل حالة الأحرف وتقليم النقطة والمسافة. يبقى
IsStaticRequest للمجلدات الخاصة الأخرى بنفس مطابقة جميع المقاطع السابقة.
العقد المستهلك مثبت في FileStore الذي يحفظ الملفات في
`/{subscriptionId}/{folder}/{fileName}` داخل جذر الشركة. تمنع المطابقة
أيضًا البادئات والتداخل والتراجع، ولا تعتمد على امتداد ملف أو جرد أفعال API.
لا تغيير في Program أو المصادقة والتفويض أو المسارات العامة أو مالك التخزين.

أضيفت ٢٣ حالة إلى CustomerProfileMediaPathTests: ١١ لمرور جذر API
والاختيارات والتفاصيل والأفعال، و١٢ لحظر الصور والمستندات مع الترميز المتكرر
والفاصل المشفر والخلفي والأحرف الكبيرة والنقطة/المسافة والبادئة والتداخل
والتراجع. تتحقق الحالات من نتيجة المالك الحقيقي، ولم تُشغل الاختبارات ضمن
حد التنفيذ الحالي؛ لا ادعاء RED/GREEN. نجح البناء النهائي للمشروع
`SigmaBackend/tests/SiGma.BranchAccess.Tests/SiGma.BranchAccess.Tests.csproj`
ومراجعه، ومنها Helpers وServerAPI: خروج صفر و٠ أخطاء و٣٧ تحذيرًا خارج
أسطر الإصلاح. استُخدم مخرج مؤقت لتجنب استبدال ملفات الخدمات الجارية:

```powershell
dotnet build tests/SiGma.BranchAccess.Tests/SiGma.BranchAccess.Tests.csproj --artifacts-path "$env:TEMP/sigma-identity-route-20261115" --no-restore --nologo --verbosity quiet
```

رُوجعت الفروق الكاملة لملفات الخلفية الثلاثة وفحص whitespace. لا تغيير
DTO أو AutoMapper أو حساب أو مخطط أو استعلام أو فهرس أو تحميل/cache أو
مؤشر مرئي، ولا قياس أداء أو هجرة مطلوبة. المراحل الاكتشاف المثبت وAPI/الربط
والمطابقة المحدودة؛ لا إجراء أعمال أو تغيير شاشة. لا فجوة وظيفية جديدة
تحتاج سبيد أو Odoo. روجع دليل العملاء القائم في
`UserGuide/content/customers-guide.ts` وموضوع الأفراد: تبقى خطوات البحث
والفتح وملف العميل دقيقة؛ هذا إصلاح شفاف لا يضيف خطوة لتوثيقها.

حُدّث BE6 وصف راوتر مهارة Sigma وسجل مراجعتها بقاعدة فصل جذر API عن موضع
مجلد التخزين. أُعيد توليد الوصفات الثماني وفحص تطابقها بنجاح، مع مراجعة
الفروق المولدة وحفظ التغييرات السابقة. اقتراح رسالة الخلفية:
`fix(customers): distinguish legacy photo folders from individual API routes`.
اقتراح رسالة التوثيق: `docs(api): separate static folder guards from API roots`.

التحقق المتبقي: إعادة بناء وتشغيل ServerAPI ثم فتح الأفراد بحساب المدير
وحساب عادي له المنحة وفرع العرض، وتجربة التفاصيل والاختيارات، والتحقق من
بقاء 404 لصور الشركة القديمة عند طلبها مباشرة. لم تُشغل اختبارات أو HTTP
حي أو متصفح أو أوامر قاعدة بيانات أو migrations أو commit/push، ولم تُعد
تشغيل خدمات المالك. لم يُستخدم وكلاء فرعيون لصغر النطاق.

الشاشة تستخدم أساليب أنجولار الحديثة بالفعل: مكونات مستقلة، وإشارات وحالة مشتقة وحقن حديث، وتحكم شرطي حديث، ونماذج تفاعلية ذات أنواع، وإلغاء اشتراكات بعمر المكون. بقاء زون واستعلام العرض بالزخرفة والنماذج التفاعلية ليس عيب توافق. ثبت الإصدار المعلن والمثبت محليًا، ولم يتحقق إصدار التطبيق المنشور بالتشغيل.

أصلح التنفيذ غياب متابعة المصادر المرجعية المعتمدة أثناء بقاء الشاشة مفتوحة، وأزال مؤشر تحميل التفاصيل المحلي المكرر. أضاف رسالة الحالة وإعادة المحاولة بالمالك المشترك، وحدّث دليل المستخدم بالعربية والإنجليزية. تبقى المراجعة والتعديلات مصدرية؛ لا ادعاء بقياس سرعة أو نجاح تشغيل.

## بيان النطاق والأدلة

- المسار الفعلي من جذر التطبيق: `app.routes.ts` ثم `layout/layout.module.ts` ومسارات الصفحات ثم `pages/routing.ts` واستيراد `individualpartner.routes.ts`. يفتح المسار `/IndividualPartner` القائمة، وتفتح أبناء الإنشاء والتعديل والعرض محرر التفاصيل نفسه.
- المراجع المعتمدة: كتاب الواجهة، النوع الثالث في كتالوج الشاشات، ومالكو الخطوات والأقسام والتحقق والجداول المشتركون. القائمة تستخدم مالكي العنوان والتصفية والجدول. نمط الخلفية الثاني لأن السجل يمتلك مستندات وبطاقات؛ لا تعديل له.
- حدود الأدلة: مصدر حالي وحزم مثبتة ووثائق رسمية للإصدار. لا صور أو فيديو أو متطلبات حقول جديدة. لا قرار تجاري مفقود يمنع هذا الإصلاح المحدود.
- المرحلة صفر للاكتشاف، وعقد الواجهة للمرحلة الأولى، وإصلاحات محدودة في مرحلتي القائمة والمحرر، ومراجعة توصيل المصدر المشترك، ثم مطابقة مصدرية. مرحلة الإجراءات لا تغير أي انتقال أو حذف. لم تبدأ خطة لتغيير زون أو النماذج أو واجهة البيانات.
- مستودع الواجهة هو `F:/My Work/Sigma/SiGmaAngularFrontEnd`، ومستودع الخلفية هو `F:/My Work/Sigma/SigmaBackend`، ومالك كتب الأنماط هو `F:/My Work/Shaban Documents/Shaban`. مساحة العمل العليا ليست مستودعًا صالحًا؛ سجلات المراجعة والمهارة قورنت من الملف مباشرة.
- كانت هناك تغييرات مسبقة في سندات القبض والودائع والترجمات والمسارات ودليل المستخدم خارج الملفات الخمسة المعدلة هنا. بقيت محفوظة؛ لم يتغير مسار الأفراد في فرق ملف مسارات الصفحات السابق.

## أدلة اعتماد أنجولار ٢١

جميع المسارات المذكورة في الجدول التالي تحت مجلد الواجهة إلا حيث يذكر خلاف ذلك.

| المجال | المستهلك والمنتج الفعليان | القرار |
|---|---|---|
| الإصدار | ملف الحزم والحزمة المثبتة `node_modules/@angular/core/package.json` يحددان 21.2.25؛ حزمة الواجهة المرئية 21.1.10 | مؤكد محليًا؛ إصدار النشر غير مقاس |
| التشغيل | `src/main.ts` يستدعي `bootstrapApplication` وإعداد الجذر يملك موفري العميل واعتراضاته | نمط حديث؛ لا عميل آخر في الأفراد |
| ملكية المكونات | القائمة والتفاصيل تملكان `imports` مباشرة، ولا توجد وحدة تعريف للأفراد في المسار الفعلي | مستقلتان؛ غياب العلم الصريح لا ينفي الاستقلال في الإصدار ٢١ |
| الحالة | القائمة تستخدم `signal`؛ التفاصيل تستخدم أيضًا `computed` لوضع العرض والعنوان والانشغال | حديث؛ لم يُستبدل كل متغير بإشارة دون حاجة |
| القوالب | استخدام `@if` و`@switch`، ولا توجد توجيهات النجمة القديمة في المجلد | حديث؛ خلايا الصفوف يملك تكرارها الجدول المشترك |
| الطلبات | القائمة تربط الموضوع بعملية `switchMap` وبدء مؤجل ثم إنهاء في `finalize`؛ العمر محكوم بواسطة `takeUntilDestroyed` | إلغاء القراءة السابقة والتنظيف موجودان فعليًا |
| النماذج | إنشاء الحقول ذات الأنواع بواسطة `FormBuilder` مع `nonNullable`، وأنواع صريحة لصفوف المستندات والبطاقات | اختيار مدعوم؛ نماذج الإشارة تجريبية في الإصدار ٢١ وليست مطلبًا لهذا الإصلاح |
| استعلام العرض | التفاصيل تستخدم `@ViewChild('editorBody')` للتمرير إلى بداية الخطوة | أسلوب أقدم ومدعوم؛ الترحيل إلى استعلام الإشارة اختيار منفصل عند وجود فائدة |
| تغيير العرض | لا استراتيجية تحديث صريحة في مكوني الأفراد، والجذر يحدد `provideZoneChangeDetection` | عقد توافق مقصود؛ لا تحويل إلى دون زون أو فرض استراتيجية أخرى |
| حدود التوافق | وحدات التحميل الكسول في الجذر والتخطيط وبعض الواردات المشتركة لا تعني أن شاشة الأفراد وحدة قديمة | استثناء مدعوم، دون ادعاء تحديث التطبيق كله |

المصادر الرسمية المسجلة في كتاب الواجهة: [مكونات الإصدار ٢١](https://v21.angular.dev/guide/components)، [استعلامات العرض ودعم الزخارف](https://v21.angular.dev/guide/components/queries)، [النماذج التفاعلية](https://v21.angular.dev/guide/forms)، [تجريبية نماذج الإشارة في الإصدار ٢١](https://v21.angular.dev/tutorials/signal-forms). أعيدت صياغة قاعدة الاشتراكات لتوضح أن اكتمال طلب محدود لا يثبت أمان المغادرة أو منع استجابة متأخرة؛ تبقى قواعد إلغاء الطلبات في الكتلة الثامنة والعشرين واجبة.

## بوابة الكاش: مصادر فعلية ومطابقة نهائية

كل عنوان أدناه يبدأ بعنوان واجهة البيانات المعرف في البيئة. غلاف القوائم `Results<DropDownSelect>`، ووضع الخطأ للقراءة الأولى والمتابعة متطابق: `skipErrorInterceptor: true`.

| العنوان ورمز المصدر | التصنيف والمالك | الكاتب والإبطال وإشعار المستأجر | المستهلك النهائي والعمر والتعافي |
|---|---|---|---|
| `Branch/GetSelect`، خدمة الفروع | مرجعي معتمد؛ المصدر يفعل `cacheSelect` والمالك `ReferenceLookupCacheService` | إنشاء وتعديل الفرع يمران بعامل إبطال النجاح، والحذف الموروث يمر به؛ الموضوع `lookup-branches` مسجل لخادم الزمن الفعلي | قراءة أولى محدودة في القائمة والتفاصيل؛ بعد النجاح متابعة مستقلة مرة واحدة؛ حفظ تسمية الفرع المختار؛ إعادة محاولة المصدر الفاشل فقط |
| `ContactGroup/GetSelectByType/Customer`، خدمة المجموعات | مرجعي معتمد؛ الهوية تشمل مسار النوع كاملًا | الكتابات المخصصة والموروثة تبطل عائلة المصدر؛ الموضوع `lookup-contact-groups` | متابعة نوع العميل في القائمة والتفاصيل؛ تعتمد التسمية المحتفظ بها على اختيار حوار المجموعة أو حقل المحرر الحالي؛ إعادة المحاولة داخل الحوار عند فتحه |
| `Country/GetSelect`، خدمة البلدان | مرجعي معتمد | إنشاء وتعديل البلد وعامل الحذف الموروث؛ الموضوع `lookup-countries` | متابعة في المحرر تحفظ اختياري الجنسية وبلد العنوان معًا |
| `Currency/GetSelect`، خدمة العملات | مرجعي معتمد للهوية فقط؛ لا تغيير لسياسة الأرقام أو أسعار الصرف | إنشاء وتعديل العملة وعامل الحذف الموروث؛ الموضوع `lookup-currencies` | متابعة خيارات العملة في المحرر؛ لا تعديل قيم النموذج ولا الحسابات |
| `Staff/GetSelect`، خدمة الموظفين | مرجعي مباشر دون اشتراك المصدر بالكاش؛ يرث القيمة المعطلة من الخدمة الأساسية | لا كاش ولا متابعة ولا إبطال جديد في النطاق | قراءة محدودة عند فتح المحرر أو إعادة محاولة التحميل؛ لا استنتاج أهلية كاش من اسم العنوان |
| `TariffCard/GetSelect`، خدمة بطاقات التعرفة | مرجعي مباشر دون اشتراك المصدر بالكاش | لا كاش ولا متابعة ولا إبطال جديد في النطاق | قراءة محدودة عند فتح المحرر أو إعادة المحاولة، وتحفظ تسميات التفاصيل الحالية |
| التعدادات والاختيارات المحلية | محلية دون شبكة | لا ينطبق | لا كاش ولا متابعة لازمة |
| `IndividualPartner` و`GetByWithNavigationsId/{id}` و`{id}/agreements` و`CheckUnique` | قراءات تشغيلية وتحقق مباشر | تبقى بعقودها؛ ليست مصادر كاش مرجعي | القائمة والتفاصيل والتاريخ والتحقق لا تدخل الكاش |

لا يوجد ضمن وحدات الاستيراد المباشرة المقروءة مستورد لهذه المصادر الأربعة. استيراد الأفراد مصدر آخر؛ ينعش قائمة العملاء المجمعة فقط بعد عدد صفوف محفوظ موجب، وتبقى تبعية كتابات الأفراد لمصدر العميل المجمّع كما هي. لم يُضف أي افتراض لتبعية أو إشعار.

أدلة التنفيذ النهائي:

- يُنشئ كل مكون مالك `ReferenceLookupBindings` بعمر `DestroyRef`، ويستدعي `bind` بعد فحص نجاح مصدره داخل نتيجة القراءة المحدودة. يمنع المالك المشترك تكرار ربط المفتاح وينهي الاشتراك عند تدمير المكون.
- مجموعة `bootstrappedReferences` تسجل نجاح القراءة الأولى فقط؛ لا تحفظ البيانات ولا تمثل كاشًا جديدًا. تتخطى إعادة محاولة التحميل المصادر التي أصبحت تحت متابعة، فلا تستبدل لقطة متابعة حديثة بقراءة أولية متأخرة. الموظفون والتعرفة يبقيان قراءتين مباشرتين.
- دوال تطبيق المتابعة لا تفعل إلا استبدال مصفوفة الخيارات. توفر دوال الاختيار والخيارات الحالية احتفاظًا بالتسمية المختارة حتى عند وصول قائمة فارغة؛ لا تعديل لقيم الحقول أو حالة المسودة.
- تصفير السياق ينشر مصفوفة فارغة عبر المالك المشترك؛ مسارات متابعة الخيارات لا تدمج تفاصيل `loaded` القديمة. دمج تسميات التفاصيل يبقى محصورًا بتحميل التفاصيل والقراءة الأولى.
- فشل الغلاف والنقل في القراءة الأولى يبقيان خطأ تحميل مع إعادة محاولة. فشل المتابعة يحتفظ بالخيارات ويظهر خطأ المالك المشترك؛ `retryLookups` يعيد المصادر الفاشلة فقط. يختفي تحديث البيانات المحتفظ بها عن حالة التحميل المحلية ويبقى مؤشره المشترك في الرأس.
- عناوين المصدر والكتّاب والموضوعات تأكدت من الخدمة الأساسية وخدمات الفروع والمجموعات والبلدان والعملات وخرائط الكاش وتسجيلات الزمن الفعلي؛ القبول الشبكي للمستأجر والمدة والعودة للتبويب وإعادة الاتصال ما زال عند المالك.

## بوابة التحميل

المسار لا يحدد إخفاء تحميل الصفحة. يحسب التخطيط `showPageLoading` بقيمة افتراضية صحيحة، ويعرض المضيف العام في قالب التخطيط. عداد `LoadingService` يحتفظ بالتقدم عند تغير الاستعلام أو الجزء المرجعي ويصفره عند تغير شجرة مسار الصفحة.

| العملية الفعلية | مالك التقدم | البدء والإنهاء والإلغاء | الحالة النهائية |
|---|---|---|---|
| قائمة الأفراد في `bindListQueries` | عام للصفحة | بدء داخل `defer` بعد الاشتراك؛ `finalize` يقابله عند النجاح والفشل والإلغاء؛ `switchMap` يلغي القراءة السابقة | الجدول وزر البحث يحتفظان بالانشغال، ويخفي المالكان المشتركان مؤشرهما عندما يعمل العام |
| تحميل التفاصيل في `loadDetails` | عام للصفحة | بدء قبل الاشتراك المباشر وإنهاء في `finalize`؛ إلغاء بعمر المكون | أزيلت رسالة التحميل المحلية المكررة؛ بقيت أعلام التحميل والانشغال وخطأ التفاصيل وزر إعادة المحاولة |
| الحفظ والحذف وتعديل المجموعة والتصدير | عام للصفحة | أزواج البدء والإنهاء الحالية مع `takeUntilDestroyed` | لا تغيير للحماية من التكرار؛ رسائل نجاح وفشل الكتابة يملكها الاعتراض، وأخطاء التصدير تملكها القائمة |
| القراءة الأولى للقوائم المرجعية | محلي مساعد | القراءة محدودة بواسطة `forkJoin`؛ `lookupLoading` ينتهي في `finalize` | مكون حالة مرجعي مشترك واحد؛ ينتقل إلى داخل حوار المجموعة بدل نسخة أخرى خلفه |
| إعادة تحقق كاش بقيمة محتفظ بها | صامت في الشاشة | عمر المتابعة والطلب يديرهما الكاش المشترك | لا تعطيل للمحرر ولا تعديل مسودة؛ مؤشر نشاط الرأس يملكه الكاش |
| تاريخ الاتفاقيات | محلي للحوار | المكون المشترك يملك الاشتراك و`finalize` والتدمير | عقد الحوار القائم بقي دون تعديل؛ ليس سببًا لبدء تحميل صفحة مخفي خلف الحوار |
| التحقق من التكرار والملفات | محلي للحقل أو للعملية المساعدة | مدقق التكرار يلغي السابق ويستخدم عمر المكون؛ تتبع الرفع والتنظيف له إنهاء وحالة مستقلة | لم يضف تقدم عام أو إعادة كتابة لمدقق/رفع مشترك |

مراجعة المصدر تثبت التوصيل فقط. ظهور المؤشر وتداخل القراءات والتوقيت تحتاج قبولًا تشغيليًا.

## السرعة والاستعلامات والفهارس

| المسار | حدود الطلب والحجم من المصدر | نتيجة المراجعة |
|---|---|---|
| فتح القائمة | طلب صفحة تشغيلية وقراءتا خيارات محدودتان ومتوازيتان منطقيًا؛ قراءة الخيارات قد تصيب الكاش؛ الصفحة الافتراضية ١٠ والأقصى ١٠٠ | لا طلب تفاصيل لكل صف؛ مفتاح الطلب يمنع إعادة طلب الاستعلام نفسه، والفرز/التصفية يطبقان قبل الترقيم |
| فتح محرر الإنشاء أو التعديل | ست قراءات خيارات؛ الأربع المعتمدة عبر المصدر المشترك واثنتان مباشرتان؛ التعديل يضيف طلب تفاصيل واحدًا دون انتظار الخيارات | لا سلسلة قراءة خيارات متعاقبة؛ المتابعة تنفصل عن `forkJoin` ولا تبقيه مفتوحًا |
| استعلام القائمة بالخادم | `Service.GetManyAsync` يبني استعلامًا بلا تتبع، يعد الصفوف، ثم يرتب ترتيبًا ثابتًا ويطبق التقطيع؛ `MaterializeListAsync` يسقط حقول القائمة في الاستعلام | حدّا تجسيد مصدريان للعدد والصفحة؛ عدد أوامر قاعدة البيانات الفعلي وخطة الوراثة غير مقاسين |
| تصفية الاتفاقيات | `AgreementStatusFilter` يبني استعلام معرفات اتفاقيات بشرط الحالة ثم يستخدمه داخل استعلام العملاء | لا تجسيد أو قراءة لكل عميل من هذا الفلتر؛ خطة الربط والفهارس المنشورة غير معلومة |
| تصدير القائمة | صفحات من ١٠٠ بنفس التصفية والترتيب عبر `fetchAllPages` | عمل يتناسب مع عدد الصفحات؛ تجميع التصدير بالذاكرة باقٍ بعقده، ولا تقارن مدته بصفحة واحدة |
| إعادة محاولة الخيارات | قبل الإصلاح كانت تعيد جميع الخيارات؛ الآن تتخطى المراجع التي أصبحت متابَعة | تحسين مؤكد في حدود المصدر ومنع استبدال اللقطات؛ لا يدعي زمنًا مقاسًا أو انخفاضًا ثابتًا في الشبكة |

تقييم الفهارس: روجعت إعدادات الكيان الفعلي والأساس المرتبط والاتفاقيات، بما فيها الجداول `IndividualPartner` و`Partner` و`Agreement`. تحدد العلاقات مفاتيحها الخارجية، بينما لا تعلن هذه الملفات فهرسًا مركبًا خاصًا بطلب الشاشة. لا يعني ذلك غياب فهرس من المخطط المنشور. بسبب التوارث وتوزع حقول التصفية بين الجداول، وعدم وجود خطة أو حجم بيانات أو بطء مثبت، لا يبرر الإصلاح الحالي اقتراح فهرس مركب جديد أو فهرس لكل عمود. لا مفاتيح أو تضمينات أو مرشحات جديدة مقترحة، وبالتالي لا كلفة كتابة أو تخزين جديدة. إن أثبت قياس المالك كلفة فلتر الاتفاقيات أو ترتيب الصفحة، تُراجع أولًا تغطية المفتاح الخارجي وخطة الربط والفهارس الفعلية قبل تحديد مفاتيح مرشح؛ لا يجوز تخمين فهرس على جدول لا يملك العمود.

خطة قياس قابلة للتكرار: نفس إصدار الواجهة والخادم ونفس المستأجر والفرع واللغة وحجم البيانات والتصفية والترتيب وحجم الصفحة؛ خمس عينات باردة وخمس دافئة لكل من القائمة والتعديل والتصدير. يسجل المالك زمن الطلب وحجم الاستجابة ووقت العرض، وأوامر قاعدة البيانات وقراءاتها وخططها بتفويض مستقل. يقارن إصدار ما قبل هذا الإصلاح وبعده، مع إعادة محاولة فشل مصدر واحد وتحديث كاش محتفظ به. لا زمن قبل/بعد متاح في هذه المهمة، ولا هدف رقمي مخترع.
