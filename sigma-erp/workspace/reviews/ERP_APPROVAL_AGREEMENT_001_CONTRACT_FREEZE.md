## العقد المعتمد وحدوده

المعالجة تخص نوع المستند العام `Agreement`، وليست تنفيذ الموافقات لعقود التأجير `RentalAgreement` أو تعديل آثارها. نتيجة المراجعة وأدلتها في [سجل المتابعة](ERP_APPROVAL_SCREEN_REVIEW_TRACKER.md#البند١--الاتفاقيات-العامة--general-agreements-agreement).

| الاهتمام | القرار والمالك |
|---|---|
| انطباق السياسة | حذف تسجيل `Agreement` وحده من DocumentApprovalCatalog؛ ينخفض الكتالوج من٧٧ إلى٧٦. يبقى رقم١ في جرد المراجعة التاريخي كنوع مستبعد، ولا يعاد ترقيم بقية البنود |
| السياسات والمستندات | لا نوع سياسة عام جديد، ولا توريث/تحويل تلقائي إلى المشتقات؛ الرفض للنوع غير المدعوم يتبع مالك الخدمة الحالي |
| الكتابات | منع AddAsync/UpdateAsync/RemoveAsync/HandleActivateAsync على Agreement عبر مالك تصنيف/حراسة HTTP نفسه المستخدم لجذر InvoiceBase؛ المنع قبل تجاوز المدير وباستجابة405؛ لا منح قابلة للإسناد لهذه الأفعال |
| القراءات | بقاء GetSelect وبقية قراءات Agreement وعقود استجابتها وحدود الشركة/الفرع والصلاحيات كما هي؛ لا تغيير اختيارات فاتورة النقل أو قارئي الوديعة/القبض/الصيانة |
| البيانات | إبقاء الكيان والعلاقات والسجلات والسياسات والمحاولات المحفوظة دون حذف أو تحديث بيانات. لا هجرة؛ السياسة العامة القديمة لا تصبح سياسة لمشتق |
| الواجهة | قائمة Settings تستهلك كتالوج الخادم دون فلتر منافس بالواجهة؛ لا تغيير نموذج أو حسابات أو ListVM |
| دليل المستخدم | إضافة توضيح بالعربية والإنجليزية لموضوع الموافقات داخل دليل Administration، عبر مساره القائم /UserGuide/administration |
| التحقق | مواصفات مصدرية لمسار الفلتر الفعلي، والمنح القديمة/المدير، وبقاء القراءات وفصل الكتالوج؛ بناء مشروع الاختبارات المتأثر فقط. تنفيذ الاختبارات وHTTP/المتصفح/SQL معلق |

## التناسب والمطابقة

هذه معالجة محددة مبنية على توصية مقبولة؛ لا تصميم جديد أو طلب موافقة متكرر. مهارة Sigma والكتب Master4/5/7 وBE6/8/10 وUI26 هي المرجع؛ مالك النمط الفعلي PermissionEndpointResolver وPermissionAuthorizationFilter وحماية InvoiceBase السابقة، دون تغيير قواعد ذلك الجذر. فحص recipe -Check نجح للحزم الثماني قبل استخدام الحزمة. دليل سبيد وكوده C0539 المؤرخ2026-10-28 تمت مطابقتهما في المراجعة؛ يخصان شاشة عقود فعلية ولا يقرران وجود شاشة للجذر العام. لا حاجة لفجوة أودو إضافية.

التحميل/cache والأداء: لم تتغير طلبات القراءات أو الإسقاط أو التقطيع أو invalidation؛ لا قياس سرعة أو اقتراح فهرس جديد لأن التغيير تصنيف ومنع كتابة، ولا يغيّر predicates/joins. بقاء تكلفة GetSelect العامة وقياس الحجم وخطة SQL ضمن متابعة الأداء، دون توسيع التنفيذ إلى مالك مشترك غير مصرح.

## عقد المراجعة الموسعة

بعد طلب «راجع كل البنود»، تفحص البنود٧٧ بنطاق Approval مصدري: الاسم الإنجليزي، المسار والمستهلك الحقيقي، الأفعال والآثار، بوابة الموافقة الفعلية، الصلاحيات والفروع وواجهة السير والملاحظات والقرارات والقبول المتبقي. أُسندت مجموعات٣–٢٧ و٢٨–٥٢ و٥٣–٧٧ لثلاثة وكلاء قراءة فقط بملفات تقرير مستقلة غير متداخلة؛ الجذر يملك البندين١ و٢ ومعالجة١ والمصالحة والتتبع. لا تفويض تنفيذ آثار مالية أو صلاحيات جديدة في بقية البنود، ولا اعتبار فحص Approval قبولًا كاملًا لكل حقل في كل شاشة.
