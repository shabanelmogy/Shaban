## الأدلة والاكتشاف

الصورة دليل على الفترة والإجمالي وعمودي نوع المصروف والمبلغ وRefresh وExcel وPrint؛ لا تثبت مصدر الأرقام أو صلاحيات الخادم. لم يكن للشاشة مسار أو مكوّن أو API قائم، وكان بند Expenses في sidebar-menu-data يفتح Account. تعريف VehicleExpense يحمل Code وDescription وCategory فقط، وExpenseType يحمل Name؛ لا علاقة محفوظة بينهما وبين قيود المصروف. اعتمد المالك تجميع حسابات المصروفات من القيود المرحّلة المرتبطة بمركبة.

قُرئ دليل Speed بتاريخ2026-10-27، الفصل16 للربحية والتقارير، والمصدر S003 «A Magic Wand to Control Your Expenses» من `library/pages/875ba9f800dd4684.html`؛ شرح عام لا يحدد حساب التقرير. قُرئ تقرير Expenses20 من لقطة2026-10-28: المسار R0424 والمتحكم C1083، والأصل `raw/application.js:286958–287074`. يثبت period وgetVehicleExpenseReport وتجميع مبلغ الصفوف والتصدير. تقريب Speed للإجمالي إلى عدد صحيح لا يُنقل؛ تحكمه سياسة Sigma المالية. تقرير Vehicle Expense Type21 تفصيلي مستقل خارج النطاق. فُحص مدخل Odoo19 المكمل بعد Speed؛ تبقى حسابات Sigma الفعلية وقرار المالك مصدر هذا التقرير، ولا يُستنتج تصنيف مالي من وصف خارجي.

استخدمت مهارة Sigma ومهارات Superpowers المتاحة للمراجعة والتصميم المحدود والتحقق، وAngular21.2.25 مع المكونات المشتركة. كتل UI20/21/22 وBE17 وشكل UI07 تحكم التنفيذ، ومرجع ReportPage/ReportActions وStatementOfAccount. أظهر فحص الوصفات اختلاف مشتقتين؛ أُعيد توليد PLAN00 وPHASE06 من مصادرهما عبر المولد، ثم نجح فحص الوصفات الثماني. لا تعديل يدوي لحزمة مولدة.

## التحقق والأداء

التنفيذ المصدري اكتمل، ونجح بناء الواجهة والخادم وتجميع مواصفات التقرير. لا تشغيل اختبارات أو متصفح أو قاعدة بيانات أو التزام أو نشر ضمن هذه المراجعة. تبقى خطة SQL والقياس البصري والمخرجات الفعلية قبولًا منفصلًا.

المسار الخلفي يستخدم ثلاث قراءات ثابتة: عملة الأساس، وفحص دقة مساهمات القيود قبل التجميع، ثم تجميع SQL بالحساب مع الحسابات النهائية عديمة الحركة. لا طلب لكل صف، ولا قراءة لكل سند، ولا تحميل لجميع تفاصيل القيود إلى الذاكرة. الإجمالي يحسبه الخادم من صفوف الحسابات المجمعة بالسياسة المالية، ولا يجمع حسابات الأبناء مرة أخرى. اعتمدنا الفهارس القائمة على مفاتيح القيد والمركبة والحساب. مرشح تحسين يحتاج خطة فعلية هو `JournalVoucher(SubscriptionId, IsPosted, IsVoided, Date, Id) INCLUDE (BranchId)` مع تقييم تغطية القيد والتفاصيل؛ لا إضافة فهرس قبل إثبات الحاجة وكلفة الكتابة والتخزين. لا تغيير مخطط أو هجرة. لا قياس سرعة قبل/بعد لأن الشاشة وقراءتها كانتا مفقودتين، وتوقيت SQL الفعلي معلق.

راجعت المطابقة جذور ReportEffects الفعلية: أضيفت العمليات الثلاث إلى BranchOperationRules. يخضع JournalVoucherDetail لملكية فرع السطر الفعلي، ويخضع Vehicle لفرعه الحالي. يحافظ القيد المختلط على المساهمات المسموحة دون عرض سطور الفروع الأخرى. تحمل الفلاتر FromDate/ToDate فقط، وتحمل صفوف الاستجابة AccountId للهوية وExpenseType وAmount للعمودين. لا AutoMapper أو علاقات جديدة؛ إسقاط التقرير مباشر، وتسجله آلية مسح واجهات الخدمات القائمة في DependencyResolver.

أضيفت مواصفات مصدرية لأصفار الحسابات دون تجميع أبوي، وآخر يوم والعكوس السالبة واستبعاد القيد غير المرحّل والملغى وغير المرتبط بمركبة والمستأجر الآخر، وفحص الدقة قبل أن يخفيها تعاكس المبالغ، والتحقق من التاريخ. تغطي مواصفات الإذن وجوب Read مع Print/Export ومالك ReportEffects؛ التنفيذ الفعلي وSQL Server ما زالا معلقين.

المكونات النهائية: ReportPage وFeatureTitle وReportActions وSummaryCards بإجمالي واحد وDataTable بعمودين فقط. يبقى الترقيم في قاع منطقة النتائج وتظل أدواته متاحة إذا اختار المستخدم حجم صفحة أكبر من الصفوف، فلا تختفي وسيلة تغييره. لا تغيير للمالك المشترك أو حسابات مالية في الواجهة. يملك report-read-state التبديل والإلغاء والمخرجات المستقلة، وخيارات التقرير محلية. دليل التطبيق في `SiGmaAngularFrontEnd/src/app/modules/UserGuide/content/vehicle-expense-report-topic.ts`، ضمن دليل Reports الحالي. أضيفت الملفات الأربعة الجديدة صراحةً إلى tsconfig.app.json لحماية تجميع التطبيق من مشكلة مداخل الملفات المفقودة السابقة.

التنفيذ المتوازي استُخدم بعد تثبيت العقد: وكيل بنفس النموذج الموروث لملفات الواجهة حصريًا، والجذر للخادم والعقود والمطابقة. روجع تسليم الواجهة في الجذر وصُححت ملاحظة عمر أدوات الترقيم قبل البناء. لم تصل نتيجة طلب المراجعة الإضافي من الوكيل السابق قبل استكمال المحادثة؛ أُسندت مراجعة نهائية مستقلة للقراءة فقط إلى وكيل محدد النطاق، ولا تُحتسب نتيجة غير مستلمة. حدّ الفصل بين المستودعين من التعارض وتكرار الاكتشاف. قُرئ مكمل Odoo19 `applications/hr/fleet/service.rst` بعد Speed، وهو يوضح فصل نوع الخدمة والمركبة والتكلفة وربط فاتورة المورد؛ لا يقرر وحده تصنيف حساب Sigma، الذي حسمه المالك صراحةً.

نجح بناء مشروع `tests/SiGma.BranchAccess.Tests/SiGma.BranchAccess.Tests.csproj` مع مشروع API واعتمادياته إلى مجلد مخرجات معزول `.codex/builds/vehicle-expense-backend` برمز خروج0: عدد الأخطاء0 والتحذيرات41 خارج ملفات التقرير الجديدة. لم تُنفذ الاختبارات. تعذر البناء الأول إلى مجلد التشغيل بسبب قفل DLLs من نسخة API المفتوحة؛ لم نوقفها ولم نعدّلها. يلزم إعادة بناء وتشغيل نسخة API المحدثة عند القبول لتسجيل المسارات الجديدة. سجل النتيجة `.codex/vehicle-expense-backend-isolated-build.log`.

نجح بناء `npm run build -- --configuration=development` إلى `.codex/builds/vehicle-expense-report` برمز خروج0. راجع الجذر مصدر الملفات الجديدة والفروقات المحددة في كل مستودع، واجتاز `git diff --check` النطاق المتأثر. اجتازت المطابقة المصدرية المسارات والمنح ودقة المبالغ وغياب حساب مالي في الواجهة ووجود عمودين فقط ومخرجات كاملة. فحص الوصفات النهائي8/8 ناجح. سجل بناء الواجهة `.codex/vehicle-expense-frontend-build.log`.

طابقت مصادر خرائط الحزمة النهائية ملفات المكوّن وقالب HTML والخدمة والترجمة ودليل الشاشة حرفيًا بعد تطبيع نهاية السطر. انتهت المراجعة المصدرية المستقلة المحددة دون مشكلة مؤكدة تتطلب تعديلًا: شملت التجميع وLEFT JOIN بالمبلغ nullable والفروع والتواريخ وعلامات المبلغ ودقته والمنح والمخرجات وأعمار الطلب والترقيم. لم ينفذ المراجع بناءً أو اختبارًا أو تشغيلًا؛ نتائج البناء المذكورة منفذة بواسطة الجذر، وقبول SQL والواجهة منفصل.

متابعة TS2339 حول showPaginator: الرسالة المرسلة من المالك تخص محاولة بناء في18:25:35Z؛ سجل البناء النهائي الناجح في18:32:34Z أحدث منها. الخاصية موجودة في المكوّن الحالي، وأُعيد التحقق من تطابق ملفَي TypeScript وHTML حرفيًا مع مصادر الحزمة الناجحة ووجود الخاصية والنداء فيها. لم يُعَد إنتاج الخطأ على الملفات الحالية، ولا دليل يبرر تعديل منطق صحيح أو حذف ذاكرة تجميع. لم توجد عملية Angular serve أو مستمع4200 وقت الفحص؛ لا عملية نشطة لإعادة تشغيلها. يحتاج التشغيل التالي قراءة المصدر الحالي. لم يُغير مصدر التطبيق في متابعة هذه الرسالة.

## القبول المتبقي وتسليم المتابعة

أعد بناء وتشغيل API المحدث، ثم افتح التقارير ← المالية والمصروفات ← Vehicle Expense Report. تحقّق من الشهر الافتراضي، وآخر يوم، وحساب بلا حركة بصفر، وعكس مرحّل بالسالب. راجع حسابًا مقيّد الفروع وقارن إجمالي القيود المسموحة بالنتيجة. جرّب تغيير حجم الصفحة والعودة منه، ثم Print وExcel لأكثر من صفحة للتأكد من جميع الصفوف وإجمالي واحد. هذه خطوات قبول مقترحة لم تُنفذ؛ لا يُثبت بناء المصدر SQL الفعلي أو الشكل أو المخرجات.

لا تغييرات AutoMapper أو كيانات أو EF أو هجرة أو بيانات. لا نشر أو التزام. رسالتا الالتزام المقترحتان فقط: للواجهة `feat(reports): add vehicle expense summary report`، وللخادم `feat(reports): aggregate posted vehicle expenses by account`.
