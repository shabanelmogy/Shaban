# خانة Rate لأيام الإيجار — عقد الإدخال الحالي

التاريخ: ٢ نوفمبر ٢٠٢٦. الحالة Frozen. المالك طلب أن تكون Rate في بند Rent
عدد الأيام من تاريخ البداية والإرجاع، دون بند زائد، وقابلة للتعديل. فوض اختيار
الأنسب بعد المقارنة. حُذفت رسالة اختيار نوع المركبة بطلبه، ويجب بقاء بطاقات
الإجماليات الأربع ظاهرة. هذه الشريحة لا تعيد تصميم سعر التعريفة أو فاتورة الإيجار.

## الاختيار المثبت

- التواريخ هي مصدر المدة المحفوظ. Rate في صف Rent يعرض مدخل أيام صحيحة موجبة
  محليًا؛ بقية صفوف Rate تحتفظ بمعناها وسلوكها الحاليين.
- تغيير البداية أو الإرجاع يعيد عدد الأيام حسب قاعدة أيام التقويم القائمة،
  بحد يوم واحد للفترة الصحيحة في اليوم نفسه. لا انتقال الآن إلى حساب ساعات سبيد.
- تعديل الأيام ثم مغادرة الخانة يغيّر يوم الإرجاع بالنسبة للبداية، مع الاحتفاظ
  بساعة الإرجاع السابقة. إن لم توجد ساعة إرجاع صحيحة تستخدم ساعة البداية.
- إذا ساوى العدد المدة الحالية لا يعاد ضبط الوقت أو إرسال طلب جديد.
- العدد مدخل صحيح موجب ضمن حدود DateTime؛ لا عشريات أو سالب أو صفر، ولا انتقال
  إلى سنة تتجاوز ٩٩٩٩. الحقل جزء من النموذج والمسودة والتحقق والـdirty guard.
- Save يطبق التعديل غير الملتزم أولًا ثم ينتظر التعريفة الحالية. لا يرسل
  عدد الأيام بدل السعر المالي أو إجماليًا موثوقًا؛ يحفظ تاريخ الإرجاع عبر API
  القائم ويعيد الخادم الحساب. لا حقل أيام مالي موازٍ ولا هجرة أو DTO جديد.
- تبقى بطاقات الملخص مركبة بعد bootstrap؛ تستعمل valuesPending في المالك
  المشترك لتعليق القيم غير المحسومة بدل إخفاء المربعات. لا spinner محلي ثانٍ.
- المخفي من مولد البيانات هو حقل الأيام التابع فقط، عبر mockDataIgnore عام
  اختياري في المحوّل الحالي. تولد التواريخ من السنة الحالية، ولا يغير هذا
  الإعفاء التحرير اليدوي أو شروط حفظ العقد. لا توليد يوم عشوائي ينسخ فوق التواريخ.
- View/Print يعرضان الأيام في Rate والمبلغ المحفوظ في Charges، دون إعادة
  تسعير تاريخي. لا تغيير لبقية الرسوم أو الفواتير أو الصلاحيات أو القفل.

## الأدلة والحدود

استكمال مصدر السعر: نُفذت [مطابقة نوع التعريفة والحفظ](RENTAL_TARIFF_PRICING_FINAL_RECONCILIATION.md)
بطلب المالك بعد استمرار غياب المبلغ. Rate تبقى أيامًا، والسعر المالي ووحدته
ظاهران للقراءة في الصف نفسه. معاينة الأيام تستخدم وحدة السعر اليومية أو
الأسبوعية أو الشهرية، ويجدد تغيير السياق السعر بدل الاحتفاظ بصفر سابق.

تعديل توضيحي بتاريخ ٢ نوفمبر ٢٠٢٦ بعد بلاغ أن الكتابة لا تحسب Charges:
تحديث حقل الأيام الصحيح يعرض معاينة مبلغ Rent والإجماليات فورًا، عبر مالك
الحساب الموجود وبسعر التعريفة المالي الحالي، دون طلب شبكة لكل ضغطة أو تغيير
التواريخ أثناء الكتابة. يبقى الالتزام بتاريخ الإرجاع على مغادرة الخانة أو
الحفظ كما سبق. السعر الصفري لا يتحول إلى سعر مفترض؛ المدة وحدها لا تنشئ تعريفة.
المصدر المؤكد: المدخل كان مربوطًا بـonBlur فقط، بلا مستهلك valueChanges للأيام؛
InputNumber المثبت يحدث نموذج Angular قبل إخراج onInput. أضيف مستهلك محدود
وملغى عند تدمير المكوّن، ولا تعديل API أو ملكية الحساب المحفوظ أو رسوم أخرى.

الأساس سبيد بالشرح والكود، وOdoo مكمل للنقص أو الغموض فقط حسب توجيه المالك
الأخير. C0530 في لقطة سبيد٢٨ أكتوبر يربط تاريخي العقد بحساب الأيام والساعات؛
لا يثبت نفس اختصار الإدخال المقترح. وثيقة Odoo19 الرسمية لإنشاء طلب الإيجار
تربط مدة الطلب بالتواريخ وإعادة التسعير. ربط المدخل القابل للتعديل بتغيير
الإرجاع اختيار سيجما محافظ يبقي API والحساب المحفوظ متفقين، وليس ادعاء حقل
مطابق في Odoo أو نسخة من معادلته المالية. الشرح/اللقطات لا تثبت تشغيل سيجما.

المراجعة مصدرية وفق القواعد الحية: TS/Angular parsing، عقود المالكين والاستيراد
والمفاتيح والفروق. لا build/test/lint/DB/migration/commit/push/deploy. تعذر الوصول
للتطبيق بأداة المتصفح موثق سابقًا؛ قبول إدخال الأيام والـblur/Save والتبديل
والإلغاء والطباعة وثبات الملخص لدى المالك بعد البناء والتشغيل.
