## الأدلة والقرارات

كان المسار القائم يستدعي Report/CollectionAndRefundsReport بلا متحكم مقابل، ويخلط جدولًا مسطحًا بشجرة، ويفتقد Created By. كان يقرأ الفروع مرتين ويجلب العملاء كخيارات للمندوب، ثم يرسل أسماء مرشحات مختلفة عن أسماء عناصر النموذج، ويضيف يومًا في تحويل التاريخ، ويراكم النتائج عند إعادة البحث. طلب المالك المراجعة والتنفيذ وفق صورة Collection And Refunds Report 2/1.png.

قُرئ دليل Speed النصي فصل ١١، وشرحا S077 وS080 المحفوظان في مكتبة ٢٧ أكتوبر، ثم كود ٢٨ أكتوبر لشاشة Reports10 ومسار R0420 ومتحكم C0975 مستقلًا. يثبت الكود المرشحات الخمسة وقراءتي التقرير والتصدير. لا يحتوي على حسابات الخادم لتوزيع الأعمدة. استُخدمت وثيقة Odoo 19 payments.rst المحفوظة في لقطة ٢ نوفمبر لتوضيح الفرق بين الدفعة المرتبطة وغير المخصصة. مصدر الدليل الإضافي لا يحدد الحسابات في Sigma.

## التحميل والكاش والأداء

يرتبط المسار الفعلي بمكون CollectionAndRefunds2 نفسه، والخدمة الجديدة تستهلك CollectionRefundDetailReports/Options وRead وPrint وExport. طلب الخيارات مباشرة يجمع الخيارات التشغيلية المسموحة، وطلبات التقرير ومخرجاته قراءات مالية مباشرة. لا ذاكرة مالية أو مصدر lookup اختار reference cache في هذا المسار. يملك createCollectionReportState الطلبات وstart/finalize، ومالكه المرئي LayoutComponent عند showPageLoading الافتراضي، مع منع مؤشر جدول ثانٍ. تلغي تغييرات الفلاتر أو المستخدم أو نطاق الفروع أو إصدار الوصول الطلبات والمخرج المحضر. يستخدم Print الجلسة المشتركة للتحقق قبل نافذة الطباعة.

أزال مصدر الواجهة قراءتي الفروع المستقلتين وتراكم الصفوف. لا تؤكد هذه التغييرات سرعة مقاسة. يجب مراجعة ترجمة SQL وخطته وتوقيت القراءة على بيانات واقعية. تُفحص استعلامات الخادم المجمّعة وربط الفهارس أثناء المصالحة. تسجل نتيجة البناء والمراجعة النهائية بعد اكتمال الدمج.

## مصالحة المصدر والأمن

ترجع الخدمة الصفوف من سندات القبض المؤهلة، وردود الوديعة ذات القيد المرحل الصحيح، وسندات الصرف المعتمدة لعميل فردي أو شركة. تثبت صلاحية مصدر الصرف بضم مجموع سطوره المجمع في SQL إلى إثبات القيد. يُستبعد الدفع المملوك للمورد أو الرواتب أو الأقساط، وتظهر مدفوعات العملاء غير المرتبطة بعقد في Others وبلا بيانات عقد أو مركبة.

تقرأ فئات الإيجار والمخالفات وسالك من JournalVoucherAllocation المنشورة والبنود المحفوظة للفاتورة. يطابق القارئ العملة والطرف وإجمالي البنود والضريبة والمبلغ، ثم يوزع قيمة التخصيص عبر FinancialNumberPolicy.AllocateProportionally مع حفظ أصغر وحدة نقدية. يبقى Darb وغير المخصص في Others. مصدر إنشاء فاتورة الإيجار يختار مبالغ موجبة، وRentalInvoicePostingPolicy يحتفظ بقيدها الموجب، وAccrualsService.Prepare يرفض البنود السالبة؛ لذلك احتفظ القارئ بنفس شرط البنود الموجبة. رد الوديعة سالب في Deposit بقرار المالك.

وجدت المراجعة المستقلة تكرار ترجمة عمودي Others وOther إلى الاسم العربي نفسه، وكان مصدر Excel القائم يجعل الاسم مفتاحًا للخلية. عولجت التسميتان إلى مبالغ أخرى وطرق دفع أخرى. تُكتب بيانات العنوان والفترة والعملة في صفوف وصفية تحت الأعمدة النصية القائمة، ويُمرر ترتيب الأعمدة الثمانية عشر صراحةً إلى مصدر Excel المشترك.

كشفت المراجعة أيضًا أن IgnoreQueryFilters داخل استعلام استبعاد مركب يعطل مرشحات الفروع في الاستعلام الخارجي. أصبح فحص هويات استعمال الوديعة وملكية السندات وتكرار قيودها قراءات مستقلة ترجع مصفوفات معرّفات داخل الشركة. تستهلك الصفوف والخيارات المصفوفات مع بقاء استعلاماتها المقيّدة العادية. يشمل الإصلاح مالك التحصيل المشترك المستهلك في التقريرين القائمين، بنفس عقودهما العامة. أكدت إعادة المراجعة المستقلة المصدرية انتهاء الملاحظتين.

أقصى عدد أوامر القراءة تسعة للتقرير الثاني وأحد عشر لخياراته، مع اختصار الأوامر عند غياب المصدر أو تطبيق مرشحات العقد. زاد فحص الهوية المشترك أمرًا واحدًا لقراءة تقرير التحصيل القائم وخياراته. هذه تكلفة صريحة للحفاظ على حدود الشركة والفروع، دون استعلام لكل صف. تحتاج أحجام مجموعات المعرّفات وترجمة الاستعلام وخطته إلى قياس تشغيلي.

تحقق فحص metadata بالقراءة فقط من الهدف sql5106 / db_a82a9c_sigmaoperations1. ظهرت فهارس Receipt وPayment للمراجع والفرع والعملة والقيد، وفهرس PaymentDetail.PaymentId وفهارس JournalVoucherAllocation.ReceiptId وJournalVoucherDetail.JournalVoucherId وRentalInvoiceItem.InvoiceId. ظهرت فهارس CustomerDepositRefund المركبة حسب الشركة والفترة أو الشركة والفرع والفترة وفهرس القيد الفريد. لم يكشف الفحص فهرس فترة مركبًا لسندات القبض أو الصرف. اقتراح القياس هو فهرس لكل منهما بالمفاتيح (SubscriptionId, Date, Id) وتضمين BranchId/CreatedBy/ApprovalStatus/IsVoided، مع اختبار أثره على نطاق الفرع وعمليات الكتابة وحجم التخزين قبل اختيار مخطط جديد. لا تغيير schema مطلوب للتنفيذ الحالي.

وُثقت قاعدة حفظ نطاق الفروع في BE9 ومهارة Sigma في صف مراجعة ١٨ نوفمبر، وجُددت الحزم الثماني بالمولد ثم نجح فحص الاتساق. المراجعة المصدرية النهائية للوكيل المستقل تخص التصحيح الأمني وصحة التوزيع والحقول والمخرجات، وتظل منفصلة عن قبول التشغيل.

## التحقق وقبول المالك

أضيفت ثلاث مواصفات مصدرية في tests/SiGma.BranchAccess.Tests/CollectionRefundDetailReportTests.cs. تغطي الإشارات ومنع تكرار استعمال الوديعة وعدم توفر تكاليف بطاقات الصرف، والتوزيع الدقيق لأصغر وحدة مع باقي المبلغ، ومستخدمًا مقيّدًا بفرع واحد وصفوفه وخياراته وشجرة الاستعلام. تجميعها يتحقق من الأنواع فقط، وتنفيذها غير مصرح في هذه المهمة.

قبول المالك المتبقي يشمل تشغيل API المحدث، وتجربة Read/Options/Print/Export على SQL Server، وصفوف قبض وصرف ورد وديعة جزئية، وتخصيص فاتورة مختلطة مع الضريبة، وتغيير المرشحات والصلاحيات، ومقارنة الخادم والجدول والطباعة وملف Excel في اللغتين والثيمين. تعرض تكاليف البطاقات غير المسجلة وإجمالياتها المتأثرة كخلايا فارغة. لا تعرض الشاشة ملاحظات شرح إضافية داخل الجدول.

نفّذ وكيل الواجهة مجلد التقرير فقط، ووكيل الخلفية قارئ المصادر ومواصفاته، ووكيل ثالث مراجعة مصدرية مستقلة. احتفظ الجذر بالعقد والقرارات والربط والترجمات والدليل والتحقق والمصالحة. استعمل الوكلاء النموذج الموروث، بملكية ملفات منفصلة لتقليل زمن العمل المتوازي، وعادت ملاحظات المراجعة إلى إصلاح مصدرها.

رسالتا commit المقترحتان هما Update collection and refunds detail report للواجهة وAdd scoped collection refund detail reader للخادم.

أكد الفحص المصدري تطابق أسماء خصائص DTO وصف Angular، ووجود ١٨ اسم عمود مختلفًا في العربية والإنجليزية، وفحص فرق المصدر في مستودعي الواجهة والخادم. روجع فرق الوثائق والحزم المجددة وفحص اتساقها. لم تُنفذ اختبارات التشغيل أو المتصفح أو نشر أو commit. عملية قاعدة البيانات الوحيدة في هذا النطاق قراءة metadata للفهرسة بلا تعديل صفوف أو مخطط. لا هجرة جديدة مطلوبة للتقرير الثاني.

حُدث دليل الشاشة داخل قسم التقارير بمساره القائم /UserGuide/reports. يلزم تشغيل نسخة API المحدثة لإتاحة CollectionRefundDetailReports، وتظل تجربة HTTP وSQL Server والواجهة والطباعة/Excel وقياس الزمن معلقة للمالك.
